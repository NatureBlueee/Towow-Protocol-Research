# 研究方法地图

| 方法 | 适合回答 | 代表材料 | 当前证据角色 | 主要误用风险 |
|---|---|---|---|---|
| 概念谱系重建 | 一个概念解决过什么缺口、后来被什么替代 | 原始 handoff lineage、v1.0 loss audit | 理论追溯 | 用最新术语覆盖历史能力 |
| 形式反例 / 命题 | 某种合并或普遍主张为何不成立 | 静态投影、Authority 正交、Effect 链 | 设计依据 / 划界 | 把教科书结果包装成新证据 |
| 合成机制实验 | 某机制在显式生成假设下可能产生什么 | Boundary Oracle、概率、R6 | 机制探索 / CI | 样本量冒充现实外推 |
| 构造一致性测试 | Schema、事件图和 Router 是否按定义运行 | ontology/materiality、OPCBench | CI / 可执行后果 | 出题、答题、评分自指 |
| 有界模型检查 / mutation | 安全不变量能否抓住被建模捷径 | 状态探索、mutation tests | 形式保障 | “范围内无反例”冒充生产安全 |
| 真实仓库与状态域实验 | 实际路径、权限、日志和消费者如何失败 | R5、R5.2 | 决策性工程证据 | 把局部 bug 升格为普遍社会理论 |
| 真实模型配对实验 | 模型互动是否改变候选和结果 | R5.4 | 决策性负结果 | transport failure 导致不公平基线 |
| 跨技术权威域形成 | probe、拒绝、readback 是否形成技术路径 | R5C | 最强有限建设性证据 | 把软件域当成人类 Principal |
| 公开制度过程编码 | 识别 Authority、Standing、Effect 和 reopen | v0.6 七案 | 档案校准 | 选案和单编码者偏差 |
| 去标识访谈重分析 | 发现非正式权威、自治、资源和机制多样性 | QDR | 定性校准 | 将别的制度域外推 OPC |
| 盲化历史诊断 | 判断结构是否能提前暴露风险 | checkpoint | 仪器校准 | 高召回误写成预测能力 |
| 前瞻性真人研究 | 委托、认领、因果形成和净值 | H0–H4、Q2/Q3 | 尚未执行 | 计划复杂度超过执行能力 |
| 主张—证据—Design Delta 账本 | 区分发现与事后确认 | v1.2 decision ledger | 研究调度 | 事后回填时序造成虚假因果 |

## 方法选择规则

下一项方法不由“能否生成漂亮结果”决定，而由待决问题决定：

1. 写明被卡住的设计决策；
2. 写明一个合理的反向结果；
3. 写明反向结果出现后具体改变什么；
4. 选择最便宜、能区分结果的方法；
5. 若结果无论如何都只会保留同一设计，则归入 CI、说明或实现检查。

## 方法之间不能互相替代

- 形式反例能推翻普遍主张，不能给出现实频率；
- 合成实验能暴露机制和参数敏感性，不能证明真实净值；
- 真实仓库实验能证明工程语义，不能证明人类认领；
- 公开档案能校准制度变量，不能证明 Towow treatment effect；
- 真人单案能建立 existence proof，不能证明总体优势；
- 长期重复关系才能开始回答编译复用和后悔。
