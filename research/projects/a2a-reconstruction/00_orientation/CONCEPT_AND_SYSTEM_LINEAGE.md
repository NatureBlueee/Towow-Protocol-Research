# 概念与系统谱系

本谱系按“解决的缺口”组织，不按是否成为当前 root 排名。

## 发现与边界线

`HDC / FHRR / 多语义签名`
→ `NAC / NC`
→ `BIC / task-relative boundary`
→ `Boundary Oracle / Context Compiler`

- 保留能力：从主体完整世界中只形成任务相关的可交互边界；
- 被放弃的过强主张：固定向量或 NAC 是开放任务族的普遍充分表示；
- 当前接口：本地查询、Unknown、最小披露、可反驳边界响应。

## 共同问题构成线

`Coordination Schema`
→ `SJAC`
→ `JAA / Shared Artifact`
→ `RelationVersion + Institutional Frame`

- 保留能力：任务、角色、动作、权威、证据和结果语义可以在互动中形成；
- 当前分层：制度框架提供元规则，具体 RelationVersion 记录事项版本；
- 风险：把所有变化都叫 schema change，或把 Shared Artifact 误作唯一全局真相。

## 可能性与能力线

`Unknown 分类`
→ `PFE / formation operator`
→ `CRA`
→ `Capability Claim / AssuranceCase`

- PFE 处理怎样改变可达行动集合；
- CRA 处理形成后的路径是否足以被承诺；
- 两者不能因都涉及“做得到”而合并；
- 当前开放：现实中 formation operator 的因果增量和 Capability Claim 的前瞻预测力。

## 权威与规范线

`Principal / Sovereign Domain`
→ `Agent Entity / Authority Locus`
→ `Mandate`
→ `Recognition / Stance`
→ `Commitment / Reservation`

- 身份只回答行为归因；
- Mandate 回答允许代表谁做什么；
- Recognition/Stance 回答主体对精确版本的立场；
- Commitment 回答对未来行为、资源或责任的承担；
- 当前开放：哪些对象应显式暴露给真实用户。

## 现实效力线

`ActionAttempt`
→ `Effect`
→ `Verification`
→ `Adoption`
→ `Acceptance`
→ `Settlement / Dispute`

这是被 R5/R5.2/R5C 最强支撑的线。它阻止三类错误：

- 生产者日志冒充目标域改变；
- 目标域采用冒充 Principal 接受；
- 一次绿色结果抹掉撤销、离线、争议和恢复历史。

## 运行时线

`Harness`
→ `Effect Gateway / Event Ledger`
→ `Formation Phase`
→ `Compiled World`
→ `Defeater + scoped reopen`
→ `Mechanism Router`

该线的稳定洞见是“开放判断与确定性运行需要不同控制制度”。尚未确定的是 Router 自动化程度、
真实编译净值，以及中心语义层与联邦拓扑的构建顺序。

## OPC 应用线

`Responsibility Root`
→ `OPC Operating Envelope`
→ `Task Sovereignty`
→ `Capability Graph`
→ `temporary coalition`

这些是对核心主体模型的 OPC 视图，不是新的权威事实根。OPC 的关键贡献是把个人责任、多个
Authority Locus、外部能力网络和注意力稀缺放在同一真实使用场景中。

## 六个 canonical roots 的正确位置

```text
Entity
Mandate
RelationVersion
Assertion
Commitment
Operation
```

它们是 v0.4 以后为了统一事件和实现生命周期提出的 aggregate root 候选。以下内容不能从
“只有六个 root”推出：

- Boundary Oracle 不重要；
- PFE/CRA 已被 RelationVersion 吸收；
- Effect 与 Acceptance 可以只是相同 Assertion 的两个标签；
- Compiled World 只是最终投影；
- 历史体系之间的差异已经被证明可无损合并。

更安全的整合方式是统一引用和事件接口，同时保留异构机制的原生状态与验收用例。
