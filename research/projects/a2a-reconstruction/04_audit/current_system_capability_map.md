# 当前可建设系统能力图

## 结论先行

当前最可建设的系统不是一个更大的统一本体，而是：

```text
七条异构研究内核
        ↓ 通过引用而不是对象熔合
共享接口：identity / version / event / evidence / provenance / dependency
        ↓ 按问题组合
平台 / 中心 Agent / 本地 Oracle / 双边形成 / 联邦关系 / 确定性执行 / 人工裁决
```

六个 canonical roots 适合承担“已经进入关系运行时的正式事实”，不适合替代发现协议、
问题形成、能力资格化、Harness 研究 IR 或机制 Router。

## 第一层：异构研究内核

| 内核 | 当前作用 | 能力引用 | 当前判断 |
|---|---|---|---|
| Discovery providers | 生成任务投影、方向性信号和候选 | CAP-DISC-001, CAP-DISC-002, CAP-DISC-003, CAP-DISC-004, CAP-DISC-005 | HDC/NAC 可替换；前缀预算和方向性仅部分保留 |
| Boundary Oracle | 返回 cut、witness、unknown、refuse | CAP-DISC-006, CAP-DISC-007 | 充分性思想已转换；类型化运行协议需恢复 |
| Relation constitution | 形成 Schema、版本和多作者共同对象 | CAP-REL-001, CAP-REL-002, CAP-REL-003, CAP-REL-004, CAP-REL-005 | 版本与承诺保真；本地 column 机制丢失 |
| Formation planner | 将 Unknown 路由到 probe、反条件和条件创造 | CAP-FORM-001, CAP-FORM-002, CAP-FORM-003, CAP-FORM-004, CAP-FORM-005 | 技术局部成立；真人 causal formation 未成立 |
| Capability assurance | 环境索引 claim、holdout、组合资格化和恢复 | CAP-CAP-001, CAP-CAP-002, CAP-CAP-003, CAP-CAP-004, CAP-CAP-005 | 单 claim 和 readback 强；组合与前瞻仅部分 |
| Authority runtime | 责任根、Mandate、Stance、Commitment、Standing | CAP-AUTH-001, CAP-AUTH-002, CAP-AUTH-003, CAP-AUTH-004, CAP-AUTH-005 | 核心权威链保真；第三方 Standing 部分 |
| Reality-effect runtime | Attempt、Effect、Adoption、Acceptance、恢复 | CAP-EFF-001, CAP-EFF-002, CAP-EFF-003, CAP-EFF-004, CAP-EFF-005 | 当前保真度最高、证据最直接 |
| Harness research runtime | Problem/Design/Engineering IR、Context、Evidence Closure | CAP-RUN-001, CAP-RUN-002, CAP-RUN-005 | 不能由关系本体替代；必须恢复独立 owner |
| Formation compiler | 稳定子图编译、Defeater 和 scoped reopen | CAP-RUN-003, CAP-RUN-004 | 机制可实现；现实复用净值未证 |
| Coordination router | 选择中心、平台、联邦、人类和确定性机制 | CAP-RUN-006, CAP-RUN-007 | 条件规则清楚；从原材料自动推断仍开放 |

## 第二层：共享接口

共享接口只统一跨内核引用，不要求各内核放弃原生对象。

| 接口 | 最小含义 | 不应承担什么 |
|---|---|---|
| `entity_ref` | 指向 Agent Entity、责任根或 Authority Locus | 不把 Entity 当 Principal 的全部意见 |
| `version_ref` | 指向精确 RelationVersion、Mandate 或 Operation spec | 不自动继承旧 Stance |
| `event_envelope` | 记录谁、何时、针对什么版本发生什么 | 不把事件存在当 Effect |
| `evidence_ref` | 指向来源、readback、probe、反例和 verifier | 不把 producer 日志升为目标事实 |
| `provenance_edge` | 保存候选、派生、贡献和结论的来源 | 不制造第二套正式状态 |
| `dependency_edge` | 表达哪些事实、授权和运行依赖什么 | 不由图存在自动决定 materiality |

## 第三层：按问题选择的机制组合

| 现实条件 | 优先机制 | 必须保留的内核 |
|---|---|---|
| Schema 成熟、权威可完整委托、Effect 可事务读回 | 平台或确定性服务 | Authority Gate、Effect chain |
| 信息可授权集中、存在可信 Hub | 权威感知中心 Agent | Mandate、版本、Effect/Acceptance |
| 私有世界不能集中，但问题语法稳定 | 中心协调 + 本地 Oracle | Boundary Oracle、本地 Stance |
| 角色、动作、证据或条件本身未形成 | 双边/多边形成 | Relation constitution、Formation planner |
| 多个独立责任根临时组装能力 | 联邦关系或临时联盟 | Capability assurance、Reservation、Commitment |
| 高语境身份判断或不可自动裁决价值冲突 | 人类经纪/裁决 | 来源、Standing、Stance、recourse |
| 关系局部稳定且可观察 | Formation compiler | 最小权限 Operation、Effect readback、Defeater |

## 稳定保留的能力

以下能力已经跨三个截点保持现实差异与行为 Gate：

- 精确版本与 Stance：CAP-REL-002、CAP-AUTH-003；
- 候选、承诺、授权和预留分离：CAP-REL-005、CAP-AUTH-002、CAP-AUTH-004；
- Principal/Entity 责任分离：CAP-AUTH-001；
- 环境索引能力和目标证据：CAP-CAP-001、CAP-CAP-003；
- Attempt/Effect/Adoption/Acceptance：CAP-EFF-001、CAP-EFF-002、CAP-EFF-003；
- 负状态、恢复和 identity：CAP-EFF-004、CAP-EFF-005；
- 形成的使用/停止条件与中心/联邦条件选择：CAP-FORM-005、CAP-RUN-007。

## 必须恢复的历史设计

### 1. 本地 column generation（已丢失）

CAP-REL-004 没有当前 owner。RelationVersion 能保存最后的候选，却不能重建：

- 候选在谁的私有世界产生；
- 为何只披露该候选；
- 未披露全集的情况下如何证明它改善当前解；
- 中心为什么没有权取得完整行动集。

恢复目标是一个本地候选/反例接口，不是恢复旧术语。

### 2. 类型化 Boundary Oracle（部分）

CAP-DISC-007 需要恢复 cut、witness、unknown、refuse 的结构化返回与提升规则。当前只有角色名和
原则，不能防止自由文本被误升为能力、授权或全局不可行。

### 3. Harness 三层 IR 与 Context Compiler（部分）

CAP-RUN-001、CAP-RUN-002、CAP-RUN-005 不是 RelationVersion 的内部字段问题。它们负责：

- 原始问题是否被目标缩小；
- 设计为什么选择；
- 实现是否真的覆盖设计；
- 当前执行者得到何种最小上下文；
- 主张怎样由证据和 Acceptance 闭合。

它们必须继续作为研究/工程运行内核存在。

### 4. 形成因果链与组合资格化（部分）

CAP-FORM-001、CAP-FORM-002、CAP-FORM-003、CAP-CAP-002、CAP-CAP-005 需要把 Unknown、
operator、holdout、依赖和容量从论文策略变成可回放 Gate。

## 可以删除的纯术语重复

删除缩写不等于删除能力。下列历史名词无需成为顶层事实对象：

- HDC/FHRR：作为 discovery provider 实现名；
- NAC：作为可选信号/连接器格式；
- BIC：作为 Boundary Oracle 的充分性判据；
- SJAC：作为关系构成研究线名称；
- JAA：其正式版本状态由 RelationVersion 承担，多作者贡献边另行保留；
- PFE：作为 formation strategy；
- CRA：作为 capability qualification pipeline；
- Assurance Case、Capability Envelope、Compiled World：作为派生视图或编译产物。

删除这些词时必须继续保留对应 CAP 能力；否则属于有损删除。

## 必须并列、不能合并的机制

- Discovery provider 与 Boundary Oracle：前者生成候选，后者对本地边界作权威响应；
- Formation planner 与 Capability assurance：前者创造条件，后者判断形成后的能力是否可依赖；
- Commitment 与 Reservation：规范义务和资源事实不同；
- Effect Gateway 与 Acceptance Stance：目标状态变化和主体接受不同；
- Harness IR 与关系运行时：研究/工程谱系和现实关系状态不同；
- 中心 Hub 与联邦 Relation：部署选择由任务决定，不能用一个默认拓扑覆盖。

## 六 roots 的合适运行时范围

| Root | 合适承担 | 不应吞并 |
|---|---|---|
| Entity | 可寻址实体、责任根引用、Authority Locus | 完整私有世界、Principal 全部认知 |
| Mandate | 范围、目的、期限、撤销和资源授权 | Capability、Acceptance、技术 token 本身 |
| RelationVersion | 当前共同关系版本与 material diff | 本地候选生成算法、Harness Problem IR |
| Assertion | 带来源的主张、未知、证据引用 | 独立维护第二套 Effect 或 Mandate 状态 |
| Commitment | 对精确版本的义务及预留引用 | 候选、Recognition、资源容量本身 |
| Operation | 被授权动作规范、尝试和幂等身份 | 自动生成 Effect、Adoption 或 Acceptance |

## 当前没有证据支持的能力

- 自动 Router 能从未经编码材料可靠判断 CollapseSafe：CAP-RUN-006；
- 真实 OPC 能低成本维护显式 Mandate：CAP-AUTH-002 的产品形态部分；
- 真人 Principal 条件下存在可消融的 causal formation：CAP-FORM-002；
- Compiled World 在真实重复关系中产生正净值：CAP-RUN-003；
- 联邦拓扑相对权威感知中心 Hub 有独立增量：CAP-RUN-007 的经验部分；
- 对抗性参与者下 Boundary Oracle 和 countercondition 仍可靠：CAP-DISC-007、CAP-FORM-003。

## 会改变产品或架构的开放问题

1. Q1：若权威感知中心 Agent 打平联邦系统，先建语义控制层，联邦成为条件插件。
2. Q4：若 Router 冷启动一致性低，它应成为人机 checklist，不应自动决定机制。
3. Q2：若显式 Mandate explain-back 失败，Mandate 保留为内部对象，用户只确认高风险差异。
4. Q3：若真实 formation 消融不成立，PFE 从核心引擎降为候选/过程日志。
5. Q5：若重复关系没有净节省，Formation Compiler 降为高风险场景的保障工具。
