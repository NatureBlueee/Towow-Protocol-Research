# 原生研究线 01：发现与边界

## 当时面对的真实问题

主体拥有巨大、私有且变化的本地世界。系统既不能先复制完整世界，也不能相信一份有限静态画像
已经包含未来任务所需的一切。最初设计尝试用 HDC/FHRR 形成跨模型可比表示，随后因角色绑定、
跨模型对齐和信息损失问题转向 NAC；第二轮又进一步把“边界”从固定描述改成任务相关的交互式
充分性判断。[SRC-PROBLEM-DEFINITION:11-31] [SRC-PROTOCOL-DESIGN:36-43]

## 原生机制与能力

### CAP-DISC-001：任务相关投影

- 区分：完整世界与某任务所需的最小投影。
- 机制：根据任务、角色和风险生成投影，而不是维护一次性全画像。
- 输入：本地世界、当前任务、角色、风险预算。
- 输出：可披露的任务相关事实和未知。
- 状态/权威：原始事实仍由本地域持有；投影不成为新的全局真相。
- 关键决定：投影必须随任务重新计算。
- 正例：同一主体面对采购和维护任务时暴露不同的相关维度。
- 移除失败：把投影当静态能力卡后，新任务所需条件被遗漏，或无关隐私被持续披露。
- 来源：[SRC-PROBLEM-DEFINITION:57-103] [SRC-NAC-SPEC:57-75]

### CAP-DISC-002：HDC 的角色绑定表示

- 区分：相同局部内容在不同角色中的意义，与无角色上下文的相似向量。
- 机制：HDC/FHRR 的绑定与叠加，用可组合表示承载角色—值关系。
- 关键决定：角色不能只作为外部标签，必须进入组合表示。
- 正例：资源、需求和约束在组合中仍能按角色区分。
- 移除失败：交换角色后仍得到相同相似度，导致错误候选。
- 证据边界：主要是设计与合成机制材料；跨模型对齐和解绑定损失促成后续降级。
- 来源：[SRC-PROTOCOL-DESIGN:1-43]

### CAP-DISC-003：NAC 的跨模型锚点

- 区分：共享自然语言全文与最小自描述锚点。
- 机制：以稳定 header、facet、provenance、version 组成可扩展信号；不同模型可保留内部表示。
- 输入：本地结构化意图或能力。
- 输出：可索引、可路由、可继续询问的 NAC。
- 关键决定：统一的是外部锚点，不是内部 embedding。
- 正例：两个内部模型不同的主体仍可基于相同 facet 继续发现。
- 移除失败：依赖模型内向量等价，模型升级或供应商变化后索引关系失效。
- 来源：[SRC-NAC-SPEC:1-55]

### CAP-DISC-004：前缀式渐进披露

- 区分：能路由的最小公开前缀与为完成判断所需的更深披露。
- 机制：信号前缀、披露深度、预算和 provenance 联动。
- 关键决定：先给可路由前缀，再按价值和风险扩展，而不是一次公开完整方案。
- 正例：初筛只暴露 facet；出现候选后再询问边界。
- 移除失败：全量公开导致隐私和策略信息泄漏；过小固定摘要导致漏配。
- 来源：[SRC-NAC-SPEC:37-75]

### CAP-DISC-005：SEEK/OFFER 方向性

- 区分：主体正在寻求什么与主体当前可以提供什么。
- 机制：方向性 signal verb，避免把需求和供给压成无方向标签。
- 关键决定：索引和匹配必须保留关系方向。
- 正例：同一 facet 在 SEEK 与 OFFER 中形成互补候选。
- 移除失败：只按主题相似度连接两个都在寻求同一资源的主体。
- 来源：[SRC-PROTOCOL-DESIGN:1-43] [SRC-NAC-SPEC:13-35]

### CAP-DISC-006：BIC 的交互式充分性

- 区分：没有暴露完整集合，与已经足以判断当前可行性。
- 机制：把边界表示为对当前约束和候选的充分信息，而不是固定字段清单。
- 关键决定：边界是否充分由当前问题判别，不由资料完整度判别。
- 正例：本地 Oracle 只回答会改变当前候选可行性的 cut 或 witness。
- 移除失败：静态表单要么继续索取无关信息，要么在关键未知未闭合时提前承诺。
- 来源：[SRC-ROUND2-PAPER-I:250-275] [SRC-ROUND2-PAPER-II:270-320]

### CAP-DISC-007：类型化 Boundary Oracle

- 区分：可证明不可行的 cut、可推进候选的 witness、仍未知、拒绝披露。
- 机制：Oracle 返回类型化响应并保留本地权威；协调器只能据此调整候选或提出下一 probe。
- 输入：候选关系、查询、披露/权限预算。
- 输出：cut、column/witness、unknown 或 refuse。
- 关键决定：`UNKNOWN` 与 `REFUSE` 不等价，局部证据与全局决定不等价。
- 正例：不可行条件产生反约束，不泄漏完整私有集合。
- 移除失败：自由文本回答被协调器误解成授权或完整能力声明。
- 来源：[SRC-ROUND2-PAPER-II:270-320] [SRC-ROUND2-PAPER-I:490-520]

## 后续解释与整合结果

- v0.4 把 NAC、BIC、Boundary Oracle 主要归为 provider、policy 或方法，没有独立事实根。
  这避免本体膨胀，但对象映射本身不保证 Oracle 的响应类型、局部权威和渐进披露仍被运行时执行。
  [SRC-V04-ONTOLOGY:197-253]
- v0.7 的本地世界、机制 Router 和关系形成阶段恢复了部分运行位置，但 HDC、NAC 的方向性与
  前缀预算没有成为 OPC 内核的明确 Gate。[SRC-V07-OPC:56-102]
- v1.1 保留 Local World、Boundary Oracle 和 Mandate，但可执行语义的中心重量已转向六 roots；
  原生 discovery protocol 的端到端保真尚无重建测试。[SRC-V11-MONOGRAPH:2810-2865]

## 当前保留建议

- 事实对象：本地事实和其 provenance；不把 NAC 或 BIC 升为事实根。
- 运行时：任务相关投影、类型化 Oracle、披露预算。
- 策略：HDC/FHRR、NAC 编码、query 排序可以作为可替换 provider。
- 研究假说：跨模型 NAC 是否比自然语言+强模型更有净价值，尚未被现实判别。
