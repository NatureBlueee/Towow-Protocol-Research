# 案例 3：NASA HLS（固定关系模式的负控制）

## 为什么选它

它用于防止“任何复杂协调都要进入 Towow formation”。该采购真实、复杂、金额巨大、存在多方争议，但核心制度语法高度预先定义。

## 关键重建

- solicitation 明确保留多个、一个或零个 award，并把数量绑定 funding；
- 因此资金实际值低于预期并不自动改变关系模式；
- source selection authority 和 contracting officer 已被授权对选定者进行 post-selection negotiation；
- payment phasing 和额外 FRR 是获准修订的 proposal 内容，不是新制度的共同构成；
- 提案外信息即使 NASA 过去接触过，也不能自动成为当前可采纳证据。

## 对理论的压力

1. surprise、金额和争议不等于 schema materiality；
2. `CollapseSafe` 必须识别已预留 contingency 和确定性制度；
3. `E/D` 需要明确 evidence admissibility 与 version incorporation；
4. 更多上下文并非总是更好——有时制度要求上下文被明确重提并纳入当前版本。

## 路由结论

该任务在正式 procurement schema 内应优先路由到 `STATIC_PLATFORM / CENTRAL_WORKFLOW`，只在授权规则本身需要修订时才进入 formation。
