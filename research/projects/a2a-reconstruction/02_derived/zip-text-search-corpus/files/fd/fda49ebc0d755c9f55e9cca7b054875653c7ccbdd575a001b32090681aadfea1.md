# Round 03 — Joint Alignment

## Protocol decision

两位模型主体都 `ACCEPT` 了下一步协议，但没有接受当前系统已经满足它。当前事实仍是
`UNKNOWN / UNVERIFIABLE`。

共同边界：

1. execution claim、Allbuddy consumer adoption、Agent World presentation 是三层不同权威；
2. Allbuddy 先建立 persistent、authenticated、tenant-bound 的 consumer adoption readback；
3. 先用低风险双租户 synthetic case 形成 adopted / not-adopted、correction / revocation 现实状态；
4. 跨边界只允许 viewer-scoped、non-enumerable、non-replayable 的粗粒度引用与状态；
5. World 必须同时执行授权读取和 wrong-tenant / unauthorized 读取；
6. 不跨界传 prompt、query、artifact、object、raw tenant、reason、action/scope 或 payload commitment；
7. producer `PASS/completed` 没有 consumer readback 时，最多是 `claimed / UNKNOWN`；
8. World 只确认“有权 consumer 报告了当前 adoption 状态”，不确认执行正确性、业务效果或商业价值；
9. not-adopted、failed、revoked、stale、conflict 与 unknown 都是一等结果。

## What the interaction formed

- 形成了双方都接受、可由现实执行证伪的权威分工和下一动作；
- 删除了 World 第一轮没有现实依据的固定 TTL、action/scope、payload commitment 与 HMAC；
- 把 Allbuddy 第一轮的笼统“不能泄露”变成 wrong-tenant 不可区分、重复读取一致、revision 单调、
  correction/revocation 可见的局部实验；
- 尚未形成跨系统 Capability、目标域采纳或净值主张。

## Next action

Allbuddy 主体实现它自己提出的 canonical consumer adoption readback，并用双租户、
unauthorized viewer、revision 与 sentinel 测试先证伪。接口经独立 readback 冻结后，
Agent World 主体才据实实现 adapter / projection，而不是针对预写 schema。
