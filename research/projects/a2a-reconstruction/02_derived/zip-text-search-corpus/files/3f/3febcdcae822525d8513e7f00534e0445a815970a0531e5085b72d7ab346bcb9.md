# Open re-review 04 — source freeze after recovery hardening

## Verdict

`COUNTER`. The external outbox/readback was implementation-ready for a
single-host synthetic independent HTTP consumer, but the combined ProductShell
consumer authority and source interface could not freeze.

## Decisive counterexample

The reviewer intercepted the response from `/api/workspace/adoption` after the
server had already committed `adopted@revision 1` and its outbox entry. The
user then clicked “终止”.

ProductShell deleted the recovery marker and displayed “没有生成新的业务
Artifact”. A separate Node HTTP process subsequently claimed, read, durably
persisted and acknowledged the same `adopted@revision 1`, all with HTTP 200.

This is a local authority contradiction, not a production extrapolation or a
test artifact.

## Evidence retained

- latest focused source tests: 11/11;
- repository Vitest run: 8 files / 46 tests;
- exact revision CAS/replay, revision-specific read, lease token replay,
  privacy projection and same-host lock recovery passed;
- an independent Node HTTP consumer completed
  claim → read → local persist → ack;
- initial-response loss and abort-after-prepare browser cases passed.

The remaining failure is specifically abort-after-adoption-commit-before-
response.

## Minimal acceptable countercondition

Either:

1. abort retains recovery authority and reports Unknown until canonical
   readback converges; or
2. abort is an authoritative cancel/revoke operation serialized with adoption.

If adoption has not been externally claimed, the cancelled transient event may
be superseded. If World may already have observed it, a monotonic correction
revision must be emitted. The UI must never claim “no Artifact” while the
canonical source still reports adopted.

Production use remains out of scope and unsupported.
