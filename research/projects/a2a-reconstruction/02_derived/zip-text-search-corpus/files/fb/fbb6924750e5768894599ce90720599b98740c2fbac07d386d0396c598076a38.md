# B5-M3 · 传播与披露层详设 v0.9

**消费契约：** IF-1（quest/disclose动词、错误分类学）、IF-2（信号格式、深度度量、版本窗口）、IF-3（评分语义、包络代数、I-O1/2/3）。本文不得与上述冻结件冲突；冲突即本文缺陷。

## 1. 意图陈述

M3的存在理由：让模糊意图以**不随网络规模爆炸、且不漏掉任何结构性可能**的成本，到达"不知道是谁、但可能有戏"的端侧。两条价值取向贯穿一切实现选择：**召回的保证属于数学，效率的提升属于学习**——两者永不交易；**阶段一的中继拓扑是语义设施不是性能设施**——物理中心化时逻辑拓扑照常运行，因为课程数据（E3的local_path_hypothesis）与R19影子网CI需要真实拓扑作参照系。实现者禁止以"单库全查更快"为由省略中继逻辑——那不是优化，是把未来的分布式语义和今天的课程数据一起删除。

## 2. 职责边界

**管**：信号在册与包络维护；查询路由与候选提名；quest/disclose四态机与对等执行；披露预算记账；R6/R7工作点的双旋钮控制。
**不管**：信号生成（M1）、算子内部逻辑（M2/端侧）、候选命中后的结晶（M4）、学习（M5——M3只产仪表与日志）。

## 3. 内部构件分解

- **C1 在册库（Registry）**：party/facet/坐标/头部的当前态与历史版本。
- **C2 包络维护器（EnvelopeKeeper）**：逻辑中继树上逐节点Box_k存取；**加宽优先更新协议**实现（I-O2）。
- **C3 路由器（Router）**：W折叠→自顶向下UB剪枝→候选集→全前缀精排→提名输出。双路径：包络路径（保证器）＋反射路径stub（H7接口预留，v0空实现）。
- **C4 探问引擎（QuestEngine）**：match_context四态机、对等校验（IF-2§5度量）、预算记账、VOI选维接口（阶段一由中心催化侧估计，终态移端侧）。
- **C5 阈值管理器（ThresholdManager）**：按锚点版本发布物加载θ_k表；K_max上限；逐查询预算曲线落日志。
- **C6 仪表（Telemetry）**：§7全量指标的采集点。

## 4. 数据结构（阶段一具体选型）

存储＝单实例Postgres（或SQLite起步），五张表：`parties, facets(coords bytea, header jsonb), envelopes(node_id, k, lo[], hi[], widen_seq), match_contexts(state, budget, depth_ledger jsonb), events(append-only, E1–E5)`。坐标运算numpy。**诚实选型声明**：园区千级规模下暴力精排快于任何索引且零运维——包络机械在阶段一为语义与课程而维护，不为速度；任何人以性能为由质疑它，答案在§1。逻辑中继树初版三级：scenario→cluster（按行业/楼宇）→party，cluster划分为可配置参数。

## 5. 算法与状态机

**5.1 路由主流程**：
```
admit(query) → 校验头部/版本窗口 → 对每k∈使用级: q′_k = W_kᵀ q_k（W缺省=I）
→ 自根DFS: UB_k(q′,Box)≥θ_k 才下行；叶层全前缀score精排
→ 候选截断: min(达θ者, K_max) → 提名事件(E3, 含local_path_hypothesis自动草拟+人工修订位)
```
**5.2 召回等级（本详设新增裁决）**：查询声明`recall_class`——`GUARANTEED`：仅包络路径，全UB扫描，零漏检硬保证；`FAST`：反射路径先行，包络对随机抽样查询全量回测以测量统计漏检率，预算曲线入仪表。**反射在任何等级下只许重排与加速，不许单独剪枝。**v0全部查询默认GUARANTEED（反射stub未启用）。
**5.3 加宽优先协议**：成员更新→沿叶到根逐节点`widen(Box, new_coord)`并递增widen_seq→全链ack后新坐标对路由可见→收窄任务入后台队列（重算子树紧包络，低优先级）。崩溃恢复：以events重放widen链，未完成链按"已加宽未生效"处理（安全侧）。
**5.4 四态机**：严格按IF-1§2/§3；对等校验在请求入队前同步执行；`PARITY_INSUFFICIENT`时随附披露不落对方账（IF-1 I-Q1后半句的实现点：暂存区销毁，不写events的对方可见侧）。
**5.5 R6/R7双旋钮**：θ_k为漏检安全侧地板（仅作用于UB剪枝，数学上不致漏）；K_max为误唤醒上限；K_max溢出时记录"超额候选数"——这是θ_k需要锚点进化（R20b）的信号源。

## 6. 契约引用

评分与UB：IF-3§1/§3，本文零重复。深度度量：IF-2§5。错误码：IF-1§0分类学。版本窗口行为：IF-2§4（窗口内双版本并行路由，窗口外发射方责任）。

## 7. 失败模式与降级

- 加宽ack滞后/部分失败→受影响子树标记STALE，路由对其**禁用剪枝、全量下行**（保守即安全），仪表告警。
- θ表缺失/版本错配→拒绝路由该k级，降级到已配置k级；全缺→GUARANTEED全扫（千级规模可承受）。
- K_max持续溢出→自动升θ_k仅在记录预算曲线后允许（J3口径：预算可知），并发锚点进化信号。
- 对等校验不可判（自定义面无bits定义）→按被探测方计算为准；其拒绝即终局。
- 反射路径（启用后）与包络结论分歧→包络为准，分歧样本入H7训练集。

## 8. 设计级可观测性与验收

**仪表**：剪除率@零漏检（聚类度量，M5目标函数）、逐查询预算曲线（θ_k、K、超额数）、轮次分布、对等违例计数、STALE子树时长、widen链延迟。
**验收判据**：(a)契约回归——IF-1的X系测试全绿；(b)重放审计——任取一查询，仅凭events能复现完整剪枝树与每个剪除决策的UB值；(c)零漏检验证——对随机查询关闭剪枝全扫对照，剪枝路径候选集必须⊇阈上真集（差集恒空）；(d)埋点规范§四五问全答。
**十问自检样例**（零上下文工程师应能仅凭本文回答）：包络为什么不折W？STALE子树为什么不剪？反射为什么不许单独剪枝？阶段一为什么要维护中继树？……答案全部可在§1/§5/IF-3内定位。

## 9. 挑战记录

- **向量数据库（HNSW/IVF）替代包络树**——否决于阶段一：近似索引引入统计漏检，违GUARANTEED语义；千级规模暴力更快；分布式终态它根本不可用（中心索引）。翻案条件：单中继子树规模>10⁵且FAST类查询占比>80%。
- **质心＋协方差草图替代min/max盒**——否决（外审W3结论归档）：概率剪枝无零漏检；盒的损失是剪枝效率，由聚类学习赎回。
- **对等校验放到接收端事后**——否决：事后即已泄露；同步前置是R21语义本体。
- **阶段一砍掉中继树直连查询**——否决，理由见§1意图陈述（本详设最重要的一条禁令）。
