# 通爻与现有协议、授权和协调理论的边界

**资料状态：截至 2026-07-26 的工作综述。IETF Agent 授权材料仍是 Internet-Draft，不应当作已定标准。**

## 1. 不是替代 A2A Protocol

A2A Protocol 的官方规范把重点放在相互独立、内部不透明的 Agent 之间进行能力发现、消息交换、任务管理和 Artifact 交付。它解决的是：已存在的 Agent 怎样找到对方、协商模态、推进 Task，并且不必暴露内部状态。

通爻不应声称 A2A 缺少一切权威或状态语义。更准确的边界是：

- A2A 的核心对象是 Agent、Message、Task、Artifact 与协议交互；
- 通爻关心的是 Task、参与者、权威、能力路径、数据权利和 Acceptance 尚未完整形成时，怎样构造一个可行动的 RelationVersion；
- RelationVersion 稳定后，A2A 可以成为其执行和通信载体之一；
- 通爻不要求所有主体直接点对点通信，中心路由和托管仍可存在。

参考：A2A Protocol Specification，`https://a2a-protocol.org/latest/specification/`

## 2. 不是替代 MCP

MCP 的授权规范主要处理 MCP client 代表资源所有者访问 server 资源时的 transport-level authorization，并以 OAuth 体系作为基础。它为工具调用与资源访问提供重要的底层控制。

通爻需要 MCP 或同类机制，但不能把资源访问令牌直接等同于：

- Principal 对联合目标的认领；
- 对外承诺；
- 目标域 Adoption；
- 业务 Acceptance；
- Agent 对任务语义的正确理解。

`Mandate` 可以被编译为 MCP/OAuth scope、策略和运行门，但 Mandate 的语义来源先于具体访问令牌。

参考：MCP Authorization，`https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization`

## 3. 可验证凭证证明来源，不自动证明内容真实

W3C Verifiable Credentials Data Model 2.0 提供 issuer、holder、subject、proof 和验证模型。它适合携带角色、资格、授权来源和证明材料。

但可验证性与真实性必须分开：验证一个凭证能够证明其来源和完整性符合验证规则，不自动证明其中陈述在现实中为真，也不证明 issuer 有权替所有受影响者决定。

因此：

- VC 可承载 Mandate、资格和事实声明；
- `Assertion` 仍要记录适用范围、证据、权威来源和 Defeater；
- Effect、Adoption 与 Acceptance 仍需各自相称的事实来源。

参考：W3C VC Data Model 2.0，`https://www.w3.org/TR/vc-data-model-2.0/`

## 4. Agent 授权正在向任务绑定和可衰减委托演进

2026 年的 IETF Internet-Draft 已直接讨论 Agent delegation chain、task-scoped attenuation、agent authorization use cases、跨域链条、emergent permissions 和 mission-bound authorization。这说明“OAuth scope 足够”已经被实践界认为不够。

这些草案与通爻高度相关：

- Attenuating Authorization Tokens 支持委托链只能收窄、不可无声扩大；
- Agent Authorization use cases 总结跨域、长链和动态权限缺口；
- Mission-Bound Authorization 试图把任务/使命批准与执行绑定。

通爻不应重复发明这些密码学和令牌机制。它需要进一步回答：

- Mission 本身尚未被完整定义时怎样形成；
- 谁拥有目标；
- 哪些 Stance 构成有效授权；
- material RelationVersion 变化怎样使旧 token 失效；
- 权限收窄以外，如何处理拒绝、反条件、Acceptance 与 reopen。

参考：

- `https://datatracker.ietf.org/doc/draft-niyikiza-oauth-attenuating-agent-tokens/`
- `https://datatracker.ietf.org/doc/draft-chen-oauth-agent-authz-use-cases/`
- `https://datatracker.ietf.org/doc/draft-mcguinness-oauth-mission/`

## 5. 社会承诺理论已经提供公开可验证的互动语义

Singh、Yolum、Chopra 等人的 commitment-based interaction 传统强调：开放多 Agent 系统不应把消息意义建立在不可观察的内部心智状态上，而应建立在公开社会承诺及其创建、履行、委托、取消和违反上。

这直接支持通爻的几个判断：

- 自然语言消息不应成为最终事实；
- Commitment 必须与 Agent 的内部信念分开；
- 交互协议可以围绕社会状态而非消息序列定义；
- 合规与执行需要可观察事件。

通爻不能把 Commitment 当作原创概念。其新增问题在于：commitment language、必要参与者和可执行能力本身尚未给定时，怎样通过局部私有世界、拒绝和 probe 形成。

参考：Munindar P. Singh, *A Social Semantics for Agent Communication Languages*；Yolum & Singh, *Commitment Machines*。

## 6. Matching with Contracts 处理了丰富合同，但合同集合仍是模型输入

Hatfield 与 Milgrom 的 Matching with Contracts 将匹配基本单元扩展为合同，使身份、价格和职责等条款可以共同进入匹配，并在给定合同集合与偏好条件下讨论稳定分配。

它与通爻的关系是：

- 当合同语言、参与者和可行合同集合已给定，Matching with Contracts 是更成熟的下游理论；
- 通爻不应另造一个劣化版匹配算法；
- 通爻的上游问题是：合同集合、角色、能力和接受语义如何从私有世界与现实 probe 中形成；
- 一旦形成，既有 matching、CSP、MILP、SAT 或拍卖机制都可以成为求解器插件。

参考：Hatfield & Milgrom, *Matching with Contracts*, American Economic Review, 2005。

## 7. Institutional Grammar 已区分构成性与规制性规则

Institutional Grammar 及其 2.0 Codebook 提供把规则、规范和策略编码为结构化 institutional statements 的方法，并区分：

- regulative statements：规定主体在条件下允许、必须或禁止什么；
- constitutive statements：定义位置、实体和制度场域本身。

这对“关系模式”的约束非常重要。通爻的 Relation Schema 不应声称首次发现“规则也有语法”，而应吸收该传统并进一步处理：

- 多主体私有世界中 schema 尚不完整；
- 规则由谁有权提出和认领；
- 现实 Effect 怎样反证规则；
- 哪些 schema 子图可以编译并在 Defeater 时局部重开。

参考：Frantz & Siddiki, *Institutional Grammar 2.0 Codebook*；Bushouse et al., *The Institutional Grammar*。

## 8. 动态人机协作强调目标与工作流会在互动中变化

近期关于 dynamic human-AI workflows 的工作指出，对齐不能只看一次静态偏好，而应研究交互序列中目标、分工和评价如何变化。这与通爻对静态画像的批评一致。

通爻仍需保持自己的边界：它不仅研究单个用户与 AI 的动态对齐，还研究多个不可互相代行的权威域如何形成共同 RelationVersion，并把模型建议与制度权威、现实 Effect 和 Acceptance 分离。

参考：*Align AI to Dynamic Human-AI Workflows*，arXiv:2607.14240。

## 9. 通爻当前可以承担的独立贡献

最有根据的贡献候选不是单个概念，而是以下组合：

1. 把开放世界 A2A 的上游问题定义为**不可折叠权威条件下的共同可行动关系形成**；
2. 用 Relation Schema / RelationVersion 区分关系语义与实例参数，并给出 materiality、稳定、编译和 scoped reopen 的操作判据；
3. 把 Entity、Capability、Authority 和 Objective Ownership 保持正交；
4. 把形成、Commitment、Operation、Effect、Adoption 和 Acceptance 放入同一条可执行证据链；
5. 把拒绝、Unknown 和 NoDeal 视为真实处置，而不是优化失败；
6. 用 strict formation 和 CollapseSafe 判据区分新能力形成、优秀中介发现、规范细化与可安全中心化；
7. 通过真实 Principal 实验检验这套组合是否产生正净协调剩余。

## 10. 不能承担的过度主张

- 首次提出 Agent 有身份、权限、承诺或组织结构；
- 首次提出协议之外还需要治理；
- A2A 必须去中心化；
- 任何非标准任务都需要 Towow；
- VC、OAuth、A2A 或 MCP 无法支持主权系统；
- 合成实验已证明真实人类愿意认领；
- Relation Schema 可以完整形式化所有社会关系。

通爻的学术价值最终取决于：能否把多个成熟理论之间尚未闭合的上游—下游关系做成一套真实可运行、能产生 Design Delta、并在现实实验中允许失败的系统。
