# GLM 5.2 本地接入交接

更新时间：2026-07-25

本目录只处理正常研究与工程协作的模型接入，不包含安全对抗类实验内容。这里没有 API
Key，也不会修改 `~/.codex/config.toml`、`~/.claude/settings.json` 或 Harness 项目代码。

## 结论

当前最稳妥的本地入口是 **Claude Code + 智谱 Anthropic Messages 端点**，并通过本目录的
启动脚本把配置限制在单次子进程内。

当前 **不应把 GLM 5.2 直接配置成 Codex CLI provider**：

- 本机 Codex CLI 是 `0.145.0`。
- 当前 Codex 官方配置参考只支持 custom provider 的 Responses 协议。
- 本机对 `wire_api = "chat"` 的只解析校验明确返回
  ``wire_api = "chat" is no longer supported``。
- 智谱当前官方公开的是 Anthropic Messages 与 OpenAI Chat Completions 端点；没有找到
  GLM 5.2 的 Responses API 官方说明。
- GLM Coding Plan 的官方支持工具清单目前包含 Claude Code、OpenCode 等，但没有 Codex。

所以，Codex 直连目前属于“协议未闭合”，不是“已经配置好但还没填 Key”。在智谱正式提供
Responses API，或 Codex重新支持 Chat Completions 之前，不应把它写成可用方案，也不应
自行增加协议转换代理。

## 已确认的官方参数

| 项目 | 值 |
|---|---|
| API 模型编码 | `glm-5.2` |
| Claude Code Coding Plan 模型别名 | `glm-5.2[1m]` |
| 通用 OpenAI-compatible Base URL | `https://open.bigmodel.cn/api/paas/v4` |
| Coding Plan OpenAI-compatible Base URL | `https://open.bigmodel.cn/api/coding/paas/v4` |
| Coding Plan Anthropic Base URL | `https://open.bigmodel.cn/api/anthropic` |
| 官方上下文上限 | 1M tokens |
| 官方最大输出 | 128K tokens |

通用 API Key 与 Coding Plan Key 的来源和额度口径不同。使用哪一种 Key，就必须配套使用
对应端点；不要混用。

## 推荐入口：隔离启动 Claude Code

本机已安装 `claude 2.1.218`，高于智谱文档列出的已验证版本 `2.1.140`。

1. 通过你已有的密码管理器或安全注入方式，在当前 shell 中提供 Coding Plan
   `ZHIPU_API_KEY`。不要把值写进本目录、Git、命令行参数或 shell 历史。
2. 进入要交给 GLM 5.2 的工作目录。
3. 运行：

   ```bash
   bash /Users/nature/个人项目/Harness/.ai-research/towow-a2a-r5-2/glm-handoff/launch-claude-glm52.sh
   ```

脚本只为启动的 Claude Code 子进程设置变量：

- `ANTHROPIC_AUTH_TOKEN`
- `ANTHROPIC_BASE_URL`
- `ANTHROPIC_DEFAULT_*_MODEL`
- `CLAUDE_CODE_AUTO_COMPACT_WINDOW`
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
- `API_TIMEOUT_MS`

它不会持久化配置，不会输出 Key，也不会启动后台服务。退出 Claude Code 后，这些子进程
变量随之消失。

主会话由脚本固定选择 `opus`，因此会映射到 GLM 5.2；`haiku` 仍按智谱官方模板映射到
GLM 4.7，不把未经官方说明的模型映射写进配置。

启动后可在 Claude Code 内用 `/status` 确认当前模型映射。确认的是实际会话状态，而不是
仅凭环境变量名推断成功。

## 可选：最小 API 连通性检查

`smoke_chat_completion.py` 只发送一个普通的短文本请求，不读取或修改项目文件。

通用 API：

```bash
python3 /Users/nature/个人项目/Harness/.ai-research/towow-a2a-r5-2/glm-handoff/smoke_chat_completion.py
```

Coding Plan API：

```bash
GLM_API_BASE=https://open.bigmodel.cn/api/coding/paas/v4 \
python3 /Users/nature/个人项目/Harness/.ai-research/towow-a2a-r5-2/glm-handoff/smoke_chat_completion.py
```

两种方式都要求调用前已有 `ZHIPU_API_KEY`。脚本不会回显该值，失败时也只输出异常类型与
HTTP 状态码，不输出原始响应体。

## 后续研究交接边界

- 由使用者决定具体研究问题；本目录不预写实验结论。
- 首次使用先做一个可回滚、无外部副作用的普通本地任务，确认文件读取、工具调用、长上下文
  保持和结果验证是否正常。
- 不修改全局模型配置，不部署服务，不触碰生产环境。
- 将“配置可解析”“API 可连通”“工具可调用”“研究任务完成”视为四个不同层级，逐层留证，
  不用前一层的成功代替后一层。
