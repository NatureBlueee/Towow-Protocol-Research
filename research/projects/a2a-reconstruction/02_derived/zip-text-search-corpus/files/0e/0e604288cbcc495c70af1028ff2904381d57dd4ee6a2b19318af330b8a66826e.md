## 2026-07-24T12:39:46Z — Move action granularity into the Effect Gateway contract

- **Previous plan:** Test whether separating Effect, Verification, and Acceptance is enough to explain the Git anomaly.
- **Triggering evidence / anomaly:** Stdout and composite exit each had five false acceptances across nine cases; the actual Git trace had success text and outer exit 0 with an unchanged branch. Postcondition alone still misclassified an effect followed by executor failure.
- **Decision:** Require every effect claim to identify an action-aligned executor result and authoritative postcondition, with Acceptance evaluated separately. Treat this as an adapter/Gateway invariant rather than a new protocol object.
- **Why this changes the plan:** Ontology-level separation is inert when the execution adapter records the wrong unit of action.
- **Alternatives considered:** Trust the last command exit; trust state only; add a new `AtomicEffectUnit` top-level object; ban composite commands globally.
- **Expected information or capability gain:** Prevent false state transitions while retaining partial-effect and refusal evidence.
- **Safety / cost impact:** Minimal local record; no external effect. Eager full projection cost 3.64x serialized bytes in this task without accuracy gain.
- **Files / runs / commits:** `runs/r5-run-002-effect-granularity/`; `tools/effect_trace_lab.py`; no commit.
- **What would reverse this decision:** A real adapter where a composite transaction has one authoritative atomic commit/rollback result and a separate postcondition is redundant.
