# 公开现实证据后的统一理论修订 v0.6

## 0. 修订性质

本文件不是另起炉灶，也不新增一组顶层概念。它只记录公开案例对 v0.4 施加的有效修正。核心对象仍是：不可折叠权威条件下，共同可行动关系的形成、效力与重开。

## 1. 从一层 Relation Schema 改为同构的双分辨率

v0.4 把 `Γ=<R,V,T,A,E,D,O>` 定义为关系模式。公开案例显示，同一套结构要在两个分辨率上读取：

```text
Institutional frame Γᴵ
  法律、行业、平台、组织与公共制度已经提供的元规则

Relation-specific version Γᴿ
  当前主体围绕具体事项形成的条件、权威与轨迹
```

这不是两种本体，也不新增 aggregate root。`RelationVersion` 只需要：

```text
frame_scope: institutional | relation
inherits_from: [relation_version_ref]
overrides: [typed_delta]
```

Microsoft–LinkedIn 的大多数协商发生在成熟 `Γᴵ` 内；Sidewalk 和 Open Banking 的关键转折包含 `Γᴵ` 自身的改变；Crossrail说明 `Γᴵ/Γᴿ` 的纸面声明还必须通过 enacted evidence。

## 2. Relation Schema 的缺失项：standing 与 enactment

### 2.1 Standing

`R/A` 过去主要问谁参与、谁有权决定。现实还必须问：

- 谁会承受显著外部性；
- 谁有资格提出 challenge 或要求解释；
- 谁被代表、通过什么渠道；
- 谁有签署权、否决权、咨询权、申诉权或仅有知情权。

这些是角色/权威属性，不创建 `Standing` 根对象。Sidewalk 和 SGMA 都显示：formal participation、decision authority 与 legitimate affected-party claim 可以分离。

### 2.2 Enactment

Crossrail 与 Open Banking显示，declared authority/governance 不等于 enacted authority/governance。每条 material rule 应能回答：

```text
who observes violation
who can intervene
what evidence reaches them
what sanction/rollback/escalation exists
whether the locus has time/resources to act
```

这些进入 `A/E/T` 的 assurance fields，不新建协议层。

## 3. 稳定是多维闭合，不是单一状态

建议将 v0.4 Stability 向量重新分组为：

```text
technical_operational
  语法、能力、接口、恢复、运行时环境

authority_governance
  Mandate、决定权、监督、争议、制度继任

epistemic_assurance
  证据、依赖、独立挑战、Effect witness、未知

normative_legitimacy
  standing、representation、程序正当性、外部性

economic_resource
  预算、激励、容量、风险承担、持续性
```

一个子图只能按其风险需要的最低维度门编译。平均分无意义：Open Banking 的技术维度可以稳定而治理维度失稳；Crossrail 的包件运行可以稳定而端到端 effect 维度失稳。

## 4. Compile 的制度化解释

`Compile(Γ, x, K, N)` 的输出不只是一段代码或工作流。它可以是：

- 合同与标准条款；
- API、OAuth scope、凭证与策略；
- 审批、预算、监督和审计路径；
- 争议、退出、暂停、补偿与修订程序；
- 运营组织与职责；
- Effect witness、assurance 与 review gate。

编译的本质是：把反复依赖智能/政治判断的开放问题，压缩成一个在既定权威下可重复执行、可观察、可暂停的机制。

## 5. Reopen 的新触发器

v0.6 将 Defeater 分为六类（作为事件/策略标签，不作为新 root）：

1. `WORLD_FACT_DEFEATER`：环境、资源、能力或事实变化；
2. `AUTHORITY_DEFEATER`：Mandate、职位、制度或代表权变化；
3. `ASSURANCE_DEFEATER`：证据链、依赖模型或 Effect witness 失效；
4. `GOVERNANCE_DEFEATER`：监督、冲突、申诉、制裁或透明度失灵；
5. `STANDING_DEFEATER`：新的受影响方、遗漏代表或合法挑战出现；
6. `OBJECTIVE_DEFEATER`：目标、公共利益、经济可行性或 end-state 改变。

Reopen 仍只作用于依赖闭包。

## 6. CollapseSafe 的正式修订

旧的直觉容易把 CollapseSafe 理解成“任务简单、字段固定”。公开案例支持更深的判据：

```text
CollapseSafe(relation r, frame Γᴵ, mechanism m) :=
  InstitutionalFrameSufficient(Γᴵ, r)
  ∧ InformationCanBeCentralizedWithinGrants(r, m)
  ∧ RequiredAuthorityPreserved(r, m)
  ∧ StandingAndRecoursePreserved(r, m)
  ∧ EffectAndAcceptanceRemainDistinguishable(r, m)
  ∧ DriftWithinReviewCapacity(r, m)
  ∧ NetCoordinationCost(m) <= OpenFormationAlternative
```

`InstitutionalFrameSufficient` 意味着已有 frame 能合法处理当前变化，而不是所有合同条款不变。复杂并购可以 CollapseSafe；表面简单的数据合作可能不安全折叠。

## 7. 形成操作的最小理论

公开案例反复出现一组操作：拒绝、反条件、证据要求、scope contraction、actor enrollment、authority reallocation、standardization、staged approval、independent challenge、commitment、compile、reopen。

它们不应成为协议对象。更合理的理论位置是：

```text
FormationOperator:
  输入 = 当前 RelationVersion + 局部世界响应
  输出 = typed delta / evidence / stance / operation proposal
  有效性 = 是否改变可达轨迹、证据或权威，并被相称来源认领
```

任何 Agent 策略都必须最终落回六类 canonical facts 和 typed events。

## 8. 更新后的系统目标

“让愿意成交者更快成交、不愿意成交者更快不成交”仍成立，但“真实”现在包含四个同时条件：

```text
FactualFit
∧ AuthorityValidity
∧ ProceduralStanding
∧ EffectWitnessability
```

缺任何一个，快速处置都可能只是平台替主体做决定。

## 9. 当前最深开放命题不变，但被进一步限定

公开档案使理论具有更强现实解释力，却仍未触及 Agent 干预的核心因果命题。决定性问题仍是：

> 在已有 institutional frame 不足、但关系可以通过有限形成操作推进时，具备范围化 Mandate 的 Agent Entity 是否能以更少披露与协调成本，帮助真实 Principal 到达更真实、更稳定的 disposition，并形成一个强基线无法无损产生的路径？

下一步不应继续用更多公开案例替代它；应先用公开材料完成仪器校准、双人编码和 transcript-level 反例搜索，再进入最小 live experiment。
