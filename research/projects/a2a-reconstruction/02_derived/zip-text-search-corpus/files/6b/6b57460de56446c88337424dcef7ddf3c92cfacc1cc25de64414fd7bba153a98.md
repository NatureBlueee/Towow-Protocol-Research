# 旗舰建设性研究章程

## 1. 研究目的

本研究不以“验证 A2A 优于中心化”为目标，也不以多 Agent 对话轮数、协议字段或最终报告完整度为成果。

它要寻找一套可工作的协调方法：

> 多个真实模型 Agent 在不同私有世界、工具、资源、权威或验收条件下，怎样通过有限边界交换和现实行动，把一个初始不可达的目标逐渐变成可达、可验证、可采纳、可认领和可复用的联合能力。

## 2. 旗舰实验必须具有的现实结构

本地研究者自行选择任务和节点，但候选任务应尽量满足：

- 初始状态不存在被目标主体接受的完成路径；
- 不同主体拥有真实不同的上下文、工具、资源、权威或验收条件；
- 协调器不能任意读取全部隐藏状态；
- 至少一个关键条件可以通过互动和现实干预形成；
- Agent 有询问、拒绝、Unknown、反条件、工具使用、局部实验、任务重构或请求授权的真实动作权；
- 产生可检查的制品、状态变化或现实行动；
- 有独立目标域采纳和 Acceptance；
- 能够构造静态、中心或现有 Harness+human 的公平基线；
- 失败可回滚、隔离或保持在非生产环境。

真实结构优先于任务名称。研究者不得为了有利于 A2A 人工制造虚假主权差异，也不得把所有数据交给一个 root 后仍称为主权实验。

## 3. 探索与确认必须分离

### 建设性探索

在方法尚未形成时，允许本地研究者和 Agent：

- 自主选择下一步动作；
- 运行局部试验；
- 构造或安装低风险工具；
- 请求最小信息或把计算移动到数据旁；
- 请求授权、伙伴或审查；
- 修改任务拆分、角色和恢复路径；
- 根据执行反馈重写方案；
- 发现比当前任务更关键的设计缺口。

探索阶段可以修改协调方法，但必须保留每次变更的触发证据和 Design Delta。不能用探索结果冒充预注册确认结果。

### 机制提取

当某种循环反复表现出解释力时，将其压缩为候选方法，例如：

```text
诊断不可达原因
→ 选择信息或形成动作
→ 本地执行/试验
→ 产生 Witness 或 Defeater
→ 更新共享行动安排
→ 请求认领/授权
→ 再执行
→ 停止、接受或升级
```

这只是可能的形态，不是预设答案。

### 确认与消融

候选方法形成后，冻结关键部分并进行：

- 与静态、least-privilege central、现有 Harness+human 的同任务比较；
- 删除关键互动或形成条件的消融；
- 模型、工具与人工帮助的混杂控制；
- task-family、环境、版本或时间留出；
- 独立 Agent 或实现路径复核；
- 原始目标价值和目标域采纳检查。

## 4. 新能力的判定

本轮不把更多对话、更多条款或更长计划当作能力形成。

最低判据是：


a. 互动前，目标或关键子目标在声明环境中不可达；  
b. 互动产生了一个现实条件变化；  
c. 互动后出现新的被接受行动路径；  
d. 去掉该条件或关键互动后，结果消失或显著变差；  
e. 目标没有被偷偷降级；  
f. 目标域已采纳并由有权主体接受；  
g. 新增价值高于新增成本。

可以表达为：

```text
A_post \ A_pre != ∅
```

并通过关键条件消融检验其因果作用。

## 5. 研究产物

旗舰研究最终应形成的不是“某个任务成功”，而是：

- 一套在明确问题结构下有效的协调决策方法；
- 该方法的适用条件和失败边界；
- 边界交换的具体设计知识；
- 从一次形成到能力复用的证据路径；
- 与简单方案比较后的真实 Design Delta；
- 一个能在真实 Harness 中持续运行、继续学习的纵向实现。

如果实验表明 least-privilege central 或 Harness+human 已经足够，这同样是建设性结果：通爻应缩小适用域，而不是继续叠加复杂度。
