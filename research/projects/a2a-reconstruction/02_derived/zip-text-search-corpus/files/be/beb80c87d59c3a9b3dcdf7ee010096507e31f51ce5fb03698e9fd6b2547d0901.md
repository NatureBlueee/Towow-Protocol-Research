# Flagship Task Candidate

- task name: Privacy-preserving external Acceptance bridge from Allbuddy to Agent World
- real source / historical origin: Allbuddy real-advisor branch `1a70fb5` plus Agent World open questions OQ-004/OQ-009 at `393b08e`
- original value: a private enterprise advisory result should become both usable in Allbuddy and independently, honestly visible in Agent World without disclosing enterprise content or letting either side self-award the other's authority
- why it is currently not solved: Allbuddy's consumed workspace path uses hard-coded outcomes and local `completed`; World only confirms events correlated to its own current-generation Commands and has no Allbuddy external adapter or redacted Source Map contract
- authentic non-collapsible properties: tenant data and business Acceptance cannot move to World; provenance/reality projection authority cannot be delegated back to the Allbuddy producer without losing independent verification
- what a least-privilege central system can access: public task intent, pseudonymous run/tenant references, hashes, timestamps, declared result class, target Acceptance decision, adapter snapshot/freshness and redaction metadata; it may not access prompts or private enterprise objects
- participating sovereign worlds:
  - Allbuddy data-and-product principal
  - Agent World provenance-and-projection principal
  - independent evaluator with no implementation authority
- potential condition-formation actions: ask for a claim-specific witness; move verification to the data side; construct a redacted receipt; add a typed external-observation adapter; add freshness/replay policy; require target-domain Acceptance; return `reported`, `unknown`, `disputed` or refusal instead of overclaiming
- real target-domain adoption surface: Allbuddy workspace runtime lifecycle and Agent World semantic ingestion/projection/Source Map
- Acceptance authority: Allbuddy target Artifact consumer for business/tenant integrity; Agent World semantic kernel for source/reality semantics; independent tests for the local experiment; owner alone for business-value recognition
- safe reversible execution path: isolated Allbuddy and Agent World worktrees; local fixtures/processes only; no credentials, network, production writes, push or deploy
- candidate baselines:
  - current Allbuddy hard-coded self-report
  - static one-shot capability/receipt description
  - full-access central using raw fixture data
  - least-privilege central using the same allowed projection
  - Harness+human manual reconciliation
  - adaptive sovereign A2A
- answer leakage / hidden solution risk: no implementation/reference adapter exists and World OQ-004/OQ-009 are open; agents receive source facts and authority policies but no preselected receipt schema or state mapping
- holdout potential: a scope-boundary/refusal task and a second tenant/result type not used while forming the bridge
- expected Design Delta: decide whether external facts need a distinct ingress path, what minimum boundary artifact supports independent confirmation, and when `claimed/reported` may upgrade to `source_confirmed`
- reason to select or reject: selected because it combines authentic privacy and authority separation with local, reversible target adoption, condition ablation and holdout; unlike session migration it does not require production authorization to reach a technical decision
