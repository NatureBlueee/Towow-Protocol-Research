# 07 · 证据、验证器、追溯与变更涟漪规范

## 1. 为什么验证器是 Harness 的核心

Agent 可以快速生成方案、代码和解释，但语言上的完整感很容易制造假完成。真正决定 Harness 强度的不是 Agent 数量，而是验证器能够可靠判断到哪里。

验证器的职责包括：

- 检查结构；
- 复算事实；
- 比较承诺和结果；
- 阻止非法状态变化；
- 发现漂移；
- 证明完成；
- 校准其他验证器。

## 2. 证据对象

证据至少记录：

- `evidence_id`；
- 来源类型；
- 采集时间；
- 适用版本；
- 生产者；
- 原始内容或不可变引用；
- 能证明什么；
- 不能证明什么；
- 新鲜度；
- 完整性；
- 可信等级；
- 与哪些主张关联；
- 是否存在相反证据。

## 3. 证据等级

从弱到强可以包括：

1. Agent 声明；
2. 文档声明；
3. 静态代码存在；
4. 注册与可达；
5. 单元测试；
6. 集成调用；
7. 真实运行记录；
8. 独立重算；
9. 对抗实验；
10. 长周期生产结果。

不同主张需要不同最低证据。例如“代码存在”不能证明“生产正在使用”。

## 4. 验证器分类

### 4.1 结构验证器

Schema、类型、引用、图完整性、状态机语法、目录和文件结构。

### 4.2 契约验证器

API、事件、数据、权限和跨模块协议。

### 4.3 行为验证器

给定输入和状态，系统是否产生正确输出和副作用。

### 4.4 质量验证器

性能、容量、可靠性、成本、安全、体验和可维护性。

### 4.5 语义验证器

需求覆盖、设计忠实、概念一致、任务是否偏离目标。

### 4.6 运行验证器

服务是否真实启用、事件是否被消费、结果是否到达用户。

### 4.7 治理验证器

权限、审批、Owner 判断、不可逆动作和例外使用是否合法。

### 4.8 验证器的验证器

通过独立重算、样本标注、故障注入和对照实验检查探针本身的漏报、误报与偏差。

## 5. 追溯图

建议建立完整链：

```text
原始表达
→ Problem
→ Requirement
→ Design Requirement
→ Design Object / Decision
→ Engineering Component / ADR
→ Consensus
→ Task
→ Commit / Artifact
→ Test
→ Deployment
→ Runtime Evidence
```

关系必须类型化：

- `derived_from`；
- `satisfies`；
- `implements`；
- `constrains`；
- `validates`；
- `depends_on`；
- `consumed_by`；
- `supersedes`；
- `conflicts_with`；
- `invalidates`；
- `observed_by`。

每条边包含创建者、理由、证据、置信度、版本和失效条件。

## 6. 影响分析

代码或共识改变后，不应让全部上游对象直接失效，而应进入怀疑和重验证：

```text
valid
→ suspect
→ revalidated
```

或：

```text
valid
→ suspect
→ invalid
→ redesign / re-engineer / replan
```

步骤：

1. 识别变更类型；
2. 找直接关联对象；
3. 沿允许的关系传播；
4. 计算受影响测试、接口、共识、设计和需求；
5. 运行低成本验证；
6. 只升级真实失败部分；
7. 保留传播路径和处理结果。

## 7. 防止变化风暴

- 限制传播关系和深度；
- 区分重构与行为改变；
- 缓存验证结果；
- 同一变化批量合并；
- 对低风险变化使用抽样和统计；
- 对高风险公共契约 fail-closed；
- 不让告警自动等同于返工。

## 8. 完成证明

一个完成声明至少回答：

- 做了什么真实改变；
- 对应哪个目标；
- 哪些代码、数据或配置变化；
- 在什么环境验证；
- 谁独立验证；
- 运行证据是什么；
- 哪些部分未验证；
- 是否产生新债；
- 后续观察窗口多长；
- 如何回滚。

## 9. Benchmark 的正确用法

Benchmark 不是单一分数，而是对机制的对照实验。

至少记录：

- 基线；
- 变量；
- 样本；
- 重复次数；
- 成功率；
- 质量；
- token 和时间；
- 人工介入；
- 返工；
- 方差；
- 失败类型；
- 长期副作用。

对 Harness 的关键评价包括：

- 问题发现率；
- 需求遗漏率；
- 设计返工率；
- 局部正确、合并错误率；
- 上下文有效利用率；
- 漂移发现延迟；
- 完成声明准确率；
- 同类故障复发率；
- 单位 token 的可验证价值。

## 10. 验证边界

存在指标不等于可以自动化裁决。价值、战略、伦理和权力判断仍需要人作为标准源头。Harness 可以提供事实、候选和后果推演，但不能用代理指标替代人的最终价值判断。
