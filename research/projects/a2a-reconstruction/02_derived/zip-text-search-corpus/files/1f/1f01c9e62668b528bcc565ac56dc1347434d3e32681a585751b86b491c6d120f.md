# 缺口—设计决定—研究方法地图

实验只有在存在真实设计歧义时才进入主线。每项主实验必须绑定一个未来要作出的设计决定。

| 当前缺口 | 相互竞争的设计解释 | 为什么不能只靠推理 | 需要的现实证据 | 结果将改变什么 |
|---|---|---|---|---|
| 下一步动作选择 | 继续询问 / 运行局部试验 / 调用工具 / 请求授权 / 引入伙伴 / 重构任务 / 停止升级 | 前沿模型在真实工具与局部信息下的行为不可由规则先验充分预测 | 自主模型 Agent 的动作轨迹、成功与失败干预、反事实消融 | 协调循环与调度策略 |
| 边界形式 | 静态 Profile / 动态查询 / 本地执行只回结果 / 传验证器 / cut-witness-unknown / 混合 | 信息价值、隐私和交互成本依任务结构变化 | 同一任务下不同边界策略的解决能力、泄露和成本 | 协议边界接口与 Context Compiler |
| 条件形成 | 只做信息澄清 / 创建工具 / 获取授权 / 训练 / 联合伙伴 / 风险与恢复设计 | 条件是否真正扩大行动空间必须通过状态变化和执行观察 | pre/post reachability、条件消融、目标域采纳 | PFE 的工作策略，不是对象数量 |
| 共享协调介质 | 对话 / 版本化计划 / JAA / 黑板 / 事件驱动任务图 | 共享状态会影响分歧、返工和自主行动，但难以纸面判断 | 不同介质下的形成速度、冲突、恢复和人类负担 | Harness 与协调界面 |
| 停止与升级 | 固定轮数 / 置信度 / VOI / EVPF / 风险预算 / 主体 veto | 继续搜索和停止的成本依模型、任务和主体而异 | 搜索后悔、失败恢复、人工升级价值 | 调度器和人类介入规则 |
| 能力升级 | 一次成功 / 重复成功 / 条件证据 / 留出预测 / 人类认领 | 事后解释与真实复用能力无法靠一次运行区分 | 执行前 Claim、跨任务/环境 holdout、条件删除 | Capability Contract 与复用策略 |
| 架构选择 | full central / least-privilege central / Harness+human / sovereign A2A | 是否存在不可折叠属性、净价值是否为正是现实问题 | 公平同任务基线、隐私权威约束、人工时间和机会价值 | 产品适用域与部署架构 |

## 本轮旗舰设计决定

当前最高价值的设计决定是：

> **通爻运行时应采用怎样的闭环策略，使 Agent 能够在有限边界下从 Unknown 或不可行状态中选择高价值的下一步现实动作，并把产生的条件推进为可复用能力？**

该决定不能由一项固定谈判脚本回答。需要通过若干连续、适应性的现实 episode 搜索候选方法，再冻结和确认。
