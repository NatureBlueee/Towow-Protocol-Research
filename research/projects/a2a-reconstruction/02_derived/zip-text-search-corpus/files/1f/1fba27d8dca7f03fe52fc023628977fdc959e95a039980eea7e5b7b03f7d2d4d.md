# Provenance Limitations and Missing Evidence

This file is part of the packet’s evidence, not a disclaimer appended after the
claim.

## Preserved

- initial reachability and authority split;
- role prompts and normalized principal outputs;
- local implementation and failure records;
- redacted real-process source/consumer/target readbacks;
- repeated `BLOCK`/`COUNTER` findings and final scoped `PASS`;
- static and least-privilege central baselines;
- condition ablations;
- claim frozen before holdout and the separate holdout result;
- final Git commits and reconstructable source patches;
- research state, decision log, claim ledger and checksums.

## Not captured or deliberately excluded

- raw provider API envelopes, exact model checkpoint, sampling parameters and
  per-call token/exit metadata were not persisted;
- full unredacted runtime stores are excluded because they contain ephemeral
  capabilities or private source material;
- no real human/customer Recognition transcript exists because no human value
  decision was requested;
- no matched Harness+human run or same-pre-state central formation run exists;
- no production, multi-host, external-organization or cross-version run exists;
- no business-revenue or human-attention measurement exists;
- source worktree binaries and dependency caches are not bundled; pinned
  source patches are.

The principal round files are contemporaneous normalized records, not raw
provider transcripts. This limits audit of model-level causality, so the packet
does not claim that A2A uniquely caused the design or that a weaker model would
fail.

## Consequence

The supported result remains a synthetic local technical Capability Claim.
Human value, commercial value, general transfer and A2A uniqueness stay
`UNKNOWN`. Integrity verification proves only that the transferred files are
complete and unchanged relative to the manifest.
