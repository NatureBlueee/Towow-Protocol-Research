# Agent Consumer Protocol

你正在消费一个 AI 原生规格包，而不是阅读一篇普通文档。

## 0. 不要立刻输出答案

首先读取：

1. `package.manifest.yaml`
2. `00_constitution/constitution.md`
3. `01_ai_native_spec_protocol/reader_protocol.md`
4. 当前项目的 `project.manifest.yaml`
5. 当前任务的 `task.manifest.yaml`（若存在）

## 1. 建立消费记录

创建 `ConsumerSession`，至少记录：

- consumer_id
- runtime_type
- model_or_human
- package_version
- project_spec_version
- loaded_nodes
- unresolved_dependencies
- context_conflicts
- output_contract
- validation_profile

## 2. 按依赖图读取

不得假设文件顺序等于逻辑优先级。  
每个节点通过 `id`、`type`、`status`、`scope`、`depends_on` 和 `supersedes` 确定其意义。

## 3. 区分陈述类型

必须区分：

- FACT
- INFERENCE
- ASSUMPTION
- HYPOTHESIS
- DECISION
- PRINCIPLE
- REQUIREMENT
- EXAMPLE
- EXTERNAL_CLAIM
- UNKNOWN

不得把 ASSUMPTION 写成 FACT；不得把 planned capability 写成 current capability。

## 4. 只加载最小充分上下文

先按 concern 路由 Context Pack。  
若包缺失、过期、冲突或权限不足，必须生成显式缺口，不得用常识静默补齐。

## 5. 先生成中间产物，再生成最终视图

典型顺序：

```text
Evidence → Claims → Decisions → Concepts/Objects → Closed Loops
→ Policies/Risks → Views → UI/PRD/External Language
```

不得直接从散文描述跳到页面。

## 6. 执行质量门

最终输出前必须运行项目指定的 conformance profile。  
任何 MUST 失败都必须：

- 修复；
- 降低主张强度；
- 标记未决；
- 重路由能力；
- 或升级给人类责任主体。

## 7. 完成条件

只有当另一个不共享当前对话的消费者，可以依赖发布产物重建同一产品世界，任务才算完成。
