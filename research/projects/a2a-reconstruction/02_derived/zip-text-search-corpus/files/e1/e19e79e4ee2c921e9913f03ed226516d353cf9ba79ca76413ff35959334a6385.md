# 通爻 Agent-to-Agent 研究交接总说明

## 1. 交接目的

这项工作的对象不是一套已经完成、等待润色的协议，也不是几篇阶段论文的合订本。它是一项仍在生长的理论与系统研究，试图回答：

> 当具备理解、判断、规划和行动能力的智能体大量进入现实世界后，多个拥有独立上下文、工具、资源、权威、责任和接受权的主体，怎样发现彼此、形成新的行动可能性、建立关系、承担承诺、协调执行、验证结果、解决冲突，并使一项候选合作逐步成为真正作数的共同现实？

接手者的核心责任不是“把现有材料写得更整齐”，而是以全部材料为研究输入，再做一次新的统一建模：

- 找出各阶段共同建立的研究对象；
- 分辨哪些概念是本体、状态、机制、算法、Pipeline、Provider、派生视图或实验方法；
- 重新建立层层递进的理论结构；
- 保留必要现实区分，同时消除语义冗余和阶段拼接；
- 将形式结论、机制证据、工程现实和开放假说放到正确强度；
- 形成能够独立解释、指导代码和接受反驳的统一论文。

本次交接的一个重要背景是：此前已经形成一篇约二十余页的短篇统一论文。它在“权威事实内核最小化”方面有价值，却过度压缩了理论层次，把“不应拥有第二套正式事实”误写成“理论上可以一笔带过”。因此新研究不能只在这篇短文上扩写，而需要重新回到全部原始材料。

## 2. 当前最佳问题定义

### 2.1 研究对象不是消息传输

官方 A2A、MCP 等协议已经处理 Agent 的互操作、消息、任务、工具和资源接口。通爻研究的是更上游与更下游的问题：

- 主体尚未完整知道自己的需求、能力和合作对象时，怎样形成新的联合行动；
- 主体完整世界不能安全集中时，怎样通过有限、任务相关的边界交互；
- 模型产生的候选如何避免冒领人的意图、权威和责任；
- 一条可能路径怎样被试验、见证、资格化、认领和授权；
- 传输成功怎样进一步变成目标域采纳、业务接受、结算和责任闭合；
- 主权协调的新增价值何时高于其成本。

因此，通爻的中心不是消息、Agent 人格或单个向量，而是：

> **多个主权世界之间的共同现实形成过程。**

### 2.2 核心矛盾

研究迄今反复触及五个不可相互替代的矛盾：

1. **无限私有世界与有限公共边界**：主体上下文巨大、动态、异构且敏感，任何公共表示都是有损投影。
2. **概率智能与制度权威**：大模型能够理解、生成和协商，但置信度不能自动产生授权、责任或接受。
3. **候选可能性与现实能力**：一条模型方案、逻辑计划或一次成功，不等于可复用、可承诺的能力。
4. **技术执行与现实效力**：消息送达、工具返回、文件存在或日志写入，不等于目标域采纳，更不等于业务接受。
5. **主权价值与协调成本**：若最小权限中心能够安全保留任务、隐私、权威、责任和退出权，复杂 A2A 可能没有必要。

### 2.3 研究的最终社会对象

完整 Principal 应是拥有价值、责任、最终拒绝权、Recognition 与 Acceptance 的人或组织。软件、仓库、Agent World 和业务系统可以是 `SovereignDomain` 或局部 `AuthorityDomain`，它们有权决定某些技术事实，却不能自动代表人的价值和责任。

这一点是后期现实实验的重要修正。技术域之间的 adoption/revocation 闭环能够证明局部机制，却不能冒充真实人的共同意图。

## 3. 为什么这次交接本身是一项研究

资料中存在多个看似相近、实则层次不同的概念：NAC、NC、Boundary Oracle、BIC、Coordination Schema、SJAC、JAA、PFE、CRA、CapabilityEnvelope、AssuranceCase、Harness、Compiled World、Recognition、Commitment、Domain Adoption 等。

简单整理通常会采取两种错误方式：

- **全量保留**：每个阶段概念继续作为独立引擎或模块，最后形成一张对象购物清单；
- **激进压缩**：只保留最小权威对象，其他全部降为“策略”或“视图”，导致理论解释力和形成过程消失。

真正的统一需要回答：

- 这个概念解决哪个不可替代的现实缺口？
- 它是一个外部世界中的持久事实，还是系统内部的计算方法？
- 它是否拥有权威状态，还是只产生候选、证据或投影？
- 它在共同现实形成链中位于哪一层？
- 它依赖哪些上游对象，又向下游提供什么？
- 删除或合并后，哪类现实失败会重新不可见？
- 保留为独立对象的成本是否超过判别力？

这些问题不能靠文件去重回答，必须重新建模。

## 4. 当前推荐的三维统一模型

现阶段最有解释力的起点是一个三维模型，而不是一个平面对象列表。

![三维统一模型](../diagrams/three_axes.png)

### 4.1 第一维：共同现实生成链

这条纵向链解释一项合作怎样从私有世界逐步变成现实：

```text
L0 主权世界
→ L1 边界与发现
→ L2 问题构成与共同介质
→ L3 可能性形成
→ L4 能力兑现与资格化
→ L5 主体认领与制度化
→ L6 执行与现实效力
→ L7 演化与编译世界
```

各层含义如下。

#### L0 主权世界

每个 Principal 拥有私有上下文、目标、工具、资源、关系、政策、本地 Harness 和不可任意委托的权威。Agent 只是其在某次执行中的智能代理。

#### L1 边界与发现

回答谁可能相关、应当释放什么、应当把数据移出还是把计算移入本地。包括 NC/NAC、多语义签名、Agent Card、Embedding、图、行为边界、Local Oracle、cut/witness/unknown/refuse 等。

#### L2 问题构成与共同介质

多个主体是否在讨论同一个问题，角色、变量、约束、证据和候选行动如何进入一个共同、版本化、可分叉、可编辑的介质。包括 Coordination Schema、SJAC、JAA、SharedArtifactVersion。

#### L3 可能性形成

当前无解时，系统下一步应询问、试验、引入工具、训练、伙伴、授权、任务拆分、风险保障还是退出。PFE、类型化 Unknown、VOI、EVPF、CEGIS 和 formation policy 位于此层。

#### L4 能力兑现与资格化

一条可能路径何时成为可复用能力。包括 Capability Experiment、Witness、环境指纹、运行域、留出、迁移、容量、组合、漂移、CRA、CapabilityEnvelope 和 AssuranceCase。

#### L5 主体认领与制度化

谁理解并愿意承担什么，什么开始形成义务。包括 Recognition、AuthorityGrant、Commitment、ResourceReservation、权利、拒绝、退出和争议条件。

#### L6 执行与现实效力

Harness 如何把承诺编译为受控动作；LogicalActionKey 与 AttemptID 如何区分现实动作和重试；Effect、Domain Adoption、Verification、Acceptance 与 Settlement 如何分别闭合。

#### L7 演化与编译世界

事件、结果、失败、Defeater 和人工决定如何改变以后系统的 Schema、Skill、能力合同、边界策略和可观察世界。

### 4.2 第二维：五种贯穿语义

每一层都同时包含：

1. **认识语义**：知道什么、未知什么、证据和反例是什么；
2. **生成语义**：可以提出、组合和形成什么；
3. **规范语义**：谁有权、谁认领、谁负责；
4. **操作语义**：实际尝试、效果、恢复和采纳是什么；
5. **经济语义**：价值、成本、容量、风险、隐私和人类注意力是什么。

例如 PFE 不能只负责生成候选。它还需要：

- 识别 Unknown 的类型；
- 遵守本地 Authority；
- 调用真实工具和局部试验；
- 计算形成动作的成本、风险和披露；
- 向 CRA 提供可验证的形成轨迹。

### 4.3 第三维：成熟度与保证等级

任何方案或能力都处于某个成熟状态：

```text
Unknown
→ Hypothesis
→ Candidate
→ Counterfactual
→ Sandboxed
→ Witnessed
→ Qualified
→ Recognized
→ Delegated
→ Committed
→ Performed
→ Verified
→ Adopted
→ Accepted
→ Settled
```

这条轴防止：

- 模型建议被写成能力；
- 一次沙箱成功被写成生产能力；
- 主体认领被写成代理授权；
- 执行成功被写成目标域采纳；
- 技术验证被写成业务接受。

### 4.4 三维模型的研究地位

这个模型是当前最强的统一假说，不是不可修改的终稿。接手者需要用全量主张谱系和概念依赖图检验：

- 是否存在无法放入三维模型的重要事实；
- L2 与 L3 是否需要重新分界；
- PFE 与 CRA 是两个层、一个循环的两种相位，还是其他结构；
- 成熟度轴是否应按 Claim 类型分裂；
- 经济语义是否需要成为独立的选择与机制设计层；
- Compiled World 是 L7 的投影，还是贯穿全链的操作界面。

## 5. 现有概念应如何被对待

### 5.1 NAC / NC / 多语义签名

NAC 的普适协议本体主张已被否定或限定，但它仍然承载重要研究：异构模型之间怎样以公共锚点、多尺度前缀和安全包络进行发现。它应作为 L1 的发现算法族被完整论述，而不是只写一句“降级为 Provider”。

需要保留：

- 为什么旧 HDC/FHRR 路线被调整；
- NAC 的锚点坐标和嵌套前缀；
- 包络剪枝的局部完备性与端到端 Recall 区分；
- 跨空间不变性条件；
- 与普通检索、空间翻译、图和人工转介的比较；
- 其失败边界和实验结果。

### 5.2 BIC / Boundary / Oracle

BIC 和动态边界不是简单的隐私过滤器，而是解决“有限边界怎样对当前任务足够”的核心理论。Boundary Oracle 的 cut、column、witness、unknown、refuse 等响应可以作为特定世界中的实现，但必须区分保证等级，防止模型 objection 被当成永久 hard cut。

### 5.3 Coordination Schema / SJAC / JAA

JAA 是共同编辑的行动安排，不应退化成普通 JSON 文档。SJAC 强调在行动安排形成前，协调问题的语言、变量、角色和约束本身可能尚未存在。Coordination Schema 与 JAA 的双层版本关系需要完整建模。

### 5.4 PFE

PFE 不是一个拥有正式事实的独立社会实体，但它是 L3 的完整形成理论：

- 诊断型与构造型 Unknown；
- 类型化否定；
- VOI 与 EVPF；
- 工具、训练、伙伴、授权、风险和恢复等形成算子；
- 有限闭包、开放前沿和不可判定边界；
- CEGIS 与设计—执行—反馈循环；
- 形成 episode 的因果归属。

### 5.5 CRA / CapabilityEnvelope / AssuranceCase

CRA 解决“存在一条路”怎样变成“可以在声明范围中依赖这条路”。它涉及复现、留出、迁移、容量、漂移、组合和再认证。CapabilityEnvelope 和 AssuranceCase 可以是派生视图，但其理论内容必须完整展开。

### 5.6 Recognition / Commitment / Harness / Effect

这些结构负责从候选世界进入现实。需要严格区分：

- Recognition 与 Authority；
- Commitment 与计划；
- LogicalActionKey 与 AttemptID；
- ActionAttempt 与 Effect；
- transport receipt 与 Domain Adoption；
- Verification 与 Acceptance；
- Acceptance 与 Settlement。

### 5.7 Compiled World

Compiled World 不拥有第二套事实，但它是整个系统能够被人理解、操作、审计和传播的身体。它不仅是前端，而是权威对象、事件、候选世界、可达状态、阻塞、Defeater 和行动权限的持续投影。

### 5.8 WoWok

WoWok 位于下游信任、权限、确定性执行、托管、结算和争议层。通爻应能够把已形成、已认领和已授权的关系编译给 WoWok 或国内等价基础设施，但上游理论不能被某个链上对象模型锁定。

## 6. 现有证据的正确强度

研究材料中的结论应按至少四级表达：

### 6.1 形式结论

例如：

- 非单射有限静态投影不能保留所有未来任务相关性；
- 当前不可行不能自动推出在全部允许变换下不可行；
- 可达性不能推出可靠性；
- 单体能力不能推出联合能力；
- 模型置信度不能生成权威。

### 6.2 相对稳定的设计不变量

例如：

- 概率与权威正交；
- 候选、能力、认领、承诺、执行和接受不能混合；
- 高后果外部效果必须经过确定性中介；
- 目标物质性变化必须显式；
- 主张需要类型相关 Witness；
- 证据需要完整性、可达性、可解释、可重放和相关性。

### 6.3 限域机制证据

例如：

- Allbuddy—Agent World 的 adoption/revocation/offline/recovery；
- R5C 技术域中的 authority-first countercondition reduction；
- 真实 Harness 的 readback、false ack 和环境 holdout；
- 真实模型谈判中规范性候选条款的生成。

这些只能支持声明范围内的机制，不能外推为真实人际或跨组织结论。

### 6.4 开放核心假说

例如：

- 两个真实人或组织是否能通过各自 Agent 形成此前不存在的联合行动；
- Agent 是否减少高级人类协调的认知负担；
- 生成式协调是否产生净正机会价值；
- 主权、自适应形成后编译为确定性运行是否是普遍有效架构；
- 主体是在发现偏好、形成偏好，还是被模型投射偏好。

## 7. 新研究员的首要研究任务

### 7.1 建立全量主张谱系

每个重要主张必须记录：

```text
原始表述
首次出现材料
必要前提
后续修正
支持证据
反例和失败
当前强度
当前统一模型位置
工程 Design Delta
正文是否保留及理由
```

不能只从现有 `claim_evidence_register.csv` 开始复制。该表是种子，不是完整谱系。

### 7.2 建立概念依赖图

至少回答：

- NAC 为什么依赖边界假设；
- Boundary 为什么需要任务相关充分性；
- JAA 为什么依赖 Coordination Schema；
- PFE 为什么依赖类型化 Unknown 和现实形成动作；
- CRA 为什么依赖形成轨迹和运行域；
- Commitment 为什么依赖 Recognition 与 Authority；
- Harness 为什么需要 Commitment、ActionAttempt 和 Effect 语义；
- Compiled World 为什么依赖统一事件和对象；
- WoWok 为什么在下游而不是上游。

### 7.3 建立证据—主张—Design Delta 矩阵

每项实验不能只记录成功率。需要记录：

- 它区分了哪些竞争解释；
- 哪些结果是由任务构造预先决定的；
- 它没有区分什么；
- 哪个设计因此改变；
- 若没有改变设计，为什么仍值得保留；
- 是否只属于仓库特定 Bug。

### 7.4 重建长篇统一论文

在前三项完成前，不应直接扩写短篇统一论文。真正的论文需要重新组织问题、理论、机制、协议、工程和证据。

## 8. 研究方法与质量要求

### 8.1 不以阶段为章节

阶段只记录思想演化，不能成为统一论文的结构。最终文本应像理论从一开始就是一个整体。

### 8.2 不以对象数量衡量完整性

对象是否保留取决于现实区分，而不是审美。非权威结构仍可成为重要理论层。

### 8.3 不用流畅语言掩盖证据不足

每个强主张都要有类型：形式结论、设计不变量、限域证据或开放假说。

### 8.4 不让实验替代研究问题

工程审计、幂等、日志和 Schema 应后台化。主实验只用于存在实质设计分歧、现实运行能产生新知识的问题。

### 8.5 理论必须回到构造能力

每个理论结论都要说明：

- 它迫使系统放弃什么；
- 它创造什么新方法；
- 它改变哪个接口、状态机或产品适用域；
- 它如何被实现和反驳。

## 9. 推荐的最终成果

建议形成：

1. **主论文／研究专著**：70–100+ 页中文主文，统一理论、机制、协议、系统、现实证据和适用边界；
2. **形式化规格附录**：对象、状态机、定理、协议接口和不变量；
3. **证据与审计附录**：实验、主张谱系、反例、代码覆盖和证据强度。

若主论文能够良好承载，可只保留一篇主文和两个附录，不必按阶段拆成多篇。

## 10. 交接成功的判据

交接完成不等于新研究员看完文件。真正成功应表现为：

- 能用自己的语言重建元问题；
- 能解释所有主要概念为何存在；
- 能指出哪些旧结论被限定，而不是简单删除；
- 能画出完整依赖和生成链；
- 能从原始实验回到 Claim 和 Design Delta；
- 能提出一个比现有短篇论文更强的统一模型；
- 能写出一篇不依赖阶段历史也能独立成立的长篇论文。
