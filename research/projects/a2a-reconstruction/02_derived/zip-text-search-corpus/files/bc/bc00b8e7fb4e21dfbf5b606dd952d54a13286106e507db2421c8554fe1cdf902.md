# r5-run-003-action-space-claims

## Research question

Does a static list of installed CLIs/connectors predict executable action space,
or must a Capability Claim include the operation, executor, policy path,
resource/service state, and evidence freshness?

## Pre-registration

`input/predictions_before.json` was written after static binary discovery and
before any Docker daemon or sandbox-exec functional probe.

## Holdouts

1. Docker daemon read capability.
2. Permissive sandbox-exec child launch.
3. Enforced denial of a synthetic canary to a sandboxed child while the parent
   can read it.

The Git and CodexPro cases are retrospective calibration and are not counted as
new holdout evidence.

## Decision impact

- A working canary denial would create a locally available mechanism for a
  stronger sovereignty experiment.
- Failure would show that independent processes or tool names alone cannot meet
  the sovereignty bar in this environment.
- Static-profile false assertions would support operationally scoped,
  evidence-bearing Capability Claims and safe `Unknown`.

## Safety

Docker is queried read-only; no image or container is created. The canary is
synthetic and temporary. No external model or network request is made.
