# 系统演进章程 v1.0

**意图陈述：** 这个系统会长很多年。章程回答一个问题：**怎么让它长而不烂**——新东西怎么进来、旧东西怎么退役、什么时候该加、什么时候该等。未覆盖情形按此外推：当"现在就加"与"守住结构"冲突时，先证明结构真的挡了路，再动结构。

## 一、冻结分级与变更协议

| 级 | 内容 | 变更协议 |
|---|---|---|
| **F0 宪法** | 问题定义书：公理 A、条件 R、裁决 D | **修宪**：新证据＋与 Nature 讨论清楚＋"原判断在什么条件下不成立"的论证入册（先例：J3 对 R7 的讨论）。频率预期：年级 |
| **F1 冻结接口** | IF-1/2/3、四动词语义、NAC 格式、账本对象格式、E1–E5 事件语义 | **单调加宽律**（见第二节）：小版本只加不改不删；破坏性变更＝大版本＋双跑重叠窗。详设不得反向改接口 |
| **F2 模块详设与本章程类文档** | M1–M5 详设、工作流、测试规格、本文 | 修订体例：改了什么／为什么／原结论为何不成立；挑战记录带翻案条件 |
| **F3 参数与配置** | 阈值 θ_k、K_max、ε、n、聚类划分、特性开关 | 自由改，但**每次变更是一个事件**（配置即事件→可重放可二分），经金丝雀；禁止改代码里的魔法数——一切参数入配置 |
| **F4 实验假设** | B7 预注册件 | 运行前冻结判停；运行后改判读＝违规；改设计＝新实验号 |

**归级测试**：拿不准一个改动属于哪级，问"它改变了谁对谁的承诺"——改变协议对端侧的承诺＝F1；改变模块对模块的承诺＝F2；只改变行为的调门＝F3。

## 二、单调加宽律（F1 的核心规则）

接口演化只有两种合法形态：
- **小版本（加宽）**：新增可选字段、新增错误码、新增动词参数、锚点尾部追加——旧客户端零感知，前缀/旧报文永远有效。可高频。
- **大版本（重排）**：删字段、改语义、锚点重排序——必须：双跑重叠窗（新旧并行有效，窗长入版本发布物）＋迁移程序（案例沉淀走 provenance 重投影；参数化沉淀走双写迁移）＋与 Nature 讨论后发布。必须低频。

此律借的是包络维护那条数学的**形状**（先加宽后生效、收窄走后台）——借形状不借保证：包络的保证来自线性代数，接口的保证来自纪律与契约测试（T1 的 X 系跨版本测试为其哨兵）。**违反方向（静默变窄）的历史教训就在本项目里**：C1 收敛把多面束压成单点、无人申报丢了什么——C8 为此立的收敛纪律，本章程推广为全系统规则（见第三节第 2 步）。

## 三、加法协议（任何新东西进系统的七步）

1. **归层**：按第一节归级测试定它碰哪一级；碰 F0/F1 的先停，走对应变更协议。
2. **收敛申报**：凡引入新表示、新抽象、或压缩既有表达力的，必须书面列明"**从此不再能表达什么**"与"新增能表达什么"——收益与代价同页。
3. **同构三问**：凡借外部方案——老家的承重假设是什么／在我们公理下成立否／借的是形状还是保证、保证怎么重新挣回。
4. **笨对照先行**：优化型组件的朴素孪生先合并（测试规格第四节）；无孪生不上线。
5. **实验闸门**：任何"上位"（替换默认路径、从旗标转默认、L 级晋升）须预注册证据；打不赢在位者不许上位——机制强度=证据强度。
6. **挑战记录**：被否决的替代方案连同**翻案条件**入档——今天的否决是带日期的，不是永久的。
7. **无仪表不合并**：新功能落地必须自带诊断钩子（脊柱挂载点＋至少一个漏斗归属仪表）＋对应 T0/T2 测试。定义完成＝可运行＋可归因。

## 四、晋升与退役

**晋升管道**：特性开关（内部租户）→ 金丝雀（试点租户）→ 默认开启——每步有回滚按钮与监控阈值（与 [Z§11.5] 灰度条款共用轨道）。**退役**：任何能力弃用前须使用遥测（谁还在用哪个老接口——[Z§11.2] 已要求后台可见）＋迁移窗口＋迁移工具；**沉淀数据永不退役**——格式过期的沉淀走重投影/双写迁移，删除历史事件在任何情形下违规（志只增不改是 F0 级）。

## 五、策略层：什么时候加，什么时候等

- **触发器睡眠清单**（Q-08 纪律的常设形态）：分布式路由、锚点治理实施、隐私密码学、W 联邦训练——各挂触发条件（AIP 征求意见稿现身／注册平台试点／客户自发问 agent 对接／标签量与密度阈值），触发前提议写码即违规。
- **预算判据**：每一块钱每一小时，要么买现金流，要么买验证阶梯上的证据，要么买未来端点的人口——三样都不买的不花。
- **纸面停机条件**：当新一轮讨论不再改变任何实验的设计或判读，纸面阶段的信息价值归零，唯一合法动作是去跑现实。

## 六、与召集台标准的接缝

[Z§11.2] 的版本固定、兼容矩阵、弃用策略、功能开关为两系统共同上位标准；本章程在其上叠加协议特有的三样：单调加宽律、收敛申报、笨对照先行。冲突时以更严者为准。

## 七、本章程自身的修订

本文属 F2，按修订体例演化；但第一节的分级结构本身若要改，视同 F1 级（它是"承诺的承诺"）。
