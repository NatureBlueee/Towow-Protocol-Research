# 公开现实证据研究方法 v0.6

## 1. 为什么改变证据路径

现实 Principal 的前瞻性实验仍然是决定性证据，但它不是研究继续推进的唯一入口。公开档案、监管复盘、交易文件、项目审查和已存档访谈能够先回答五类问题：

1. `Γ=<R,V,T,A,E,D,O>` 是否能编码真实制度转折；
2. 哪些变化在现实中被参与者当作 material，而不只是参数调整；
3. 形成、编译、运行与 reopen 是否在既有制度里有可观察对应物；
4. 哪些任务其实已经有成熟 institutional frame，不值得进入重型形成机制；
5. 当前 Fieldkit 会漏掉哪些权威、standing、assurance 与 outcome 变量。

它不能回答 Towow 是否因果地提高成交/不成交效率，也不能替代真实 Mandate、实时 Agent 行为、参与者负担、安全和长期 Acceptance。公开材料是“现实校准与理论反例源”，不是“无参与者的 R7”。

## 2. 研究设计

本轮采用结构化聚焦比较（structured, focused comparison）与时间序列过程追踪。每个案例都回答同一组问题：

- 冻结前态中，关系的 institutional frame 与 relation-specific frame 是什么；
- 必要角色、权威、证据和结果如何分布；
- 哪些事件只改变实例参数，哪些改变合法轨迹或效力语义；
- 哪种操作产生了 RelationVersion 变化；
- Operation、Effect、Adoption、Acceptance 是否被混淆；
- 是否存在成熟的 central/human/legal mechanism，可以构成强基线；
- 哪些解释与通爻候选理论竞争；
- 该案例实际要求系统做出什么 Design Delta。

### 2.1 理论抽样

五个案例不是统计样本，而是最大差异的理论样本：

- Sidewalk Toronto：公共外部性、数据权利与 affected-party standing；
- UK Open Banking：技术标准成功但治理失灵；
- Crossrail：局部交付与端到端现实效力断裂；
- SGMA：同一协调命令下的多中心权威与机制选择；
- Microsoft–LinkedIn：成熟制度框架下的复杂但可折叠关系，作为负对照。

### 2.2 证据层级

不以“是不是论文”简单排序。优先级取决于要证明什么：

- 合同、监管命令、SEC filing、目标世界记录：适合证明正式权威、承诺、退出或 Effect；
- 独立审计/调查：适合发现治理、证据与执行缺口；
- 同行评议实证研究：适合比较机制与结果，但须尊重其研究设计；
- 公开咨询与访谈：适合观察异议、standing、目标与解释，不自动等于代表性民意；
- 机构自述/新闻稿：可证明其公开立场，不足以证明争议事实。

每个案例用七维 evidence coverage 描述而不合成一个虚假的总分：来源接近度、过程粒度、权威可见性、Effect 可见性、参与者声音、反事实支持、三角验证；另记录选择偏差风险。

## 3. 编码单位

### 3.1 不新增协议对象

公开档案编码使用研究标签，不把它们升级成协议 aggregate root。`formation_operators` 只是描述反复出现的过程：

```text
actor_enrollment
refusal_or_objection
countercondition
authority_reallocation
scope_expansion / scope_contraction
evidence_demand / real_world_probe
standardization / staged_approval
independent_challenge
commitment_binding
compilation / institutionalization
reopen / termination
```

### 3.2 两个分辨率，而不是两套本体

同一套 Relation Schema 在两个分辨率上使用：

- `institutional frame`：法律、行业、组织或公共制度已经提供的角色、权威、证据、争议和退出语法；
- `relation-specific version`：当前主体围绕具体事项形成的条件、责任和操作路径。

它们通过引用和覆盖关系连接，不新增 `InstitutionalFrame` aggregate root。实现上可在 RelationVersion 中加入 `frame_scope` 与 `inherits_from`。

### 3.3 Materiality 判据

仍使用 v0.4 判据：只有变化改变任务相关可达轨迹、权威有效性、证据/Effect、数据权利、outcome/acceptance、恢复/退出/争议或角色完整性，才是 material。公开案例增加两项检查：

- **standing materiality**：变化是否新增/移除有合法受影响主张的人群或代表渠道；
- **enactment materiality**：纸面规则是否有真实执行能力、信息和制裁/升级路径。

二者是 R/A/E/T 的检查项，不新增顶层维度。

## 4. 时间纪律与因果纪律

1. 时间线按当时可获得的文件排列；后见之明不得改写前态。
2. “前态缺口与后来变化一致”只算 chronology-consistent diagnostic，不算盲化预测。
3. 每项机制主张必须列出至少一个竞争解释。
4. 官方给出的退出原因不得被研究者用更喜欢的理论替换。
5. 缺乏完整私有材料时，标记 observability gap，不把它误写成本体不存在。
6. 没有 Towow 干预，就不能给出 Towow treatment-effect 结论。

## 5. 公开材料可以达到的证据级别

### 可以提高

- 构念效度：我们的对象是否能映射到现实制度；
- 生态效度：关键机制是否真实出现；
- 边界条件：在哪些条件下 central/platform/human broker 已经足够；
- 设计效度：哪些字段、Gate、Defeater 和 witness 真正必要；
- 竞争解释质量：理论是否能经受反例和负案例。

### 不能提高到决定性水平

- Agent 介入的因果增量；
- 真实人对 Mandate/RelationVersion 的可用性与理解；
- 实时最小披露的隐私收益；
- live formation 的净协调剩余；
- 长期信任、后悔、操纵和权力效果。

## 6. 复核要求

v0.6 是单编码者初版。下一证据门不是再加案例数量，而是：

- 第二编码者在不知道本轮 Design Delta 的情况下独立编码至少三个案例；
- 对 `materiality`、`changed_components`、Authority Locus 和 outcome chain 计算一致性；
- 所有分歧保留 adjudication log；
- 通过 QDR 获取 SGMA 原始去标识访谈后，验证正式文件编码是否遗漏非正式权威、拒绝和机制选择原因。

只有完成这些步骤，公开档案语料才从 `single_coder_provisional` 升级为 `adjudicated archival evidence`。
