本轮真正需要解决的是：

> 在多个不能安全折叠的主体世界之间，什么样的互动方法能够用有限的信息交换和现实干预，把一个初始不可达的目标逐渐变成被目标主体接受的联合行动路径；并使这条路径能够被复用，而不是一次偶然成功？

你拥有研究自主权。不要机械执行固定步骤，也不要以证明通爻正确为目标。首先理解真实工作区和任务结构，然后自行选择最高判别力、最高解决能力增量的研究入口。

优先寻找一种真实任务结构：

- 不同主体分别控制互补但私有的知识、工具、资源、权威或验收条件；
- 初始没有被接受的完成路径；
- least-privilege central 不能在不破坏必要属性的条件下简单得到同样结果，或者应作为认真竞争的基线；
- Agent 能够自主询问、拒绝、返回 Unknown、提出反条件、运行局部实验、构造工具、请求授权、引入伙伴、修改任务结构和恢复路径；
- 互动可以形成真实条件，而不只是生成更多文本；
- 最终产生真实制品或状态变化，由独立目标域采纳和有权主体接受；
- 可以删除关键互动或条件做消融；
- 可以在未知任务或环境中检验复用。

不要为了符合上述描述人工编写一个必然有利于 A2A 的玩具任务。优先真实历史任务、真实跨项目问题、真实但低风险的协作阻塞，或者不由根研究者预写答案的任务材料。

研究过程可以分为建设性探索和冻结确认，但不要用固定轮数压死探索：

```text
理解不可达原因
→ 选择询问或现实形成动作
→ 在本地执行或试验
→ 获得 Witness / Defeater
→ 修改边界、计划或角色
→ 再执行
→ 提取候选协调方法
→ 冻结关键结构
→ 基线、消融、留出和独立复核
```

这只是一个研究循环示意，不是必须实现的新状态机。

你需要主动比较和发现：

- 什么时候应该询问，什么时候应该行动；
- 静态投影、动态查询、本地执行、验证器传递、cut/witness/unknown 等边界方式在什么任务里更有效；
- 哪些形成动作真正扩大了行动空间；
- 哪些只是语言重述、任务分配、强模型收益、人工兜底或目标降低；
- 什么形式的共享状态最支持设计—执行—反馈共同演化；
- 何时继续搜索、何时停止、拒绝或升级；
- 一次形成何时能够升级为可复用 Capability Claim；
- A2A 是否减少人类高认知工作，还是只增加 Agent 对话；
- 新增价值是否高于模型、等待、人类注意力、披露、验证、返工和恢复成本；
- 更简单的中心或 Harness+human 是否已经足够。

在没有真实外部阻塞时，至少完成一个由实际大模型驱动的 Agent-to-Agent Formation Episode。确定性代码可以实施边界、工具执行、日志和验证，但不能以预写 Python 角色代替主体智能，也不能预写成功路径。

每个承重 episode 必须保存互动前可达性、现实条件变化、目标域采纳、Acceptance、关键条件消融、原始目标价值和成本。形成后的成功不得回填为形成前预测命中。

如果结论涉及真实偏好、认领、责任或商业价值，引入真实人类或真实历史主体材料；不能让模型替主体完成最终价值判断。
