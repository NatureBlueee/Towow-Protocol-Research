# 通爻最小协议内核 v0.5

本规范只定义研究和实现中必须长期保持的 canonical facts。它不是网络传输标准，也不要求所有部署采用相同数据库或消息协议。

## 1. 六类 aggregate root

### 1.1 Entity

表示对外可寻址、可认证、可归因并具有行为连续性的实体包络。

最小字段：

```text
entity_id
identity_proof_refs
operating_domain_refs
governance_endpoint
status
version
```

Entity 不证明其陈述真实，也不自动拥有 Principal 的全部权威。

### 1.2 Mandate

表示某权威来源在特定时间、对象、动作、用途、金额、风险和升级条件下授予 Entity 的代理范围。

```text
mandate_id
principal_ref
delegate_entity_ref
valid_from / valid_until
scope
must_escalate
revocation_conditions
status
version
```

Mandate 必须可独立引用、过期、撤回和被新版本取代。

### 1.3 RelationVersion

表示多个权威域共同引用的精确关系版本。

```text
relation_id
version
schema Γ
instance x
dependencies
required_stances
stance_refs
mandate_refs
unresolved_counterexamples
status
supersedes
content_hash
```

它不是所有主体私有世界的合并，也不包含未经授权的完整上下文。

### 1.4 Assertion

表示一个有来源、适用范围、证据和可反驳条件的主张。

```text
assertion_id
proposition
issuer_ref
authority_basis
scope
evidence_refs
validity_window
defeater_refs
status
```

Effect、Adoption 和事实资格可以作为不同类型的 Assertion，但其 issuer 与证据规则必须不同。

### 1.5 Commitment

表示有权主体对未来行为、资源、责任或联合规则的承担。

```text
commitment_id
debtor_ref
creditor_or_beneficiary_refs
content
activation_conditions
discharge_conditions
violation_or_compensation
mandate_ref
relation_version_ref
status
```

共同制品权利只有在独立认领、修改、执行或争议时才提升为 Commitment；否则保留为 Relation policy。

### 1.6 Operation

表示一次实际尝试，不能自动等同于 Effect。

```text
operation_id
action_type
executor_ref
mandate_ref
relation_version_ref
inputs
execution_environment
start/end
producer_result
effect_assertion_refs
```

## 2. EventEnvelope

EventEnvelope 是哈希、传输、排序和审计封套，不是新的本体根。

```text
event_id
event_type
actor
timestamp
relation_version
authority_ref
payload
prev_hash
event_hash
```

典型类型：Assertion、Stance、Refusal、Countercondition、Probe、Commitment、Operation、Effect、Adoption、Acceptance、Defeater、Reopen、Dispute。

## 3. Stance

Stance 是有权主体针对精确对象版本作出的事件，不单独成为 aggregate root：

```text
stance_type ∈ {
  COMMIT,
  REJECT,
  CONDITIONAL,
  DEFER_UNKNOWN,
  WITHDRAWN,
  DISPUTED,
  ACCEPT,
  NOT_ACCEPT
}
subject_ref
object_ref + object_version/content_hash
conditions
reasons
mandate_or_authority_basis
explainback
```

Recognition 是理解并认领对象的 Stance 过程，不应被一个 `recognized=true` 布尔值替代。

## 4. Relation Schema

```text
Γ = <R,V,T,A,E,D,O>
```

- R：角色、参与拓扑和分离职责；
- V：对象与动作词汇；
- T：状态转移、恢复、退出和争议；
- A：提出、认领、承诺、执行、见证、采用和接受的权威；
- E：主张与 Effect 的证据语义；
- D：披露、用途、派生、保留、训练和再传递；
- O：处置、Adoption、Acceptance 和 Settlement 语义。

实例参数 `x` 不进入 Γ，除非越过阈值后改变上述语义。

## 5. 共同可行动条件

对关系版本 `r`，只有以下条件都通过，才标记 `ACTIONABLE`：

```text
TypedTrace(r)
∧ ValidMandates(r)
∧ RequiredStances(r)
∧ PreconditionsQualified(r)
∧ CapabilityAndResources(r)
∧ EffectWitnessDefined(r)
∧ AcceptanceCriteriaDefined(r)
∧ NoUnresolvedMaterialDefeater(r)
∧ ExitOrCompensationDefined(r)
```

`ACTIONABLE` 不等于已执行，不等于被采用，也不等于被接受。

## 6. 编译合同

稳定子图可以编译到 A2A、MCP/OAuth、工作流、审批或目标系统操作。编译必须满足：

- 不增加权限；
- 不改变目标所有权；
- 不把建议变成 Stance；
- 不把 Operation 结果变成目标域 Effect；
- 不丢失撤回、超时、补偿和 reopen；
- 保留 RelationVersion 和 Mandate 引用；
- 运行日志不是第二套权威状态。

## 7. 物化规则

一个语义差异只有在满足以下多项时才升级为独立对象：

- 独立身份和外部引用；
- 独立版本或撤销；
- 独立权威来源；
- 独立生命周期；
- 不能从其他 canonical facts 重算；
- 跨任务复用；
- 合并会造成真实错误；
- 独立争议、监管或执行需要。

否则优先作为事件类型、字段、策略、派生边或视图。

## 8. 风险分级

### 低风险

标准化、可逆、同目标、低漂移：优先中心化或确定性执行，RelationVersion 可非常薄。

### 中风险

多权威、私有条件、可逆现实 probe：使用完整 Mandate、Stance、Effect witness 和 scoped reopen。

### 高风险

不可逆、监管、第三方重大影响、持久学习或高价值承诺：需要独立凭证、审批、合规和可能的法律对象；v0.5 Fieldkit 仍不足以承载。

## 9. 兼容与演化

- 参数变化：同 schema version 下记录 instance event；
- 非实质 schema 变化：建立兼容版本，不重开已稳定子图；
- 实质 schema 变化：新 RelationVersion，重开影响闭包；
- 破坏性变化：明确 supersede、迁移、旧承诺处理和跨版本一致性；
- 分叉：不同主体可拒绝新版本并维持旧路径或退出。

## 10. v0.5 范围、挑战与来源扩展

### 10.1 RelationVersion 可选规则组

```json
{
  "standing_rules": {},
  "jurisdiction_rules": {},
  "challenge_rules": {},
  "settlement_rules": {}
}
```

它们属于现有 `R/A/T/O` 语义，不是新 root。

### 10.2 Assertion provenance

公开或私有 Assertion 可携带：

```text
source_role
contemporaneity
incentive_or_conflict
adversarial_testing
corroboration
redaction_and_completeness
claim_type_fit
source_locator
```

来源签名只证明出处与完整性，不自动证明内容真实、授权充分或适合当前 claim type。

### 10.3 Challenge Event

Challenge 至少引用：

```text
challenger_or_representation_locus
standing_basis
jurisdiction
challenged_relation_version
challenged_assertions_or_operations
evidence_refs
requested_disposition
scope
```

### 10.4 Scoped Settlement view

```text
SettlementView = derive(
  relation_version,
  jurisdiction_set,
  standing_set,
  challenge_horizon,
  evidence_state,
  open_challenges,
  effects,
  stances
)
```

它不得成为第二套事实源。

### 10.5 Compile states

```text
READY
READY_WITH_CONTINGENCY
NOT_READY
```

`READY_WITH_CONTINGENCY` 只适用于挑战范围明确、动作可逆、触发/暂停/补偿/升级机制存在的局部子图。
