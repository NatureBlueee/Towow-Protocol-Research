# Least-Privilege Central Baseline Result

The evaluator could inspect only the frozen public interfaces and registered
oracle. It could not read private Artifact bodies, impersonate consumer
authority or skip independent World Acceptance.

## Verdict

There is no single overall winner:

- after the interface is formed, a least-privilege central coordinator can
  mechanically run claim→read lineage→persist/project→ack. It ties A2A for
  execution and is simpler;
- it cannot independently create `adopted` without possessing or
  impersonating the consumer session. It must wait for the actual ProductShell
  consumer authority;
- whether a central designer could have invented the final interface from the
  same pre-state is `UNKNOWN`, because no matched central implementation
  attempt was run before formation.

The evaluator counted at least eight design decisions in the formed boundary,
but that is a design lower bound, not evidence that A2A uniquely supplied
them.

## Consequence

The reusable result should be split:

- use adaptive sovereign interaction for authority discovery, refusal,
  Defeater generation and countercondition reduction;
- once the boundary is frozen, use the simplest central/deterministic
  coordinator for routine execution and regression.

Full-access central is not a fair comparison because it changes the privacy
and authority problem.
