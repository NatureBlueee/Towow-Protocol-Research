# 通爻 Agent-to-Agent 研究交接总说明

## 1. 交接目的

这项工作的对象不是一套已经完成、等待润色的协议，也不是几篇阶段论文的合订本。它是一项仍在生长的理论与系统研究，试图回答：

> 当具备理解、判断、规划和行动能力的智能体大量进入现实世界后，多个拥有独立上下文、工具、资源、权威、责任和接受权的主体，怎样发现彼此、形成新的行动可能性、建立关系、承担承诺、协调执行、验证结果、解决冲突，并使一项候选合作逐步成为真正作数的共同现实？

接手者的核心责任不是“把现有材料写得更整齐”，而是以全部材料为研究输入，再做一次新的统一建模：

- 找出各阶段共同建立的研究对象；
- 分辨哪些概念是本体、状态、机制、算法、Pipeline、Provider、派生视图或实验方法；
- 重新建立层层递进的理论结构；
- 保留必要现实区分，同时消除语义冗余和阶段拼接；
- 将形式结论、机制证据、工程现实和开放假说放到正确强度；
- 形成能够独立解释、指导代码和接受反驳的统一论文。

本次交接的一个重要背景是：此前已经形成一篇约二十余页的短篇统一论文。它在“权威事实内核最小化”方面有价值，却过度压缩了理论层次，把“不应拥有第二套正式事实”误写成“理论上可以一笔带过”。因此新研究不能只在这篇短文上扩写，而需要重新回到全部原始材料。

## 2. 当前最佳问题定义

### 2.1 研究对象不是消息传输

官方 A2A、MCP 等协议已经处理 Agent 的互操作、消息、任务、工具和资源接口。通爻研究的是更上游与更下游的问题：

- 主体尚未完整知道自己的需求、能力和合作对象时，怎样形成新的联合行动；
- 主体完整世界不能安全集中时，怎样通过有限、任务相关的边界交互；
- 模型产生的候选如何避免冒领人的意图、权威和责任；
- 一条可能路径怎样被试验、见证、资格化、认领和授权；
- 传输成功怎样进一步变成目标域采纳、业务接受、结算和责任闭合；
- 主权协调的新增价值何时高于其成本。

因此，通爻的中心不是消息、Agent 人格或单个向量，而是：

> **多个主权世界之间的共同现实形成过程。**

### 2.2 核心矛盾

研究迄今反复触及五个不可相互替代的矛盾：

1. **无限私有世界与有限公共边界**：主体上下文巨大、动态、异构且敏感，任何公共表示都是有损投影。
2. **概率智能与制度权威**：大模型能够理解、生成和协商，但置信度不能自动产生授权、责任或接受。
3. **候选可能性与现实能力**：一条模型方案、逻辑计划或一次成功，不等于可复用、可承诺的能力。
4. **技术执行与现实效力**：消息送达、工具返回、文件存在或日志写入，不等于目标域采纳，更不等于业务接受。
5. **主权价值与协调成本**：若最小权限中心能够安全保留任务、隐私、权威、责任和退出权，复杂 A2A 可能没有必要。

### 2.3 研究的最终社会对象

完整 Principal 应是拥有价值、责任、最终拒绝权、Recognition 与 Acceptance 的人或组织。软件、仓库、Agent World 和业务系统可以是 `SovereignDomain` 或局部 `AuthorityDomain`，它们有权决定某些技术事实，却不能自动代表人的价值和责任。

这一点是后期现实实验的重要修正。技术域之间的 adoption/revocation 闭环能够证明局部机制，却不能冒充真实人的共同意图。

## 3. 为什么这次交接本身是一项研究

资料中存在多个看似相近、实则层次不同的概念：NAC、NC、Boundary Oracle、BIC、Coordination Schema、SJAC、JAA、PFE、CRA、CapabilityEnvelope、AssuranceCase、Harness、Compiled World、Recognition、Commitment、Domain Adoption 等。

简单整理通常会采取两种错误方式：

- **全量保留**：每个阶段概念继续作为独立引擎或模块，最后形成一张对象购物清单；
- **激进压缩**：只保留最小权威对象，其他全部降为“策略”或“视图”，导致理论解释力和形成过程消失。

真正的统一需要回答：

- 这个概念解决哪个不可替代的现实缺口？
- 它是一个外部世界中的持久事实，还是系统内部的计算方法？
- 它是否拥有权威状态，还是只产生候选、证据或投影？
- 它在共同现实形成链中位于哪一层？
- 它依赖哪些上游对象，又向下游提供什么？
- 删除或合并后，哪类现实失败会重新不可见？
- 保留为独立对象的成本是否超过判别力？

这些问题不能靠文件去重回答，必须重新建模。

## 4. 当前推荐的三维统一模型

现阶段最有解释力的起点是一个三维模型，而不是一个平面对象列表。

![三维统一模型](diagrams/three_axes.png)

### 4.1 第一维：共同现实生成链

这条纵向链解释一项合作怎样从私有世界逐步变成现实：

```text
L0 主权世界
→ L1 边界与发现
→ L2 问题构成与共同介质
→ L3 可能性形成
→ L4 能力兑现与资格化
→ L5 主体认领与制度化
→ L6 执行与现实效力
→ L7 演化与编译世界
```

各层含义如下。

#### L0 主权世界

每个 Principal 拥有私有上下文、目标、工具、资源、关系、政策、本地 Harness 和不可任意委托的权威。Agent 只是其在某次执行中的智能代理。

#### L1 边界与发现

回答谁可能相关、应当释放什么、应当把数据移出还是把计算移入本地。包括 NC/NAC、多语义签名、Agent Card、Embedding、图、行为边界、Local Oracle、cut/witness/unknown/refuse 等。

#### L2 问题构成与共同介质

多个主体是否在讨论同一个问题，角色、变量、约束、证据和候选行动如何进入一个共同、版本化、可分叉、可编辑的介质。包括 Coordination Schema、SJAC、JAA、SharedArtifactVersion。

#### L3 可能性形成

当前无解时，系统下一步应询问、试验、引入工具、训练、伙伴、授权、任务拆分、风险保障还是退出。PFE、类型化 Unknown、VOI、EVPF、CEGIS 和 formation policy 位于此层。

#### L4 能力兑现与资格化

一条可能路径何时成为可复用能力。包括 Capability Experiment、Witness、环境指纹、运行域、留出、迁移、容量、组合、漂移、CRA、CapabilityEnvelope 和 AssuranceCase。

#### L5 主体认领与制度化

谁理解并愿意承担什么，什么开始形成义务。包括 Recognition、AuthorityGrant、Commitment、ResourceReservation、权利、拒绝、退出和争议条件。

#### L6 执行与现实效力

Harness 如何把承诺编译为受控动作；LogicalActionKey 与 AttemptID 如何区分现实动作和重试；Effect、Domain Adoption、Verification、Acceptance 与 Settlement 如何分别闭合。

#### L7 演化与编译世界

事件、结果、失败、Defeater 和人工决定如何改变以后系统的 Schema、Skill、能力合同、边界策略和可观察世界。

### 4.2 第二维：五种贯穿语义

每一层都同时包含：

1. **认识语义**：知道什么、未知什么、证据和反例是什么；
2. **生成语义**：可以提出、组合和形成什么；
3. **规范语义**：谁有权、谁认领、谁负责；
4. **操作语义**：实际尝试、效果、恢复和采纳是什么；
5. **经济语义**：价值、成本、容量、风险、隐私和人类注意力是什么。

例如 PFE 不能只负责生成候选。它还需要：

- 识别 Unknown 的类型；
- 遵守本地 Authority；
- 调用真实工具和局部试验；
- 计算形成动作的成本、风险和披露；
- 向 CRA 提供可验证的形成轨迹。

### 4.3 第三维：成熟度与保证等级

任何方案或能力都处于某个成熟状态：

```text
Unknown
→ Hypothesis
→ Candidate
→ Counterfactual
→ Sandboxed
→ Witnessed
→ Qualified
→ Recognized
→ Delegated
→ Committed
→ Performed
→ Verified
→ Adopted
→ Accepted
→ Settled
```

这条轴防止：

- 模型建议被写成能力；
- 一次沙箱成功被写成生产能力；
- 主体认领被写成代理授权；
- 执行成功被写成目标域采纳；
- 技术验证被写成业务接受。

### 4.4 三维模型的研究地位

这个模型是当前最强的统一假说，不是不可修改的终稿。接手者需要用全量主张谱系和概念依赖图检验：

- 是否存在无法放入三维模型的重要事实；
- L2 与 L3 是否需要重新分界；
- PFE 与 CRA 是两个层、一个循环的两种相位，还是其他结构；
- 成熟度轴是否应按 Claim 类型分裂；
- 经济语义是否需要成为独立的选择与机制设计层；
- Compiled World 是 L7 的投影，还是贯穿全链的操作界面。

## 5. 现有概念应如何被对待

### 5.1 NAC / NC / 多语义签名

NAC 的普适协议本体主张已被否定或限定，但它仍然承载重要研究：异构模型之间怎样以公共锚点、多尺度前缀和安全包络进行发现。它应作为 L1 的发现算法族被完整论述，而不是只写一句“降级为 Provider”。

需要保留：

- 为什么旧 HDC/FHRR 路线被调整；
- NAC 的锚点坐标和嵌套前缀；
- 包络剪枝的局部完备性与端到端 Recall 区分；
- 跨空间不变性条件；
- 与普通检索、空间翻译、图和人工转介的比较；
- 其失败边界和实验结果。

### 5.2 BIC / Boundary / Oracle

BIC 和动态边界不是简单的隐私过滤器，而是解决“有限边界怎样对当前任务足够”的核心理论。Boundary Oracle 的 cut、column、witness、unknown、refuse 等响应可以作为特定世界中的实现，但必须区分保证等级，防止模型 objection 被当成永久 hard cut。

### 5.3 Coordination Schema / SJAC / JAA

JAA 是共同编辑的行动安排，不应退化成普通 JSON 文档。SJAC 强调在行动安排形成前，协调问题的语言、变量、角色和约束本身可能尚未存在。Coordination Schema 与 JAA 的双层版本关系需要完整建模。

### 5.4 PFE

PFE 不是一个拥有正式事实的独立社会实体，但它是 L3 的完整形成理论：

- 诊断型与构造型 Unknown；
- 类型化否定；
- VOI 与 EVPF；
- 工具、训练、伙伴、授权、风险和恢复等形成算子；
- 有限闭包、开放前沿和不可判定边界；
- CEGIS 与设计—执行—反馈循环；
- 形成 episode 的因果归属。

### 5.5 CRA / CapabilityEnvelope / AssuranceCase

CRA 解决“存在一条路”怎样变成“可以在声明范围中依赖这条路”。它涉及复现、留出、迁移、容量、漂移、组合和再认证。CapabilityEnvelope 和 AssuranceCase 可以是派生视图，但其理论内容必须完整展开。

### 5.6 Recognition / Commitment / Harness / Effect

这些结构负责从候选世界进入现实。需要严格区分：

- Recognition 与 Authority；
- Commitment 与计划；
- LogicalActionKey 与 AttemptID；
- ActionAttempt 与 Effect；
- transport receipt 与 Domain Adoption；
- Verification 与 Acceptance；
- Acceptance 与 Settlement。

### 5.7 Compiled World

Compiled World 不拥有第二套事实，但它是整个系统能够被人理解、操作、审计和传播的身体。它不仅是前端，而是权威对象、事件、候选世界、可达状态、阻塞、Defeater 和行动权限的持续投影。

### 5.8 WoWok

WoWok 位于下游信任、权限、确定性执行、托管、结算和争议层。通爻应能够把已形成、已认领和已授权的关系编译给 WoWok 或国内等价基础设施，但上游理论不能被某个链上对象模型锁定。

## 6. 现有证据的正确强度

研究材料中的结论应按至少四级表达：

### 6.1 形式结论

例如：

- 非单射有限静态投影不能保留所有未来任务相关性；
- 当前不可行不能自动推出在全部允许变换下不可行；
- 可达性不能推出可靠性；
- 单体能力不能推出联合能力；
- 模型置信度不能生成权威。

### 6.2 相对稳定的设计不变量

例如：

- 概率与权威正交；
- 候选、能力、认领、承诺、执行和接受不能混合；
- 高后果外部效果必须经过确定性中介；
- 目标物质性变化必须显式；
- 主张需要类型相关 Witness；
- 证据需要完整性、可达性、可解释、可重放和相关性。

### 6.3 限域机制证据

例如：

- Allbuddy—Agent World 的 adoption/revocation/offline/recovery；
- R5C 技术域中的 authority-first countercondition reduction；
- 真实 Harness 的 readback、false ack 和环境 holdout；
- 真实模型谈判中规范性候选条款的生成。

这些只能支持声明范围内的机制，不能外推为真实人际或跨组织结论。

### 6.4 开放核心假说

例如：

- 两个真实人或组织是否能通过各自 Agent 形成此前不存在的联合行动；
- Agent 是否减少高级人类协调的认知负担；
- 生成式协调是否产生净正机会价值；
- 主权、自适应形成后编译为确定性运行是否是普遍有效架构；
- 主体是在发现偏好、形成偏好，还是被模型投射偏好。

## 7. 新研究员的首要研究任务

### 7.1 建立全量主张谱系

每个重要主张必须记录：

```text
原始表述
首次出现材料
必要前提
后续修正
支持证据
反例和失败
当前强度
当前统一模型位置
工程 Design Delta
正文是否保留及理由
```

不能只从现有 `claim_evidence_register.csv` 开始复制。该表是种子，不是完整谱系。

### 7.2 建立概念依赖图

至少回答：

- NAC 为什么依赖边界假设；
- Boundary 为什么需要任务相关充分性；
- JAA 为什么依赖 Coordination Schema；
- PFE 为什么依赖类型化 Unknown 和现实形成动作；
- CRA 为什么依赖形成轨迹和运行域；
- Commitment 为什么依赖 Recognition 与 Authority；
- Harness 为什么需要 Commitment、ActionAttempt 和 Effect 语义；
- Compiled World 为什么依赖统一事件和对象；
- WoWok 为什么在下游而不是上游。

### 7.3 建立证据—主张—Design Delta 矩阵

每项实验不能只记录成功率。需要记录：

- 它区分了哪些竞争解释；
- 哪些结果是由任务构造预先决定的；
- 它没有区分什么；
- 哪个设计因此改变；
- 若没有改变设计，为什么仍值得保留；
- 是否只属于仓库特定 Bug。

### 7.4 重建长篇统一论文

在前三项完成前，不应直接扩写短篇统一论文。真正的论文需要重新组织问题、理论、机制、协议、工程和证据。

## 8. 研究方法与质量要求

### 8.1 不以阶段为章节

阶段只记录思想演化，不能成为统一论文的结构。最终文本应像理论从一开始就是一个整体。

### 8.2 不以对象数量衡量完整性

对象是否保留取决于现实区分，而不是审美。非权威结构仍可成为重要理论层。

### 8.3 不用流畅语言掩盖证据不足

每个强主张都要有类型：形式结论、设计不变量、限域证据或开放假说。

### 8.4 不让实验替代研究问题

工程审计、幂等、日志和 Schema 应后台化。主实验只用于存在实质设计分歧、现实运行能产生新知识的问题。

### 8.5 理论必须回到构造能力

每个理论结论都要说明：

- 它迫使系统放弃什么；
- 它创造什么新方法；
- 它改变哪个接口、状态机或产品适用域；
- 它如何被实现和反驳。

## 9. 推荐的最终成果

建议形成：

1. **主论文／研究专著**：70–100+ 页中文主文，统一理论、机制、协议、系统、现实证据和适用边界；
2. **形式化规格附录**：对象、状态机、定理、协议接口和不变量；
3. **证据与审计附录**：实验、主张谱系、反例、代码覆盖和证据强度。

若主论文能够良好承载，可只保留一篇主文和两个附录，不必按阶段拆成多篇。

## 10. 交接成功的判据

交接完成不等于新研究员看完文件。真正成功应表现为：

- 能用自己的语言重建元问题；
- 能解释所有主要概念为何存在；
- 能指出哪些旧结论被限定，而不是简单删除；
- 能画出完整依赖和生成链；
- 能从原始实验回到 Claim 和 Design Delta；
- 能提出一个比现有短篇论文更强的统一模型；
- 能写出一篇不依赖阶段历史也能独立成立的长篇论文。

# 当前统一模型：共同现实生成链 × 贯穿语义 × 成熟度

## 1. 模型目的

当前研究需要同时解决两个问题：

- 不能把所有阶段性概念继续堆成平面对象表；
- 不能为了最小内核而把 PFE、CRA、NAC、JAA、Harness 等承重理论结构压扁。

因此，本文件提出一个供后续研究检验的三维统一模型。它不是最终定理，而是当前最能容纳全部研究发现、又能保持层层递进的理论骨架。

![共同现实生成链](diagrams/unified_chain.png)

## 2. 第一维：共同现实生成链

设第 $i$ 个 Principal 的私有世界为：

$$
W_i = \langle K_i, G_i, C_i, T_i, R_i, P_i, H_i \rangle
$$

其中：

- $K_i$：知识、记忆、关系和历史；
- $G_i$：目标、偏好和价值；
- $C_i$：能力、Skill、模型和方法；
- $T_i$：工具、数据与环境；
- $R_i$：资源、容量和预算；
- $P_i$：政策、权限、责任与风险约束；
- $H_i$：本地 Harness、执行和事件历史。

共同现实的形成可抽象为：

$$
W
\xrightarrow{B}
C
\xrightarrow{S}
F
\xrightarrow{Q}
I
\xrightarrow{X}
W'
$$

其中：

- $B$：边界与发现；
- $C$：共同问题和协调介质；
- $S$：可能性搜索与条件形成；
- $F$：形成后的能力与资格化；
- $Q$：认领、权威、承诺与资源；
- $I$：受控执行、采纳、验证、接受和结算；
- $W'$：经行动更新后的各主体世界和共同制度。

为便于工程与论文组织，将其展开为 L0–L7。

### L0：主权世界 Sovereign Worlds

**解决的问题**：谁拥有完整上下文、价值、权威、资源和责任？

**核心结构**：

- Principal；
- SovereignDomain；
- AgentExecution；
- 本地上下文、工具、资源和 Harness；
- 不可任意委托的 Acceptance、拒绝和退出权。

**关键结论**：软件域可以有局部技术权威，但不能自动成为完整 Principal。AgentExecution 是一次受限执行，不应由拟人身份掩盖授权链。

**向下输出**：经过目的、受众、时间和权威限制的边界接口。

### L1：边界与发现 Boundary and Discovery

**解决的问题**：在无法读取完整世界时，怎样发现可能相关的主体和信息？

**核心结构与方法**：

- 全局画像、Agent Card、能力索引；
- NC / NAC、多尺度锚点坐标、多语义签名；
- Embedding、图、关系网络、人工转介；
- Behavioral Boundary / BIC；
- Local Oracle、cut、witness、countercondition、unknown、refuse；
- 计算移到数据侧与局部验证程序。

**理论边界**：有限非单射静态投影不能保留主体对所有未来任务的相关性。因此静态画像只能作为 Discovery Provider，不能成为主体行动空间的完整定义。

**核心设计问题**：怎样在决策价值、披露、风险、通信和人类注意力之间形成任务相关的边界。

**向下输出**：候选主体、边界响应、局部证据和需要共同表达的问题。

### L2：问题构成与共同介质 Problem Constitution and Shared Medium

**解决的问题**：不同主体是否在讨论同一个问题？角色、变量、约束、证据、目标和候选行动怎样共同存在？

**核心结构与方法**：

- Coordination Schema；
- SchemaRevisionRequest 与 SemanticCounterexample；
- SJAC；
- JAA / Joint Action Arrangement；
- SharedArtifactVersion；
- Patch、Fork、Stance、Claim、Assumption、Risk；
- 黑板、事件流和版本化共同对象。

**关键结论**：对话历史不是共同事实。JAA 不只是一个 JSON，而是多方共同作者化、版本化、可分叉的行动安排。Schema 本身也可能需要在反例中形成。

**向下输出**：一个可以被形成、试验、修改和认领的共同问题与行动空间。

### L3：可能性形成 Possibility Formation

**解决的问题**：当前无解或 UNKNOWN 时，系统应该怎样行动，使问题逐渐可解？

**核心结构与方法**：

- PFE；
- 诊断型 Unknown 与构造型 Unknown；
- 类型化否定：缺工具、缺伙伴、缺授权、缺恢复、拒绝、当前不可行、全局不可行；
- VOI：问什么最可能改变决策；
- EVPF：什么现实动作最可能扩展可达行动空间；
- 工具、训练、伙伴、授权、任务拆分、风险重构和恢复设计；
- CEGIS；
- authority-first countercondition reduction；
- 开放前沿、多策略搜索和现实 probe。

**关键结论**：Agent 只有谈判权、没有条件形成权时，多轮交流通常只能细化已有冲突。真正的形成需要设计—执行—反例—修正共同演化。

**向下输出**：候选形成路径、现实试验、Witness、Defeater，以及更新后的 JAA。

### L4：能力兑现与资格化 Capability Realization and Qualification

**解决的问题**：存在一条形成路径，什么时候能够成为可复用、可承诺的能力？

**核心结构与方法**：

- CRA；
- CapabilityExperiment；
- CapabilityWitness；
- EnvironmentFingerprint；
- OperationalDomain；
- CapabilityEnvelope；
- AssuranceCase；
- 复现、任务留出、环境迁移、压力、容量、组合、漂移和再认证；
- 开放复核、关键条件消融和 Defeater registry。

**能力主张形式**：

$$
Capability =
\langle
Goal, Executor, Environment, Domain, Preconditions,
Authority, Recovery, Evidence, Validity, Defeaters
\rangle
$$

并以条件性保证表达：

$$
Assumptions(x)
\Rightarrow
\Pr[Guarantee(x)] \ge 1-\epsilon,
\quad x\in\Omega.
$$

**关键结论**：一次成功只能证明并非完全不可能。形成后成功不能回填为形成前预测正确；能力与容量、组合、环境稳定性是不同问题。

**向下输出**：限定范围、可反驳、可过期的 Capability Claim，以及主体可以理解的能力视图。

### L5：主体认领与制度化 Recognition and Institutionalization

**解决的问题**：谁理解、愿意并有权承担什么？候选方案什么时候产生义务？

**核心结构与方法**：

- RecognitionAction；
- AuthorityGrant；
- Commitment；
- Obligation；
- ResourceReservation；
- 条件、撤回、退出、争议、责任和救济；
- Commitment Compiler；
- 目标版本和能力包络的精确绑定。

**关键结论**：模型预测主体会接受，不等于主体认领；主体认领不等于对 Agent 授权；技术域 adoption 不等于人的 Recognition。

**向下输出**：可由 Harness 执行、具有明确权威和责任的承诺网络。

### L6：执行与现实效力 Execution and Real-World Effect

**解决的问题**：系统究竟尝试了什么、现实改变了什么、谁采纳了什么、目标价值是否实现？

**核心结构与方法**：

- Harness；
- LogicalActionKey；
- ActionAttempt；
- Effect Gateway；
- canonical commit / authoritative readback；
- DomainAdoptionReceipt；
- Verification；
- Acceptance；
- Settlement / Dispute；
- 补偿、回滚、重试、幂等和至少一次投递。

**主张相关见证**：

$$
W_p = \langle S_p,F_p,C_p,I_p,Q_p,D_p,A_p \rangle
$$

不同 Claim 需要不同证据来源、时效、一致性、独立性、阈值、Defeater 和接受谓词。

**关键结论**：命令成功、最后退出码、日志写入、文件存在和消息送达，都不能自动代答 Effect、Adoption、Verification 或 Acceptance。

**向下输出**：权威事件、结果、失败、争议和可学习的现实证据。

### L7：演化与编译世界 Evolution and Compiled World

**解决的问题**：一次行动怎样改变系统未来的行为，怎样让人和 Agent 看见并操作共同世界？

**核心结构与方法**：

- Event Ledger；
- Compiled World；
- 因果归因；
- Schema、Skill、Workflow 和 Policy 演化；
- Defeater 与 reopen trigger；
- 形成阶段与稳定运行阶段切换；
- 多风险级别的物化；
- 观察、审计、传播和研究证据包。

**关键结论**：Compiled World 是权威对象和事件的投影，不是第二套事实。但它是系统获得身体、可理解性和操作性的关键层。

## 3. 第二维：五种贯穿语义

### 3.1 认识语义 Epistemic Semantics

关注：Claim、Evidence、Unknown、Assumption、Defeater、版本和认知状态。

任何层都要明确：

- 什么是直接观察；
- 什么是模型推断；
- 什么是主体声明；
- 什么是候选假设；
- 什么证据能够支持或推翻；
- 何时因离线、陈旧或冲突降级为 Unknown。

### 3.2 生成语义 Generative Semantics

关注：候选、组合、形成算子、搜索、任务重构和新行动空间。

一项新方案只有在改变可达状态、工具、伙伴、授权、任务结构、风险或恢复条件时，才可能构成真正的形成；纯语言扩写不应被当作行动空间扩张。

### 3.3 规范语义 Normative Semantics

关注：Principal、Authority、Recognition、Commitment、责任、拒绝、退出和接受。

概率智能可以建议，却不能靠置信度获得制度权力。

### 3.4 操作语义 Operational Semantics

关注：ActionAttempt、Effect、Adoption、Verification、Recovery、Idempotency 和 Settlement。

系统必须能从候选计划落到真实动作，并以权威状态而不是自述判断结果。

### 3.5 经济语义 Economic Semantics

关注：形成成本、机会价值、人类高认知时间、等待、披露、风险、容量、返工和机会后悔。

通爻的价值不能只与另一个 Agent 的 token 费用比较，还应与机会未发生、高级经纪人、人工+AI、最小权限中心和主权 A2A 比较。

## 4. 第三维：成熟度与保证等级

建议将成熟度作为 Claim 和 Artifact 的状态，而不是给整个系统一个单一成熟度。

| 状态 | 含义 | 不允许推出 |
|---|---|---|
| Unknown | 尚无足够信息 | 不代表不可行 |
| Hypothesis | 模型或主体提出可能性 | 不代表真实存在 |
| Candidate | 已进入共同介质 | 不代表可执行 |
| Counterfactual | 存在逻辑形成路径 | 不代表现实可达 |
| Sandboxed | 已在受限环境试验 | 不代表可迁移 |
| Witnessed | 有明确效果见证 | 不代表稳定能力 |
| Qualified | 在限定运行域满足资格 | 不代表主体认领 |
| Recognized | 主体理解并认领精确版本 | 不代表 Agent 获得执行权 |
| Delegated | 已授予执行权限 | 不代表义务已形成 |
| Committed | 正式义务网络成立 | 不代表已经履约 |
| Performed | 现实动作已执行 | 不代表技术或业务成功 |
| Verified | 规则层核验通过 | 不代表目标域或业务接受 |
| Adopted | 目标技术域正式采纳 | 不代表 Principal 接受 |
| Accepted | 有权主体接受目标价值 | 不自动代表结算完成 |
| Settled | 承诺效力和责任闭合 | 仍可能存在长期 Defeater |

## 5. 三维模型如何指导论文与工程

### 5.1 对论文

主论文应按共同现实生成链展开，每一层都同时讨论五种语义，并说明对象处于哪些成熟状态。这样 PFE、CRA、NAC 等不再是平行模块，也不会因不拥有权威事实而被理论删除。

### 5.2 对协议

协议应定义跨层不可混淆的对象和转换条件，而不规定所有领域必须采用同一发现算法、求解器或资格化方法。

### 5.3 对 Harness

Harness 是 L3–L7 的操作底座：承接 formation probe、执行候选、生成证据、编译承诺、控制 Effect、记录事件和触发 reopen。

### 5.4 对产品

产品不应一次性展示全部对象。应根据风险和任务阶段物化必要视图：

- 低风险内部任务可以只显式显示目标、行动、证据和结果；
- 高风险跨主体任务需要显式 Authority、Recognition、Commitment、Adoption、Acceptance 和 Dispute；
- Compiled World 可用不同视图呈现同一权威事实，而不复制状态。

## 6. 需要新研究员验证的核心问题

1. L2 问题构成和 L3 可能性形成是否应当更紧密地表示为一个循环？
2. Boundary 是否只属于 L1，还是贯穿所有层的主权接口？
3. PFE 与 CRA 是否应当作为形成与资格化两个相位，还是统一为一个生成—反驳循环？
4. 经济语义是否应当独立为机制选择层？
5. Compiled World 是 L7 的结果，还是贯穿 L0–L7 的交互界面？
6. Recognition、Authority 和 Commitment 在真实组织中最小需要哪些不同事件？
7. 技术域 Adoption 与 Principal Acceptance 的边界，在不同业务中是否会合并？
8. 哪些层是协议必须标准化的，哪些只需提供 Provider 接口？
9. WoWok 与国内等价效力层，应接收什么稳定中间表示？
10. 真实人或组织的主权 A2A 是否会迫使三维模型增加新的轴或层？

# 研究谱系与概念演化

## 1. 使用说明

本文件不是按时间线回顾“做过什么”，而是帮助新研究员理解：每个主要概念最初为了解决什么问题，后来受到什么证据压力，当前应当处于什么位置。

历史概念可能经历四种变化：

- **扩展**：原问题被证明更大，需要增加新的条件；
- **限定**：机制仍然有效，但成立范围比原主张窄；
- **归位**：概念不再拥有正式事实，却仍是重要理论层或算法；
- **淘汰**：概念把不同现实情况混为一谈，已被更准确结构替代。

## 2. 从匹配到生成式协调

### 原始问题

早期通爻试图解决陌生 Agent 的发现与协作：面对海量、动态、异构、端侧且拥有巨大私有上下文的 Agent，怎样从模糊需求出发，发现可能相关的主体。

初始范式接近：

```text
需求/供给表示
→ 语义签名
→ 路由与匹配
→ 渐进披露
→ 方案生成
```

### 关键转变

研究逐渐发现，现实关系并不是预先存在、等待搜索：

- 主体未必知道自己真正需要什么；
- 主体当前描述的能力不等于条件变化后的可达能力；
- 多方互补不能退化为两两匹配；
- 方案本身会帮助主体形成偏好、角色和条件；
- 协调的产物不是“匹配结果”，而是一个共同编辑的行动安排。

因此中心从“撮合”迁移到“生成式协调”。

### 当前结论

匹配与发现仍然重要，但属于 L1 的 Discovery。协议真正的对象是 L2–L6 的共同现实形成。

## 3. HDC / FHRR / 多语义向量签名

### 原始贡献

早期高维表示试图同时承担：

- 多段语义；
- 角色绑定和组合；
- 端侧隐私投影；
- 分布式路由；
- 粗筛和精筛；
- 低成本匹配。

### 暴露的问题

- 不同模型空间不可直接比较；
- 表示技术无法天然承载权威、披露、责任和承诺；
- 一个向量对象被迫同时解释主体、需求、角色、关系和状态；
- 对未来开放任务不存在通用有限充分表示。

### 当前身份

HDC/FHRR 应保留为特定本地表征和组合代数候选，不再承担协议本体。

## 4. NAC / Nested Anchor Coordinates

### 原始贡献

NAC 使用公共锚点相似度作为跨模型相对坐标，试图实现：

- 不共享同一模型也能获得可比较信号；
- 多尺度前缀表示；
- 由子树包络进行安全剪枝；
- 渐进传播和披露。

### 重要理论与工程价值

- 将“统一模型”改成“统一公共锚点”；
- 把粗到细检索和多尺度路由显式化；
- 区分剪枝局部完备性与预算截断后的端到端 Recall；
- 为陌生 Agent 网络提供可研究的 Semantic Rendezvous 算法。

### 受到的限定

- 相对表示成立依赖空间关系条件；
- 锚点坐标不能统一任意模型与任意任务；
- 多尺度锚点排序并不自动等同 Matryoshka 训练结构；
- NAC 不能决定主体权威、意图、承诺或现实效果。

### 当前身份

L1 Discovery Provider 中的一个重要算法族。论文需要完整展开其形式、实验和失败边界，而不是只写“降级”。

## 5. 四动词接口

`emit / quest / disclose / crystallize` 形成了易用的协议外观：发布信号、探问、披露、结晶方案。

其价值是提供简洁 SDK façade；问题是四个动词曾经被迫承载消息语法、世界对象、协商状态和承诺生命周期。

当前应保留为外观接口，背后映射到：

- Boundary response；
- SharedArtifactVersion；
- Proposal/Counter/Refuse/Unknown；
- Recognition/Commitment 等正式事件。

## 6. 类型账本与执行适配器

类型账本早期试图把生成方案变成结构化资源流、约束和承诺。它首次把“方案文本”推向可检查对象。

后续研究指出，候选方案、主体认领、Commitment、执行和 Settlement 之间仍需分层。类型账本应被理解为 JAA/Commitment 的某种领域 IR 或 Solver 输出，而不是直接代表全部社会效力。

## 7. Flowness Harness

Flowness 建立了：

```text
Problem IR
→ Design IR
→ Engineering IR
→ Consensus
→ Plan
→ Execution
→ Independent Validation
→ Evidence Closure
```

其核心贡献包括：

- 问题、设计和工程方案不能混在一起；
- 任务由事件触发，而不只由人或时间触发；
- 隔离工位和回流；
- 证据门、审查、修复、值班和自我观测；
- Context Compiler；
- 行为 Trace 和变更涟漪。

Harness 不是通爻之外的旁支。它是共同现实生成链中 L3–L7 的操作底座，也是现实实验能够发生的基础设施。

## 8. PRSE / PRSE-OS

PRSE 把研究和设计质量转化为 Gate：使命、证据、语义、闭环、体验、保证、语言和移交。它帮助发现通爻 v1.5 过早冻结接口、把研究假说写成协议事实的问题。

PRSE 的长期位置不是一套外部管理流程，而是：

- Coordination Schema 演化；
- PFE/CRA 设计变更；
- Claim 强度和 SRL；
- 盲实现与变更传播；
- 研究制品的证据闭合。

## 9. BIC：行为边界充分性

### 原始直觉

“体边对偶”试图表达：无限复杂的内部世界可以通过有限边界与外部形成有效关系。

### 严格化

BIC 将其改写为任务相关、交互式的行为边界充分性：边界不需要恢复完整世界，只需在给定任务族、风险和预算下保留足够决策价值。

### 当前位置

BIC 是 L1 的上位理论，也贯穿 L2–L6：

- 发现时决定发布什么；
- 协调时决定探问什么；
- 资格化时决定证据范围；
- 执行时决定允许什么；
- 接受时决定谁能看到什么。

它不是单一数据结构，而是一套主权边界设计理论。

## 10. Coordination Schema / SJAC

同行研究指出，JAA 之前还存在一个更上游问题：协调问题本身的角色、变量、约束和验证语言可能尚未形成。

SJAC、Benders、cut 与 column 提供了一个可形式化私有约束世界中的具体求解方法。

当前需要区分：

- `CoordinationSchema`：版本化公共语法；
- `JAA`：该 Schema 下的候选行动安排；
- `Solver Provider`：寻找可行实例的算法；
- `Boundary Oracle`：本地返回的约束、贡献和 Witness。

SJAC 的具体算法不应被写成所有领域的唯一引擎，但“问题语法也需要形成”是重要理论发现。

## 11. JAA / Shared Artifact

JAA 把协调中心从 Agent 对话转向共同对象：

- 参与主体和角色；
- 任务与依赖；
- 资源流；
- 条件和风险；
- 事实、假设和证据；
- 版本、分叉和各方 stance。

统一后，JAA 可以作为 `SharedArtifactVersion` 的一种重要类型。它不需要独占一个事实系统，但必须在理论上作为共同作者化介质完整展开。

## 12. PFE：可能性形成引擎

第三阶段的关键发现是：主体当前描述出来的能力不等于条件变化后的可达能力。

PFE 研究：

- 如何把 Unknown 分类；
- 如何诊断缺少工具、训练、伙伴、授权、风险、恢复或任务结构；
- 何时询问，何时行动；
- 如何用 EVPF 衡量形成动作；
- 如何通过局部实验和 CEGIS 形成新条件；
- 如何在开放世界中进行有预算搜索；
- 如何诚实停止。

### 重要限定

多轮语言谈判不是 PFE。形成必须改变现实可达状态。PFE 不应维护正式能力事实，它输出候选路径、实验和证据。

## 13. CRA：能力兑现与保障

第四阶段将“发现一条路”与“具备生产能力”分开。CRA 研究：

- 复现；
- 任务族与环境留出；
- 运行包络；
- 容量；
- 组合能力；
- 漂移与有效期；
- 目标物质性重构；
- open review 与消融；
- 资格化和重新资格化。

CapabilityEnvelope 和 AssuranceCase 是 CRA 输出的运行/审计视图。它们不应与 Claim/Evidence 平行维护正式状态，但 CRA 仍是 L4 的理论主层。

## 14. ActionAttempt / Effect / Adoption / Acceptance

现实实验逐步建立：

```text
LogicalActionKey
→ ActionAttempt
→ Effect
→ Domain Adoption
→ Verification
→ Acceptance
→ Settlement
```

它解决“系统说成功”与“现实真的改变”之间的断裂。

关键发现包括：

- 最后退出码可掩盖中间失败；
- raw bytes 不等于 canonical event；
- 消息送达不等于目标域采用；
- 目标域采用不等于真实人接受；
- Evidence 必须按 Claim 类型解释；
- adoption、revocation、offline、dispute 和 correction 必须是一等状态。

## 15. 形成阶段与确定性运行阶段

R5C 技术域闭环提出一个候选架构：

```text
主权、自适应形成
→ 边界合同冻结
→ 最小权限确定性运行
→ 监测 Defeater、版本和环境
→ 必要时重开形成
```

该架构有 scoped mechanism evidence，但没有 matched central formation 和真实 Principal 证据。因此应作为候选架构完整论述，而不是最终定理。

## 16. 真实模型谈判负对照

R5.4 真实模型实验表明，在一个可折叠、已有技术解、核心剩余问题是规范价值取舍、Agent 又没有条件形成权的任务中，多轮 A2A 主要产生更丰富的合同和救济条款，没有形成新能力或被双方接受的路径。

它的价值是提供适用边界：

- A2A 不应默认用于可安全折叠任务；
- 谈判不等于 PFE；
- `COUNTER / UNKNOWN / REFUSE` 可以是正确结果；
- 模型生成条款不等于真实主体偏好。

## 17. R5C 跨技术域形成闭环

Allbuddy—Agent World 实验形成：

```text
consumer authority
→ canonical adoption/revocation readback
→ scoped claim
→ target journal-before-ack
→ C2/C4 materialization
→ verified ack
→ restart replay
```

它支持目标域采纳、边界形成、现实 probe、反条件削减和形成后编译运行。

但 Allbuddy 和 Agent World 是技术域，不是完整 Principal。下一核心研究对象必须转向两个真实人的独立上下文、资源、权威和接受权。

## 18. Compiled World 与企业 Harness

Compiled World、企业 Agent 工作环境和可观测世界是通爻、Harness 与现实组织连接的身体：

- World 让人看见；
- Desk 让主体工作；
- Trace 让人相信和审计；
- 运行时把企业对象、权限、动作、证据和状态编译成 Agent 可进入的局部世界。

这一方向与 A2A 主线并不冲突。企业只是共同现实形成系统的一类部署世界。

## 19. WoWok 与效力基础设施

WoWok 提供 Service、Machine、Guard、Permission、Treasury、Repository、Arbitration 等确定性效力对象。通爻的任务是把已形成、已认领和已授权的关系编译到此类基础设施，而不是替代它。

国内可用电子签、平台实名、持牌支付、托管、发票、仲裁和企业系统承担相似功能，但需明确能力差异。

## 20. 接手者必须补全的谱系

本文件只提供主线。接手研究员仍需逐份阅读原始材料，补全：

- 每个主张首次出现的精确来源；
- 早期被压缩掉的公式、算法和反例；
- PFE、CRA 和同行研究的全部实验；
- 每次现实实验的设计选择与失败路径；
- 所有被后续限定但仍有价值的旧机制；
- 最新三维模型是否能够容纳全部发现。

# 当前主张、证据与边界状态

## 1. 为什么需要单独的证据状态文件

这项研究横跨形式推导、合成机制实验、参考实现、真实 Harness 轨迹、跨技术域闭环、真实模型协商和首席研究复核。不同证据的强度不可互换：

- 一个形式反例可以否定普适性，却不能证明某个替代方案在现实中有效；
- 合成实验可以区分机制，却不能估计真实世界频率；
- 真实仓库 Bug 可以揭示工程语义，却不一定改变核心理论；
- 技术域跨仓闭环可以证明 adoption 机制，却不能代表真实人的 Recognition；
- 模型对话可以证明模型会生成反条件，却不能证明主体真实偏好。

因此，新研究必须维护一张持续更新的 Claim–Evidence–Boundary 图，而不是只给每个主张一个“支持/不支持”标签。

## 2. 建议的证据分类

### E0：概念与定义

定义本身不需要经验支持，但必须能区分现实情况并产生设计后果。

### E1：形式推导与反例

适合支持不可能性、必要条件和复杂性边界。

### E2：合成机制实验

适合回答“在明确生成机制下，某种差异能否出现”。不能外推真实频率或商业价值。

### E3：参考实现与状态机验证

适合证明对象模型、状态转换和某类捷径能够机械阻止。

### E4：真实仓库与历史轨迹

适合揭示实现中的真实隐含条件、故障和语义错位。

### E5：跨技术权威域闭环

适合证明局部软件域之间的 adoption、revocation、offline、replay 和边界形成。

### E6：真实模型 Agent 互动

适合观察模型的提问、拒绝、反条件、计划修改和失败模式。但若主体材料由研究者编写，仍不能代表真实人偏好。

### E7：真实 Principal 认领与生产结果

当前核心缺失。需要真实人或组织拥有独立上下文、权威、接受权和责任。

## 3. 相对稳定的形式结论

### 3.1 静态投影不完备

**主张**：有限非单射静态投影不能保留主体对全部未来任务的相关性。

**证据**：构造性反例、任务相关充分性理论。

**可推出**：能力卡、Agent Card、NAC 或知识图谱只能作为特定任务的发现和投影，不应定义主体完整行动空间。

**不可推出**：任何静态投影都无用；特定封闭任务可能存在充分统计量。

### 3.2 当前不可行不等于全局不可行

**主张**：主体当前报告“不会/不能”不能安全升级为在所有允许变换下不可行。

**证据**：状态变换反例、工具/授权/环境干预实验。

**可推出**：需要类型化否定与形成动作。

**不可推出**：系统一定能形成能力；某些目标确实全局不可达。

### 3.3 可达性不推出可靠性

**主张**：存在一条逻辑路径，不能推出该路径在现实运行域中具有足够成功率。

**证据**：形式构造、one-shot false certification、漂移与工具压力实验。

**设计后果**：PFE 与 CRA 分离；需要复现、留出、容量、组合、有效期和 Defeater。

### 3.4 概率与权威正交

**主张**：模型置信度不能自动生成 Authority、Recognition、Commitment 或 Acceptance。

**证据**：职责定义、真实越权风险和多层 Gate 反例。

**设计后果**：模型语义引擎与确定性权威内核分离。

### 3.5 单体能力不推出联合能力

**主张**：多个局部可靠能力组合后，可能因接口、共享资源、时序或共同故障而失效。

**设计后果**：JAA 中的联合能力需要 IntegrationWitness 与组合资格化。

## 4. 相对稳定的设计不变量

### 4.1 候选、能力、认领、承诺、执行、采纳和接受不能混合

现有形式反例、状态机实验和现实轨迹共同支持该区分。具体对象可以按风险压缩物化，但语义不可消失。

### 4.2 目标物质性变化必须显式

系统不能通过缩小目标制造成功。ObjectiveVersion 需要记录保留价值、放弃价值、剩余缺口和 Recognition。

### 4.3 主张相关 Witness

不同 Claim 需要不同证据政策。文件 readback 不能证明业务接受；签名不能证明权限；日志不能证明目标域 adoption。

### 4.4 Evidence Closure 不止 checksum

至少包括：

$$
Integrity \land Reachability \land Interpretability \land Replayability \land Relevance.
$$

### 4.5 Effect 必须由目标世界的权威状态证明

ActionAttempt、outer exit、stdout 和日志都不能自动代答 Effect。

### 4.6 目标域 adoption 与 Principal Acceptance 分离

技术域可以决定记录是否进入自己的 canonical state；真实主体才能最终接受目标价值与责任。

## 5. 获得 scoped mechanism evidence 的主张

### 5.1 目标域 adoption

**证据**：Allbuddy → Agent World adopted@rev1 → revoked@rev2 → offline unknown → adopted@rev3；fresh restart、负状态 holdout、假 ack、journal conflict 等。

**支持范围**：单机、本地、固定协议、合成 consumer policy 的跨技术域 adoption/revocation/replay。

**未证明**：真实人或组织的业务接受与责任。

### 5.2 现实 probe + 反条件削减

**证据**：R5C 中本地权威拒绝过度设计、现实探针暴露并发与恢复缺陷、最终形成最小边界合同。

**支持范围**：类似跨技术权威域任务中的 formation policy。

**未证明**：跨行业、真实主体、异质模型和复杂经济关系的普适性。

### 5.3 主权形成后编译为最小权限运行

**证据**：R5C 形成阶段产生边界，稳定期由 deterministic coordinator 执行。

**支持范围**：目标、边界和权威稳定的窄域技术任务。

**未证明**：matched central formation、跨组织普遍性和长期漂移下的优势。

### 5.4 多轮模型协商生成更丰富的规范条件

**证据**：R5.4 生成 severability、entitlement floor、disclosure、dispute 等候选条款。

**支持范围**：模型可根据反条件扩展规范候选空间。

**未证明**：真实偏好、主体认领、技术可行和能力形成。

## 6. 被现实证据限定的主张

### 6.1 “多轮 A2A 自然创造新能力”

已被限定：当 Agent 只有语言谈判权、没有工具、实验、授权和任务重构权时，多轮互动主要细化已有冲突，不会自动扩大现实行动空间。

### 6.2 “主权 A2A 优于中心化”

已被限定：在 `CollapseSafe(T)` 成立的任务中，least-privilege central 可以更简单、更便宜。主权 A2A 的必要性来自不可折叠权威、责任、隐私、策略和退出权，而不只是部署分散或数据很多。

### 6.3 “一次形成成功证明能力”

已被否定：形成后成功需要另行资格化，且不能回填为形成前预测正确。

### 6.4 “NAC 是通用跨模型语义基础”

已被否定/限定：NAC 在部分表示关系和发现任务中有价值，不能承担完整协议本体。

### 6.5 “软件域可以作为完整 Principal”

已被否定：软件域是局部 AuthorityDomain，不拥有人的最终价值和责任。

## 7. 仍为核心开放假说的主张

### 7.1 真实主体的生成式协调

两个真实人或组织是否能通过各自 Agent，在不共享完整世界的情况下，形成此前不存在、双方分别理解和认领的联合行动路径？

### 7.2 偏好发现、偏好形成与模型投射

当 Agent 提出主体此前没有意识到的角色、条件或合作方式时，怎样判断它是在揭示隐含偏好、帮助主体形成新偏好，还是替主体发明偏好？

### 7.3 人类认知成本与机会价值

通爻是否减少高级经纪人、经理人、顾问和跨组织协调者的高认知工作？是否让原本不会发生的机会发生？

### 7.4 动态边界的最优或有效方法

不同任务中，应交换数据、问题、证据、验证器、局部执行结果还是条件性计划？何时信息已经充分？

### 7.5 PFE 的通用协调决策方法

系统如何选择询问、试验、工具、伙伴、授权、任务重构和停止？是否存在可迁移的策略族，而不是每个任务重新探索？

### 7.6 CRA 的真实预测力

能力合同能否在跨任务、跨模型、跨版本和跨环境的前瞻留出中预测成功，而不只是事后解释？

### 7.7 形成期与运行期分离

“主权、自适应形成 → 编译为最小权限确定性运行 → Defeater 触发重开”是否是广泛有效的架构，还是局部技术域现象？

## 8. 证据不能替代的内容

即使所有当前代码和实验通过，也不能自动证明：

- 法律效力；
- 主体真实理解；
- 组织愿意委托；
- 长期策略行为和串谋；
- 市场规模；
- 经济净价值；
- 大规模异构网络可扩展性；
- 真实社会中的公平与权力结构。

# 新研究员使命、方法与工作纪律

## 1. 角色定义

你不是文档编辑、资料管理员或阶段总结者。你是这项研究的下一位共同建模者。

你的任务是：

> 在不丢失现实区分、不保护历史答案、也不把研究压缩成对象清单的前提下，从全部原始材料中重新建立一个统一、分层、可证伪、可实现的 Agent-to-Agent 生成式协调理论与系统。

交接工作本身就是一轮研究，因为你需要决定：

- 什么是同一个问题的不同表述；
- 什么是不同现实问题，不能合并；
- 什么是权威事实对象；
- 什么是理论层、机制、算法、Pipeline、Provider、视图或实验方法；
- 哪些早期结构被后续研究真正吸收；
- 哪些只是在最新摘要中被过度压缩；
- 哪些主张已经被否定、限定或仍待验证；
- 最终统一模型怎样才能从主权世界递进到共同现实。

## 2. 不要做什么

### 2.1 不要按阶段汇编

最终成果不能以“第一阶段做了什么、第二阶段做了什么”作为主结构。阶段只应出现在研究史或证据来源中。

### 2.2 不要只扩写现有短篇统一论文

该论文是高度压缩入口，不是完整理论。直接扩写会继承它的 recency bias 和过度内核化。

### 2.3 不要把“非权威事实源”理解为“理论不重要”

PFE、CRA、NAC、JAA、SJAC、BIC、Compiled World 等可以不拥有第二套正式状态，但仍可能是共同现实生成链中的主层。

### 2.4 不要为了统一而强行消除分歧

如果两个理论在不同假设下成立，应保留条件。若证据不足，应给出能区分它们的研究路径。

### 2.5 不要用页数或文件数量代替完整性

长文的目标是充分推导，不是堆字；短文的问题是承重结构未展开，不是“看起来不像本科论文”。

### 2.6 不要把所有工程 Bug 升级为理论

仓库特定缺陷、可迁移工程不变量、机制证据和核心理论变化必须分开。

## 3. 研究原则

### 3.1 从问题缺口而非概念名称出发

每个概念都要回答：它消除了什么不可替代的失败？

### 3.2 以层级依赖而非平面对象组织

应建立：

```text
主权世界
→ 边界与发现
→ 共同问题与行动介质
→ 可能性形成
→ 能力兑现
→ 主体认领与承诺
→ 执行与现实效力
→ 演化与编译世界
```

并检验该链是否需要调整。

### 3.3 每个主张都标明强度

至少区分：

- 定义；
- 形式结论；
- 设计不变量；
- 限域机制证据；
- 工作假说；
- 核心开放假说；
- 已否定主张。

### 3.4 每个机制都需要接口

说明：

- 输入什么；
- 输出什么；
- 依赖什么；
- 什么状态不由它维护；
- 如何失败；
- 如何被替换；
- 如何与上下层连接。

### 3.5 每个实验都需要 Design Delta

实验不是证据装饰。需要明确它迫使理论、协议、代码或产品适用域改变了什么。

### 3.6 不可能性要转化为构造知识

若某目标不能普遍实现，继续回答：

- 需要放弃哪个要求；
- 改变哪些条件可使问题局部可解；
- 怎样限制失败；
- 当前最佳可达方案是什么。

### 3.7 真实世界优先但不放弃抽象

形式化用于定义边界和必要条件；合成实验用于隔离机制；真实轨迹用于暴露隐含变量；真实主体用于价值、认领和责任。

## 4. 第一阶段工作：建立研究底图

不要立即写正文。先完成以下制品。

### 4.1 全量主张谱系

目标不是抄现有 20 条 Claim，而是从全部材料中找出：

- 核心命题；
- 算法主张；
- 设计主张；
- 工程语义；
- 产品与经济假说；
- 被否定的旧假说；
- 尚未得到名称但反复出现的关系。

### 4.2 概念依赖图

至少覆盖：

- NC / NAC；
- Boundary / BIC / Oracle；
- Coordination Schema / SJAC / JAA；
- PFE / EVPF / CEGIS；
- CRA / Capability Contract；
- Recognition / Commitment；
- Harness / Effect / Adoption / Acceptance；
- Compiled World；
- WoWok。

### 4.3 证据图

将形式证明、合成实验、真实仓库轨迹、技术域闭环、模型协商和真实 Principal 缺口分别标出。

### 4.4 术语冲突表

例如：

- Actor 在早期指人、Agent 或软件节点；
- Capability 有时指当前工具存在、有时指可达路径、有时指生产资格；
- Adoption、Recognition 和 Acceptance 曾被混用；
- Boundary 有时指静态投影、有时指交互式 Oracle、有时指权限；
- Harness 有时指内部执行系统、有时指企业运行时。

统一论文必须消除这些歧义。

## 5. 第二阶段工作：提出统一模型候选

至少比较三种组织方式：

1. 权威事实内核为中心；
2. 共同现实生成链为中心；
3. 三维模型：生成链 × 贯穿语义 × 成熟度。

可以提出第四种更强模型，但必须说明它比三维模型增加了什么解释力和构造能力。

评估标准：

- 是否能容纳全部重要概念；
- 是否能解释概念为何存在；
- 是否支持协议和代码接口；
- 是否区分候选与权威事实；
- 是否支持不同风险级别的简化物化；
- 是否能放置所有现实证据和开放问题；
- 是否减少阶段拼接感。

## 6. 第三阶段工作：写长篇统一论文

写作时不要从已有论文复制段落后拼接。每一章按统一论证模板重写：

```text
问题缺口
→ 必要区分
→ 正式定义
→ 机制与算法
→ 与上下层接口
→ 不变量与失败方式
→ 证据
→ 设计与工程后果
→ 适用边界
```

每一层都要能回答：为什么上一层不足、这一层新增什么、为什么不能跳过、下一层为何仍然需要。

## 7. 建议的研究协作方式

### 7.1 主研究员

负责：

- 判断问题；
- 统一模型；
- 解释反例；
- 决定概念去留；
- 写核心论证。

### 7.2 子 Agent / 工具

可以承担：

- 文件索引；
- 主张抽取；
- 术语对齐；
- 公式和引用核验；
- 代码与实验复现；
- 盲审和反例搜索；
- 图表与附录生成。

但不得让自动抽取结果直接成为统一模型。

## 8. 质量 Gate

统一成果至少应通过：

### G0 问题 Gate

是否清楚定义了完整元问题，而不是某个局部协议？

### G1 概念 Gate

每个核心概念是否有不可替代的现实职责？

### G2 层级 Gate

是否形成从私有世界到现实效力的连续链？

### G3 权威 Gate

候选、证据、认领、承诺、执行和接受是否清楚分离？

### G4 证据 Gate

每个强主张是否有匹配强度的证据？

### G5 构造 Gate

理论是否给出怎样做，而不只解释为什么难？

### G6 工程 Gate

对象、状态机、接口和失败恢复能否指导实现？

### G7 现实 Gate

是否诚实说明真实 Principal、经济价值和长期社会证据仍缺什么？

### G8 盲读 Gate

未参与阶段研究的人能否只读主文理解整体？

## 9. 停止条件

研究不以读完文件、写满页数或完成目录为停止。

合理停止条件是：

- 全部承重主张已经进入谱系；
- 所有主要概念有依赖位置；
- 统一模型能够解释所有重要反例；
- 主文可独立成立；
- 证据强度与语言一致；
- 未决问题清楚且不会被伪装成已解决；
- 新研究员或盲审者能够据此设计系统和下一项高价值研究。

## 10. 最重要的心智提醒

不要问：

> 哪个阶段的版本是对的？

要问：

> 每个阶段看见了完整问题的哪一部分？这些部分怎样共同组成一个能够形成现实的系统？

不要问：

> PFE 是否应该被删掉？

要问：

> PFE 在统一生成链里承担什么不可替代的变换，其输出怎样进入权威事实而不制造第二套真相？

不要问：

> 论文应该有多少页？

要问：

> 每一个承重结构是否被充分推导、验证、连接和限制？

# 长篇统一论文重建蓝图

## 1. 建议定位

建议最终成果定位为一篇“研究专著式建设性系统论文”，暂定题目：

# 主权智能主体的共同现实形成
## Agent-to-Agent 生成式协调的统一理论、形成机制、协议与运行系统

它不是：

- 标准协议说明书；
- 产品白皮书；
- 阶段实验合集；
- 纯数学论文；
- 普通计算机系统论文。

它应同时承担：

- 理论对象定义；
- 不可能性与必要条件；
- 机制和算法；
- 协议对象与状态机；
- 工程构造；
- 现实证据与反例；
- 适用边界；
- 开放核心假说。

建议主文约 70–100+ 页中文 A4；形式化规格与证据审计可作为附录或配套文稿。页数仅为承载能力估计，不是完成指标。

## 2. 中心命题候选

> 多个无法安全折叠的 Principal 世界，可以通过任务相关的交互边界、共同问题与行动介质、状态改变型可能性形成、可反驳的能力资格化、主体认领与承诺，以及主张相关的现实效力闭环，共同生成此前不存在的联合行动；协议的核心职责不是让 Agent 互发消息，而是规定一项候选可能性如何在不同主权世界中逐步作数。

该命题仍需真实 Principal 证据限定，因此论文应区分：

- 已建立的形式与系统结构；
- 获得 scoped mechanism evidence 的局部闭环；
- 尚未验证的社会级生成式协调价值。

## 3. 建议总体结构

## 第一部：研究对象与理论地基

### 第 1 章　理解力不再稀缺以后，协调为什么仍然稀缺

需要回答：

- 大模型吸收了哪些过去稀缺的认知能力；
- 为什么理解增强没有自动产生权威、责任和关系；
- A2A、MCP 已经解决什么；
- 通爻试图解决的缺口是什么；
- 为什么研究中心是共同现实形成。

### 第 2 章　Principal、AgentExecution 与 Sovereign World

需要建立：

- Principal 与软件域的区别；
- AgentExecution 的授权和归因；
- 私有世界的组成；
- 权威、拒绝、退出和接受为何不可自动中心化；
- Actor、Agent、Domain、Organization 等历史术语的统一。

### 第 3 章　静态表示的不完备性与任务相关充分性

完整展开：

- 非单射投影反例；
- 特定任务充分统计量；
- Blackwell、信息瓶颈和交互信息复杂度；
- 为什么静态能力卡有用但不完整；
- 为什么动态边界不是简单隐私过滤。

### 第 4 章　折叠边界：什么时候需要主权 A2A

建立 `CollapseSafe(T)`：任务、隐私、权威、责任、战略、时效、故障和经济保真。

需要说明：

- 中心协调服务为何不与主权冲突；
- 数据量大、部署分散为何不是原则性非折叠；
- 最小权限中心何时足够；
- 哪些属性一旦中心吸收就破坏问题；
- 折叠边界本身怎样被形成。

### 第 5 章　概率智能与制度权威

系统论证：

- 模型智能承担什么；
- 置信度、校准和风险门；
- 语义熵的价值与系统性错误；
- 模型为什么不能产生 Authority；
- 未来更强模型会吸收哪些模块，哪些结构仍必须存在。

### 第 14 章　权威事实内核

主权、自适应形成

### 第 19 章　不可能性与复杂性

- 当前否定与全局否定；

- 有限证据不能保证全部未观测域；
- 机制设计不可能性；
- 中心化与主权的不可兼得属性。

每个结论必须写出 Design Delta。

### 第 20 章　建设性替代

回答：

- 不完备时怎样采用 anytime search；
- 不可靠时怎样校准、弃权和升级；
- 不可证明全部运行域时怎样声明包络；
- 不可集中时怎样建立边界；
- 不可自动决定价值时怎样进入 Recognition；

# 开放问题与关键设计决策

## 1. 使用方式

本文件不是下一轮固定实验清单。它记录的是当前统一理论仍然依赖、且不同答案会导致实质不同架构的关键未知。新研究员需要先判断：

- 该问题是否已能通过现有理论和证据作出设计决定；
- 是否只剩工程实现；
- 是否存在两个以上实质不同的候选解释；
- 哪种新证据最能改变设计；
- 问题是否值得进入主论文的开放核心。

## 2. 统一模型本身的开放问题

### Q1　三维模型是否足够

当前候选：共同现实生成链 × 五种贯穿语义 × 成熟度。

未决：

- 是否还需要独立的经济/机制设计轴；
- Boundary 是否贯穿所有层而非只在 L1；
- Compiled World 是否是纵向结果或全链界面；
- 成熟度是否应按 Claim 类型分裂。

**不同答案的 Design Delta**：论文结构、协议对象和运行时模块边界会改变。

### Q2　PFE 与 CRA 是两个层还是一个循环

候选 A：PFE 形成可能性，CRA 独立资格化。

候选 B：形成和资格化交替迭代，属于一个生成—反驳循环。

候选 C：PFE/CRA 只是 Harness 中不同 policy mode。

**需要判断**：哪种模型最能解释现实 probe、holdout、Defeater 和 reopen。

### Q3　Coordination Schema 与 JAA 的关系

- Schema 是否必须始终独立版本化；
- 何时局部 Artifact 已足够；
- Schema 演化如何避免方言碎片；
- 反例什么时候修 JAA，什么时候重构 Schema。

## 3. 折叠边界与主权 A2A

### Q4　`CollapseSafe(T)` 能否成为可操作评估

当前只是理论条件集合。需要判断：

- 是否能形成可计算或可审计的检查表；
- 哪些属性是硬约束，哪些可通过风险定价；
- 最小权限中心怎样证明未冒领权威；
- 折叠边界能否动态变化。

### Q5　主权 A2A 的不可替代价值

核心假说：某些主体间的隐私、权威、责任、竞争和退出权不能被中心吸收。

缺失证据：真实人/组织场景下，主权 A2A 是否产生中心无法获得的联合行动和净价值。

## 4. 边界与发现

### Q6　动态边界如何选择信息形式

候选：

- 静态投影；
- 交互式问题；
- 本地执行，只返回结果；
- 传验证器；
- cut/witness/countercondition；
- 差分隐私、安全计算、TEE；
- 条件性披露。

需要判断：不同任务结构下何种边界最保留解决能力，且披露成本最低。

### Q7　NAC 的最终位置

需要补全：

- 它在哪些空间假设和任务中优于普通检索；
- 是否适合作为 coarse rendezvous；
- 多尺度锚点怎样治理和版本化；
- 与本地 Oracle、图和模型翻译怎样组合；
- 是否存在值得专利化或产品化的独立价值。

### Q8　边界交互何时停止

需要统一 VOI、EVPF、披露成本、风险和人类注意力。停止规则既不能过早丢失机会，也不能无限探问。

## 5. 可能性形成

### Q9　怎样选择下一项形成动作

系统面对 Unknown 时应询问、试验、引入工具、伙伴、授权、任务重构还是退出？

当前存在 VOI、EVPF、CEGIS、countercondition reduction 等候选方法，但缺少真实跨任务策略证据。

### Q10　新行动空间怎样被证明

需要区分：

- 原本存在但未发现；
- 通过互动新形成；
- 强模型直接找到；
- 人工兜底；
- 目标降级；
- 语言重述。

理想证据需要形成前可达集、形成后可达集和关键条件消融。

### Q11　开放世界搜索怎样可持续

- 模型排序可能出现覆盖坍缩；
- 枚举和 BFS 成本过高；
- 新形成算子可以无限扩张；
- 需要多样性、负结果档案和 budgeted regret。

## 6. 能力合同与资格化

### Q12　能力合同是否有前瞻预测力

当前 Claim 字段较完整，但真实 holdout 很少。需要回答：

- 是否优于一次成功、最近成功率和模型置信度；
- 环境指纹需要多细；
- 哪些条件是因果关键，哪些只是相关；
- 能力能否跨模型或工具版本迁移。

### Q13　能力、容量与组合怎样统一

一个能力可以执行，不代表能承诺并发和截止期；单体能力也不代表组合能力。需要统一 Capability Contract、CapacityProfile 和 IntegrationWitness。

### Q14　CRA 何时值得显式存在

低风险内部任务是否只需轻量 Gate？高风险任务何时需要完整 AssuranceCase、独立复核和留出？

## 7. 主体、认领和偏好

### Q15　真实主体 Recognition

需要研究：

- 主体如何理解 exact version；
- 多少解释和 comprehension check 足够；
- 界面默认和模型总结是否诱导；
- 何时需要局部逐项认领；
- 撤回、冷静期和代理误导责任。

### Q16　偏好发现、形成与投射

当 Agent 提出新角色、权利或合作方式时：

- 是揭示隐含偏好；
- 帮助主体形成新偏好；
- 还是模型投射常见模板？

这是完整社会 A2A 的核心盲区。

## 8. 承诺、效力和外部基础设施

### Q17　技术域 adoption 与 Principal Acceptance 的关系

不同业务中两者可能完全分离、部分合并或由同一人/系统承担。需要定义通用接口而不强制过多对象。

### Q18　WoWok 中间表示

需要决定通爻向 WoWok 或国内等价基础设施输出：

- 哪种 Commitment IR；
- 哪些 Evidence；
- 哪些 Authority；
- 哪些资源与结算条件；
- 如何处理链下业务接受和争议。

### Q19　形成期与运行期切换

候选架构有 scoped evidence。需明确：

- 何时边界可冻结；
- 哪些 Defeater 触发 reopen；
- 冻结后中心协调器如何保持最小权限；
- 运行中如何防止边界逐渐失真。

## 9. 人类协调与经济价值

### Q20　通爻替代或增强的对象是谁

不只是另一个 Agent，可能是：

- 高级经纪人；
- 跨组织经理人；
- 顾问；
- 专家会议；
- 人工上下文阅读；
- 没有发生的合作机会。

需要建立匹配的现实基线。

### Q21　人类高认知成本怎样测量

可能指标：

- 阅读时长；
- 需要人处理的决定数量；
- 每个决定所需上下文；
- 上下文切换；
- 会议和等待；
- 返工；
- 决策后悔；
- 关系与信任成本。

### Q22　机会创造价值怎样估计

当基线是机会根本不会发生时，不能只比较 token。需要估计发现、形成、接受、执行概率与价值。

## 10. 长期制度与网络问题

### Q23　策略性主体与信息操纵

- 虚假 Claim；
- 策略性 cut/column；
- 隐瞒；
- 声誉操纵；
- 串谋；
- 边界重建攻击。

### Q24　协调器权力

谁定义 Schema、目标函数、排序、搜索预算和风险？中央协调面可能成为新的结构性权力中心。

### Q25　长期演化

重复合作如何形成惯例、Skill、Workflow 和制度？怎样避免一次错误学习污染未来？

## 11. 论文重建中的关键决策

### Q26　主论文是单篇还是主文 + 两附录

应按功能拆分，而非阶段。建议主文统一理论，形式规格和证据审计作为附录；需根据写作后实际承载判断。

### Q27　旧概念如何安放

每个旧概念需进入：

- 当前主理论；
- 条件机制；
- 特定算法；
- 失败边界；
- 历史淘汰假说；
- 附录。

不能无说明消失。

### Q28　统一模型是否需要新名称

新命名应增加解释力，不应制造第六个平行引擎。若“三维共同现实形成模型”足够，不必追求品牌化缩写。

## 12. 优先级判断方法

建议用以下函数评估研究问题：

$$
Priority(q)=
\frac{
P(\text{改变核心设计})\cdot
InformationGain(q)\cdot
SolutionCapabilityGain(q)\cdot
Reality(q)
}{
Cost(q)+Risk(q)+Setup(q)
}.
$$

高优先级问题应满足：

- 结果会改变统一模型、协议或产品适用域；
- 现有推理不足；
- 现实运行能够产生独特信息；
- 成功或失败都产生建设性 Design Delta。

# 统一术语表（研究交接版）

## Principal

拥有最终价值、责任、拒绝权、Recognition 与 Acceptance 的人或组织。Principal 可以委托，但模型不能自动产生其权威。

## SovereignDomain / AuthorityDomain

由 Principal 控制的软件、数据、工具、策略或业务域。它可以决定局部技术事实，例如是否采纳一条记录，但不自动等于完整 Principal。

## AgentExecution

某一模型、程序或 Agent 在具体时间、上下文、工具和 AuthorityGrant 下的一次可归因执行。应避免用长期拟人身份掩盖授权和版本。

## AuthorityGrant

限定动作、对象、目的、期限、资源和撤销条件的授权。

## RecognitionAction

Principal 对精确目标版本、方案、能力范围或承诺条款的理解与认领。Recognition 不等于 Agent 获得执行权。

## ObjectiveVersion

原始目标及其物质性修订谱系。目标重构必须记录价值保留、放弃和剩余缺口。

## Sovereign World

Principal 的私有世界，包括知识、目标、能力、工具、资源、政策、关系、本地 Harness 和历史。

## CollapseSafe(T)

任务 $T$ 能否安全折叠到一个最小权限中心的条件集合，包括任务、隐私、权威、责任、战略、时效、故障和经济保真。

## Boundary / Behavioral Boundary

主体与外部世界之间任务相关、可交互的有限接口。它可以返回投影、Witness、Defeater、Countercondition、Unknown、Refuse 或局部执行结果。

## BIC

Behavioral/Boundary Interactive Sufficiency 的研究简称，用于表达任务相关的交互边界充分性。它是理论，不必对应单一运行时对象。

## NC / NAC

早期多语义/锚点坐标发现体系。NAC 以公共锚点相似度形成相对坐标和多尺度前缀，当前归位为 Discovery Provider，而非协议本体。

## Discovery Provider

负责提名可能相关主体、资源或关系的可替换方法，例如 NAC、Embedding、图、Agent Card、人工转介。

## Coordination Schema

共享协调语言的版本化定义，包括角色、对象、关系、约束、证据和动作类型。

## SJAC

Sovereign Joint Action Constitution。强调在具体行动安排之前，协调问题的语法、变量和约束本身可能需要形成。相关 Benders/Column Generation 是特定 Solver 路线。

## JAA

Joint Action Arrangement。多方共同编辑、版本化、可分叉的联合行动安排。可作为 SharedArtifactVersion 的重要类型。

## SharedArtifactVersion

候选方案、JAA、边界合同或合同草稿的版本化共享对象。包含作者、哈希、Patch、Fork、Stance 和 Provenance。

## Unknown

尚无足够信息或条件。需要区分诊断型 Unknown（能力已存在但未知）与构造型 Unknown（能力需要改变条件才能形成）。

## PFE

Possibility Formation Engine / 可能性形成理论与策略族。负责诊断缺口、选择探问或形成动作、运行局部实验并更新候选方案。PFE 不维护正式能力事实。

## VOI

Value of Information。衡量一个问题的回答是否可能改变决策，扣除披露、等待和人类注意力成本。

## EVPF

Expected Value of Possibility Formation。衡量一个现实形成动作是否扩大可达行动空间，扣除成本、风险、隐私和人类注意力。

## Formation Operator

能够改变状态或条件的动作，例如工具接入、训练、伙伴加入、授权、任务拆分、风险保障和恢复结构。

## CEGIS

Counterexample-Guided Inductive Synthesis。候选方案经验证器或现实反例推翻后继续修复和迭代。

## CRA

Capability Realization and Assurance / Qualification Pipeline。负责将形成路径通过复现、留出、迁移、容量、组合、漂移和开放复核限定为可依赖的能力 Claim。

## Capability Claim

在明确目标、运行域、环境、前置条件、Authority、恢复、证据、有效期和 Defeater 下的条件性能力主张。

## CapabilityEnvelope

从 Capability Claim、Scope、Evidence 和 Defeater 派生的运行视图。便于调度和审计，但不应维护第二套正式状态。

## AssuranceCase

从 Claim、Evidence、Assumption 和 Defeater 生成的审计论证视图。论证文本不能替代证据。

## Claim

带 issuer、scope、validity 和 status 的限定主张。可以被 Evidence 支持、降级或推翻。

## Evidence

支持或反驳 Claim 的可解释、可搬迁、可重放材料。完整 Evidence Closure 不仅是 checksum。

## WitnessPolicy

某类 Claim 允许的证据来源、时效、一致性、独立性、阈值、Defeater 和接受谓词。

## Defeater

一旦出现会降级、暂停或推翻 Claim 的条件或证据。

## Commitment

经 Recognition、Authority 和资源可行性 Gate 后形成的正式义务网络。

## ResourceReservation

对稀缺资源、预算、容量或唯一席位的正式占用。

## LogicalActionKey

同一现实意图在重试间保持稳定的逻辑身份。

## AttemptID / ActionAttempt

一次具体物理执行尝试的唯一身份和记录。多个 Attempt 可对应一个 LogicalActionKey。

## Effect

目标权威世界中实际发生的状态变化。不能由工具自述或最后退出码代答。

## DomainAdoptionReceipt

目标技术域正式采纳、撤销或拒绝某项输入的权威记录。它不等于人的最终 Acceptance。

## Verification

依据明确规则核验 Claim、Artifact 或 Effect。

## Acceptance

有权 Principal 或业务域对目标价值的接受。技术测试通过不能自动代替。

## Settlement / Dispute

承诺履行后的效力、结算、救济和争议状态。

## Harness

将目标、上下文、计划、Agent、工具、验证、失败恢复和事件回流组织成长期可靠执行的运行系统。它是通爻共同现实形成链的操作底座。

## Context Compiler

根据任务、主体、权限、状态和政策动态生成最小充分执行环境的机制。

## Effect Gateway

所有高后果外部副作用的受控中介，实施权限、幂等、验证、补偿和日志。

## Event Ledger

追加式权威事件记录。事件存在不代表所有消费者已经采纳或接受。

## Compiled World

权威对象和事件的可操作、可视化投影。它让人和 Agent 看见、操作和审计共同世界，但不拥有第二套事实。

## Formation Phase / Compiled Runtime

候选架构：在开放、不确定阶段使用主权、自适应形成；边界和合同稳定后，编译为最小权限确定性运行；Defeater 触发重新形成。

## WoWok

下游可编程信任、权限、确定性执行、托管、结算和争议基础设施。通爻向其输出已形成、已认领和已授权的 Commitment，而不受其当前对象模型锁定。
