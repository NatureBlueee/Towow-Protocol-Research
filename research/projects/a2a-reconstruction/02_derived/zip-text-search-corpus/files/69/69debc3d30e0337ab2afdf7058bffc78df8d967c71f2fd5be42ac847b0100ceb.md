# 阅读路径与资料导航

## 1. 阅读策略

不要按照文件名顺序从头到尾机械阅读。建议分五轮：

1. **问题与当前模型**：先知道我们究竟试图解释什么；
2. **原始协议与方法基础**：理解早期假设和设计语言；
3. **理论跃迁**：理解边界、JAA、PFE、CRA 等怎样出现；
4. **现实压力**：理解哪些理论被真实代码、技术域和模型互动修正；
5. **谱系重建**：回到原始材料补全主张、依赖和证据。

每份材料阅读时至少记录：

```text
它解决什么问题？
它默认了什么？
它引入什么概念？
它声称什么保证？
后续什么证据支持或推翻？
它在当前统一模型中应位于哪里？
```

## 7. 文件类型与用途

| 类型 | 用途 | 注意事项 |
|---|---|---|
| Markdown | 理论、决策、任务说明 | 可能是阶段性解释，不自动代表当前结论 |
| PDF/DOCX | 论文与可读版本 | 检查是否有更完整源稿或证据附录 |
| CSV/JSON/YAML | Claim、实验、状态和 Manifest | 注意 Schema、路径和 evidence reference |
| Python/代码 | 参考实现与实验 | 代码实现的只是论文主张的一部分 |
| Return packet | 现实运行证据 | 先验证可搬迁性、Manifest 和 replay |
| ZIP/TAR.GZ | 原始归档 | 保留原样，用 extracted_sources 便于阅读 |

## 9. 阅读完成的判断

阅读完成不是“所有文件打开过”，而是能够：

- 从早期 NAC 解释到动态边界；
- 从 JAA 解释到 Schema 和 PFE；
- 从 PFE 解释到 CRA；
- 从 CRA 解释到 Recognition、Commitment 和 Harness；
- 从 Harness 解释到 Effect、Adoption、Acceptance；
- 从现实实验反推适用边界和开放主张；
- 说明所有主要概念的当前身份而不依赖阶段名称。
