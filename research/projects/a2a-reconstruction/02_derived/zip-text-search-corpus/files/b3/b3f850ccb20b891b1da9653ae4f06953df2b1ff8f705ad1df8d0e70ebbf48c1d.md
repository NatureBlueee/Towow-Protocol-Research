# Formation Oracle

本文件在 Allbuddy 实现返回前冻结，只定义可观察结果，不规定接口字段或密码实现。

## Pre-state

- 实际消费者可把硬编码 outcome 标为 `completed`；
- 没有 persistent、tenant-bound 的 canonical consumer adoption readback；
- World 可保存 commandless EventRecord，但没有据外部 consumer authority 形成诚实投影的路径；
- 因此跨系统 adoption 事实是 `UNKNOWN`。

## A condition is formed only if

1. Allbuddy 的实际 consumer authority 在本地持久状态中作出 adopted 或 not-adopted 决定；
2. 决定可由同一授权 Viewer 重复读回，且 revision 单调；
3. correction / revocation 改变 canonical current state，不覆盖历史；
4. 错 tenant 与未授权 Viewer 无法区分引用不存在、属于其他 tenant 或已经撤销；
5. 输出不包含输入 sentinel、query、artifact body、企业对象、raw tenant 或可枚举引用；
6. producer-only `completed` 在没有 consumer adoption 时不能被提升为 adopted；
7. World 在不知道私域正文的情况下独立读取并只投影 consumer authority 有权声明的状态；
8. 移除 adoption readback 或授权绑定后，World 的结果退化为 `UNKNOWN / claimed / disputed`；
9. Allbuddy 的目标 consumer 与 World 的独立展示/Source Map 都采用该状态语义。

## Immediate falsifiers

- 只有测试夹具自报 PASS，没有实际 consumer 路径；
- World 通过共享 fixture、硬编码答案或读取 Allbuddy 内部正文得知结果；
- wrong-tenant 返回的状态、错误或时序可泄露引用存在性；
- correction / revocation 只是覆盖行，无法证明 revision 关系；
- 以签名、digest、HTTP 200 或 EventRecord 写入替代目标域 adoption；
- 为获得成功而把 adopted 改写成 produced、completed 或 displayed。

## Claim boundary

即使全部局部条件通过，也只说明这一次 episode 形成了新的被接受路径。只有静态、中心、
Harness+human 对照、关键消融、未知 holdout 和独立复核通过后，才评估可复用
Capability Claim 与净值。
