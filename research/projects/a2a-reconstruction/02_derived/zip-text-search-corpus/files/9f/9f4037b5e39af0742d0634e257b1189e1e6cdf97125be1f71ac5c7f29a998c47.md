# Open Re-review 01 — First Implementation Defeated

复核提示未预置具体问题空间：`grep-based checking could miss issues`。复核者只读检查
Allbuddy 当前 diff、运行测试并自行构造并发复现；未读取研究日志。

## Verdict

`BLOCK — do not freeze the interface for Agent World.`

## Blocking evidence

1. file ledger 使用无锁的 read-whole-file → mutate → rename：
   - 64 个并发 `prepare` 最终只保留 21 条记录；
   - 同一 write capability 并发提交 64 次，有 16 次返回成功；
   - 因而不满足无丢失更新、one-shot consumption 或线性化决策。
2. `consumer-adoption-runtime` 丢弃 `controlCapability`；真实 ProductShell 记录之后没有调用方
   能 grant World reader、correction 或 revocation。单测成功是因为测试保存了生产路径没有的权限。
3. 服务端先永久记录 `adopted`，随后才把 Artifact 放进 React 内存；刷新、关闭标签页或渲染失败后，
   ledger 仍可声称 adopted，形成 false adoption。
4. tenant 绑定只是固定佛山样本 enterprise，不是认证会话或实际调用方 tenant。
5. 默认 `tmpdir` 账本不是跨实例 canonical authority。

## What did pass

- 顺序单进程下 capability 哈希落盘，顺序 replay 被拒绝；
- 粗粒度 readback 不含 tenant、task、artifact 或输入 sentinel；
- ProductShell 已真实调用 adoption endpoint，且收到成功后才显示 completed；
- 39 个 Vitest、TypeScript、目标 ESLint 和 `diff --check` 通过。

这些绿灯不覆盖并发、consumer persistence、真实 tenant authority 或 World read path。

## Browser evidence boundary

临时纳入现有 `workspace-shell.spec.ts` 后，测试先被既有 onboarding overlay / testDir
问题阻断；Google Fonts 网络限制也阻断 production build。这些不是本 diff 的回归，
但同样不能充当 adoption E2E 通过。

## Research consequence

这是首次由现实执行产生、足以改变协调方法的 Defeater：只约定 coarse receipt 不够；
如果 source authority 本身不能线性化、不能回读 target consumer 的 canonical persistence，
再克制的字段边界也会制造权威成功投影。
