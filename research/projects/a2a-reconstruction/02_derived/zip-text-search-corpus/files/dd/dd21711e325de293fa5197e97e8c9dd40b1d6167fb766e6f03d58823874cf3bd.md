# 摘要说明：本文主张的强度

本文是一篇建设性系统论文，而不是已经完成大规模外部验证的标准提案。为了避免把流畅的理论叙述误写成确定事实，全文采用四种主张状态：

- **形式结论**：在明确假设下可以由反例、定义或推导支持；
- **相对稳定的设计不变量**：由多种理论与现实反例共同支持，足以指导当前实现；
- **限域机制证据**：已在特定仓库、运行域或合成环境中形成可重放证据，但不能外推到全部场景；
- **开放假说**：对完整通爻价值至关重要，但仍缺少真实 Principal、跨组织任务或经济结果验证。

本文把所有阶段性概念重新归并到一个当前体系中。历史文档只作为证据和演化记录，不构成并列协议版本。附录给出概念去留账本与主张—证据边界。

# 1. 问题：智能进入世界以后，协调缺少什么

现有大模型正在快速吸收理解、翻译、搜索、计划、工具调用和代码生成能力。随着模型能够读取长上下文、调用工具并产生长程行为，过去因理解成本过高而必须依赖固定部门、标准表单、人工汇报和中心经理的协作结构，会出现新的可替代空间。Kimi K2.5、DeepSeek-V3 等系统展示了模型在复杂推理、并行 Agent 与工具执行上的增长方向，但模型能力增长本身不会自动提供权威、责任、承诺、证据和结算结构 [@kimi2026; @deepseek2024]。

官方 A2A 协议已经为独立 Agent 的发现、消息、任务、制品和异步通知提供互操作框架；MCP 则为 Agent 与工具、资源、Prompt、Sampling、Roots 和 Elicitation 等环境能力建立接口 [@a2a2026; @mcp2025]。这些基础非常重要，但它们主要回答：

> 已经决定要交互的 Agent，怎样连接、传输和执行任务？

本文研究的是更上游也更下游的问题：

> 当主体尚未完整知道自己的需求、能力和合作对象时，怎样形成新的联合行动；当候选行动形成以后，怎样让它在多个主权世界中分别作数，并最终产生受控现实效果？

这不是普通消息协议可以独立解决的问题。它同时包含：

1. **认识问题**：各主体拥有巨大、动态、异构而私有的世界；任何公共表示都只是投影。
2. **生成问题**：需求、角色、能力组合和解决方案常常不是预先给定的，而是在看到候选方案、运行局部试验和改变条件以后才出现。
3. **权威问题**：模型可以理解和建议，却不能凭置信度获得代表主体承诺、披露、花费资源或接受结果的权力。
4. **现实问题**：消息送达、工具返回成功、日志写入和文件存在，都不自动等于目标世界已经改变，更不等于业务主体接受。
5. **制度问题**：跨主体协作包含责任、拒绝、退出、争议、托管、补偿和结算；这些不能隐藏在对话文本中。
6. **经济问题**：主权协调本身有成本。若一个最小权限中心能够安全保留任务、隐私、权威和责任，复杂 A2A 可能没有必要。

因此，本文把研究对象定义为：

> **生成式 Agent-to-Agent 协调**：多个独立 Principal 通过各自 Agent，在有限而受控的边界上共同发现、构造、验证和认领联合行动，并把被认领的行动编译为可执行、可验证、可接受和可结算的现实关系。

这里的中心不是 Agent 的人格，也不是消息，而是**共同现实的形成过程**。

# 2. 主权世界与不可无条件折叠性

## 2.1 Principal、SovereignDomain 与 AgentExecution

本文严格区分三类主体。

**Principal** 是拥有价值、责任、最终拒绝权、Recognition 与 Acceptance 的人或组织。Principal 可以委托，但某些权威和责任不可被模型自动产生。

**SovereignDomain** 是 Principal 控制的软件、数据、工具、策略或业务域。它可以拥有局部技术权威，例如决定某条记录是否被自己的系统采用；但它不是完整意义上的 Principal，不能自动拥有人的价值、法律责任或最终意图。

**AgentExecution** 是某一模型、程序或 Agent 在具体时间、上下文、工具和 `AuthorityGrant` 下的一次可归因执行。模型可以替换，执行实例可以终止；责任应回到授权链，而不是依赖一个拟人化的“数字员工身份”。

这一划分修正了早期把软件域视作完整 Actor 的倾向。跨技术域采用闭环能够证明域级状态如何变更，却不能证明真实人已经认领或接受。

## 2.2 静态公共画像的不完备性

设主体私有世界为 $X$，协议发布的有限公共投影为

$$
\pi:X\rightarrow Z.
$$

只要 $\pi$ 不是单射，就存在 $x_1\neq x_2$ 且

$$
\pi(x_1)=\pi(x_2).
$$

对于未来任意开放任务族，总可以构造某个任务相关函数 $R$，使

$$
R(x_1,y)=1,\qquad R(x_2,y)=0.
$$

任何只读取 $Z$ 的算法，都无法在这两个世界上给出不同判断。因此：

> **不存在一个有限静态画像，能够保留主体对所有未来任务的全部相关性。**

这不是说静态能力卡、Agent Card、Embedding 或知识图谱没有价值。它们可以是高效的发现索引，但不能被误写成主体真实行动空间的完整定义。早期的 NAC 多尺度锚点坐标因此被降级为可插拔 Discovery Provider，而非协议本体。相对表示、信息瓶颈和 Blackwell 意义下的任务充分性为这种降级提供理论背景 [@tishby2000; @blackwell1953]。

## 2.3 体边直觉的严格替代：任务相关边界充分性

“体边对偶”最初表达了一个重要直觉：近乎无限的内部世界可以通过有限边界与外部发生有效关系。但它不是经典数学意义上的对偶。本文用**任务相关的行为边界充分性**替代这一模糊说法。

设任务族为 $\mathcal T$，主体完整世界为 $X$，边界策略 $B$ 可以根据历史交互 $h_t$、任务 $T$ 和查询 $q_t$ 产生有限响应：

$$
B:(X,h_t,T,q_t)\rightarrow (r_t,h_{t+1}).
$$

若在至少 $1-\delta$ 的概率下，使用边界交互得到的最优决策，相比读取完整世界的理想决策，其价值损失不超过 $\epsilon$，且满足安全条件，则称 $B$ 对任务族 $\mathcal T$ 是 $(\epsilon,\delta)$-充分的：

$$
\Pr\left[
U^*(X,T)-U^{B}(X,T)\le \epsilon
\land Safe(B)
\right]\ge 1-\delta.
$$

这一定义带来三个设计含义：

1. 边界必须是**任务相关**的，而不是一次生成后永久有效；
2. 边界可以是**交互式**的：查询、本地运行、返回 Witness、拒绝或反条件；
3. 边界质量需要以决策损失、风险、披露和人类注意力共同评价，而不是以向量相似度或字段完整度评价。

交互信息复杂度说明，多轮通信有时可以用较少信息实现单次摘要无法实现的决策；但多轮本身不保证有价值，若主体只能继续写文本、不能改变条件，它可能只是把既有冲突表达得更长 [@braverman2015]。

# 3. 什么可以集中：折叠边界

通爻不以“没有中心”为目标。中心协调服务可以承担共享制品、路由、求解、调度、重试、日志和固定策略执行。真正的问题是：中心化是否在当前任务上保留了必要属性。

定义 $CollapseSafe(T)$：对于任务 $T$，若存在一个中心表示与策略，同时满足以下条件，则该任务可安全折叠到最小权限中心：

- **任务充分性**：关键候选和区别没有因集中投影而消失；
- **隐私保真**：没有披露超出授权和目的范围的信息；
- **权威保真**：中心只执行获得委托的动作；
- **责任保真**：来源、决定和后果仍可正确归因；
- **战略保真**：集中不摧毁主体的谈判位置、竞争关系和激励；
- **时效保真**：集中状态足够新，更新成本可接受；
- **故障与退出保真**：保留必要的独立故障域、拒绝和退出能力；
- **经济可行**：中心化总成本和风险不高于主权协调方案。

若任一承重属性不能保留，则需要主权 A2A。非折叠性的原则来源通常不是“数据很多”或“系统部署分散”，而是：数据不能披露、权威不能委托、责任不能合并、利益不一致、资源控制必须独立、主体必须保留拒绝和退出权。

![图 2：任务级折叠边界。](../figures/fig4_collapse_boundary.png){#fig:collapse width=82%}

因此，通爻的目标架构更接近：

> **中央协调面 + 本地主权世界 + 动态边界交互**，而不是无中心网络。

在一个可安全折叠的本地工程任务中，least-privilege central 往往是更简单、更便宜的基线。真实模型谈判负对照表明，多轮 A2A 可以丰富救济和权益条件，却未必创造新能力或净价值 [@r54negative2026]。这不是对通爻的否定，而是产品适用域的重要边界。

# 4. 统一对象模型：一个事实只由一个权威来源维护

多轮研究曾分别形成 PFE、CRA、CapabilityEnvelope、AssuranceCase、JAA、Compiled World 等对象。统一收束的原则不是概念越少越好，而是：

> **同一现实事实只有一个权威来源；不同失败、责任和证据必须仍然可区分。**

当前事实内核分为四个平面。

## 4.1 主体与权威平面

- `Principal`：最终价值、责任、拒绝、Recognition 和 Acceptance 主体；
- `SovereignDomain`：受 Principal 控制的局部技术与政策域；
- `AgentExecution`：一次可归因的模型或程序执行；
- `AuthorityGrant`：对动作、对象、目的、期限和资源的限定授权；
- `RecognitionAction`：Principal 对精确目标、方案、范围或能力版本的认领。

## 4.2 认识与证据平面

- `Claim`：带 issuer、scope、validity 和 status 的限定主张；
- `Evidence`：支持或反驳 Claim 的可解释、可搬迁和可重放证据；
- `WitnessPolicy`：某类 Claim 允许哪些证据来源、时效、独立性、阈值与接受谓词；
- `Assumption`：主张成立所依赖的条件；
- `Defeater`：一旦出现会降级、暂停或推翻 Claim 的事件或证据。

## 4.3 协调与规范平面

- `ObjectiveVersion`：原始目标及其物质性修订谱系；
- `CoordinationCase`：一次协调问题的边界、参与方和当前状态；
- `SharedArtifactVersion`：共同编辑的方案、JAA、边界合同或候选协议版本；
- `Commitment`：经 Recognition 和授权后形成的义务网络；
- `ResourceReservation`：稀缺资源和容量的正式占用。

## 4.4 操作与效力平面

- `LogicalActionKey`：同一现实意图在重试间保持稳定的逻辑身份；
- `ActionAttempt`：一次具体物理执行尝试；
- `Effect`：权威目标世界中实际发生的状态变化；
- `DomainAdoptionReceipt`：目标技术域正式采纳、撤销或拒绝某项输入的记录；
- `Verification`：依据明确规则核验 Claim 或 Effect；
- `Acceptance`：有权 Principal 或业务域对目标价值的接受；
- `Settlement` / `Dispute`：承诺履行后的效力、结算与争议状态；
- `Event`：所有权威状态变化的追加式记录。

![图 3：统一对象模型的四个语义平面。](../figures/fig2_planes.png){#fig:planes width=100%}

## 4.5 哪些不再是权威对象

以下结构仍然有用，但不拥有第二套事实：

- NAC、Embedding、图、Agent Card：Discovery Provider；
- Benders、MILP、列生成、MCTS、模型规划：Solver Provider；
- PFE：可能性形成与条件搜索策略族；
- CRA：资格化、开放复核、消融、留出、漂移与再认证流水线；
- CapabilityEnvelope：从 Claim、Evidence、Scope 和 Defeater 生成的运行视图；
- AssuranceCase：同一事实的审计论证视图；
- Compiled World：权威对象和事件的可操作投影。

这种归位减少了“每个阶段一个引擎”的拼接感，也防止 PFE、CRA 和 UI 分别宣布主体已经具备能力。

## 4.6 权威状态与候选状态

统一内核必须把候选状态与权威状态放在不同命名空间中。模型输出、Solver 解、Agent 对话和局部试验首先产生候选对象：

```text
Hypothesis
CandidateClaim
DraftArtifact
ProposedBoundary
ProposedCommitment
```

只有满足相应 Gate 后，候选才触发权威事件。例如：

```text
DraftArtifact + Principal Recognition
+ valid AuthorityGrant
+ resource feasibility
→ CommitmentCreated
```

```text
ActionAttempt + target-domain authoritative readback
→ EffectObserved
```

```text
EffectObserved + WitnessPolicy satisfied
→ VerificationRecorded
```

```text
VerificationRecorded + authorized value decision
→ AcceptanceRecorded
```

Gate 不应由自然语言 Prompt 隐式承担。每次转换至少记录：输入对象版本、授权来源、验证规则、失败原因、产生的事件和可逆/补偿属性。

## 4.7 统一事件语义

系统内部建议采用追加式事件模型，但“事件存在”不意味着所有消费者都已经接受它。事件至少包括：

| 事件类别 | 表达的事实 | 典型权威 |
|---|---|---|
| `ProposalEmitted` | 某执行实例提出候选 | AgentExecution |
| `BoundaryResponseRecorded` | 主权域返回 Witness、Defeater、Countercondition 等 | SovereignDomain |
| `ArtifactVersionCreated` | 共同制品形成新版本 | Coordination ledger |
| `RecognitionRecorded` | Principal 认领精确版本 | Principal |
| `CommitmentCreated` | 义务和条件正式生成 | Commitment compiler + parties |
| `ActionAttempted` | 发生一次现实执行尝试 | executing runtime |
| `EffectObserved` | 目标世界出现可读回状态变化 | target domain |
| `DomainAdoptionRecorded` | 目标技术域将输入纳入本地正式状态 | target domain authority |
| `VerificationRecorded` | 明示规则得到结果 | verifier |
| `AcceptanceRecorded` | 目标价值被有权主体接受或拒绝 | Principal / business authority |
| `SettlementRecorded` | 结算、解除、补偿或争议状态变化 | Trust Adapter |
| `ClaimDefeated` | 新证据使旧 Claim 降级或失效 | WitnessPolicy / adjudicator |

这组事件可以由不同物理服务实现，但语义必须跨实现保持一致。

# 5. 生成式协调：从 Unknown 到新行动路径

## 5.1 Unknown 的机制类型

同一句“不能做”可能意味着完全不同的现实：

- 能力已经存在，但系统不知道；
- 缺少信息或证据；
- 缺少工具、训练、伙伴、权限、资源、验收或恢复条件；
- 当前任务结构不合理；
- 主体不愿意参与；
- 这是一个必须由 Principal 取舍的价值冲突；
- 对允许的全部变换仍然不可行。

因此，系统不能用一个二元 `capable` 字段处理所有否定。边界响应至少需要表达 `WITNESS`、`DEFEATER`、`COUNTERCONDITION`、`REFUSE`、`UNKNOWN` 和有范围的不可行性证书。

## 5.2 形成动作的统一价值

设当前共同状态为 $s$，候选动作 $a$ 可以是查询、局部探针、传递验证程序、创建工具、请求训练、邀请伙伴、申请授权、修改任务结构、增加恢复条件或停止。动作后的状态为 $s'$。系统选择动作时，应评价：

$$
a^*=\arg\max_{a\in\mathcal A(s)}
\mathbb E\left[V^*(s')-V^*(s)\right]
-C(a)-\lambda_rR(a)-\lambda_dD(a)-\lambda_hH(a),
$$

其中 $C$ 是执行与协调成本，$R$ 是风险，$D$ 是披露成本，$H$ 是人类注意力成本。

若动作只改变信念，不改变世界状态，该式退化为信息价值（VOI）；若动作改变工具、授权、伙伴或环境，它评价的是可能性形成价值。第三阶段的合成实验表明，在“能力原本存在但未知”的世界中，VOI 式查询更有效；在“能力必须通过现实干预形成”的世界中，状态改变动作更有价值。该结果只支持机制区分，不构成通用最优策略。

## 5.3 建设性的形成循环

真正的形成不是先把合同谈完，再让 Builder 实现，而是设计与执行共同演化：

```text
诊断不可达原因
→ 选择最有价值的边界交互或现实动作
→ 在本地主权域执行局部试验
→ 返回 Witness / Defeater / Countercondition
→ 修改边界、角色、工具、授权或方案
→ 继续，直到形成 scoped path 或诚实停止
```

![图 4：从 Unknown 到形成路径的建设性循环。](../figures/fig3_formation_loop.png){#fig:formation width=100%}

R5.4 的真实模型负对照说明，若 Agent 只有语言谈判权、没有运行试验、构造工具、申请授权或改变任务结构的能力，多轮交流主要会产生更精确的冲突描述，而不是新能力 [@r54negative2026]。

R5C 跨技术域实验则给出一个限域的正例：Allbuddy 域和 Agent World 域通过拒绝无权证明的字段、本地现实探针、最小反条件交换、持久 adoption/revocation lineage、目标域 journal-before-ack 和开放复核，形成了一条实验前不存在的技术采纳路径 [@r5c2026]。该路径经历 `adopted@rev1 → revoked@rev2 → source offline/unknown → adopted@rev3`，并在重启和负状态 holdout 中保持 scoped 语义。它支持“现实探针 + 反条件削减”作为一种形成策略，但不证明两个真实 Principal 已经形成联合意图。

## 5.4 参考形成算法

下面的伪代码不是协议公理，而是统一体系当前最一般的运行骨架：

```text
function FORM(case, budget):
    state ← compile_shared_state(case)
    while budget remains:
        if accepted_path_exists(state):
            return QUALIFY(state.best_path)

        gaps ← diagnose_unreachability(state)
        actions ← propose_boundary_and_formation_actions(gaps, state)
        actions ← remove_unauthorized_or_unsafe(actions)
        a ← select_by_expected_solution_gain(actions)

        if a is value_decision or nondelegable_authority:
            return ESCALATE_TO_PRINCIPAL(state, a)
        if a is empty or marginal_value(a) ≤ 0:
            return STOP_WITH_UNKNOWN(state)

        result ← execute_locally_under_boundary(a)
        append(result.witnesses, result.defeaters, result.costs)
        state ← revise_artifact_and_boundary(state, result)

    return STOP_WITH_BUDGET_EXHAUSTED(state)
```

该算法要求两个显式区分：

1. `diagnose_unreachability` 必须区分信息缺口、形成缺口、权威缺口和价值冲突；
2. `execute_locally_under_boundary` 只返回必要 Witness 或反条件，不默认上传完整私有世界。

系统可以在不同任务中替换动作生成器、Solver 和价值估计器。若一个普通中心 Agent 已经拥有任务充分且合法的表示，`FORM` 可以退化为中心规划；若本地权威不可折叠，则动作必须通过主权边界运行。

## 5.5 目标修订的价值守恒检查

任务重构可以创造可行路径，也可能成为制造成功的捷径。对原目标 $O_0$ 和修订目标 $O_1$，系统应保存价值维度向量 $v(O)$，并至少检查：

$$
Retention(O_1\mid O_0)=
\frac{\sum_k w_k\min(v_k(O_1),v_k(O_0))}
{\sum_k w_k v_k(O_0)}.
$$

加权保留率仍可能掩盖某一关键维度被完全牺牲，因此每个不可替代价值维度还应有最低阈值：

$$
v_k(O_1)\ge \tau_k,\qquad k\in K_{material}.
$$

物质性修订必须明确记录：保留了什么、放弃了什么、这是阶段性结果还是最终结果、怎样继续接近原目标，以及哪个 Principal 认领了该变化。

## 5.6 主体拒绝不是错误

`REFUSE`、`COUNTER` 和 `UNKNOWN` 是协调的有效状态。它们可以阻止系统：

- 用模型乐观替代主体意愿；
- 为了收敛而偷换目标；
- 让来源方冒充接收方采纳；
- 把未验证假设写入正式合同；
- 让一个中心 Schema 设计者垄断所有语义。

拒绝的价值不在于增加对话，而在于使本地主权世界能够把真实约束带入共同介质。

# 6. 边界形成：交换什么，而不是交换多少

边界设计的错误问题是：“应该公开多少字段？”正确问题是：“当前决策还缺哪一种可区分事实，最小成本的获得方式是什么？”

## 6.1 边界动作类型

协议应支持多种边界动作，而不是只支持文本披露：

- 静态能力或事实投影；
- 任务相关动态查询；
- 本地 Oracle 返回 cut、witness、unknown 或 countercondition；
- 把计算或验证程序移动到数据所在地；
- 返回零知识式、签名式或可重放的验证结果；
- 在本地域运行局部试验，只发布效果与范围；
- 由接收方反向声明所需证据和接受规则；
- 主体拒绝、缩小目的或设置有效期。

边界的经济性不能用消息字节代替。一个六字段状态可能泄漏关键商业信息，而一个较大的本地计算日志可能完全不离开主权域。

## 6.2 Authority-first countercondition reduction 的位置

跨技术域形成实验使用了如下方法：

```text
冻结谁有权声明什么
→ 运行能推翻方案的本地探针
→ 交换最小现实反条件
→ 删除无权威或无真实需求支撑的机制
→ 形成恢复、readback 和 handoff
→ 各目标域只物化自己有权认领的事实
→ 开放复核和关键消融
```

它不应升级成新的顶层引擎。更准确的身份是 PFE 中的一种 formation policy，结合协商、CEGIS、边界最小化和 CRA 资格化。CEGIS 提供“候选—反例—修正”结构；Benders cut 和列生成则在可形式化私有约束世界中提供局部边界求解方法 [@solarlezama2006; @benders1962; @dantzig1960]。

系统可以将下一动作近似选择为：

$$
a_t=\arg\max_a
\frac{
\mathbb E[\Delta DefeaterReduction]+
\mathbb E[\Delta Reachability]
}{
C(a)+Disclosure(a)+Risk(a)+HumanAttention(a)
}.
$$

这个公式是决策框架，不是已验证的普适算法。若权威不是瓶颈、中心可以安全折叠、本地域无法产生可靠 Witness，或者反条件只增加文字而不改变可达集，该策略就不应成为主要路径。

# 7. 从可能性到可复用能力

## 7.1 能力是条件性可达性，而非主体标签

能力应被表达为：在给定目标、任务、环境、工具、授权、资源、策略和恢复条件下，是否存在一条可验证的行动路径。

设实现配置为 $z$，执行策略为 $\rho$，模型/工具/代码版本为 $\theta$，运行域为 $\Omega$，EffectContract 为 $G$。一个限定能力 Claim 可以写为：

$$
\Pr_{\omega\sim D_\Omega}
\left[
Accept_G(Y)=1 \land Violation(Y)=0
\mid z,\rho,\theta,\omega
\right]\ge 1-\epsilon.
$$

这里必须明确：

- 目标和不允许偷换的价值维度；
- 运行域与环境指纹；
- 前置条件、授权和资源；
- 可观察性与恢复路径；
- 证据、有效期和 Defeater；
- 容量和并发限制。

## 7.2 可能性、一次成功与能力合同

找到一条逻辑路径只证明“可能”；一次沙箱成功只证明路径并非完全不可行。它们都不能自动升级成可重复承诺。

能力生命周期可以理解为：

```text
Declared → Hypothesized → Counterfactual → Sandboxed
→ Witnessed → Recognized → Delegated → Committable
→ Performed → Accepted
```

这些不是必须各自成为独立服务的十个对象，而是不同保证等级。每次升级解决不同问题：模型假说、逻辑路径、现实见证、主体认领、代理权、生产承诺、真实履约和业务接受互不替代。

## 7.3 资格化和反驳

CRA 作为 Pipeline，应执行：

- 重复试验与分层任务；
- 关键条件消融；
- 任务、时间、环境和版本留出；
- 开放复核与未预设 Defeater；
- 容量和并发压力；
- 漂移监测、降级和再认证；
- 能力组合的 Integration Witness。

本地 Harness 留出实验中，六轴能力描述仅在 6 个可执行任务上正确 4 个，静态安装基线正确 3 个；样本太小，不足以证明六轴优越。两个失败在改变环境后成功，只证明条件能够形成，不能回填为干预前 Claim 命中 [@r52harness2026]。因此，当前能力轴只是诊断目录，不是已经校准的预测模型。

# 8. 从候选行动到现实生效

## 8.1 概率与权威正交

模型概率可以决定排序、探问、弃权、升级和风险门，但不能决定谁有权披露、承诺或接受。语义熵和风险控制方法有助于识别部分模型不确定性，却无法把高置信变成权威 [@farquhar2024; @bates2024; @blot2025]。

形式上，若 $P_	heta(p\mid E)$ 是模型对主张 $p$ 的置信度，$Auth(e,p)$ 是执行实例 $e$ 对该对象的授权，则：

$$
P_	heta(p\mid E)\not\Rightarrow Auth(e,p).
$$

同样，有权主体可以在不确定性存在时作出合法决定。系统必须把“判断可靠性”和“行为合法性”分开。

## 8.2 ActionAttempt、Effect、Verification 与 Acceptance

真实 Harness 轨迹显示：命令输出“成功”、复合 shell 最终退出码为 0，都可能掩盖中间失败；timeout 也可能发生在效果已经提交以后。于是必须区分：

- `LogicalActionKey`：同一现实意图；
- `ActionAttempt`：第几次物理尝试；
- `Effect`：目标世界实际变化；
- `Verification`：按规则核验 Effect；
- `Acceptance`：有权主体判断目标价值是否实现。

接受不是统一布尔公式，而是主张相关函数：

$$
Accept_p=\mathcal A_p(Objective,Attempt,Effect,Evidence,Risk).
$$

## 8.3 证据闭合

返回包的可搬迁实验曾出现：所有文件 checksum 通过，但 29 个 Claim 引用在新目录中 0 个可解析。修复相对路径、Schema 和 portable verifier 后才达到 29/29。这说明证据闭合至少需要：

$$
EvidenceClosure=
Integrity\land Reachability\land Interpretability\land Replayability\land Relevance.
$$

SLSA provenance 和 W3C Verifiable Credentials 强调来源、签名和可验证数据模型，但密码学完整性仍不自动证明业务事实或主体接受 [@slsa2025; @w3cvc2025]。

## 8.4 传输、目标域采纳与主体接受

跨技术域实验进一步区分：

```text
Source report
→ transport receipt
→ target-domain canonical commit
→ consumer adoption
→ Verification
→ Principal Acceptance
```

来源方不能自行宣布接收方已经采用。Allbuddy—Agent World 实验中的 adopted、revoked、offline/unknown 和 restart replay，足以把 Target-domain Adoption 从纯理论升级为限域机制证据 [@r5c2026]。但软件域的 adoption 仍不是人的 Recognition 或 Acceptance。

## 8.5 Claim-specific WitnessPolicy

证据没有全局固定强度。一个 Git commit 对“代码版本是什么”可能很强，对“客户已经接受交付”则几乎无关。对 Claim $p$，WitnessPolicy 可表示为：

$$
W_p=\langle S_p,F_p,C_p,I_p,Q_p,D_p,A_p\rangle,
$$

其中：

- $S_p$：允许的证据来源；
- $F_p$：新鲜度、版本和环境约束；
- $C_p$：一致性与 readback 要求；
- $I_p$：独立性或多方见证要求；
- $Q_p$：阈值、签名、quorum 或统计标准；
- $D_p$：会推翻 Claim 的 Defeater；
- $A_p$：该 Claim 的接受谓词。

于是 Claim 在时刻 $t$ 的闭合为：

$$
Close(p,t)=A_p(E_t)\land Fresh_p(E_t)\land Consistent_p(E_t)
\land \neg MaterialDefeater_p(E_t).
$$

这一定义防止系统建立一条错误的全局“证据梯度”，例如把数据库 readback、签名 receipt 或测试报告当作所有上层事实的替代品。

## 8.6 效果交付的跨域状态机

跨域 Effect 建议使用以下最小状态：

```text
prepared
→ attempted
→ source_effect_observed
→ transported
→ target_committed
→ adopted | rejected | revoked | disputed
→ verified
→ accepted | not_accepted
→ settled | compensated | arbitrated
```

并非每个场景都需要物化全部状态，但任何省略都必须证明被省略状态不影响该风险等级下的判断。异步系统中，`transported`、`target_committed` 和 `adopted` 尤其不能合并；至少一次投递还要求目标域根据 `LogicalActionKey` 幂等处理。

# 9. 候选运行架构：形成与运行的双阶段

现有证据支持但尚未证明一种候选架构：

```text
主权、自适应形成
→ 冻结边界、目标、权威和 Witness 合同
→ 编译为最小权限确定性运行
→ 监测 Defeater、版本、成本与环境漂移
→ 物质变化时重新打开形成
```

![图 5：形成期与运行期的候选双阶段架构。](../figures/fig5_two_regime.png){#fig:tworegime width=96%}

## 9.1 形成阶段

形成阶段允许：

- 本地私有上下文参与；
- `REFUSE / COUNTER / UNKNOWN`；
- 局部探针与工具形成；
- 请求授权、伙伴和资源；
- 调整任务结构和恢复条件；
- 共同编辑 SharedArtifact/JAA；
- 识别需要 Principal 取舍的价值冲突。

## 9.2 编译运行阶段

当目标、Schema、权威、边界、接受规则和运行域稳定以后，可以把日常执行编译为最简单的 least-privilege coordinator，承担：

- 固定路由和工具调用；
- journal、dedupe、retry 与 replay；
- 固定 Schema 验证；
- 目标域采纳适配；
- Defeater 和漂移监测。

主权要求权威留在本地，不等于每次执行都要让多个智能 Agent 持续谈判。

## 9.3 重开条件

以下事件应重新打开形成：

- ObjectiveVersion 物质变化；
- Principal、AuthorityGrant 或 Acceptance policy 改变；
- 新主体进入或退出；
- 冻结 Schema 无法表达新状态；
- 模型、工具、协议、环境或成本指纹漂移；
- holdout 或生产运行出现 Defeater；
- revocation、dispute 或不可恢复 Unknown；
- 隐私、责任或风险边界变化。

该架构在一个本地跨技术域形成实例中成立，但 matched central formation 尚未公平运行，不能升级为通用定理。

# 10. 协议与系统分层

通爻不应重新实现 A2A 的传输、MCP 的工具协议或 WoWok 的确定性效力对象。它应提供一层独立的协调语义和运行时。

![图 6：通爻与 A2A、MCP 和信任基础设施的关系。](../figures/fig6_protocol_stack.png){#fig:stack width=92%}

## 10.1 通爻协议内核

协议内核规定：

- 主体、执行和授权如何标识；
- Objective 和 SharedArtifact 如何版本化；
- Claim、Evidence、WitnessPolicy 和 Defeater 如何表达；
- 边界如何查询、拒绝和返回反条件；
- 候选方案何时只是假说，何时被 Recognition；
- Commitment 如何绑定精确版本、权威、义务和资源；
- ActionAttempt、Effect、Adoption、Verification、Acceptance 如何分离；
- 修正、撤回、离线、Unknown、争议和再形成如何传播。

## 10.2 兼容现有协议

- A2A 承载 Agent Card、Message、Task、Artifact 和通知；
- MCP 承载本地工具、资源和上下文入口；
- 通爻对象可以作为 A2A Artifact/extension 或应用层协议传输；
- 主权域可以使用 MCP 或本地 Harness 执行 probe、tool 和 validation；
- 通爻不要求所有节点使用同一模型、向量空间或软件栈。

## 10.3 WoWok 和其他 Trust Adapter

WoWok 的 Demand、Service、Machine、Guard、Treasury、Permission、Repository 和 Arbitration 等对象，适合承接已形成、已认领承诺的确定性权限、托管、状态机和结算 [@wowok2026]。通爻应通过 `TrustExecutionAdapter` 将 Commitment 编译到这些基础设施，但不能让某个当前链上对象模型定义上游全部协调本体。

国内环境可以采用实名与企业认证、可靠电子签、持牌支付或托管、平台事件账本、发票、仲裁和企业系统审批，承担相同功能。协议应固定功能语义，而非固定某一司法区的技术实现。

## 10.4 协调消息的最小语义包络

通爻不固定具体 JSON 字段，但跨实现消息至少应能引用以下语义：

```json
{
  "message_id": "...",
  "case_id": "...",
  "sender_execution": "...",
  "authority_ref": "...",
  "purpose": "...",
  "object_ref": "...",
  "object_version": "...",
  "speech_act": "PROPOSE|QUERY|WITNESS|DEFEATER|COUNTER|REFUSE|UNKNOWN|RECOGNIZE|ACK",
  "claim_refs": ["..."],
  "evidence_refs": ["..."],
  "disclosure_scope": "...",
  "validity": "...",
  "signature_or_provenance": "..."
}
```

协议不应把完整私有材料内嵌为默认 payload。`object_ref` 可以指向本地域执行入口、可验证制品、加密数据、临时授权资源或 A2A Artifact。接收方应按自身 WitnessPolicy 解释，不能因为来源签名就自动接受语义。

## 10.5 四动词的兼容位置

早期 `emit / quest / disclose / crystallize` 可以保留为 SDK 外观：

- `emit` 发布一个 Claim、Projection 或 Proposal；
- `quest` 创建 Query、Probe 或 Information Need；
- `disclose` 依据授权返回 Evidence 或受控投影；
- `crystallize` 创建或修订 SharedArtifactVersion。

但四动词不得绕过其背后的对象生命周期。例如 `crystallize` 只能生成候选方案，不能自动生成 Recognition 或 Commitment。

# 11. 工程构造蓝图

## 11.1 最小内核

一个可用实现至少需要：

1. 追加式事件存储与版本哈希；
2. Principal、Execution 与 AuthorityGrant 管理；
3. Objective、CoordinationCase 和 SharedArtifact 版本；
4. Claim—Evidence—WitnessPolicy—Defeater 图；
5. 边界调用接口：query、witness、countercondition、refuse、unknown；
6. 形成策略接口与本地 probe 执行器；
7. Recognition 与 Commitment 编译器；
8. Effect Gateway、LogicalActionKey 和 Attempt ledger；
9. Target-domain Adoption、Verification 与 Acceptance Adapter；
10. 派生视图：CapabilityEnvelope、AssuranceCase、Compiled World；
11. 监测与 formation reopen 机制。

## 11.2 上下文编译

共享上下文不应是全企业大仓库。Harness 应针对每个任务编译最小工作环境：目标版本、相关对象、有效 Claim、证据、工具、权限、接受规则、风险、未知和升级路径。Problem IR、Design IR、Engineering IR 与 Consensus 的分离，避免把设计假说过早冻结成工程事实 [@flowness2026; @prse2026]。

## 11.3 风险触发物化

并非每个低风险工具调用都需要完整 Commitment、Recognition 和 Settlement 对象。系统可以根据后果等级物化：

- L0：只读观察；
- L1：可恢复本地动作；
- L2：代表他人或跨边界动作；
- L3：承诺、稀缺资源或不可逆 Effect；
- L4：多 Principal 生成式协调。

高风险层保留完整对象与审计；低风险层可以在不丢失语义的前提下编译成轻量运行记录。

## 11.4 一致性与分布式状态

草稿、注释和候选证据可以使用最终一致或 CRDT；稀缺资源、付款、唯一席位、正式承诺和不可逆 Effect 需要事务、租约、共识、托管或同等强度的串行门。协调避免原则不能越过不可交换的不变量 [@bailis2014; @kleppmann2017]。

跨服务长事务可以使用 Saga 和补偿，但补偿不是时间倒流，必须保留原 ActionAttempt 和 Effect 轨迹 [@garciamolina1987]。线性化和端到端论证提醒我们：中间层成功不能代替最终消费者验证 [@herlihy1990; @saltzer1984]。

## 11.5 参考部署拓扑

一个最小跨主体部署可以包含：

```text
Principal A domain                    Shared coordination plane                 Principal B domain
------------------                    -------------------------                 ------------------
Local context store                   Case / Artifact / Claim index             Local context store
Local AgentExecution  <------------>  A2A transport / coordination API  <---->  Local AgentExecution
Local probe/tool runtime              Formation policy / solver providers       Local probe/tool runtime
Local authority service               Version/event ledger                       Local authority service
Local evidence store                  Compiled shared views                      Local evidence store
Effect/adoption adapter               Monitoring / reopen controller             Effect/adoption adapter
```

共享面不拥有双方完整上下文，也不拥有未委托权威。它可以缓存已授权投影和共享制品；本地域可以随时返回 `REFUSE`、`UNKNOWN`、Defeater 或撤销。

## 11.6 实现次序

为了避免先造一座过度抽象的平台，工程应按纵向切片展开：

1. 选一项真实、低风险但存在不可折叠属性的协调 Case；
2. 先实现 Principal/Execution/Authority、Objective、SharedArtifact 和 Claim/Evidence；
3. 接入一个本地 probe 与一种 Countercondition；
4. 形成一个可运行候选，并加入 Recognition；
5. 经 Effect Gateway 写入一个可恢复目标域；
6. 实现 DomainAdoption、Verification、Acceptance；
7. 加入留出、Defeater 和重开；
8. 只有真实重复路径出现后，才提取通用 Skill、Provider 和协议扩展。

这一顺序与 Harness 的认知工程原则一致：先建立真实闭环，再从重复轨迹结晶基础设施，而不是先冻结一个假想通用平台 [@flowness2026]。

# 12. 证据：我们已经知道什么

![图 7：现有证据阶梯与尚缺的 Principal 层。](../figures/fig7_evidence_ladder.png){#fig:evidence width=80%}

## 12.1 形式和理论证据

较强的结论包括：

- 有限静态画像对开放未来任务不完备；
- 概率不能产生权威；
- 候选、能力、Recognition、Commitment 和 Effect 不可等同；
- 有限证据不能无条件保证未观测运行域；
- 开放能力形成包含规划难题，不存在通用完备且保证终止的求解器；
- 双边机制设计中，效率、真实性、自愿和预算平衡不能在所有场景同时完美满足 [@myerson1983]。

## 12.2 合成机制证据

合成实验支持以下机制方向：

- 多方组合问题不能退化为简单两两匹配；
- CEGIS 在可形式化反例下比“验证失败即拒绝”更能同时提高安全和吞吐；
- VOI 与状态改变型形成价值适用于不同 Unknown；
- 校准和风险门可以形成覆盖率—错误率工作点；
- 草稿 CRDT 与承诺串行门需要分离；
- 静态画像、一次成功和永久能力证书会产生系统性误判。

这些实验主要证明“机制可能有用”和“某类失败可以发生”，不能作为现实商业效果估计。

## 12.3 真实 Harness 证据

真实仓库和运行时暴露：

- outer exit、成功文本和 terminal label 可能误判真实 Effect；
- timeout 可能丢失已经完成的 verdict；
- EventLog raw bytes 不等于 canonical event；
- 环境、worktree、PYTHONPATH、temp-root、工具路由会改变能力；
- 能力轴的留出预测仍然很弱；
- least-privilege central 在本地可折叠任务中是强基线 [@r52harness2026]。

## 12.4 真实模型负对照

R5.4 中，静态 Agent 已发现主要源码身份缺陷，固定中心查询已暴露核心价值冲突。多轮 A2A 增加了披露、救济、权益底线和恢复条款，却没有产生被双方接受的新能力或补丁。该结果支持：

- 语言互动能够生成更丰富的规范候选；
- 在可折叠、无干预权、剩余问题是主体价值选择的任务中，A2A 不应被默认使用；
- 不能把更多条款或对话轮数当作可能性形成 [@r54negative2026]。

## 12.5 跨技术权威域形成证据

R5C 首次形成：

```text
consumer authority
→ canonical adoption/revocation readback
→ independent world claim/read
→ durable journal
→ local materialization
→ verified ack
```

并通过撤销、离线、错误权威、私域字段、假 ack、revision 冲突、journal 冲突、重启和同协议负状态 holdout。它支持：

- 来源报告与目标域采纳分离；
- 拒绝和现实探针可以削减过度设计；
- 边界冻结后可由最小权限协调器执行；
- 开放复核和消融应进入资格化。

但它的 Principal 是技术域，不是真实人；静态中心拥有一个高质量跨域摘要；matched central formation 没有运行。因此，它不是完整主权 A2A 的证明 [@r5c2026]。

## 12.6 证据如何改变设计，而不只是增加置信

现有研究的价值不在于测试总数，而在于若干现实结果直接改变了系统：

| 现实结果 | 被否定的旧理解 | 设计变化 |
|---|---|---|
| terminal/exit 与真实 Effect 不一致 | 工具成功可以直接完成任务 | 增加 LogicalActionKey、ActionAttempt 和 claim-specific readback |
| raw JSON 存在但 EventLog 不可见 | 文件中有字节即制度事件存在 | canonical writer 与消费者采纳分离 |
| 返回包 checksum 全过但 Claim 引用 0/29 | 完整性等于证据可用 | EvidenceClosure 增加可达、解释、重放与相关性 |
| 静态 Agent 已找到主要源码缺陷 | 多轮 A2A 天然创造技术方案 | 可折叠任务先采用 least-privilege central |
| 纯谈判产生条款却无可执行路径 | 更丰富文本等于可能性形成 | 形成实验必须赋予现实条件形成权 |
| adopted/revoked/offline/restart 可跨域复建 | 目标域采纳只是理论对象 | DomainAdoptionReceipt 获得 scoped mechanism evidence |
| 过度签名/TTL/HMAC 被本地域拒绝 | 更复杂边界必然更安全 | 权威优先、反条件削减、删除无 issuer 的机制 |
| 软件域闭环不等于人认领 | 技术域可充当 Principal | SovereignDomain 与 Principal 正式分离 |

这张表也说明，建设性系统研究需要理论、实验与工程互相施压：若代码只负责实现理论，研究会越来越自洽而不真实；若实验只修仓库 Bug，研究又会失去元问题。

# 13. 经济与产品适用性

## 13.1 A2A 不是默认最优

通爻的部署前提应先通过 `CollapseSafe(T)`。若一个最小权限中心能够：

- 获得任务充分的投影；
- 合法调用本地工具；
- 保留正确责任；
- 不损害竞争和退出；
- 以更低成本完成任务；

则应优先使用中心化 Harness，而不是为了“主权”制造多 Agent 对话。

## 13.2 真实经济模型

只比较 token 成本会严重扭曲判断。应比较：

```text
机会不发生
高级人工经纪人/经理人
人工 + AI
全信息中心 Agent
最小权限中心 Agent
主权 A2A
```

一个更完整的净价值函数为：

$$
\begin{aligned}
NetValue(m)=
&\;\mathbb E[V_{accepted}] + V_{new\ opportunity}
+V_{risk\ avoided}+V_{human\ attention\ saved}
+V_{reusable\ learning}\\
&-C_{model}-C_{human}-C_{waiting}-C_{disclosure}
-C_{integration}-C_{failure/recovery}-C_{governance}.
\end{aligned}
$$

如果通爻的主要价值是让本来不会发生的机会出现，则基线可能是零，而不是“另一个 Agent 完成同一任务的成本”。但目前尚无真实组织数据支持这种经济主张。

## 13.3 人的不可替代位置

在当前理论中，人并非每一步的操作员，而是：

- 价值和责任的来源；
- 不可委托权威的持有者；
- 物质性目标修订的认领者；
- 模糊结果的最终 Acceptance；
- 不可逆风险的承担者；
- 真实关系、声誉和退出选择的主体。

未来强模型可以吸收更多翻译、搜索、候选生成和计划，但不能因此消除上述制度角色。

# 14. 如何使用这套系统

对一个新的真实场景，推荐采用以下判断顺序。

## 14.1 判断是否需要通爻

先问：任务能否在 least-privilege central 下安全折叠？若能，使用普通 Harness 和最小权限工具接口。若不能，明确不可折叠的具体属性，而不是泛称“数据很多”或“跨组织”。

## 14.2 建立 Principal 和域边界

识别：

- 谁是 Principal；
- 哪些是 SovereignDomain；
- 哪些权威可委托；
- 哪些数据、资源和接受权必须留在本地；
- 哪些公共协调对象可以集中。

## 14.3 编译初始协调 Case

保存：

- 原始 ObjectiveVersion；
- 允许与禁止的目标修订；
- 主体边界和 AuthorityGrant；
- 已知 Claim、Evidence、Unknown 和 WitnessPolicy；
- 可用 Discovery、Solver、Tool 和 Trust Adapter；
- 成本、风险和停止条件。

## 14.4 运行形成循环

让 Agent 在主权域内：

- 查询和执行局部 probe；
- 返回最小 Witness、Defeater 或 Countercondition；
- 形成工具、授权、伙伴、恢复或验证条件；
- 修改 SharedArtifact/JAA；
- 在价值冲突时升级 Principal，而不是无限对话。

## 14.5 资格化与认领

在承诺前：

- 运行关键条件消融与留出；
- 冻结环境、版本、范围和 Defeater；
- 让 Principal 认领精确 Objective 和 SharedArtifact 版本；
- 预留资源和容量。

## 14.6 编译执行与闭合

将稳定路径编译为 least-privilege runtime：

```text
LogicalActionKey
→ ActionAttempt
→ Effect readback
→ target-domain adoption
→ Verification
→ Principal Acceptance
→ Settlement / Dispute
```

持续监测重开条件。

## 14.7 一个示例：私有数据、外部方法与独立验收

考虑三个真实 Principal：

- A 拥有私有制造数据和问题，但不能披露原始数据；
- B 拥有分析方法和工具，但无权读取 A 的世界；
- C 拥有合规与验收权，但不能代替 A、B 行动。

静态能力匹配只知道“A 有数据、B 会分析、C 会审核”，无法说明怎样合作。通爻式路径可能是：

1. A 发布任务相关症状和本地可执行边界，不发布原始数据；
2. B 返回一个可在 A 本地运行的验证程序和所需最小统计；
3. A 的 Agent 在本地试跑，返回失败 Witness，指出缺少单位映射和只读权限；
4. B 修改工具并提出条件；A 请求临时只读授权；
5. C 提供验收规则，而不是查看 A 全部数据；
6. 工具在 A 本地生成候选制品，C 的域根据自己的规则采纳或拒绝；
7. A、B 分别认领自己的责任和交付范围；
8. 稳定路径被编译为最小权限运行流程。

若移除本地执行、临时授权或独立验收中的任一关键条件，路径重新不可达，则可以说互动形成了条件，而不只是重新描述了已有能力。该例说明系统的目标不是“让 Agent 多聊几轮”，而是让计算、证据、权威和责任移动到正确的位置。

# 15. 现有边界与尚未成立的核心主张

本文尚不能证明：

1. 两个真实人或组织能够通过各自 Agent 稳定形成此前不存在的联合行动；
2. Agent 生成的新角色和条件是发现主体偏好，而不是替主体投射偏好；
3. 动态边界策略在真实高维私有世界中比静态投影或最小权限中心更有效；
4. 一次形成路径可以可靠迁移成跨任务、跨版本和跨环境能力；
5. 形成—编译运行双阶段是所有领域的最佳默认架构；
6. 主权 A2A 能够减少高级经理人、经纪人或顾问的高认知工作；
7. 新机会价值能够覆盖模型、等待、披露、治理和失败恢复成本；
8. 通用 Coordination Schema 能够跨行业稳定存在；
9. 一个协调平台不会成为新的权力集中点或通过多轮边界查询重建私有世界。

这些不是附属“未来工作”，而是决定通爻能否从强研究原型升级为社会基础设施的核心缺口。

# 16. 结论

本文建立的不是一个万能多 Agent 框架，也不是另一个消息协议。

它是一套关于**共同现实如何形成**的理论和系统：

- 主体的完整世界不被强制集中；
- Agent 通过任务相关边界理解和试探；
- 候选方案在共同介质中被编辑、拒绝和修正；
- 新工具、伙伴、授权、任务结构和恢复条件可以被形成；
- 模型的概率智能与主体权威严格分离；
- 候选可能性只有经过证据、认领和资源约束才成为承诺；
- 承诺只有经过现实 Effect、目标域采纳、Verification 和 Acceptance 才进入共同事实；
- 稳定路径可以编译成更简单的最小权限运行时；
- 新反例、漂移和价值变化会重新打开形成。

最小而完整的中心命题是：

> **通爻使无法安全折叠的 Principal 世界，通过有限边界和概率智能共同形成新的行动路径；协议的职责不是让模型替人决定，而是让这种路径在不混淆事实、权威、责任和接受的前提下，逐步成为现实。**

现有研究已经足以指导一个统一内核、边界接口、形成策略、资格化流水线和现实效力链的实现。它也已经形成真实 Harness 和跨技术域的限域机制证据。但完整主张仍停在门槛前：真实 Principal 之间的联合行动形成、偏好认领和净经济价值尚未被证明。

因此，我们迄今建立的最准确身份是：

> **一套可实现、可反驳、具有限域现实证据的生成式协调基础设施理论；它已经知道“什么才作数”和“局部条件怎样形成”，但尚未证明真实社会协作能够因此稳定产生净新价值。**

# 附录 B：协议不变量与禁止捷径

1. 模型置信度不得生成 AuthorityGrant。
2. 未认领的 SharedArtifact 不得直接编译为高后果 Commitment。
3. 物质性 ObjectiveRevision 必须形成新版本和 Recognition。
4. `producer completed` 不得自动推出 `consumer adopted`。
5. `transport delivered` 不得自动推出目标域 canonical commit。
6. `Verification passed` 不得自动推出 Principal Acceptance。
7. 重试必须共享 LogicalActionKey，并拥有独立 AttemptID。
8. 稀缺资源不得在无 Reservation 的情况下承诺。
9. 旧 Evidence 出现物质 Defeater 后必须降级或暂停 Claim。
10. UI、AssuranceCase、CapabilityEnvelope 和 Compiled World 不得成为事实源。
11. 主权边界不得仅以 Prompt 声明；其保证必须来自权限、协议、密码学、隔离或可审计制度。
12. 形成失败不得通过无限缩小目标制造成功；必须记录原始价值保留、放弃与继续条件。
13. 来源域不得替目标域签发 AdoptionReceipt。
14. 技术域 Adoption 不得冒充人的 Recognition 或 Acceptance。
15. dry-run、shadow 和 synthetic result 不得描述为生产落地。

# 附录 C：主张证据等级

完整主张—证据—边界账本见随附 `claim_evidence_register.csv`。本文采用以下解释：

- `相对稳定`：足以指导当前内核和接口；
- `scoped strong`：在明确运行域内可依赖，超出范围需重新资格化；
- `部分支持`：存在机制证据，但不能作为默认架构保证；
- `UNKNOWN`：对最终价值关键，但现有证据不能决定设计。

# 附录 D：概念去留原则

完整概念决策账本见随附 `concept_decision_ledger.csv`。合并或降级一个概念时，需要回答：

1. 原来区分的现实情况是否仍可表达？
2. 原来阻止的错误是否仍能阻止？
3. 权威、证据和责任被移动到哪里？
4. 什么反例会证明合并丢失必要能力？

通过这一标准，PFE、CRA、NAC、CapabilityEnvelope 和 Compiled World 被保留为策略、Pipeline、Provider 或视图，而不再作为平行权威世界。
