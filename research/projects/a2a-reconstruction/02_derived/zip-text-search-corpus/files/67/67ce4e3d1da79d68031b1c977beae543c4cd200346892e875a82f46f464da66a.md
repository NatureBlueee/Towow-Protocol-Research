# Independent review — return-packet portability contract

## Reviewer and scope

Reviewer: context-separated `return_contract` subagent. Scope was read-only
inspection of v1.2's return template, schemas, verifier, task-packet manifest,
and relocation attestation.

## Hard gates found

- The final return manifest is `manifests/MANIFEST.json`; packet file
  `08_MANIFEST.json` is not a reusable return manifest.
- `manifests/CHECKSUMS.sha256` must use two spaces between hash and relative
  path.
- Manifest file records exclude the manifest and checksum files; checksums cover
  payload plus manifest and exclude the checksum file itself.
- A verifier process exit of zero is insufficient. The JSON result must be
  exactly `status: passed` with no warnings and no errors.
- Claim evidence paths are relative to the return-packet root; experiment
  `evidence_paths` are relative to each experiment directory.
- The generic verifier does not execute replay commands or judge evidence
  relevance. A domain-specific replay/readback tool is still required.
- Final bytes must be extracted into a fresh directory and verified again.

## Historical packet finding

The task packet's stored relocation result reports 35 files while the current
task manifest has 36 records and the live task-packet validator reports 36.
That historical result therefore applies to an earlier candidate byte set and
must not be reused for the final return packet.

## Required final check

Build candidate payload, generate manifest/checksums, run source verifier, run
fresh relocation plus core replay, write the relocation result, regenerate
manifest/checksums, build the final zip, and verify a second fresh extraction
without mutating the zip afterward.
