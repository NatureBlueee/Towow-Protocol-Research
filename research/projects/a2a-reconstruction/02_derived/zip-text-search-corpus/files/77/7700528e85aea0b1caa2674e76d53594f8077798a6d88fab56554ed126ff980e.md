# 最小本体与概念收敛 v0.5

## 1. 为什么现在必须收敛

历史研究不断发现真实区别：授权与能力不同，ActionAttempt 与 Effect 不同，Adoption 与 Acceptance 不同，数据使用与派生不同。问题在于，“语义必须区分”不等于“每个区别都必须成为顶层协议对象”。若每次发现一种风险就新增 aggregate root，系统会出现：

- 多套平行事实源；
- 对象间生命周期冲突；
- 同一现实被重复维护；
- 简单任务被迫承担重型治理；
- 研究创新被误写成名词数量；
- 工程实现无法判断什么必须持久化。

v0.5 采用**对象准入测试 + 风险触发提升**。

---

## 2. 顶层对象准入测试

一个候选概念只有在满足大部分以下条件时，才应成为长期 aggregate root：

1. **独立身份**：需要稳定 ID，被其他对象直接引用；
2. **独立版本/撤销**：可以在其他对象不变时被修改、撤回或 supersede；
3. **独立权威**：由不同 Authority Locus 签发或拥有；
4. **独立生命周期**：有自己不可压缩的状态机和不变量；
5. **不可派生**：不能从现有 canonical facts 确定性重建；
6. **跨任务复现**：不是单一高风险行业特例；
7. **区分必要性**：省略后会把现实上不同、且会改变处置的状态混为一谈；
8. **外部执行需要**：下游系统、法律/安全控制或跨域互操作必须直接验证它；
9. **成本相称**：其独立维护成本低于由模糊或重复造成的风险。

若只满足一两项，优先考虑：字段、事件类型、策略、provenance edge、Commitment 条款或派生视图。

## 3. 六类长期 aggregate root

### 3.1 Entity

**承担：** 持续身份、来源、实例谱系、治理和追责入口。  
**不承担：** 完整能力、默认授权、真实偏好或自动接受。

最小字段：

```text
entity_id
entity_type
lineage
identity_proofs
governance_ref
recourse_ref
status
```

### 3.2 Mandate

**承担：** 可独立签发、撤回和版本化的权限/代表范围。  
**不承担：** 动作实际发生、能力存在或主体已经接受结果。

```text
mandate_id
issuer_authority
holder_entity
actions / objects / clauses
purpose
limits / risk / amount
time / preconditions
delegation rules
revocation / supersession
```

### 3.3 RelationVersion

**承担：** Relation Schema、实例、依赖、当前候选和共同 content hash。  
**不承担：** 各方自动同意。每方 stance 独立记录。

### 3.4 Assertion

**承担：** 关于世界、能力、条件、Effect 或 Adoption 的限定主张。

```text
assertion_id
claim_type
issuer / source domain
subject / predicate / value
scope / validity
supporting evidence
assumptions / defeaters
status
```

Effect 和 Domain Adoption 是具有特殊来源要求的 Assertion 类型，而不是新的平行事实系统。

### 3.5 Commitment

**承担：** 有权主体对未来行为、资源、责任、数据权利或救济的义务网络。  
**不承担：** 现实履行结果。

JointArtifactRights 在需要共同签署、独立修订或争议时，作为 Commitment bundle 或其独立版本存在。

### 3.6 Operation

**承担：** 一次现实尝试的逻辑动作、物理 attempt、执行器、输入、幂等、结果和 Effect 引用。  
**不承担：** 自我证明成功。

## 4. EventEnvelope 的位置

事件封套包含：

```text
event_id
event_type
actor
relation_version
authority_ref
timestamp
payload
prev_hash / integrity
```

它用于传输、顺序、审计和重放，不是第七类社会事实。事件中的语义必须回指 canonical aggregate 或被明确声明为短暂观察。

典型事件：

- `STANCE_RECORDED`
- `MANDATE_ISSUED / REVOKED`
- `RELATION_VERSION_CREATED`
- `REFUSAL / COUNTERCONDITION`
- `PROBE_REQUESTED / RESULT`
- `DATA_USE_OBSERVED`
- `OPERATION_ATTEMPTED`
- `EFFECT_ASSERTED`
- `ADOPTION_ASSERTED`
- `ACCEPTANCE_STANCE`
- `DEFEATER_RAISED / REOPENED`

## 5. 五个被点名概念的重新安置

### 5.1 UsageGrant

**默认位置：** `Mandate` 的一种用途受限授权，或 Relation Schema 的数据策略绑定。

成为独立顶层对象的条件：

- 数据授权由独立 Authority Locus 签发；
- 可在主 Mandate 不变时单独撤销；
- 外部 enforcement point 必须直接验证；
- 具有独立期限、再委托和合规状态。

多数低风险案例不需要新的 `UsageGrant` aggregate root；只需 `Mandate.kind=data_use`。

### 5.2 DataUseEvent

**默认位置：** `EventEnvelope.event_type=DATA_USE_OBSERVED`。

若需要高吞吐审计，可进入专门 event stream；它仍然是事件，不是一个长期权威对象。只有当某次使用本身形成可争议、可结算的独立权利义务时，才通过 Assertion/Commitment 升格。

### 5.3 DerivationRecord

**默认位置：** Assertion、Artifact 或输出对象上的 provenance edge：

```text
derived_from
transformation
purpose
operator/model version
lineage completeness
```

它是图边或证据 payload。若一条派生链需要独立签发、外部验证和撤销，可物化为 Assertion，但不默认拥有一套新本体。

### 5.4 JointArtifactRights

**默认位置：** RelationVersion 或共同制品关联的 `Commitment` 条款集合。

以下情况需要独立 versioned Commitment：

- 权利由多方分别 ratify；
- 可以在制品内容不变时修改；
- 存在许可、收益、删除、训练、再发布或争议；
- 下游系统必须直接执行。

否则可作为关系实例字段。

### 5.5 LearningUpdate

**默认位置：** 一种持久状态 Effect：Operation 触发，目标模型/记忆域签发 Effect Assertion。

只有当长期学习拥有独立治理、可撤回、可审计和跨关系复用生命周期时，才需要单独 aggregate root。低风险临时上下文更新只记录为事件或 Execution metadata。

## 6. 其他历史概念的层级

### 6.1 顶层对象

| 概念 | 位置 |
|---|---|
| Agent Entity | Entity |
| AuthorityGrant / MandateVersion | Mandate |
| Coordination Schema / SharedArtifactVersion / JAA | RelationVersion 的模式或表现 |
| Claim / Effect / DomainAdoptionReceipt | Assertion 类型 |
| Commitment / ResourceReservation / Joint rights | Commitment 或条款 |
| ActionAttempt / Effect Gateway invocation | Operation |

### 6.2 Stance 事件

以下对象具有独立语义，但默认作为针对精确对象版本的 stance event：

```text
RECOGNIZE
REJECT
CONDITIONAL
UNKNOWN
WITHDRAW
ACCEPT
DISPUTE
```

当某 stance 本身成为长期义务或法律文件时，可以产生 Commitment/Assertion，而不是新增一个平行对象类型。

### 6.3 策略与过程

| 概念 | 当前身份 |
|---|---|
| NAC / Embedding / KG | Discovery Provider |
| BIC | 任务相关交互边界理论 |
| Boundary Oracle | 本地域响应策略 |
| SJAC | Relation Schema 形成方法族 |
| PFE | 形成操作选择策略 |
| CRA | 能力资格化与再认证 Pipeline |
| CEGIS / Benders / Column Generation | 可插拔求解/反例策略 |
| Authority-first countercondition reduction | 候选形成策略 |
| Harness | 运行、验证、恢复和证据闭合底座 |

这些方法可以有实现对象和运行记录，但不拥有正式现实状态。

### 6.4 派生视图

```text
CapabilityEnvelope
AssuranceCase
Settlement
CompiledWorld
Maturity / SRL dashboards
Claim–Evidence matrix
```

视图应可从 canonical objects 和事件确定性重建。视图修改不得反向改写事实。

## 7. 风险触发物化

同一语义在不同风险中可以有不同物化程度：

### 低风险、标准化

- 数据用途是 Mandate 字段；
- 使用记录是普通日志事件；
- 接受是单一 stance；
- Settlement 是派生状态。

### 中风险、多权威

- 数据 Mandate 独立版本；
- 关键使用进入 hash-chained event stream；
- 每个 Authority Locus 条款级 stance；
- Joint rights 形成 Commitment bundle。

### 高风险、外部执行

- 数据授权可验证凭证化；
- 每次高后果使用由 enforcement point 生成 receipt；
- 派生物有完整 lineage；
- learning effect 独立审批和删除/失效流程；
- 第三方审计直接引用对象 ID。

协议核心不应强迫所有任务使用最高等级，但必须允许风险升级时不丢失语义。

## 8. 本体收敛实验说明

`experiments/ontology_reduction/` 构造 50,000 个数据治理场景，并提出五类查询：事件时授权、派生链完整性、当前共同权利、持久学习授权、联合权利是否需要独立对象。

结果：

- `Mandate + typed Event + provenance edge + conditional Commitment` 的收敛表示在生成查询上 0 错误；
- 把所有语义压成当前字段/布尔值的 naive 表示，在 250,000 个查询中错误 48,926 次，错误率 19.5704%；
- 12,312 个场景（24.624%）中，共同权利因独立 ratification/amendment 需要提升为独立 Commitment。

这项实验不证明六对象本体是唯一或现实法律上充分。它只表明两个极端都不好：五个概念全部顶层化没有必要；全部压成无时间/无来源字段又会丢失关键区别。

## 9. 对象增加的治理规则

任何新顶层对象提案必须附：

```text
现实上被混淆的两个状态
现有对象为何不能表达
独立 authority/lifecycle 的证据
至少两个任务族中的复现
新增对象的 invariant
迁移与兼容成本
删除或降级条件
```

没有这些内容，新术语只能进入研究备忘录或策略层，不能进入协议内核。

---

## 10. 当前最小结论

通爻需要丰富语义，但不需要丰富到每个语义都有自己的事实数据库。当前最稳妥的设计是：

> 用少量可版本化、可追责的 aggregate root 保存权威现实；用类型化事件保存变化；用策略和 Pipeline 产生候选；用派生视图帮助人和 Agent 操作；在高风险、独立权威或外部执行需要出现时，再把特定语义提升为独立对象。

## v0.5 公开证据后的对象决策

公开案例引入了 standing、jurisdiction、challenge、Settlement scope 与 SourceRecord，但没有形成新增顶层对象的必要性：

- standing/jurisdiction 是 RelationVersion 与 Mandate 上的范围和功能边；
- challenge 是 typed Stance/Event，并引用 Assertion、Authority 与目标版本；
- Settlement 是带范围参数的派生视图；
- SourceRecord 是 Assertion provenance；
- affected stakeholder class 是角色/representation 描述，不自动成为直接 Principal；
- regulatory order、procurement decision、completion filing 等作为 Assertion/Effect evidence 进入现有内核。

如果未来某一 jurisdictional entitlement 可以被独立签发、转让、撤销、长期引用并拥有独立并发不变量，它可以通过对象准入测试提升；当前首轮语料不要求这种提升。
