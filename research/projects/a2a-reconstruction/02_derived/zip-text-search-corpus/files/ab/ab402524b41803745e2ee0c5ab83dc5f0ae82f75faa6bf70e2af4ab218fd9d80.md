# 通爻 Agent-to-Agent 当前统一体系（旗舰实验吸收版）

## 1. 元问题

多个拥有巨大、动态、不可安全集中上下文的真实主体，怎样通过各自 Agent：

- 发现彼此可能的关联；
- 形成原本不存在的条件、角色和联合能力；
- 保留私有世界、权威、责任、拒绝与退出；
- 让候选安排被分别理解和认领；
- 把它推进为可执行、可验证、可接受和可结算的现实行动。

## 2. 主体与技术域必须分开

### Principal

人或组织，拥有：

- 价值和目标；
- 最终 Recognition / Acceptance；
- 非委托权威；
- 责任、拒绝和退出权；
- 对风险和后果的承担。

### Sovereign / Authority Domain

在 Principal 或组织委托下运行的软件、数据、工具和政策域，例如 Allbuddy 或 Agent World。它能够：

- 保存私有状态；
- 执行本地政策；
- 产生 canonical readback；
- 接受或拒绝技术事件；
- 物化本地事实。

它不能自动拥有人的价值和责任。

### AgentExecution

代表某 Principal 或 Domain、在明确 AuthorityGrant 下运行的模型或程序实例。

## 3. 权威事实源

### 身份与权威

- Principal
- SovereignDomain
- AgentExecution
- AuthorityGrant
- RecognitionAction

### 目标与协调

- ObjectiveVersion
- CoordinationCase
- SharedArtifactVersion / JointActionArrangement

### 主张与证据

- Claim
- Evidence
- WitnessPolicy
- Assumption
- Defeater

### 承诺与资源

- Commitment
- ResourceReservation

### 现实动作与效力

- LogicalActionKey
- ActionAttempt
- Effect
- DomainAdoptionReceipt
- Verification
- Acceptance
- Settlement / Dispute
- Event

同一现实事实只由一个权威对象维护。PFE、CRA、Discovery、Solver 和 Compiled World 不维护第二套正式真相。

## 4. 派生视图和策略

- PFE：可能性和条件形成策略；
- CRA：资格化、开放复核、消融、holdout 和漂移再认证 Pipeline；
- Discovery Provider：NAC、Embedding、Graph、Agent Card 等；
- Solver Provider：Benders、MILP、列生成、搜索和模型规划；
- CapabilityEnvelope：由 Claim、Evidence、Scope、Assumption 和 Defeater 生成的运行视图；
- AssuranceCase：审计视图；
- Compiled World：权威事件和对象的可操作投影；
- authority-first countercondition reduction：PFE 的一种 formation policy，不是独立引擎。

## 5. 统一纵向路径

```text
Principal worlds
→ local AgentExecution / SovereignDomain
→ controlled boundary projection
→ discovery / query / local probe
→ Witness / Defeater / Countercondition / Unknown
→ possibility formation and joint arrangement
→ domain-level technical adoption
→ exact-version Principal Recognition
→ Commitment and resource reservation
→ compiled least-privilege execution
→ ActionAttempt / Effect
→ target-domain adoption
→ Verification
→ Principal Acceptance
→ Settlement / Dispute
→ monitoring and possible formation reopen
```

## 6. 两阶段候选运行结构

### 形成阶段

需要：

- 本地私有上下文；
- 自适应提问；
- REFUSE / COUNTER / UNKNOWN；
- 本地现实探针；
- 工具、权限、伙伴和恢复条件的形成；
- 候选边界和 JAA 的修改；
- 主体或域的独立否决。

### 编译运行阶段

当目标、Schema、权威、接口和运行域冻结后，由最简单的 least-privilege deterministic coordinator 承担：

- 路由；
- claim/read/persist/ack；
- dedupe、retry、journal 和 replay；
- 固定验证和投影；
- 监测 Defeater。

### 重新打开形成的触发器

- ObjectiveVersion 物质变化；
- Principal、AuthorityGrant 或 Acceptance policy 变化；
- 新状态或新主体；
- 环境 / 模型 / 工具 / 协议漂移；
- holdout 或生产监测失败；
- revocation / dispute；
- 无法恢复的 Unknown；
- 隐私、风险或成本结构变化。

## 7. 已相对稳定的结论

- 静态公共画像不能穷尽未来相关性；
- 模型概率和主体权威正交；
- 可能性、能力、认领、承诺和执行不能混为一谈；
- producer completion 不等于 consumer adoption；
- target-domain adoption 不能由来源方自报；
- 现实动作必须经过 canonical readback 和 claim-specific Witness；
- negative decision、revocation、Unknown 和 dispute 是一等状态；
- 来源事实和目标域认知状态必须分开；
- 权威 delivery、recovery 和 ack 是能力的一部分；
- 稳定运行可以中央化，但非委托权威必须留在主体域；
- 软件域不是完整 Principal。

## 8. 仍是承重假说的内容

- 两个真实 Principal 的 Agent 能否形成此前不存在的联合行动路径；
- authority-first countercondition reduction 是否跨任务迁移；
- 形成阶段 / 运行阶段分离是否是一般默认结构；
- Agent 是否发现、帮助形成，还是投射主体偏好；
- Capability Claim 是否对跨环境和跨任务有真实预测力；
- A2A 是否降低人类高认知协调成本；
- 新机会价值是否超过模型、验证、披露和治理成本；
- 通用跨域 AdoptionReceipt 能否跨组织和制度成立。

## 9. 当前应用边界

Allbuddy—Agent World 证明了一个 scoped local technical Domain Adoption 机制。它不证明人际或组织 A2A 已经成立。

当前体系的下一承重点不是继续扩大 technical bridge，而是让真实 Principal 的私有世界、价值、权威和 Acceptance 进入闭环。
