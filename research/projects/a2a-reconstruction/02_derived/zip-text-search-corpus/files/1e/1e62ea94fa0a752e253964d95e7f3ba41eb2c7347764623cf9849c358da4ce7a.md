# 通爻 A2A 当前统一体系 v0.7.2

## 1. 元问题

通爻研究的不是两个 Agent 怎样发送消息，也不是把同一中心控制的多个子调用包装成多主体。

它研究：

> 当多个主体拥有巨大、持续变化且不能安全无损折叠的私有世界，并分别控制自己的工具、资源、权威、责任、拒绝权和最终接受权时，智能系统怎样通过有限边界理解和现实互动，发现或形成此前不存在的联合行动路径，并使它逐步成为对各方真正作数的现实事实？

系统可以存在中心协调面。关键不是“是否有中心”，而是中心能否在不破坏任务所需的隐私、权威、责任、竞争关系、退出权和故障域的条件下充分模拟协调。

## 2. 当前稳定的现实区分

### 2.1 可能性、能力、承诺与执行

- **Possibility**：候选行动路径或条件组合。
- **Capability Claim**：在明确环境、任务域、前置条件和证据下，对可重复行动能力的限定主张。
- **Recognition**：主体对具体目标、范围、风险和责任的理解与认领。
- **Commitment**：经授权后产生的社会义务。
- **ActionAttempt**：执行器在某一授权和环境下实际尝试了什么。
- **Effect**：目标世界实际发生了什么变化。
- **Verification**：某个主张是否满足其 Witness Policy。
- **Acceptance**：有权主体是否认为原始价值已经实现。
- **Settlement / Dispute**：下游效力和救济。

它们不能相互替代。

### 2.2 逻辑动作与物理尝试

同一现实意图的重试共享稳定 `LogicalActionKey`；每一次实际执行拥有独立 `AttemptID`。否则系统无法区分重试、重复投递、重复副作用和新的现实动作。

### 2.3 主张相关证据

证据不是全局强弱排行榜。不同 Claim 拥有不同 Witness Policy：来源、版本、新鲜度、一致性、独立性、Defeater 和接受谓词必须与主张匹配。

### 2.4 目标域采纳

消息到达、文件存在或事件写入，不等于接收主体已经采纳。跨域事实至少区分：

```text
transport receipt
→ target-domain canonical commit
→ consumer adoption
→ verification
→ authorized acceptance
```

### 2.5 环境索引能力

能力不是主体标签。它至少与任务、工具、依赖、模型、权限、资源、执行环境、观察和恢复机制共同相关。干预后成功不能回填成干预前预测正确。

## 3. 权威事实源

当前内核只让下列对象维护正式事实：

### 主体与权威

- `Principal`
- `AgentExecution`
- `AuthorityGrant`
- `RecognitionAction`

### 目标与协调

- `ObjectiveVersion`
- `CoordinationCase`
- `SharedArtifactVersion`
- `Commitment`
- `ResourceReservation`

### 认识与证据

- `Claim`
- `Evidence`
- `WitnessPolicy`
- `Assumption`
- `Defeater`

### 操作与效力

- `LogicalActionKey`
- `ActionAttempt`
- `Effect`
- `Verification`
- `Acceptance`
- `Settlement`
- `Dispute`
- `Event`

同一现实事实不得由多个引擎分别维护第二套状态。

## 4. 策略、Pipeline、Provider 与派生视图

- PFE：寻找和形成条件的策略族，不拥有正式能力事实。
- CRA：资格化、再认证与漂移检查 Pipeline。
- NAC、Embedding、Graph、Agent Card：Discovery Provider。
- Benders、MILP、列生成、MCTS 等：Solver Provider。
- CapabilityEnvelope：从 Claim、Environment、Evidence 和 Validity 生成的运行视图。
- AssuranceCase：从 Claim、Evidence、Assumption 和 Defeater 生成的审计视图。
- Compiled World：权威事件和对象的可操作投影。

## 5. R5.4 带来的负边界

R5.4 的源码身份实验中：

- 静态 Agent 已找到主要技术缺陷；
- 固定中心查询已暴露核心价值冲突；
- 多轮 A2A 生成了更丰富的救济、披露和权益条件；
- 没有形成双方认领的合同、被采纳的补丁或新生产能力；
- 最终 Unknown 依赖真实 legacy corpus 与有权 Owner 的价值取舍。

因此：

> 在任务可安全折叠、主要技术方案已存在、Agent 没有现实干预权且剩余问题是规范性价值选择时，A2A 的主要增量可能只是更精确的冲突表达，而不是能力形成。

这项结果保留为架构选择和协商机制的负对照，不再作为生成式 A2A 的旗舰证据。

## 6. 当前最承重的设计缺口

当前体系比较清楚地规定了“什么作数”，但还没有得到现实支持的方法来决定：

- 何时询问，何时行动；
- 何时请求边界信息，何时移动代码到数据旁；
- 如何从 `NO / UNKNOWN / REFUSE` 中诊断缺少的条件；
- 如何构造工具、训练、授权、伙伴、任务结构、风险或恢复条件；
- 如何让设计、执行和反馈共同演化；
- 如何判断继续搜索、停止、拒绝或升级；
- 如何把一次成功转化为可复用能力，而不是事后解释。

这不是再增加一个顶层对象的问题，而是缺少一套经过现实检验的 **协调决策方法**。

## 7. 当前核心研究命题

通爻的独特价值只有在以下链条同时成立时出现：

1. 主体世界存在真实不可折叠属性；
2. 初始状态中不存在被接受的完成路径；
3. 互动可以改变信息状态或现实状态，而不只是增加文本；
4. 新条件对最终结果具有反事实必要性或显著贡献；
5. 原始目标的关键价值没有被偷换；
6. 目标域真实采纳，主体真实接受；
7. 新增价值高于模型、等待、人类注意力、披露、验证和恢复成本；
8. 形成后的能力在留出任务中具有可预测的复用性。

下一项旗舰研究必须寻找实现这条链的工作机制，而不是再次证明对象和字段能够被记录。
