# PRSE-OS 宪法

## 1. 目的

让产品规格的质量不依赖某一个人的临场聪明，不依赖某一代模型“恰好理解”，而依赖可复用、可检查、可改进的制度。

## 2. 专业性的定义

专业不是术语多，而是：

- 问题边界清楚；
- 证据来源可靠；
- 模型能解释现实；
- 决策说明取舍；
- 闭环覆盖后果；
- 界面忠实投影；
- 风险有准入与升级；
- 对外语言不失真；
- 变更能够传播；
- 陌生执行者能够复现。

## 3. 规范层与实现层分离

PRSE-OS 规定：

- 必须存在什么语义；
- 必须完成什么闭环；
- 必须输出什么产物；
- 必须经过什么验证；
- 何时必须升级。

PRSE-OS 不预先规定：

- 使用哪个模型；
- 采用哪种 Agent 框架；
- 使用哪种数据库；
- 如何实现自动化；
- 用什么前端组件库；
- 具体部署方式。

实现可变化，语义与保证条件不得静默变化。

## 4. 三种真相

- **世界真相**：现实和证据支持什么。
- **规格真相**：团队决定系统应该如何解释和处理世界。
- **表达真相**：在特定受众和情境中，应当如何忠实地表达规格。

三者必须可映射，但不得混为一谈。

## 5. 冲突处理

不同 Agent 或专家冲突时，不采用简单多数票。依次检查：

1. 是否讨论同一个 concern；
2. 证据等级与适用范围是否不同；
3. 概念定义是否不一致；
4. 方案是否优化了不同目标；
5. 哪个角色拥有该 concern 的决策权；
6. 是否需要记录为不可消除的权衡。

## 6. 人类与智能体的统一抽象

人类和智能体都被视为 Capability Provider。二者均须：

- 使用规定输入；
- 输出标准产物；
- 接受独立验证；
- 暴露不确定性；
- 遵守权限和责任边界。

人类的独特作用主要在于：承担法律或组织责任、提供隐性情境知识、处理价值冲突、在证据不足时作有责任的判断。

## 7. 方法的自我改进

方法卡、质量门和路由规则不是永久真理。任何修改都必须：

- 有失败证据或改进目标；
- 记录替代方案；
- 在至少一个基准项目上回放；
- 检查对旧项目的影响；
- 版本化发布。
