# 12 · 跨领域扩展与企业改革边界

## 1. 通用性的正确理解

Flowness 的潜力不只在软件开发，但“任何可讨论的东西都可以自动化”是不成立的。

一个领域适合进入 Harness，至少需要：

- 对象可以表示；
- 过程可以留下证据；
- 结果可以接受反馈；
- 标准来源明确；
- 权限和责任可以定义；
- 失败可以被发现或限制；
- 关键行动可回滚或由人批准。

## 2. 三类可验证性

### 2.1 机械强验证

编译、类型、数学、格式、契约、数据一致性和确定性规则。适合高度自动化。

### 2.2 行为与结果验证

用户任务、业务指标、流程效率、服务质量。需要真实运行、实验和延迟反馈。

### 2.3 价值与治理判断

战略、伦理、组织结构、风险偏好和利益分配。系统可以辅助，但标准和最终授权必须来自人。

## 3. 跨领域扩展不是替换名词

从软件扩展到研究、法律、运营或组织改革，需要重新定义：

- 领域主体；
- 对象；
- 证据；
- 生命周期；
- 权限；
- 失败；
- 验证器；
- 反馈周期；
- 可逆性；
- 专家责任。

通用内核可以复用身份、事件、追溯、任务、证据、审批和回流，但领域本体不能自动从软件术语投影。

## 4. 企业改革的可承载部分

Harness 可以帮助企业：

- 把隐性流程对象化；
- 识别职责和信息断层；
- 建立决策与执行追溯；
- 把专家判断沉淀为规则、判例和验证器；
- 管理多 Agent 和人的共同工作；
- 发现流程瓶颈和重复劳动；
- 建立实验和持续改进；
- 将高风险决定保留给人。

## 5. 不能承诺的部分

- 自动决定企业战略；
- 用指标替代价值判断；
- 在没有领域专家时创造可靠标准；
- 自动解决组织政治和利益冲突；
- 对长期社会结果作确定保证；
- 仅凭讨论生成可执行且正确的改革方案；
- 用 Agent 数量替代责任主体。

## 6. 推荐扩展顺序

1. 软件工程；
2. 技术研究和尽调；
3. 有明确规则的运营流程；
4. 合规和审计辅助；
5. 项目管理和组织协作；
6. 战略和企业改革辅助。

越往后，自动执行越少，人的标准源头和审批越重要。

## 7. 企业落地产品形态

不应一开始销售“组织操作系统”。更可信的产品是：

- 大型代码库调查与迁移控制平面；
- AI 原生研发交付系统；
- 复杂项目的设计—工程—执行工作台；
- 专家知识对象化与 Agent 执行平台；
- 具备证据、审批和回流的数字员工治理系统。

这些真实场景积累的对象、失败和验证器，才可能逐步支持更大的企业改革。
