# 设计过程总览

PRSE-OS 不是先有方法论再找产品套用。它从召集台的真实混乱中长出来：

- 研究结论很多，但产品文档仍允许多种误解；
- 前端原型有风格，却可能把视觉结构误当成产品结构；
- 新内容不断追加，旧定义没有被反向改写；
- 一份文档同时服务内部规格、UI、工程和外部表达；
- 多 Agent 协作越来越强，但缺少不依赖运行主体的质量制度。

演进路径：

1. v0.6：形成丰富的产品与工程蓝图；
2. 纠偏一：从“执行约束”转向“稳定规格底子”；
3. v0.7：补对象化、本体化、闭环和可读性；
4. 原型方法：Clean-room 新生 + 旧原型设计考古 + 延迟继承；
5. v0.8：从追加式文档升级为产品本体、闭环与体验架构；
6. PRSE-OS v0.1：把方法本身对象化、流程化、可观测化；
7. v0.2：把文档改造成 AI 原生规格协议，并与任意 Harness 解耦；
8. v0.3-dev：为本地团队补全设计历史、模板、测试、治理与发展路线。
