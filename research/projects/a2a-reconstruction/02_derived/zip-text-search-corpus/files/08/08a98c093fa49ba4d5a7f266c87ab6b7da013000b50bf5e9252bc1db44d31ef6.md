# 14 · 术语表与对象目录

## 1. 核心对象

| 对象 | 定义 | 不是什么 |
|---|---|---|
| Commission | 一次工作委托、权力和范围的建立 | 普通聊天请求 |
| Problem | 经调查形成的可证据化问题对象 | 用户一句抱怨 |
| Requirement | 被确认的目标、约束或质量要求 | 解决方案 |
| Design Alternative | 核心机制不同的候选设计 | 同方案换包装 |
| Design Decision | 对候选的正式选择和权衡 | 会议结论摘要 |
| Design Object | 设计世界中的主体、对象、关系、状态和机制 | 代码类的简单别名 |
| Engineering Decision | 技术实现选择及其证据、假设和迁移 | 技术偏好 |
| Engineering Component | 真实工程组件和运行边界 | 产品功能列表 |
| Consensus | 跨任务稳定、必须共同遵守的事实与约束 | 整份工程方案 |
| Plan | 从 Engineering IR 编译出的任务图 | 待办列表 |
| Task | 有认知闭包、明确写集和验证合同的执行单元 | 一个动作描述 |
| Capsule | 针对当前任务和动作编译的最小充分上下文 | 固定 Prompt |
| Evidence | 能支持或反驳主张的可追溯材料 | Agent 的自我陈述 |
| Validator | 对对象、状态或结果进行独立判定的机制 | 提示词提醒 |
| Finding | 可追踪的偏差、风险或缺口对象 | Review 评论段落 |
| Trace | Agent 可观察行动和正式决定的事件序列 | 私有思维过程 |
| Policy | 可版本化、可实验的行为和调度策略 | 一次性提示词 |
| Reflow | 问题返回正确认知层级的机制 | 一律重新执行 |

## 2. 主要关系

| 关系 | 含义 |
|---|---|
| derived_from | 从某对象推导 |
| satisfies | 满足需求或条件 |
| implements | 工程实现设计 |
| constrains | 对对象施加约束 |
| validates | 验证某主张或对象 |
| depends_on | 生命周期或结果依赖 |
| consumes | 消费接口、数据或产物 |
| owned_by | 责任和修改权归属 |
| governed_by | 适用规则和治理区 |
| supersedes | 新版本替代旧版本 |
| conflicts_with | 同时成立会冲突 |
| invalidates | 使旧判断失效 |
| observed_by | 被观测机制监控 |
| implicated_in | 与 Finding 或事故相关 |

## 3. 回流术语

| 类型 | 适用情况 |
|---|---|
| Re-execute | 暂态、环境或一次性失败 |
| Repair | 局部实现偏差 |
| Replan | 任务和依赖错误 |
| Re-engineer | 技术方案或工程假设错误 |
| Redesign | 系统结构和机制错误 |
| Re-interview | 意图、价值或范围错误 |

## 4. 状态语义通则

- `draft`：尚未进入正式评审；
- `proposed`：已提出但未接受；
- `accepted`：可作为下游输入；
- `active`：当前生效；
- `challenged`：被证据或 Finding 质疑；
- `suspect`：变化后待重验证；
- `superseded`：由新版本替代；
- `deprecated`：仍兼容但不应新增使用；
- `retired`：正式退出运行；
- `archived`：保留历史，不参与当前决策。

具体领域对象可以有自己的状态，但必须映射到可治理的通用生命周期。
