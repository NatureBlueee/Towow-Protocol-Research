# 新研究员使命、方法与工作纪律

## 1. 角色定义

你不是文档编辑、资料管理员或阶段总结者。你是这项研究的下一位共同建模者。

你的任务是：

> 在不丢失现实区分、不保护历史答案、也不把研究压缩成对象清单的前提下，从全部原始材料中重新建立一个统一、分层、可证伪、可实现的 Agent-to-Agent 生成式协调理论与系统。

交接工作本身就是一轮研究，因为你需要决定：

- 什么是同一个问题的不同表述；
- 什么是不同现实问题，不能合并；
- 什么是权威事实对象；
- 什么是理论层、机制、算法、Pipeline、Provider、视图或实验方法；
- 哪些早期结构被后续研究真正吸收；
- 哪些只是在最新摘要中被过度压缩；
- 哪些主张已经被否定、限定或仍待验证；
- 最终统一模型怎样才能从主权世界递进到共同现实。

## 2. 不要做什么

### 2.1 不要按阶段汇编

最终成果不能以“第一阶段做了什么、第二阶段做了什么”作为主结构。阶段只应出现在研究史或证据来源中。

### 2.2 不要只扩写现有短篇统一论文

该论文是高度压缩入口，不是完整理论。直接扩写会继承它的 recency bias 和过度内核化。

### 2.3 不要把“非权威事实源”理解为“理论不重要”

PFE、CRA、NAC、JAA、SJAC、BIC、Compiled World 等可以不拥有第二套正式状态，但仍可能是共同现实生成链中的主层。

### 2.4 不要为了统一而强行消除分歧

如果两个理论在不同假设下成立，应保留条件。若证据不足，应给出能区分它们的研究路径。

### 2.5 不要用页数或文件数量代替完整性

长文的目标是充分推导，不是堆字；短文的问题是承重结构未展开，不是“看起来不像本科论文”。

### 2.6 不要把所有工程 Bug 升级为理论

仓库特定缺陷、可迁移工程不变量、机制证据和核心理论变化必须分开。

## 3. 研究原则

### 3.1 从问题缺口而非概念名称出发

每个概念都要回答：它消除了什么不可替代的失败？

### 3.2 以层级依赖而非平面对象组织

应建立：

```text
主权世界
→ 边界与发现
→ 共同问题与行动介质
→ 可能性形成
→ 能力兑现
→ 主体认领与承诺
→ 执行与现实效力
→ 演化与编译世界
```

并检验该链是否需要调整。

### 3.3 每个主张都标明强度

至少区分：

- 定义；
- 形式结论；
- 设计不变量；
- 限域机制证据；
- 工作假说；
- 核心开放假说；
- 已否定主张。

### 3.4 每个机制都需要接口

说明：

- 输入什么；
- 输出什么；
- 依赖什么；
- 什么状态不由它维护；
- 如何失败；
- 如何被替换；
- 如何与上下层连接。

### 3.5 每个实验都需要 Design Delta

实验不是证据装饰。需要明确它迫使理论、协议、代码或产品适用域改变了什么。

### 3.6 不可能性要转化为构造知识

若某目标不能普遍实现，继续回答：

- 需要放弃哪个要求；
- 改变哪些条件可使问题局部可解；
- 怎样限制失败；
- 当前最佳可达方案是什么。

### 3.7 真实世界优先但不放弃抽象

形式化用于定义边界和必要条件；合成实验用于隔离机制；真实轨迹用于暴露隐含变量；真实主体用于价值、认领和责任。

## 4. 第一阶段工作：建立研究底图

不要立即写正文。先完成以下制品。

### 4.1 全量主张谱系

目标不是抄现有 20 条 Claim，而是从全部材料中找出：

- 核心命题；
- 算法主张；
- 设计主张；
- 工程语义；
- 产品与经济假说；
- 被否定的旧假说；
- 尚未得到名称但反复出现的关系。

### 4.2 概念依赖图

至少覆盖：

- NC / NAC；
- Boundary / BIC / Oracle；
- Coordination Schema / SJAC / JAA；
- PFE / EVPF / CEGIS；
- CRA / Capability Contract；
- Recognition / Commitment；
- Harness / Effect / Adoption / Acceptance；
- Compiled World；
- WoWok。

### 4.3 证据图

将形式证明、合成实验、真实仓库轨迹、技术域闭环、模型协商和真实 Principal 缺口分别标出。

### 4.4 术语冲突表

例如：

- Actor 在早期指人、Agent 或软件节点；
- Capability 有时指当前工具存在、有时指可达路径、有时指生产资格；
- Adoption、Recognition 和 Acceptance 曾被混用；
- Boundary 有时指静态投影、有时指交互式 Oracle、有时指权限；
- Harness 有时指内部执行系统、有时指企业运行时。

统一论文必须消除这些歧义。

## 5. 第二阶段工作：提出统一模型候选

至少比较三种组织方式：

1. 权威事实内核为中心；
2. 共同现实生成链为中心；
3. 三维模型：生成链 × 贯穿语义 × 成熟度。

可以提出第四种更强模型，但必须说明它比三维模型增加了什么解释力和构造能力。

评估标准：

- 是否能容纳全部重要概念；
- 是否能解释概念为何存在；
- 是否支持协议和代码接口；
- 是否区分候选与权威事实；
- 是否支持不同风险级别的简化物化；
- 是否能放置所有现实证据和开放问题；
- 是否减少阶段拼接感。

## 6. 第三阶段工作：写长篇统一论文

写作时不要从已有论文复制段落后拼接。每一章按统一论证模板重写：

```text
问题缺口
→ 必要区分
→ 正式定义
→ 机制与算法
→ 与上下层接口
→ 不变量与失败方式
→ 证据
→ 设计与工程后果
→ 适用边界
```

每一层都要能回答：为什么上一层不足、这一层新增什么、为什么不能跳过、下一层为何仍然需要。

## 7. 建议的研究协作方式

### 7.1 主研究员

负责：

- 判断问题；
- 统一模型；
- 解释反例；
- 决定概念去留；
- 写核心论证。

### 7.2 子 Agent / 工具

可以承担：

- 文件索引；
- 主张抽取；
- 术语对齐；
- 公式和引用核验；
- 代码与实验复现；
- 盲审和反例搜索；
- 图表与附录生成。

但不得让自动抽取结果直接成为统一模型。

## 8. 质量 Gate

统一成果至少应通过：

### G0 问题 Gate

是否清楚定义了完整元问题，而不是某个局部协议？

### G1 概念 Gate

每个核心概念是否有不可替代的现实职责？

### G2 层级 Gate

是否形成从私有世界到现实效力的连续链？

### G3 权威 Gate

候选、证据、认领、承诺、执行和接受是否清楚分离？

### G4 证据 Gate

每个强主张是否有匹配强度的证据？

### G5 构造 Gate

理论是否给出怎样做，而不只解释为什么难？

### G6 工程 Gate

对象、状态机、接口和失败恢复能否指导实现？

### G7 现实 Gate

是否诚实说明真实 Principal、经济价值和长期社会证据仍缺什么？

### G8 盲读 Gate

未参与阶段研究的人能否只读主文理解整体？

## 9. 停止条件

研究不以读完文件、写满页数或完成目录为停止。

合理停止条件是：

- 全部承重主张已经进入谱系；
- 所有主要概念有依赖位置；
- 统一模型能够解释所有重要反例；
- 主文可独立成立；
- 证据强度与语言一致；
- 未决问题清楚且不会被伪装成已解决；
- 新研究员或盲审者能够据此设计系统和下一项高价值研究。

## 10. 最重要的心智提醒

不要问：

> 哪个阶段的版本是对的？

要问：

> 每个阶段看见了完整问题的哪一部分？这些部分怎样共同组成一个能够形成现实的系统？

不要问：

> PFE 是否应该被删掉？

要问：

> PFE 在统一生成链里承担什么不可替代的变换，其输出怎样进入权威事实而不制造第二套真相？

不要问：

> 论文应该有多少页？

要问：

> 每一个承重结构是否被充分推导、验证、连接和限制？
