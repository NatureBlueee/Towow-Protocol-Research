# B4-1 · 类型账本规格 v0.9（结构冻结候选；原语槽位待WP0语料实例化）

**设计意图陈述：** 类型账本是结晶产物的**轨道中立中间表示（IR）**——上接LLM的创造性文本，下编译到任意执行轨（CN/WOWOK/Plain）。它存在的根本理由：大模型结构稳定、细节不稳定（生成哲学P6）——守恒、闭合、个体理性这三件"绝不允许错"的事必须由代码机械持有，模型只做文本与账本之间的编译器。工程师遇未覆盖情形按此意图外推：**凡数值与资源流动的正确性，宁可拒绝也不交给语言模型担保。**

## 1. 对象模型

```
Structure := { structure_id, version, parties: [PartyRef≥2],
               edges: [Commitment], conditions: ConditionDAG,
               valuations: {party → {edge → value}},      // 各方自报估值（IR检查的输入）
               provenance: {edge → disclosure_refs} }      // 每条边的接地出处（启迪通道地板的承诺级延伸）

Commitment := { edge_id, from: party, to: party,
                deliverable: { type: PrimitiveType, params, unit, quantity },
                preconditions: [cond_id], produces: [cond_id],
                window: {earliest, latest},
                escrow?: { required: bool, staged?: [milestone] },
                rail_hint?: CN|WOWOK|PLAIN }

PrimitiveType：大类冻结，叶子待WP0语料枚举——
  GOODS（实物）| SERVICE（服务）| ACCESS（使用权/场地/设备时段）|
  INFO（信息/介绍/背书）| FUNDS（资金）| MEDIUM（标准媒介：积分/信用额，缩环器）|
  RISK（风险转移：保证金/担保/保险槽）
```

## 2. 三检查器（机械执行，任一红灯即拒绝进入COMMIT_READY）

**K1 守恒**：对每方每资源类型——流出总量 ≤ 该方已披露能力（画像供面/E交换势的结构化声明）；每条边的deliverable必须溯源到from方的声明能力**或**结构内的上游流入（v0允许"声明型转化"：某方声明输入X可产出Y，须有provenance）。无中生有＝红灯。四百年复式记账的类型化推广：每条边同时是一方的贷与另一方的借，账必须平。
**K2 闭合**：ConditionDAG无环；每个被引用条件要么由结构内某边的produces产生、要么签署时外部为真（带attestation_ref）、要么显式标注为外部依赖并向全体方披露；存在满足全部时间窗的拓扑执行序。悬空条件＝红灯。
**K3 个体理性**：对每方，Σ自报估值(流入) − Σ自报估值(流出) − 持有/风险成本 > 0。估值用**各方自己的**申报（验证轮收集），不用催化的估计——催化无权替任何人定价（I-C4的账本投影）。

**K4 可编译（执行前置）**：每条边映射到所选执行轨的≥1个原语；escrow需求被该轨能力满足；**环长 ≤ 轨道声明的托管环长上限**（IF-1 I-C5、清算层"托管能力决定环长"的机械落点）。

## 3. 检查器的边界（诚实声明）

- 单结构作用域：跨结构的资源争用（同一产能被两个并行结构占用）v0不查，由端侧adapter在接受前自查（其有完备本地信息，A5）；列为v1候选。
- K1查的是"声明一致性"不是"声明真实性"——吹牛由验证轮、执行结果与沉淀降温追责（H6口径）。
- 活性/死锁分析（资源互锁）v0不做；ConditionDAG语义与工作流Petri网兼容，留作v1的形式语义升级路径。

## 4. 挑战记录（动笔前否决的候选）

- **直接用智能合约语言（Solidity/Move）作账本**——否决：轨道绑定，违反适配器可插拔；账本必须是轨道中立IR，这是LLVM对编译器的教训。
- **完整Petri网形式化**——部分否决：守恒/闭合用Petri可得免费的死锁与活性分析，但v0的三检查实现成本低一个量级且对工程师可解释；裁决为"v0语义保持Petri兼容、形式化留作v1升级"，不为未观测的失败建机制（Q-08）。
- **TLA+级时序验证**——否决于v0：杀鸡用牛刀；记入协议级验证的远期工具箱。
- **无IR、LLM按轨直出合同**——否决：守恒无人持有，模型算术不可靠正是F4要测的东西；此路线作为F4的对照组保留（它输给检查器多少，就是账本的价值定价）。

## 5. 与体系的接口

输入：crystallize承诺通道的候选结构（IF-1§4）；各方估值与类型化反对（验证轮）。输出：三灯报告（K1–K4逐项）＋可编译目标集，供执行适配器（B4-2）消费。失败结构连同红灯原因完整入事件日志——失败案例与成功同等入沉淀（仅以事实形态）。
