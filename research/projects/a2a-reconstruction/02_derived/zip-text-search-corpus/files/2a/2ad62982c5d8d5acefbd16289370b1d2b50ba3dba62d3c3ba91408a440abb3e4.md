# Flagship Experiment Design Delta

## 协议层

1. 明确区分：
   - Source Report
   - Domain Adoption Receipt
   - Principal Recognition
   - Principal Acceptance
2. 外部事实协议至少支持：
   - stable logical identity
   - monotonic revision / correction / revocation
   - claim / read / persist / ack
   - offline / stale / disputed / unknown
   - target-domain adoption evidence
3. 形成阶段允许 typed `PROPOSE / COUNTER / REFUSE / UNKNOWN / WITNESS / DEFEATER`；这些消息本身不产生正式事实。
4. 软件域的技术 Adoption 不能自动升级为人类或组织 Acceptance。

## 引擎层

1. PFE 增加一条具体 formation policy：

   ```text
   authority map
   → local falsification probe
   → minimal countercondition exchange
   → condition formation
   → boundary compile
   ```

2. CRA 吸收：
   - unseeded open review
   - Defeater registry
   - critical condition ablation
   - pre-frozen holdout
   - scope-bound claim freeze
3. Boundary compiler 输出可由 deterministic coordinator 执行的最小合同。
4. Monitoring 发现新 Defeater、版本、权威和目标变化时重新打开 formation。

## 运行层

1. 默认候选：

   ```text
   adaptive sovereign formation
   → compiled least-privilege execution
   → monitor / reopen
   ```

2. 日常执行不继续支付多 Agent 谈判成本。
3. 本地权威、revocation、Acceptance 和私有状态不移交给中心。
4. 运行期 centralization 是优化，不是主权消失。

## Harness 与本地 Agent

1. Harness 提供：
   - local probe execution
   - typed Witness / Defeater / Countercondition
   - logical action identity
   - boundary contract compilation
   - target-domain adoption adapters
   - deterministic execution and replay
   - formation reopen triggers
2. Agent 代表 Principal 或 Domain，在 AuthorityGrant 下工作；软件系统本身不再默认建模为 Principal。
3. Compiled World 展示权威事实和 epistemic 状态，不能把 domain policy 误写为 human preference。

## Claim 更新

| Claim | 更新 |
|---|---|
| 目标域采纳是必要理论对象 | 升级为 scoped local mechanism evidence |
| PFE 需要现实探针和反条件形成 | 获得局部现实方法证据 |
| CRA 应含开放复核与消融 | 获得强局部支持 |
| Capability Contract 可跨域实例化 | 获得单机 synthetic 技术实例 |
| frozen interface 后 central 可执行 | 获得 scoped 支持 |
| A2A 唯一形成该架构 | 仍为 UNKNOWN，并被静态 baseline 削弱 |
| A2A 比 matched central formation 更优 | UNKNOWN，未运行公平对照 |
| 人类偏好、责任和商业价值成立 | UNKNOWN |
| 软件系统可作为完整 Principal | 被否定；应建模为 SovereignDomain / AuthorityDomain |

## 当前最小完整技术闭环

```text
Domain-local authority decision
→ canonical readback
→ stable revisioned report
→ scoped claim
→ target journal-before-ack
→ target semantic materialization
→ Domain Adoption Receipt
→ restart replay / Defeater monitoring
```

完整通爻闭环仍需在其上增加：

```text
real Principal Recognition
→ Commitment
→ real action
→ Principal Acceptance
→ responsibility / settlement
```
