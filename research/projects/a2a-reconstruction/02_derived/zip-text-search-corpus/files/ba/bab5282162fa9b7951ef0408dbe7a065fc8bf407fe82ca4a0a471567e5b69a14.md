# 附录 C · 工程方案审查清单

## 1. 架构边界

- 系统内外边界明确；
- 外部依赖有失败和替换策略；
- 组件职责单一且所有权明确；
- 跨层调用受控；
- 公共接口数量和演化方式合理；
- 不把外部框架状态当作内部事实源。

## 2. 数据与一致性

- 实体、值对象和聚合边界清楚；
- 唯一性和幂等有机制；
- 事务边界符合真实业务；
- 强一致和最终一致选择有理由；
- 重复、乱序、延迟和丢失可处理；
- schema 演化、迁移、归档和恢复明确；
- 数据删除和隐私符合治理要求。

## 3. 并发和分布式行为

- 锁、租约、乐观并发和所有权选择有证据；
- 并发修改公共对象时冲突可检测；
- 重试不会重复副作用；
- 超时、背压、熔断和退避明确；
- 任务死亡和接手不会产生双写；
- 分区、网络抖动和时钟问题被考虑；
- 长事务和全局锁不会成为瓶颈。

## 4. Agent 运行时

- Agent 身份、会话、任务、工作区和产物绑定；
- 模型可替换；
- 工具按需发现；
- 权限最小化；
- 上下文有版本、新鲜度和来源；
- 会话中断可恢复；
- 结果不依赖私有聊天历史；
- 低置信判断不会跨越高风险边界。

## 5. API 和契约

- 输入输出类型完整；
- 字段单位、范围、默认值明确；
- 错误码和部分成功明确；
- 版本和兼容期明确；
- 消费方已知；
- 限流、超时、重试和幂等明确；
- 契约测试和弃用路径存在。

## 6. 安全

- 身份和授权独立；
- Agent 借用人类身份的边界明确；
- 高风险操作有 Owner Gate；
- 沙箱和网络限制有效；
- 密钥不进入上下文和日志；
- 外部内容视为不可信输入；
- 审计日志防篡改；
- 供应链和依赖风险可扫描。

## 7. 测试

- 单元测试覆盖核心纯逻辑；
- 契约测试覆盖模块边界；
- 集成测试覆盖真实调用；
- 状态机和属性测试覆盖组合空间；
- 并发和故障注入覆盖危险路径；
- 回放测试验证历史兼容；
- 迁移和回滚被演练；
- 测试失败可定位到设计、工程或实现层。

## 8. 可观测性

- Trace、metric、log 能关联到 task/session/decision；
- 指标定义有单位、口径和数据源；
- 能区分声明完成和真实完成；
- 有关键路径和队列延迟；
- 观测器有校准；
- 告警有行动路径，避免纯噪音；
- 当前状态可以从事实重建。

## 9. 发布和运维

- 本地、测试、shadow、灰度和生产区分；
- 配置、代码、数据迁移顺序明确；
- daemon 或长进程升级后会真正加载新代码；
- 回滚不会破坏数据；
- SLO、容量和成本可观测；
- Owner、值班和事故响应明确；
- 长期依赖更新和技术债有计划。

## 10. 复杂度

- 新组件数量合理；
- 没有相同能力多套实现；
- 临时脚本不会成为隐形生产路径；
- 文档、Schema 和代码不重复维护同一事实；
- 关键路径足够简单；
- 引入框架的抽象与自身本体隔离；
- 未来退出或替换成本可接受。
