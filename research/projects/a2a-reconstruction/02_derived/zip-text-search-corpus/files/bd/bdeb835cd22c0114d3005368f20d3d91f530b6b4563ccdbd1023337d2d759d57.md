# 17　证据体系与实验方法

## 17.1 研究问题

本文用既有实验回答六类问题：

- **RQ1 边界：** 静态画像与任务自适应边界在可行性、披露和错误上有何差异？
- **RQ2 构成：** 开放贡献、countercondition 和现实 probe 能否形成静态候选空间中不存在的联合路径？
- **RQ3 可靠性：** 概率门、能力合同、资源预留和状态机能否阻止被建模的错误？
- **RQ4 现实语义：** Attempt、Effect、Adoption、Acceptance 的分离是否在真实仓库和跨域运行中改变判断？
- **RQ5 表示与制度：** Relation Schema、版本图、Standing 和稳定向量能否解释真实制度过程，并优于压缩公告或单一状态保留关键结构？
- **RQ6 OPC 适用性：** 多机制 Router 能否在构造的 OPC 场景中选择结构上有效的机制组合，并暴露其自身缺陷？

这些问题不等同于“通爻是否成功”。它们分别检验必要部件。最终的真实价值主张仍需 RQ7：真实 OPC 在强基线比较中是否获得更高净价值和长期接受。

## 17.3 R2 合成生成器

R2 使用四个独立生成器：

1. **Boundary Oracle**：每个主体拥有私有线性约束；比较 static projection、不同轮数自适应边界和 full disclosure；
2. **Team Constitution**：主体拥有公开 profile 与隐藏贡献模式；比较 public profile、随机抽样、price-guided local oracle 和 full private；
3. **Probabilistic Oracle**：制造分布漂移和高置信系统性错误；比较 unguarded、固定风险门与审计自适应策略；
4. **Trust Concurrency**：并发请求共享预算；比较 check-then-write 与 serializable reservation。

主要指标为可行率、披露量、成本比、覆盖率、错误率和超卖率。所有结果仅对生成器成立。

## 17.4 R5/R5.2 真实工程方法

R5 在真实本地环境中构造：

- 文件系统、Git、Docker、进程和 sandbox；
- 多种证据位置和不可达路径；
- 工具存在但权限/环境不满足的能力；
- stdout、外层退出码和目标状态之间的差异；
- owner approval 前后的 Operation 可达性；
- 中心审计与部分主权运行的开销。

R5.2 从真实 Harness 的事件、carrier、sentinel、索引和 fresh readback 重建 17 个场景。基线使用 naive terminal interpretation；显式方法分别重建 Attempt、Effect、Adoption 和 Acceptance。能力 holdout 预先定义六轴合同和 80% 门槛，以真实执行判断预测。

## 17.5 R5.4 真实模型负对照

R5.4 使用两个带不同合成权威上下文的真实模型 Agent，围绕真实源码身份与协作问题进行多轮协商。比较：

- 静态 builder；
- 直接 A2A；
- 尝试的中心综合路径。

记录条件数量、拒绝、披露、争议、reopen、签署、补丁、目标域 adoption、AcceptedOriginalValue 和成本。中心综合因 transport failure 未形成公平完整基线，因此任何“A2A 优于中心”结论均被禁止。

## 17.6 R5C 跨技术权威域方法

R5C 连接 Allbuddy source authority 与 Agent World target authority。实验要求：

- source 不能替 target 宣布 adoption；
- target 通过 canonical readback 证明状态；
- 支持 revoke、offline/unknown、recovery；
- 使用现实 probe 和最小 countercondition 修改 API 与恢复路径；
- 对 producer-only、wrong-authority、缺少 readback 等条件进行消融。

结果以本地服务、journal、readback、replay 和 portable verifier 复核。

## 17.7 v0.4 构造实验

### 本体收敛

生成 50,000 个场景，每个场景评估五类数据治理查询，共 250,000 次判断。比较：

- 五类概念全部独立 root；
- 收敛表示：Mandate + typed Event + provenance edge + conditional Commitment；
- naive flatten：当前状态与布尔字段。

指标为查询可区分错误和何时联合制品权利需要独立 ratification。

### Schema materiality

生成 30,000 个参数、non-material schema 和 material schema 变化。比较：never reopen、always reopen、any schema diff 与 typed materiality checker。ground truth 由生成器的可达轨迹、角色、Authority、Effect、Data 与 Outcome 语义定义。

## 17.8 公开制度过程

v0.5–v0.6 选择并购、监管、公共基础设施、开放银行、城市治理和地下水治理等理论样本。选择原则不是代表性抽样，而是最大差异与负控制：既包含关系被扩大/转化，也包含保护性收缩、失败、预留 contingency 和中心制度足够的案例。

七案扩展数据集含 58 个时间事件。每个事件编码：

- 角色与 Authority Locus；
- RelationVersion；
- \(R,V,T,A,E,D,O\) 维度变化；
- materiality；
- Standing；
- Declared/Enacted；
- 五维稳定；
- Compile/Reopen；
- 来源与可观察性。

压缩公告消融只向编码器提供最终公告或摘要，用于比较过程信息损失。

## 17.9 QDR 访谈重分析

QDR 数据包含 52 份去标识化访谈和 3 份工作簿，原研究关注加州 Sustainable Groundwater Management Act 下地方机构的协调。本文使用它校准“类似顾虑是否决定唯一机制”“Authority、自治、资源和制度框架能否在访谈中被区分”，而不把大型公共治理频率外推到 OPC。

处理流程：

1. 解析访谈文本和元数据；
2. 生成 4,394 个唯一检索单元；
3. 根据协调构型、自治、权威、资源、冲突和机制选择代码表检索；
4. 对 54 个自动命中进行单分析者人工审计；
5. 连接可匹配的 18 个流域和配置；
6. 比较最相近协调顾虑的 nearest neighbor 是否采用相同配置。

受数据协议限制，逐字文本和行级派生不进入可分享包。

## 17.10 盲化历史 checkpoint

对 Sidewalk、Crossrail、Amazon–iRobot、NASA HLS 等案例构造 11 个时间截点。诊断器只获得截点之前的信息，预测下一真实事件将影响哪些 Relation Schema 维度。比较：

- No-change；
- 历史先验；
- Last-event；
- Authority-aware 结构诊断。

指标为多标签 precision、recall、F1 和完整维度集合 exact match。该实验检验诊断和 probe 排序，不检验商业决策。

## 17.11 三机制 Replay

将同一 58 事件流分别编码为：

1. 压缩公告；
2. 单一可变全局状态；
3. Authority-aware 版本图。

查询 Authority、版本、Standing、Effect 和 Reopen 关系，计算结构召回。版本图与人工 Schema 同构，因此其上限结果是表示保真测试，不能解释为自动抽取或现实价值。

## 17.12 OPC 构造场景

24 个场景覆盖标准支付、报税、品牌合作、定制服务、数据合作、广告预算、资源互换、联合投标、长期联名、争议和内部自执行。比较：

- 固定平台；
- 单一全局 Agent；
- 初始组合 Router；
- 经失败修复后的组合 Router。

结构有效性要求：必要 Authority 不被合并、不可逆动作有 Gate、资源有预留、Effect 与 Acceptance 分离、争议有冻结与补救、关系变化可版本化。该测试是理论一致性和红队，不是现实成功率。

## 17.13 共同威胁

所有实验存在至少一种威胁：

- 生成器由研究者定义，可能把答案写入规则；
- 真实仓库仍是单一 owner 的技术域；
- R5.4 Principal 是合成角色；
- R5C 缺少真实人类认领；
- 公开案例有回溯选择和单编码者偏差；
- QDR 原研究对象与 OPC 不同；
- Replay 的版本图与编码 Schema 同构；
- OPC fixtures 和 Router 来自同一理论；
- 当前无前瞻性强基线净值比较。

因此结果章节只报告它们真正区分的机制，不使用“证明整个系统有效”的措辞。
