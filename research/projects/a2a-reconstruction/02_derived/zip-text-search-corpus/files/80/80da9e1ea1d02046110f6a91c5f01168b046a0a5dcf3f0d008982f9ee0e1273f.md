# r5-run-004-sovereign-workspace

## Research question

On the actual v1.1 evidence-reachability task, can OS-enforced local subjects
produce and validate a signed result while the runtime coordinator cannot read
the packet or either private directory; and is that path worth its coordination
cost relative to a centralized process?

## Pre-registered expectations

- Centralized full access should accept in one process and read both private
  canaries.
- Capability cards alone should leave the coordinator at `Unknown`.
- Honest sovereign flow should accept while all coordinator/private and
  cross-subject canary probes are denied.
- Tampering with the report after producer signature should be refused.
- Sovereign flow should cost more processes and wall time than centralized.

## Kill conditions

- If the coordinator reads the packet or either private canary, do not label the
  run sovereign.
- If tampered content is accepted, exact-hash/signature recognition is not
  working.
- If the trusted test controller's omniscience is confused with coordinator
  authority, downgrade the evidence.

## Reality and limits

The data task is the real local v1.1 packet. Roles are deterministic Python
processes, not strong-model Agents. A trusted experiment controller creates and
removes temporary worlds but is not the runtime coordinator.

## Safety

The exact lab command requires approval to run outside the parent seatbelt so
it can apply child sandbox profiles. It creates only temporary synthetic
canaries and Ed25519 test keys, persists no private key, uses no network, and
has no production effect.
