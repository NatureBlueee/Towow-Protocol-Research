## Static patch: format versus semantics

Format defects:

- Paths omitted the repository prefix; a deterministic path-normalized artifact
  was retained.
- Hunk headers do not describe their actual body. Exact apply reports a corrupt
  patch; `git apply --recount --check` still fails at projection context.

Semantic defects:

1. The real canonical producer emits `before_state.reference_id` and
   `source_entity`, but the static patch inferred an after-state typed shape.
2. Its projection treats any `reference_id` as globally unique and deactivates
   every matching row.
3. Its active fold only reads `after_state.at_reference`, so it misses canonical
   removals.
4. Its retire-gate tuple order is inconsistent between collection and lookup.
5. Its add logic prevents duplicates but does not implement ordered
   reactivation.

Therefore static failure is not merely a formatting penalty.

## Legacy semantic conflict

Static and hidden implementations preserve the historical rule as a wildcard:
no-source removal may affect every instance with that locator. Direct A2A
instead proposes a null-source identity that can affect only null-source state.

The null-source rule protects later sourced owners, but narrows owner A's
explicit compatibility requirement. The claim that all historical instances
were source-less was not supported by a corpus or schema measurement.
Conversely, the hidden branch's tests prove source-less add/remove replay but do
not test a source-less removal in a mixed source-less/sourced stream.

Correct classification: `Unknown / owner value decision required`, not
“oracle is necessarily correct” and not “A2A remained compatible.”
