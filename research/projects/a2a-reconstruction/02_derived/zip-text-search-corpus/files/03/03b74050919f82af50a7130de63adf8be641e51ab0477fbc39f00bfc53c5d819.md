# 问题定义如何升级

| 阶段 | 当时的问题 | 后来发现的不足 | 升级后的问题 |
|---|---|---|---|
| 产品蓝图 | 召集台要有哪些功能和页面 | 功能丰富仍可被理解成多个产品 | 如何建立唯一、自洽的产品世界 |
| 执行规格 | 怎样让工程团队不跑偏 | 过早绑定技术实现 | 哪些语义、闭环和准入长期不变 |
| UI 设计 | 怎样做得好看且像系统 | 美学和 dashboard 容易掩盖机制缺失 | 如何让领域结构成为可读界面 |
| 多 Agent | 需要哪些专家协同 | 角色 Persona 不等于能力 | 怎样按知识、方法、工具和权限路由能力 |
| 文档 | 怎样写得完整 | 叙事文档依赖顺序阅读和常识 | 怎样形成 AI 可寻址、可校验的规格图 |
| Harness | 怎样让本地系统执行 | 方法容易绑死某一框架 | 怎样定义运行主体无关的质量契约 |
| 方法论 | 怎样复用好做法 | 方法也可能成为黑盒和仪式 | 怎样观察方法是否真的提高结果 |
