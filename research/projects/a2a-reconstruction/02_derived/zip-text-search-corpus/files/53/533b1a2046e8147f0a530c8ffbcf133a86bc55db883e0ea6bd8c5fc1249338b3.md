# 形式命题、反例与可反驳条件 v0.5

**说明：** 本文件压缩当前理论的最小形式骨架。公式只用于暴露假设、竞争解释和设计边界。

## P1　开放任务下的静态投影不完备

设主体世界集合 `W`，静态投影 `φ: W → Z` 为有限、非单射映射。若未来任务族 `F` 中存在任务相关判别 `g_f(W)`，则存在：

```text
W1 ≠ W2
φ(W1) = φ(W2)
g_f(W1) ≠ g_f(W2)
```

因此静态 Agent Card、能力标签、Embedding 或知识图谱不能定义主体对所有未来任务的完整相关性；它们可以是特定任务的发现投影。

**限定：** 对封闭任务族若存在可证明充分且更低成本的表示，动态边界应被旁路。

## P2　身份、能力、权威和目标所有权互不蕴含

```text
I(e)    = 实体身份可验证
C(e,a)  = 实体能执行动作 a
A(e,a)  = 实体有权执行动作 a
G(e,o)  = 实体代表 Principal 目标 o
```

一般不存在：

```text
I ⇒ C,A,G
C ⇒ A,G
A ⇒ C,G
```

**Design Delta：** 高后果 Operation 分别引用 Entity、Mandate、Capability evidence 和 Objective source。

## P3　动作尝试不蕴含现实效力，效力不蕴含采用与接受

```text
Attempt(a) ⇏ Effect(a)
Effect(a) ⇏ Adoption(a)
Adoption(a) ⇏ Acceptance(a)
```

Operation、Effect Assertion、Domain Adoption Assertion 和 Acceptance Stance 可以按风险压缩物化，但不能互相代答。

## P4　严格形成是合格联合行动空间的可归因修订

定义：

```text
Q_t = {a |
  Executable(a)
  ∧ ValidlyAuthorized(a)
  ∧ EvidenceQualified(a)
  ∧ RightsCompatible(a)
  ∧ JurisdictionallyAdmissible(a)
  ∧ RequiredStandingAddressed(a)
  ∧ ¬EffectivelyProhibited(a)
}
```

严格形成不是“文本更多”，而是经类型化形成操作 `op` 后出现以下之一：

```text
EXPANSION:              Q_after \ Q_before ≠ ∅
PROTECTIVE_CONTRACTION: Q_before \ Q_after ≠ ∅
TRANSFORMATION:         remove(q_old) ∧ add(q_new),
                        且二者在角色/权威/证据/数据/责任/Effect path上不等价
```

`EPISTEMIC_CLARIFICATION` 只表示对 `Q` 的认识更清楚，除非相称 Authority/Evidence 使资格状态真正改变，否则不构成严格形成。

### 因果升级条件

一项“机制形成了新关系/能力”的主张至少需要：

1. 冻结前态与记录缺失状态；
2. 公平静态、人类中介或同权限中心基线；
3. 指定形成操作；
4. 消融、时序或过程证据支持该操作必要；
5. 相称权威或目标世界 witness；
6. 现实 Effect 或有证据的可执行 readiness。

公开档案可以证明现实 `Q` 被重构或收缩，却通常不能证明 Towow/Agent 是原因。

## P5　Relation Schema materiality 是任务相关语义差异

给定 `Γ1, Γ2, F, s, H, ρ`，若：

```text
Γ1 ≡_(F,s,H,ρ) Γ2
```

则差异不要求重新形成；若不等价，至少重开受影响依赖闭包。

除了可达动作，等价还必须保留：角色/representation、Authority、Evidence、Data、Outcome、standing、jurisdiction、challenge 和 Settlement scope。

**边界：** 自动 checker 只能判断被形式化的差异，不能替相称 Authority 裁决未建模的规范争议。

## P6　安全编译不能创造新的规范或制度事实

对稳定子图 `G`，编译器 `κ(G)` 若语义保持：

```text
Authority(κ(G))   ⊆ Authority(G)
Actions(κ(G))     ⊆ Actions(G)
DataRights(κ(G))  ⊆ DataRights(G)
Settlement(κ(G))  ⊆ ScopedSettlement(G)
```

编译器不能产生 Mandate、替主体接受结果、把预测升级为事实、补造 jurisdictional clearance 或宣称更宽 Settlement。

## P7　中心化安全性是反事实保真，不是部署形态

`CollapseSafe(T)` 要求中心机制与主权机制在以下维度反事实等价：

```text
outcome
information disclosure and derivative use
refusal/exit
operational authority and responsibility
incentives/bargaining
updates/learning
dependent failures/recovery
affected stakeholder rights and standing
challenge and settlement scope
```

若等价成立，应使用更简单的中心机制；若只在部分维度失败，中心仍可做计算组件，差异部分保留独立 gate。

## P8　系统目标应是稳定处置保真而非成交率

```text
DispositionLoss(d_t,Y)
 = false_commit_cost
 + missed_feasible_opportunity_cost
 + unauthorized_effect_cost
 + premature_reject_cost
 + unknown_misclassification_cost
 + rights_violation_cost
 + externalized_harm_cost
 + reversal_and_challenge_cost
```

正确 Reject/NoDeal 可以优于勉强成交；但必须比较避免损失、机会成本和治理成本，不能将监管禁止自动当作净福利证明。

## P9　数据使用会产生新的派生事实与持续影响

若：

```text
D' = f(D, context, model, purpose)
```

则 `D'` 的权利、风险和责任不能只由源数据访问布尔值决定。至少需要目的、转换、来源、保留、学习和再披露语义。

但这不推出每个 DataUseEvent 或 DerivationRecord 都成为顶层对象；默认通过 Mandate、typed Event、provenance edge、Commitment 与 Effect 表达。

## P10　最小本体是 canonical facts 最少，而不是语义最少

若候选表示 `M'` 对任务查询集合 `Q` 保持：

```text
∀q∈Q: q(M') = q(M)
```

并保持独立 authority/lifecycle 与可追溯性，则多余 aggregate root 应降级。若压缩使会导致不同处置的现实状态无法区分，则压缩非法。

公开案例没有要求新增 standing、jurisdiction、challenge 或 SourceRecord 根对象；它们要求现有事实对象承载更完整字段和来源。

## P11　能力提升不会自动提高授权安全

执行器能力 `c` 增大可扩大成功动作集合 `S(c)`。若 Mandate `M` 含糊：

```text
|S(c) ∩ Unauthorized(M)|
```

可以随能力增加。更强模型上线前应重新资格化 Capability，但不能静默扩大 Mandate。

## P12　“主体”需要权威与责任，而不是进程分离

两个仓库、进程、容器或模型上下文可以形成两个 Authority Domain；只有在具有独立拒绝、授权、责任、利益和接受权时，才构成研究意义上的不可折叠 Principal。

## P13　Settlement 是范围关系，不是布尔值

```text
Settled(RelationVersion,
        JurisdictionSet,
        StandingSet,
        ChallengeHorizon,
        EvidenceState)
```

因此：

```text
Effect ⇏ Settled(all scopes)
BilateralAcceptance ⇏ ExternalClearance
CurrentNoChallenge ⇏ PermanentlySettled
```

已完成交易、已授标或已执行 Operation 都可能被有 standing 的 Authority 在另一范围重开。

## P14　外部 standing 可以改变双边合格空间

设双边主体集合为 `P_b`，受影响者或适用 Authority 为 `P_e`。若某 `p∈P_e` 具有有效 standing，且其证据/规则改变 `Q_t`，则将其排除在 RelationVersion 的 challenge model 之外会造成不完备。

这不要求把所有受影响者都变成签约 Principal。系统至少要记录 representation、challenge channel、jurisdiction 和 residual externality。

## P15　来源资格是 Assertion 真值治理的一部分

对公开或私有来源 `s`，Assertion 的可用保证不能只由签名或 URL 决定。至少依赖：

```text
SourceRole(s)
Contemporaneity(s)
IncentiveOrConflict(s)
AdversarialTesting(s)
Corroboration(s)
RedactionAndCompleteness(s)
ClaimTypeFit(s)
```

缺失记录必须区分 `ABSENT_IN_WORLD`、`ABSENT_IN_RECORD`、`AMBIGUOUS`、`REDACTED` 和 `NOT_APPLICABLE`。

## P16　公开档案能校准结构，不能代替 Agent 因果实验

公开制度档案可以支持：Authority topology、Relation Schema 变化、Effect、challenge、reopen、protective no-deal、证据门和数据派生。

它通常不能直接支持：

```text
Agent-mediated causality
subjective explain-back and free recognition
comparable net coordination surplus
complete private pre-state
population frequency
```

因此公开案例是 `R7-0A archival calibration`，不是 `R7-A live Principal experiment`。

## 研究主张升级规则

一项主张升级至少需要：假设与适用域、竞争解释、负控制、可重现入口、现实或历史任务、Design Delta、来源资格和未证明内容。样本数量、文件数量、测试通过率与术语完整度都不能单独完成升级。
