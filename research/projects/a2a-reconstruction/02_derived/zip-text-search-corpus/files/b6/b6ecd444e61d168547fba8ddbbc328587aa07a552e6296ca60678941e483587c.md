# 通爻 A2A 第五阶段本地实验室返回摘要

## 1. 最出乎预期的发现

最承重的新变量不是一个协议对象，而是执行与边界适配器对“真实动作/真实资源”的绑定。

一次真实 Git 调用同时出现 `HEAD.lock` 权限失败、`Switched` 成功文本和外层退出码 0，
但分支没有变化。后续边界实验又连续两次“任务与签名都成功、私有读取也全部成功”：
macOS 将 `/var/...` 解析为 `/private/var/...`，未规范化的策略路径根本没有命中。

这迫使当前体系增加两条工程不变量：

1. 一个 Effect claim 必须对应一个动作自己的执行状态、权威后置条件和独立 Acceptance；
2. BoundaryPolicy 只有绑定 canonical resource identity、实际 enforcement primitive、
   runtime principal 并通过对抗 probe 后，才是边界事实。

## 2. 真实环境中发生了什么

- 真实工作区：`/Users/nature/通爻协议研究`，macOS 26.6 arm64。
- Git：仓库无任何 commit；所有基线材料是用户未跟踪文件。
- 隔离：建立 unborn `research/towow-r5-20260724-local` 分支，没有 stage/commit/push。
- 当前 Agent：`/root`，模型 `gpt-5.6-sol`，reasoning `xhigh`。
- shell 默认受 seatbelt、网络禁用；CodexPro 是本地桥，不提供模型或 Agent 执行。
- 只读 smoke 成功；受保护源文件聚合哈希研究前后均为
  `5f2eac0be138a3927ca6e22ed66ec7d23f86b64e0353c48789fdf75a2813a040`。
- 六次命令级批准仅用于 Docker 只读查询和本地 sandbox-exec 实验；没有容器、服务、
  远程资源或生产效果。

## 4. 哪些结构产生了真实增量

- `Effect / Verification / Acceptance` 的区分改变了真实 Git 失败的判定。
- 作用域化 Capability Claim 避免把“二进制存在”误写成“当前 Agent 可执行”。
- approval path 未改二进制或目标，却真实改变了 Docker/socket 与 sandbox policy 的可达性。
- exact-content signature/hash 让签名后的篡改进入 `invalid_producer_signature`，没有被接受。
- OS policy 在 canonical literal-file 范围内阻断了 coordinator 和 cross-subject 读取。

## 5. 哪些结构没有价值或应降级

在 L1 临时目录任务中，急切物化 CoordinationCase、ObjectiveVersion、Recognition、
Authority、Commitment、Settlement 等完整链条没有比最小 effect/verification/acceptance
合同多发现错误，序列化字节为 3.64 倍。

这不是全局删除结论。它支持这些对象只在成为真实决策变量时显式存在；其余作为派生视图或
风险激活状态。

## 6. 能力形成证据

形成前，同一机器上的 Docker daemon query、sandbox child 和 canary deny 在默认 seatbelt
下全部不可达。三个 exact approvals 后三者全部可达。任务、二进制和机器未变。

这是实际行动空间扩张，但价值来自权限/执行路径，不是模型自动创造能力，也不是通爻独占。
三次审批注意力必须计入成本。

## 7. 主权 A2A 真实性

成功 attempt 3 使用 sandbox-exec、独立进程、Ed25519 attribution、refusal/tamper 路径，
并阻断声明的 canary、私钥、policy 和 packet baseline 读取。

最终只标记 `partial_sovereign_literal_file_fixture`：

- 角色共享同一 OS identity；
- trusted test controller 全知；
- literal rules 不自动保护未来新增私有文件；
- 未测试 directory listing、symlink/rename/TOCTOU hostile bypass；
- 角色是 deterministic Python，不是强模型 Agent。

attempt 1/2 的边界旁路完整保留，不能由 attempt 3 的成功覆盖。

## 8. 目标与价值保真

本轮没有把用户原目标缩成“完成 smoke”或“做一个 Demo”。四轮依次检验证据闭合、effect
语义、能力预测和边界净值，并在失败后继续修复/降级。

实验任务使用真实 v1.1 packet，但不是 canonical Harness 产品任务；因此结论只覆盖当前
workspace/tool-policy 任务族，不能继承“真实 Harness 已验证”标签。

## 9. 成本和 break-even

成功 attempt 3：

- central：247 ms，1 process，任务接受，读取两个 synthetic private canary；
- partial-sovereign：1,123 ms，4 processes，任务接受，声明私有读取为 0；
- 运行时额外成本：约 876 ms、3 processes，process time 4.54x；
- 整轮到成功：6 approval gates、3 lab attempts、27 lab processes、7,664 process-ms。

在本任务没有真实隐私/法律/责任价值时，central 明显更好。只有 privacy/attribution value
高于上述额外时间、进程、审批、策略维护和恢复风险时，bounded path 才有 break-even 理由。

## 10. 独立验证与分歧

CodexPro 做了无预设结论的仓库扫描；独立 verifier 不导入实验 helper，重新计算指标、
schema、证据路径和 Ed25519 签名。结果 `passed_with_warnings`，无 error。

唯一警告：attempt 3 的原始生成 summary 仍使用过强的 `sovereign_a2a` 标签；correction、
run record 和本摘要已降级为 `partial_sovereign`。这不是独立模型复核；共享概念盲区仍可能
存在。
