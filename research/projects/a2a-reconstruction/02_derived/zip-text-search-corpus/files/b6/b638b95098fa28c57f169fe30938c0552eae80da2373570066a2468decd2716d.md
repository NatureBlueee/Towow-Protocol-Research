# Current System Patch

## Object and boundary changes

- Preserve `Effect Gateway`, `Acceptance`, `Capability Claim` and canonical
  readback as closure tools.
- Add an `External Source Report` path distinct from World Command
  confirmation.
- Represent the report as one stable opaque claim entity, commandless
  source-authoritative EventRecords and one stable WorldProjection.
- Keep source state (`adopted/not_adopted/revoked`) separate from epistemic and
  sync state (`source_reported/unknown/disputed`, `in_sync/offline/stale`).
- Treat correction/revocation as append-only source revisions, never mutation
  of old evidence.

## New invariants

1. Producer `completed/PASS` cannot establish consumer adoption.
2. Consumer authority must survive first-response loss and expose canonical
   read-after-write.
3. Abort/cancel is an authoritative monotonic decision.
4. Cross-principal authority delivery includes durable claim/persist/ack,
   recovery and exact replay.
5. World acknowledges only after its complete replayable C2/C4/delta
   postcondition exists and the source explicitly confirms ack.
6. Invalid/private evidence after prior success downgrades current knowledge;
   it cannot leave old success looking current.
7. Source Viewer authority maps to an explicit target Viewer; credentials and
   private Artifact bytes never enter the semantic journal.
8. Reality provenance remains `local_equivalent_real`; no later code path may
   upgrade it to production/external reality.

## Policy location

- source consumer policy and authority live in Allbuddy;
- transport claim/read/ack and replay journal live at the World adapter seam;
- World owns semantic validation and presentation only;
- human/customer value Recognition remains outside both model principals.

## Applicability

Applies to single-host local synthetic sources with a coarse, monotonic,
authorized readback. Does not yet apply to production tenants, multi-host
source stores, real customers, human preference, or unrelated World command
state.

## Claims removed or downgraded

- remove any implication that `completed`, a signed receipt, or a green test
  alone proves Acceptance;
- downgrade “A2A is needed for execution” to “adaptive principal interaction
  can help form the authority boundary; central execution is then sufficient”;
- do not upgrade CC-R5C-01 beyond its one held-out local task family.
