# 上下文路由政策

## 1. 原则：最小充分，而不是最大堆叠

每个 Agent 只加载完成当前 concern 所需的知识。上下文过多会造成锚定、冲突掩盖和注意力稀释。

## 2. 七类上下文包

1. **Core Method Pack**：方法宪法、对象和质量门。
2. **Project Core Pack**：产品定义、不变量、核心对象、已定决策。
3. **Current State Pack**：当前版本、变更集、开放问题。
4. **Concern Pack**：针对法律、HCI、本体、市场等 concern 的专业知识。
5. **Evidence Pack**：本任务直接使用的证据摘录及来源。
6. **Task Pack**：任务目标、范围、产物和验收条件。
7. **Language Pack**：受众、语气、术语映射、禁止表达。

可选：**Negative Pack**，专门记录旧原型锚点、常见误读和禁止模式。

## 3. 路由次序

- 先读 Core Method Pack；
- 再读 Project Core Pack；
- 根据 concern 选择专业包；
- 最后加载最小 Evidence Pack 和 Task Pack；
- 需要输出界面或外部文本时再加载 Language Pack。

## 4. 冲突处理

当两个包冲突：

1. 比较适用范围；
2. 比较版本和有效期；
3. 比较证据等级；
4. 检查是否属于不同语言层；
5. 无法消解时生成 `ContextConflict`，不得自行拼接。

## 5. 记录要求

每次装载必须记录：

- pack id / version；
- 装载理由；
- 用于哪个 concern；
- 是否发现冲突；
- 哪些结论依赖该包；
- 是否因过期降低结论强度。
