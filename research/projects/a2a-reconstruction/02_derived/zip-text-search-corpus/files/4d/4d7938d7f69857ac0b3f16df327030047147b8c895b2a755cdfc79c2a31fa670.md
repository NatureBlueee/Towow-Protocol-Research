# IF-1 · 四动词接口规格 v1.1（已冻结；v1.1为单调加宽小版本）

**层级：** 接口冻结层。三件套（IF-1/2/3）交叉检查已通过，本文为v1.0冻结版。冻结后模块详设不得反向修改本文；发现接口错误走修订体例。
**设计意图陈述：** 四动词是协议在所有部署形态（中心化/超级节点/全分布）与所有实现厚度（薄adapter/微型harness端点）之间的唯一不变量（R19、D-N4）。一切实现差异必须被压在动词语义之下。工程师遇到本文未覆盖的情形时，按此意图外推：**任何选择，以"四动词语义在四个阶段零变更"为最高约束。**

## 0. 全局约定

- **行为体**：`party`（端侧主体）经其`adapter`调用动词；阶段一所有动词由中心代理执行，但报文格式与语义与终态一致（中心是实现，不是语义）。
- **事件接地**：每次动词调用在调用方与（若有）受方的事件日志各落一条不可变事件；事件schema与《中心即课程·埋点规范》E1–E5对应（emit→E1/E2，撮合决策→E3，quest/disclose→E4，crystallize全程→E4/E5）。
- **幂等**：所有请求带`idempotency_key`；同键重放返回首次结果。
- **版本**：所有报文带`protocol_version`与`anchor_set_version`（语义见IF-2）；版本不兼容的错误语义统一为`VERSION_UNSUPPORTED`并携带本端支持窗口。
- **错误分类学**（全动词共享）：`MALFORMED`（结构错）、`VERSION_UNSUPPORTED`、`UNAUTHORIZED`、`QUOTA_EXCEEDED`、`PARITY_INSUFFICIENT`（仅quest/disclose）、`NOT_OFFERED`（请求了未声明的面/等级）、`EXPIRED`、`CONSERVATION_VIOLATION`（仅crystallize承诺通道）、`GROUNDING_FAILURE`（仅crystallize启迪通道）、`ROUND_BUDGET_EXHAUSTED`、`INTERNAL`。错误必须携带机器可读码＋人可读因；不得以静默降级代替报错。
- **记号**：schema用伪JSON表达；`?`为可选；`ref`为不可变内容指针（哈希或URI）。

## 1. emit — 发布/更新信号

**语义**：将本端的画像面或意图探针置入场。两个子型共用一个动词：`emit(kind=portrait)`为持久态（覆盖式版本化），`emit(kind=intent)`为瞬时态（带TTL的探针）。
**请求**：
```
{ idempotency_key, protocol_version, anchor_set_version,
  kind: "portrait" | "intent",
  signal: NAC_Signal,            // 见IF-2；portrait至少含OFFER面，intent至少含SEEK面
  ttl?: duration,                // intent必填；portrait禁填
  scope?: ScopeExpr,             // 传播范围表达（阶段一＝场景ID；终态＝overlay域）
  tibe_digest_ref?: ref          // 意图的T/I/B/E结构化摘要指针（可选，供quest与综合器用）
}
```
**响应**：`{ signal_id, accepted_version, effective_at }`
**状态机（portrait）**：`ACTIVE →(新emit) SUPERSEDED`；旧版本在锚点重叠窗口内仍可被比较（IF-2§4）。**状态机（intent）**：`LIVE →(TTL到/显式撤回) EXPIRED`；撤回为新事件，不删除历史。
**不变量**：
- I-E1 信号体内**不得含原始上下文**，仅坐标、明文头与指针（A2）。
- I-E2 头部声明的面必须在体内全部在场；多声明少给付＝`MALFORMED`。
- I-E3 portrait的每个面携带`provenance_ref`（可重投影出处指针，"坐标是缓存不是真相"）。
- I-E4 emit不产生任何对他方的义务；它是单边行为。
**失败模式与降级**：锚点版本过旧→接收侧按重叠窗口降级比较；窗口外→`VERSION_UNSUPPORTED`，adapter触发本地重投影后重发。

## 2. quest — 最大价值探问

**语义**：粗共振命中后，向目标方请求特定维度/面的增维披露。quest是**拉式**的、**对等的**、**有预算的**。
**请求**：
```
{ idempotency_key, protocol_version,
  match_context_id,              // 由命中事件创建的匹配上下文
  target_party,
  requested: [DimensionSpec],    // 面+锚点区间 或 目标头部声明的命名查询面
  parity_payload: Disclosure,    // 与请求深度等深的自我披露（R21）；深度计算见IF-2§5
  disclosure_grant_ref?: ref,    // 不对称披露授权凭据（J2已裁定：grant非豁免——被探测方主权下的条件化授权，含用途/期限/访问方式/撤销字段；parity_waiver_ref为其废止别名）
  requester_ledger_digest: ref,  // 反向可见性：由协议层从账本生成并签署的请求方摘要（深探量/成交率/利益冲突声明）——服务端附着，客户端零义务，不许自报
  voi_claim?: { decisions_affected, value_estimate },   // 可选，供学习；不作准入
  budget: { round_index, max_rounds }
}
```
**响应**：`{ quest_id, status: DELIVERED | QUOTED(conditions_ref) | REFUSED(typed_reason?) }`——QUOTED为v1.1新增：被探测方开出条件（Disclosure Quote对象），请求方接受后经disclose交付；REFUSED可附类型化拒绝码（不是现在/深度不够/角色不符/用途不明）。
**不变量**：
- I-Q1 **对等律**：`depth(requested) ≤ depth(parity_payload)`，除非附有效`disclosure_grant_ref`。违反＝`PARITY_INSUFFICIENT`，且本次请求的parity_payload不入目标方记录（防白嫖式试探）。
- I-Q2 每个`match_context`的轮数受`max_rounds`硬限；超限＝`ROUND_BUDGET_EXHAUSTED`，上下文转入crystallize或关闭。
- I-Q3 quest不可请求目标头部未声明的面/等级（`NOT_OFFERED`）——可发现性由emit单边定义，探问不能扩权。
**失败模式**：海量quest抽取攻击→对等律使攻击者同速率自暴露＋预算硬限＋后验记账（E4全留痕）。

## 3. disclose — 分级披露

**语义**：对quest的应答，或自愿升级披露。披露等级单调：高等级语义上包含低等级。
**请求**：
```
{ idempotency_key, protocol_version,
  quest_id | match_context_id,   // 应答型带quest_id；自愿型带context
  level,                         // 必须∈本端emit头部声明的披露阶梯
  payload: Disclosure            // 形态见IF-2§5：前缀延长｜面扩展｜T/I/B/E字段｜自由文本ref｜密文句柄
}
```
**响应**：`{ disclosure_id, receipt_ref }`
**不变量**：
- I-D1 **单调性**：同一context内，level只增不减；payload(level_n) ⊇ payload(level_{n-1})的语义包含由adapter保证、由对端可验抽查。
- I-D2 披露不可撤销但可标记`WITHDRAWN_FOR_FUTURE`（已出之物收不回，未来用途可禁止）。
- I-D3 每次披露入双方事件日志；披露深度账本（后验记账）以此为唯一原料。
- I-D4 敏感等级payload可为密文句柄（PSI/FE，O4/O8并行线），动词语义不变。
**失败模式**：内容捏造（深度真实内容假）→不在本动词职责内，由验证轮（crystallize）与执行结果证伪、沉淀降温追责（H6）。

## 4. crystallize — 结晶会话

**语义**：在匹配上下文上开启结晶会话，运行双通道（C9）。
**请求（开启）**：
```
{ idempotency_key, protocol_version,
  parties: [party_ref, ...],     // ≥2；多方与两方同一状态机
  context_refs: [match_context_id, ...],
  mode: "inspire" | "commit",
  portfolio_n?: int,             // inspire模式：候选数（由注意力经济定，默认见详设）
  constraints?: ConstraintExpr   // 硬约束（预算/时限/排除项）
}
```
**会话状态机（冻结）**：
```
OPEN → PORTFOLIO_PRESENTED → { INSPIRED | IGNORED }*          // 启迪通道
INSPIRED →(人选中/改造) VERIFYING                              // 进入承诺通道
VERIFYING ⇄ OBJECTION(typed)*  // 有界轮：综合器重构←类型化反对
VERIFYING → COMMIT_READY → COMPILED(adapter_target) → CLOSED
任意态 →(预算尽/各方弃) ABANDONED
```
**类型化反对（OBJECTION）格式（冻结）**：`{ objection_type: B_NOT_REMOVED | CAPACITY_WRONG | VALUATION_WRONG | CONDITION_INFEASIBLE | MISSING_PARTY, target_edge, evidence_ref?, counter_value? }`——自由文本仅可作附注，不可替代类型。
**候选结构对象**：必须是类型账本对象（IF-3§账本接口引用；守恒/闭合/IR三检查机械执行）；启迪通道候选可带`UNVERIFIED`标签直达人类，但**必须过接地检查**：所引主体与能力在已披露材料中存在出处（`GROUNDING_FAILURE`拦截）。
**响应（inspire）**：`{ session_id, portfolio: [ {structure_ref, grounding_labels, verification_status, novelty_tag} ] }`
**响应（commit）**：`{ session_id, structure_ref, conservation_report, adapter_targets: [CN|WOWOK|Plain] }`
**不变量**：
- I-C1 **双通道分离**：inspire产物不得自动流入COMPILED；中间必经人类的显式选择事件。
- I-C2 **端侧终审**：COMMIT_READY→COMPILED需每一方的显式接受事件；缺一即停。
- I-C3 **接受不是标签**：本动词产生的任何接受事件不得直接进入学习管道；学习只消费执行结果事件（E5）。
- I-C4 催化Agent在会话内只持有综合器与翻译角色；任何"替某方决定"的输出为缺陷。
- I-C5 每个COMPILED结构必须可编译到至少一个执行适配器目标，否则降级标记Plain并显式告知各方"无托管"。
**失败模式与降级**：验证轮死锁（互相反对不收敛）→预算尽转ABANDONED并完整留痕（失败案例是W的负样本，与成功同等入沉淀——但仍仅以执行/放弃的事实形态，不以"谁对谁错"的判断形态）。

## 5. 跨动词不变量（迁移测试基线）

- X1 四动词的请求/响应schema与状态机在阶段一至四**零变更**；每阶段发布前跑同一套契约测试（R19可测形式）。
- X2 任何动词不得要求对端具备特定模型/框架/harness（A3、R18）；能力差异只能表现为头部声明的面与等级差异。
- X3 所有动词事件可重放重建会话全史；审计员仅凭事件流能回答埋点规范§四的五问。
