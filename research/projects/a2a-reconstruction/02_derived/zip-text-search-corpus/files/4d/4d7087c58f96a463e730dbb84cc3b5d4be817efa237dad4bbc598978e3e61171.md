# Run 001 analysis — effect reality and authoritative readback

## Outcome

The semantic separation between `ActionAttempt`, `Effect`, `Verification`, and
`Acceptance` is necessary. It changed recovery decisions in timeout, delivery,
stale-index, and event-log transfer cases. The evidence does **not** support
adding four parallel authoritative objects to Harness: existing domain events,
files, and fresh readback represented the decisive facts in all 17 scored
scenarios once their authority order was made explicit.

The stronger engineering conclusion is:

> keep the four-stage distinction as a reasoning and adapter contract; make
> authoritative readback override terminal labels; add a new durable object
> only when it prevents an error that the current event plus state contract
> cannot represent.

## Preregistered claim results

- `C-AEVA-001-A` — supported. `B0_terminal` made a wrong classification or
  recovery decision in 10 of 17 scenarios, spanning verification-fork,
  escalation-reflow, index-freshness, and the unplanned event-log transfer
  family. Within the four preregistered families it failed in three: fork,
  escalation, and index.
- `C-AEVA-001-B` — supported for this scope. `B1_harness` and
  `T1_explicit_aeva` agreed on all 17 classifications when both were allowed the
  same authoritative readback. No additional error was prevented by creating
  four new top-level records.
- `C-AEVA-001-C` — supported. Timeout-with-complete-verdict changed from retry
  to no-retry; unverified answer delivery remained pending; a raw poller line
  changed from apparent success to rejected effect and then to a canonical
  writer repair.

This is local E3 evidence, not production-current or cross-organization proof.

## Transfer case: raw bytes were not a readable event

The transfer case was registered before editing or execution in
`inputs/transfer_case_preregistration.json`.

Before the repair:

1. `poll_loop` returned `symlinked`.
2. `events.log` contained matching JSON bytes.
3. The existing raw-byte assertion passed.
4. A fresh `EventLog.get_events_by_type(NodeTouched)` returned zero records.

The producer-shaped line lacked writer-stamped `sequence_number`, `timestamp`,
and `record_hash`. The canonical iterator silently skipped it because it did
not validate as an `EventRecord`. The captured red baseline is
`traces/poller-eventlog-readback-baseline-attempt2.json`.

The smallest repair replaced `append_raw_event_line` with
`EventLog.write_direct(EventIntent)`. The writer now assigns the authoritative
fields, preserves active-segment rotation behavior, and makes the event visible
to canonical readers. No new truth source was introduced.

Verification:

- target regression: 1 passed;
- complete poller test file: 5 passed;
- event-log, segment, and raw-accessor regression set: 37 passed;
- Ruff: passed;
- mypy for the changed implementation: passed.

The first baseline capture exited 4 because its pytest path redundantly included
`harness/` while the command already ran from that directory. It never executed
the test and is preserved as `traces/poller-eventlog-readback-baseline.json`;
it is not counted as experiment evidence.

## Counterexample retained: “applied” can precede consumption

The escalation replay contains a useful counterexample to event-name
terminality. In the exec-task redispatch branch,
`EscalationAnswerApplied(resumed=True)` is emitted when the answer is durably
parked for a future fresh session. A separate test later verifies that a fresh
prompt consumes the parked answer.

The durable park is a real effect and a strong recovery guarantee, but it is not
yet proof that a session consumed the answer. The event enum and payload
documentation describe delivered-and-consumed semantics, so the current label
can overstate Acceptance before the subsequent dispatch succeeds. This does
not prove data loss; it shows that current event semantics combine:

- accepted for redispatch;
- delivered to a session; and
- consumed by the intended execution.

Recommended change: retain the current carrier and add or clarify lifecycle
states such as `parked_for_redispatch` and `consumed_by_session`, or narrow the
meaning of `resumed`. A four-object parallel ledger is unnecessary.

## Baseline comparison

`B0_terminal` was cheap but frequently wrong because it treated timeout,
command completion, raw bytes, or a terminal-looking event as the outcome.

`B1_harness` performed as well as the explicit four-stage reconstruction only
when its authority rule was:

1. authoritative state/readback;
2. verified domain event;
3. terminal label or outer exit.

Without that ordering, current labels such as `EscalationAnswerApplied` can
still create false closure.

## State-burden judgment

The tested distinctions are useful; the proposed object count is not yet
justified. Existing `EventRecord`, domain payloads, parked-answer files, index
generation checks, commit sentinels, and verification-fork provenance already
carry the necessary facts. The valuable intervention is better contracts,
field semantics, and readback gates, not duplicated durable state.

## Limits and alternative explanations

- Historical tests encode intended behavior and can share assumptions with the
  implementation.
- The transfer fix was verified in isolated local fixtures, not a live daemon.
- The escalation event may intentionally mean “accepted for deterministic
  future redispatch”; if so, its public schema and consumer language should say
  that explicitly.
- All independent review used the same model family, so it is context-separated
  review rather than model-independent replication.
