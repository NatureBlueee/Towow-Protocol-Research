# Analysis

## Outcome

The third paired replay produced a bounded, signed, OS-policy-enforced flow on
the actual packet audit:

- static capability cards remained `Unknown`;
- one centralized process accepted and read both synthetic private canaries;
- four sandboxed role processes accepted while the runtime coordinator could
  not read either canary, either private key, or the baseline CSV;
- producer and validator could not read each other's canary or private key;
- changing the report after the producer signature was refused as
  `invalid_producer_signature`;
- the honest report and validator verdict remained bound to the exact report
  hash.

The successful bounded-sovereign runtime consumed 1,123 ms across four
processes versus 247 ms in one centralized process: 4.54x cumulative process
time, before pricing six approval gates and two failed boundary attempts.

## Failure and repair chain

Attempt 1 accepted the task but every privacy probe was allowed. This invalidated
the predeclared sovereignty gate even though signatures and tamper refusal
worked.

Attempt 2 replaced directory `subpath` rules with literal file rules and added
private-key probes. Reads were still allowed. The remaining difference was
resource identity: macOS exposed temporary paths as `/var/...`, while the
sandbox kernel matched `/private/var/...`.

Attempt 3 canonicalized the temporary root before compiling the same literal
rules. All declared-file probes changed from allowed to denied while task,
roles, data, and signatures remained unchanged. This paired intervention
supports path identity as the failure cause. It does not isolate whether a
canonical `subpath` rule would also have worked.

## Theory change

`BoundaryPolicy` text is not the boundary. The enforceable object is closer to:

```text
policy intent
× canonical resource identity/namespace
× compiled enforcement primitive
× runtime principal
× adversarial read/write probe
```

This should remain an implementation invariant/evidence requirement rather than
a new protocol fact object. A successful policy parse or one canary test at a
different path is not transferable boundary evidence.

## Why the result remains partial sovereignty

The final policy denies a declared finite set of files. It does not
automatically cover a new file later created in a private directory, and
directory-listing confidentiality was not tested. All roles also share one OS
identity, and a trusted omniscient experiment controller creates their worlds.
Therefore the final classification is
`partial_sovereign_literal_file_fixture`, not a general sovereign private
world or production A2A.

## Net value

For this audit, centralized execution is plainly better when disclosure has no
value: same accepted result, one process, 4.54x less process time, no approval
or boundary-maintenance burden. The bounded-sovereign path buys two things the
central path lacks:

1. runtime coordinator non-access to declared private files;
2. signed attribution and post-signature tamper refusal.

Its break-even condition is qualitative because the task has no real legal or
organizational privacy value:

> Use the bounded path only if privacy/attribution value exceeds roughly
> 876 ms additional process time, three additional runtime processes, approval
> attention, and policy maintenance/recovery risk.

No such value was established here, so this run does not support defaulting
ordinary local research tasks to sovereign A2A.
