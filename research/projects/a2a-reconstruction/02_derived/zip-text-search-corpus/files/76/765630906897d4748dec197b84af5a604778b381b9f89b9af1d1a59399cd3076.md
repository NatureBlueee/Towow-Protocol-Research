# 证据与因果合同

## 1. 重大主张需要的证据

任何声称“互动形成了新能力”的结果，必须能够回到：

- 互动前的状态、可达路径和失败原因；
- 各主体的真实边界、工具、资源、权威和目标；
- 实际模型、版本、Prompt、Agent SDK 和工具；
- 全部关键消息、动作、拒绝、Unknown、反条件和状态变化；
- 新形成条件的现实 Witness；
- 目标域采纳和有权 Acceptance；
- 关键条件或互动的消融；
- 静态、中心或 Harness+human 基线；
- 原始目标价值保留；
- 成本、等待、人类介入、披露、返工和恢复；
- 任务/环境/时间留出结果；
- 失败和相反证据。

模型语言判断本身不能证明能力形成。

## 2. Formation Episode

每个承重 episode 至少记录：

```text
Pre-state reachability
Initial objective and value dimensions
Private worlds and boundary policies
Candidate next actions considered
Chosen information/formation action
Resulting state delta
Evidence / Witness / Defeater
Shared arrangement changes
Recognition / authority changes
Post-state reachability
Target adoption and Acceptance
Counterfactual removal result
Costs and value
Design Delta
```

## 3. 因果区分

必须区分：

- 原本存在但未被发现；
- 通过互动形成的新条件；
- 新工具或更强模型单独带来的收益；
- 人工兜底带来的收益；
- 目标降低；
- 语言重述；
- 任务分配；
- 真正联合能力。

若关键条件来自新工具、授权、伙伴或人工帮助，应通过消融或配对重放判断它是否是必要或显著贡献因素。

## 4. 目标完整性

所有物质性目标修改必须保留：

- 原始目标；
- 新目标；
- 每个价值维度保留和放弃的部分；
- 新目标是临时阶段还是最终接受结果；
- 继续接近原始目标所需条件；
- 精确版本 Recognition。

完成缩小目标不能自动计作原目标成功。

## 5. 能力 Claim 的前瞻性

能力 Claim 必须在 holdout 执行前冻结。形成后成功记录为 formation evidence，不得回填为形成前预测命中。

至少记录：

- Environment Fingerprint；
- Operational Domain；
- Preconditions；
- Guarantee；
- Known Defeaters；
- Validity Window；
- task-family / version / environment / time holdout。

## 6. 证据可搬迁性

返回包必须从任意目录解压后：

- 相对路径可解析；
- checksum 可验证；
- Schema 和依赖包内可用；
- 关键实验可重算或重放；
- Claim—Evidence 引用闭合；
- Git、模型和环境事实有明确来源。

## 7. 发现分类

每项重大结果必须分类为：

- `repo_specific_defect`
- `transferable_design_principle`
- `mechanism_evidence`
- `core_theory_change`
- `product_design_delta`

不得把每个代码缺陷升级成理论，也不得把理论变化隐藏在修复日志里。
