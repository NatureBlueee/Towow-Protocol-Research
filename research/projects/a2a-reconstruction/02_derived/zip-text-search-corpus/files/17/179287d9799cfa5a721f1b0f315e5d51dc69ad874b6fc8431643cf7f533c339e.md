# Allbuddy Implementation 03 — Recoverable Authority Delivery

## Implemented local source interface

- ProductShell 在 run 前生成 non-secret operationId；
- server 通过 HttpOnly SameSite cookie 绑定 synthetic consumer session；
- reference 由 session + operationId 确定性派生，prepare retry 不产生第二事实；
- record phase：prepared → artifact_persisted → decided；
- review/adopt/recover/postcondition 均由 session + operationId 恢复，不依赖 mutation response secret；
- ProductShell adoption 后调用独立 canonical postcondition route，才显示 completed；
- adoption/revision 与 World outbox event 保存在同一 atomic record；
- World 用独立 bearer claim outbox，先持久化稳定 eventId，再 ack；
- claim lease 过期可重取同一 delivery；ack 丢失不会产生新 identity；
- revision/revocation 进入真实 authenticated route，使用 expectedRevision CAS 与 update operationId dedupe；
- external readback 只含 reference、issuer、policy、state、revision、observedAt。

## Post-review v4 discriminator

Open re-review 03 defeated this version as a freeze candidate. The source was
then narrowed again without changing the claimed production boundary:

- the HttpOnly consumer session is established before `/workspace/run`;
- an uncertain network response retains the pre-existing operation marker;
- explicit abort removes pending adoption intent and reload cannot adopt it;
- same-host orphan process locks are reclaimed only when the recorded PID is
  no longer alive;
- prepare replay binds the full request digest;
- revision replay validates original state and expected revision, returning
  the original revision result;
- readback binds the exact revision named by the claimed delivery;
- active leases cannot be reclaimed by a same-named process, and ack requires
  a lease-specific token excluded from durable semantic delivery.
- source records use fsynced temporary files plus atomic link/rename and
  directory fsync; this narrows torn-write risk but is not a power-loss or
  cross-host durability claim.

Verification after these changes:

- typecheck and target lint passed;
- 8 Vitest files / 46 tests passed, including 64-way cross-process probes,
  orphan-lock recovery, exact replay, historical revision read and active
  lease exclusion;
- real desktop Chromium + HTTP route episode passed in 31.2 seconds, including
  first-response-loss recovery and explicit abort after server-side prepare.

Redacted evidence: `allbuddy_v4_e2e_redacted_readback.json`.

This remains a candidate pending a fresh open source-freeze re-review and an
actual independent Agent World HTTP consumer.

## Post-review v5 canonical cancel

Open re-review 04 found that browser abort could contradict an already
committed adoption. Both model principals required abort to become a
monotonic consumer-authority revision rather than a client cancellation.

The source now serializes cancel and adoption on the same record lock:

- cancel before adoption commits `not_adopted@rev1`;
- cancel after adoption commits `revoked@rev2`;
- the deterministic cancel operation is idempotent and recoverable;
- an unclaimed earlier outbox entry is marked superseded, never deleted;
- a claimed/acked earlier revision remains, and the correction is appended;
- every delivery includes coarse ordered event/revision lineage;
- historical revision readback remains available through the same scoped
  reader;
- ProductShell retains a cancel marker until canonical cancel readback, shows
  Unknown on failure, and says “曾被采用，现已撤销” after revocation.

The exact adoption-response interception Defeater now passes in real desktop
Chromium. Redacted evidence:
`allbuddy_v5_cancel_race_redacted.json`.

The combined source still awaits a fifth fresh open freeze review. Production
and business-value claims remain unsupported.
