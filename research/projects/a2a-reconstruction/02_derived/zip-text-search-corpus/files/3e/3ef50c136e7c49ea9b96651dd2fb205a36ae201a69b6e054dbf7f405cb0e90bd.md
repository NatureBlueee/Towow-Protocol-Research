# 09 · Agent 行为算法化与 Trace 治理

## 1. 核心命题

Agent 的真实能力不仅体现在最终文本或代码，也体现在它如何经过一系列动作达到结果。

Trace 使以下问题第一次可计算：

- Agent 在什么时候开始偏离；
- 哪些工具调用产生信息增益；
- 哪些动作是重复和浪费；
- 哪个上下文缺失导致错误；
- 哪种任务拆分导致协调成本过高；
- 哪个策略在什么场景下有效。

因此 Harness 应把 Agent 行为视为可以观察、评价、实验和改进的策略系统。

## 2. 不把“路径短”当成唯一目标

较长路径可能代表谨慎，较短路径可能代表漏查。建议评价：

```text
Trajectory Quality =
结果质量
+ 证据质量
+ 安全性
+ 信息增益
+ 可恢复性
- 成本
- 重复动作
- 无必要风险
- 协调损失
```

## 3. Trace 事件模型

至少记录：

- session、task、plan、Agent 和模型；
- 上下文编译版本；
- 观察、推理阶段和决定；
- 工具调用与结果；
- 文件和对象访问；
- 错误；
- 重试；
- 产生的 Artifact；
- Finding；
- 人工介入；
- token、时间和资源；
- 最终验证结果。

不是要求暴露模型私有思维，而是记录可观察行动、输入输出和正式判断。

## 4. 轨迹片段本体

建议识别可复用片段：

- orientation：定位仓库和任务；
- search：搜索信息；
- evidence-chain：验证定义到运行；
- hypothesis-test：提出并验证假设；
- edit-loop：编辑—测试—回读；
- recovery：错误恢复；
- escalation：升级；
- review-loop：审查和修复；
- context-refresh：上下文重编译；
- premature-action：未理解就动手；
- redundant-reread：重复读取；
- wrong-target：在错误对象工作；
- convergence-failure：无法收敛；
- false-completion：错误宣布完成。

## 5. 结果归因

看到失败轨迹后，不应直接说“Agent 不够聪明”。需要区分：

- 模型能力；
- 上下文缺失或过载；
- 工具不可用；
- 权限错误；
- 任务拆分；
- 计划依赖；
- 环境；
- 验证器误判；
- 方案本身错误；
- 随机波动。

一个结果可能由多个因素共同造成，归因应保留不确定性。

## 6. 策略对象

可优化的不是“模型人格”，而是 Harness Policy：

- 何时搜索；
- 搜索多深；
- 何时调用子 Agent；
- 何时升级模型；
- 何时重新编译上下文；
- 何时停止；
- 何时请求人类；
- 何时回流；
- 哪些测试先跑；
- 怎样控制并行和预算。

每个策略有版本、适用场景、假设、指标、风险和回滚。

## 7. 优化循环

```text
Trace 收集
→ 轨迹片段识别
→ 结果与证据评分
→ 问题归因
→ 策略候选
→ 历史回放
→ Shadow 对照
→ 小流量启用
→ 独立验证
→ 晋升 / 回滚 / 保持实验
```

## 8. 反事实与实验

理想情况是在相同或相近任务上比较：

- 不同上下文；
- 不同模型；
- 单 Agent 与多 Agent；
- 不同任务分片；
- 不同工具顺序；
- 不同停止规则。

无法重复真实任务时，可以用历史回放、变体任务和合成故障，但必须说明外部效度限制。

## 9. 防止指标投机

Agent 或调度器可能通过压缩动作数、减少搜索、避免报告问题来让指标更好看。

因此：

- 效率指标必须和结果质量、证据质量绑定；
- 不使用单一分数；
- 监测未报告错误和后续返工；
- 定期人工抽样；
- 使用 verify-the-observer；
- 规则晋升前检查是否改变行为而非只改变记录方式。

## 10. 与 R07 的关系

R07 已经证明了这条路线的可行性：从 transcript 中计算错误率、探路长度、回读浪费和指代纠正等指标，建立越界检测与独立观测校准。

下一阶段应从“几个总体指标”升级为：

- 标准 Trace Schema；
- 轨迹片段识别；
- 上下文和策略版本绑定；
- 失败归因；
- 策略实验；
- 对照和晋升机制。

## 11. 第一版完成标准

选择三类重复任务：修 Bug、跨文件小功能、复杂调查。证明：

- 能稳定识别主要轨迹片段；
- 能区分至少三类失败来源；
- 一个策略改进在对照中改善质量或成本；
- 改进未显著增加漏检和风险；
- 结果可以回放和解释；
- 策略可以快速回滚。
