# Design Method Result

## Pre-research undecidable choice

It was unclear whether to pass data, a receipt, a verifier, or move computation
to the private source; whether consumer and producer acceptance could share an
authority; and whether World needed a Command, signature or central
orchestrator.

## Candidate method

`M-R5C-01 authority_first_countercondition_reduction`

```text
principal refuses authority it does not own
→ local probe creates a Witness or Defeater
→ send only the failing observable/verification condition
→ receiving principal proposes the smallest countercondition
→ remove fields and mechanisms with no real authority
→ freeze authority split before schema
→ implement locally and openly re-review
→ ablate acceptance, authorization, recovery and target validation
```

## How exploration changed it

- initial schema-first receipts added TTL, commitments and signatures;
  principals removed them because no key/rotation authority existed;
- file persistence looked sufficient until concurrency and browser recovery
  probes showed that authority delivery, not state alone, was missing;
- canonical adoption looked sufficient until abort-after-commit showed that
  negative decisions must be monotonic source facts;
- 50 passing World tests looked sufficient until open review showed the ack
  and Viewer postconditions were incomplete.

## Final conditions

Use this method when:

- principals control genuinely complementary private resources or acceptance;
- neither may safely impersonate the other;
- each can execute local falsification actions;
- a narrow observable postcondition can cross the boundary;
- conditions can be removed and replayed;
- a simpler coordinator can take over after formation.

Stop or centralize when:

- authority can be safely collapsed;
- no local action changes the reachable state;
- interaction only restates constraints;
- the target requires human value Recognition not available in the episode;
- repeated probes add no new countercondition.

## Rejected methods

- schema-first generic receipt: encoded unsupported crypto and expiry;
- persistent file = durable capability: failed on concurrency and authority
  delivery;
- browser-shared capability: impersonated World;
- dialogue-only refinement: prior R5.4 negative control produced no adoption;
- sovereign A2A as permanent executor: no advantage after interface freeze.
