# IF-2 · NAC信号格式规格 v1.0（已冻结）

**层级：** 接口冻结层三件套之二。交叉检查已通过，本文为v1.0冻结版。
**设计意图陈述：** 信号格式是异构互操作的唯一锚（R4）：两个互不相识、互不协调的实现，仅凭本格式即可判定"能不能比、在哪些面上比、比到什么深度"。工程师遇到未覆盖情形按此意图外推：**宁可信号自我描述冗余，不可依赖任何带外约定。**

## 1. 信号对象总览

```
NAC_Signal := { header: Header, facets: [Facet, ...], signature?: AuthSlot }
```
信号是自含的：接收方不查询任何注册表即可完成可比性判定与粗筛比较。

## 2. Header（自描述头）schema

```
Header := {
  schema_version: semver,            // 本格式版本
  anchor_set_version: { id, version, overlap_with?: [version,...] },
                                     // 锚点集标识＋版本＋本信号同时可比的旧版本窗口
  party_ref: opaque_id,              // 脱敏稳定主体标识
  facet_directory: [                 // 面目录：声明体内全部面
    { facet_id, role: "SEEK"|"OFFER"|"CONTEXT"|("X-"+custom),
      prefix_len: int,               // 本面实际携带的坐标前缀长度
      encoding: EncodingSpec,        // 见§3
      grounding: "EVIDENCED"|"DECLARED",   // 是否带可重投影出处
      custom_desc_ref?: ref }        // 自定义面必填：语义自述指针
  ],
  disclosure_ladder: [               // 披露阶梯声明：本端愿意走到的等级与各级形态
    { level: int, forms: ["PREFIX_EXT"|"FACET_ADD"|"TIBE"|"TEXT_REF"|"CRYPTO_HANDLE"] }
  ],
  emitted_at: timestamp, ttl?: duration,
  protocol_version: semver
}
```
**面语法约束（C8，机械校验）**：`role`的协议冻结集为SEEK/OFFER/CONTEXT三个**语法角色**；自定义面必须以`X-`前缀并携带`custom_desc_ref`，接收方可忽略不解析（忽略≠报错）。**任何实现把语义类目写进role枚举即违宪。**

## 3. 坐标体编码

```
Facet := { facet_id, coords: CoordBlock, provenance_ref?: ref }
CoordBlock := { dtype: "f32"|"f16"|"q8",      // q8为对称线性量化，携带scale
                values: [...],                  // 按锚点正典序的相似度，长度=prefix_len
                norm: "component_cosine" }      // 语义：每分量为内容↔锚点的余弦相似度，逐分量∈[-1,1]；
                                                // 不做向量级归一化（前缀截断保语义的前提，裁定见IF-3§1）
```
- **正典序**：锚点集每版本发布全序；`values[i]`恒对应该版第i号锚点。禁止稀疏表示（前缀语义依赖稠密正典序）。
- **前缀合法性**：任意`prefix_len ∈ [k_min, K_version]`均为合法信号；`k_min`由锚点集版本声明（初版建议64）。
- **比较语义**：两信号在同面别（SEEK对OFFER为正向匹配对）上比较时，取`min(prefix_len_a, prefix_len_b)`截齐；评分基准为公共前缀上的**均值内积**（含W核变体与上界函数），统一定义于IF-3§1/§3，本文不重复。
- **provenance_ref**：指向端侧可重投影出处（本地事件/文档指针），中心与对端不可解引用其内容，仅用于端侧重投影与审计授权场景（"坐标是缓存不是真相"的格式落点）。

## 4. 锚点版本与重叠窗口

- 锚点集版本发布物：`{ id, version, anchors_ref(密文或受控分发，按C7阶段闸门), canonical_order, k_min, K, overlap_policy }`。
- **重叠窗口**：新版本发布起，窗口期内端侧**双写**（信号同时携带两版坐标，header的`overlap_with`声明）；窗口长度由版本发布物规定，违约（窗口内单写新版）的信号对旧版接收方表现为`VERSION_UNSUPPORTED`，责任在发射方。
- 窗口结束后旧版坐标停止比较；历史沉淀经provenance重投影迁移；**参数化沉淀（W、路由反射）的迁移程序见M5详设**，本格式仅保证案例级沉淀的可迁移性。

## 5. 披露深度度量（对等律的机械基准）

对等律（I-Q1）的`depth()`按本节计算，全网统一：
```
depth(payload) := (level, bits)
level := payload所属披露阶梯等级（主序）
bits  := 同级内的信息量代理（次序）：
         PREFIX_EXT: 新增坐标分量数
         FACET_ADD:  新增面的prefix_len
         TIBE:       已填充槽位数×槽位权重表（T=1,I=1,B=2,E=2）
         TEXT_REF:   解引用后内容的token数（封顶计数）
         CRYPTO_HANDLE: 等级值本身（密文不计bits，按级对级）
```
比较规则：先比level，同级比bits；`requested`的深度按"若如实应答将达到的深度"预估，由请求方声明、应答方校验。**争议时以应答方计算为准**（被探测方主权）。

## 6. 体积预算（传播经济性）

- 粗信号（单面64前缀、q8）目标 ≤ 1 KB 含头；全信号（双面512前缀、f16）目标 ≤ 8 KB。
- 任何实现不得以压缩为由破坏正典序或前缀语义。

## 7. 示例（园区·设备闲置方）

```
header: { schema_version 1.0, anchor_set { id:"twy-cn", version:3, overlap_with:[2] },
  facet_directory: [
    { facet_id:"offer-main", role:"OFFER", prefix_len:256, encoding:f16, grounding:EVIDENCED },
    { facet_id:"seek-main",  role:"SEEK",  prefix_len:64,  encoding:q8,  grounding:DECLARED },
    { facet_id:"ctx-park",   role:"CONTEXT", prefix_len:64, encoding:q8, grounding:DECLARED } ],
  disclosure_ladder: [ {1:[PREFIX_EXT]}, {2:[FACET_ADD,TIBE]}, {3:[TEXT_REF]} ] }
facets: [ … coords … , provenance_ref: evt://party-local/0193f… ]
```
读法：该方以256维供面参与精排、64维求面参与粗筛；愿意走到第3级文本披露；供面有据可查、求面为自述。

## 8. 与IF-1/IF-3的交叉引用

- IF-1的`DimensionSpec`＝`{facet_id, [from_idx,to_idx)} | named_level`，区间语义以本文§3为准。
- 比较得分与聚合封闭性的契约（含W折叠、包络上界）由IF-3定义；本文仅保证其输入对象的良构性。
- 启迪通道的接地检查（IF-1 crystallize的GROUNDING_FAILURE拦截）以本文`grounding`字段与provenance_ref在场性为机械判据之一。
