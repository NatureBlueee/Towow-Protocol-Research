# 公开现实证据后的理论修订 v0.5

## 0. 修订原则

本轮没有用公开案例“证明通爻有效”，也没有因为案例出现新术语就扩张本体。公开档案承担三个作用：

1. 检查现有理论是否能无损描述现实制度过程；
2. 寻找会迫使正式命题和系统门发生变化的反例；
3. 识别仍然只能由真实 Agent/Principal 前瞻实验回答的问题。

## 1. 第一项修订：从行动空间扩张转为合格空间构成与修订

v0.4 的形成理论虽然写了“改变可达行动集合或合法条件”，论证和实验仍然明显偏向“创造一条新路径”。首轮十个公开案例显示，现实价值至少同等频繁地来自关系转化和保护性收缩。

- Microsoft–Activision 的新结构不是简单降价，而是把非 EEA 云流媒体权利移出交易边界并转给 Ubisoft；
- Meta–Giphy 已完成所有权变化，仍因外部竞争权威而被重开并要求剥离；
- Sainsbury’s–Asda 的有效处置是不成交；
- Deloitte、Safal 和 Walsh 采购争议中，原先可授标/已授标的路径因能力依赖、验证或实体授权问题失去资格。

因此研究对象正式改为：**构成并修订合格联合行动空间**。形成不再与“更多行动”绑定，而与“更真实的资格边界”绑定。

## 2. 第二项修订：Effect 与 Settlement 之间增加范围语义

历史研究已经区分 `Attempt ≠ Effect ≠ Adoption ≠ Acceptance`，但仍容易把最终状态写成单一 Settlement。监管案例显示，即使双边 Effect 已发生，外部 jurisdiction 和 standing 仍可合法重开关系。

Settlement 现在必须索引：

```text
RelationVersion
JurisdictionSet
StandingSet
ChallengeHorizon
EvidenceState
```

这不是增加根对象，而是修正派生视图的输入。Fieldkit 因此新增 required/covered jurisdiction、external standing、open material challenge、contingency 和 challenge horizon 检查。

## 3. 第三项修订：受影响者与外部 Authority 进入挑战模型

通爻原理论主要关注直接参与关系的 Principal。公开监管材料显示，消费者、竞争者、平台、开发者、员工或公共利益不一定是直接签约方，却可能承受后果；监管或申诉机构可能代表其中一部分利益并改变合格空间。

系统不能把所有人都虚构成直接 Principal，也不能只因双方同意就忽略外部性。当前最小表示为：

```text
affected_stakeholder_class
representation_locus
standing_basis
challenge_channel
applicable_jurisdiction
residual_unrepresented_externality
```

它们进入 RelationVersion/Assertion/Assurance view，不成为新 aggregate root。

## 4. 第四项修订：Authority 是功能拓扑

SEC、CMA 和 GAO 档案都显示，“一家公司/一个机构”内部存在不同的提议、谈判、推荐、批准、执行、见证、采用和接受权。一个签字也可能因为实体歧义或签署者绑定权不足而失效。

因此 Agent Entity 的外部认证必须与具体 authority function、scope、version 和 objective source 绑定。所谓“Agent 代表公司”不足以成为可执行授权。

## 5. 第五项修订：公开来源本身也需要证据治理

公开档案并非天然完整。交易 proxy 通常适合证明正式过程和条款，不适合读取所有私下动机；监管决定适合证明 jurisdiction 和处置，不等于每个受影响者的直接声音；采购争议可以显示同期记录与后设解释的差异，却是争议选择样本。

因此 SourceRecord 需要记录来源角色、同期性、利益激励、对抗检验、交叉支持、删节与 claim-type fit。缺失不再默认等于“世界中没有”。

## 6. 第六项修订：数据派生获得现实支持，但不扩张本体

Meta–Giphy 档案中的第三方材料表明，有限的原始字段仍可能通过聚合搜索、IP 和使用趋势形成战略推论。这支持“使用数据会生产新数据”的结构主张。

但它仍不能证明每次 Agent 调用都需要完整谱系或独立权利对象。v0.5 保持风险触发物化：普通使用记为 event/provenance，高风险持久学习、多方权利或可独立撤销义务才提升治理强度。

## 7. 首轮语料真正支持与不支持什么

十个案例是最大差异、理论压力测试式选择，不是代表性样本。它们支持现实中确实存在：多权威功能、外部 Authority 改变路径、Effect 后挑战、保护性收缩、关系类别转化、数据派生、证据门和身份授权失败。

它们没有直接观察：

- Agent 对关系形成的因果贡献；
- 参与者对精确 RelationVersion 的 explain-back；
- 与优秀人类中介可比的净协调剩余。

因此 C18、C19、C20 必须继续为 UNKNOWN。公开材料的价值是使未来真人实验更少问错问题，而不是使真人实验消失。

## 8. 对系统设计的直接修改

v0.5 已落实以下 Design Delta：

1. P4 改为 qualified-space revision；
2. Relation Schema 显式覆盖 standing、jurisdiction、challenge 与 Settlement scope；
3. Fieldkit 对这些规则变化默认判 material；
4. compile readiness 增加 jurisdiction/standing/challenge gate；
5. 引入 `READY_WITH_CONTINGENCY`，避免把所有开放挑战都粗暴等同为停止；
6. Assertion provenance 增加来源资格；
7. 公共档案适配器与可重算案例语料进入发布包；
8. 不增加新的 aggregate root。

## 9. 下一步不是继续堆案例数量

下一阶段公开研究应按“能否反驳当前命题”扩展，而不是只追求 N：

- 增加法院争议、联盟终止、技术许可、监管沙盒和标准组织历史；
- 为选定案例做第二编码者复核，估计维度级一致性；
- 对 3–5 个过程丰富案例进行 transcript/document-level shadow reconstruction；
- 构造同权限中心/优秀中介的反事实表示，判断哪些信息和权威真的不可折叠；
- 选择能校准参与者负担、explain-back 和净价值测量的公开访谈数据。

当公开材料不再产生新的 Design Delta，而只重复已知结构时，应停止扩充，把研究资源转回最小 live Principal 实验。
