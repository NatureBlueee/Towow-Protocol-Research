# 20　跨实验综合：稳定结论、被限定主张与系统 Design Delta

## 20.1 当前最稳定的形式与设计结论

综合理论、实验和公开历史，以下结论目前具有最高稳定性：

### 静态表示不普遍完备

开放任务中的行动空间会因工具、伙伴、授权、学习和任务重构而变化，任何固定 profile 都只能承担受限任务族中的投影。设计上，profile 用于提名，任务相关边界用于资格化。

### 当前不可行不等于全局不可行

一个候选被本地 Oracle 拒绝，可能暴露缺少的条件、工具、伙伴或执行位置。PFE 必须把 Unknown 和 Countercondition 转化为形成动作，而不是把所有拒绝当成永久失败。

### 可达性不推出能力、可靠性或接受

能够运行一次不等于可承诺；工具成功不等于 Effect；Effect 不等于 Adoption；Adoption 不等于 Acceptance。系统必须保持成熟度和效力链。

### 概率与权威正交

模型可以高置信地错，也可以正确但无权作数。选择性执行、Mandate、Evidence 和 Authority 必须同时存在。

### 单体能力不推出联合能力，联合能力也不等于各方责任闭合

高阶互补可能创造新路径，但必须同时闭合资源、权威、Effect 和对外责任。

### 稳定部分应编译，异常部分应重开

持续智能协商不是默认最优。零漂移与标准任务中，确定性机制更低成本；关系变化时只重开受影响子图。

## 20.2 获得限域机制支持的主张

以下主张已经获得明确但受限的机制证据：

- 交互式边界在合成凸/线性世界中可减少披露并保持可行性；
- 本地贡献列在隐藏模式团队构成中优于公开 profile；
- 风险门能够降低被建模错误，但可能牺牲覆盖率；
- 原子预留可以消除生成器内的共享预算超卖；
- 目标域 readback 能修正真实仓库的终态误判；
- Authority-first probe 与 countercondition 能在技术域内形成新可运行路径；
- 收敛本体能保留给定查询而减少顶层对象；
- materiality + dependency closure 能在有界模型中避免全局重开；
- 版本化权威图能保留公告和覆盖式单状态丢失的结构。

这些结论不能直接外推为真实用户价值。

## 20.3 被后续证据限定或推翻的主张

### “多轮 A2A 自然创造新能力”

R5.4 只证明更丰富的规范表达。能力形成必须有可达路径变化、现实 probe、资源/授权变化或 Effect 证据。

### “主权 A2A 优于中心化”

R5 的 4.54 倍开销、标准任务旁路和公开制度负控制表明，中心化常是系统必要组件。正确命题是：权威和信息不可无损折叠的局部需要主权机制。

### “一次形成成功证明能力”

R5.2 能力 holdout 未通过预注册门槛，说明资格化、恢复和 freshness 必须长期维护。

### “NAC 是通用语义基础”

NAC 保留为发现入口和多视角索引，不再承担开放世界本体。

### “软件仓库或进程可作为完整 Principal”

技术域可以拥有状态与局部 Authority，却不具备人的价值认领、法律责任和长期接受。R5C 因此被限定为技术权威域证据。

### “Relation Schema 七维已经完备”

58/58 映射只说明当前编码无残差，不排除编码者吸收偏差。七维是当前最简操作化候选，不是已证完备本体。

## 20.5 当前统一理论的最简表达

可以把本文的核心压缩为一条依赖链，但不能再把链条写成简单流程：

\[
\{W_i\}
\xrightarrow{boundary}
\Gamma_v
\xrightarrow{formation}
Q_t
\xrightarrow{qualification}
Cap
\xrightarrow{recognition/commitment}
C
\xrightarrow{operation}
Eff
\xrightarrow{adoption/acceptance}
S
\xrightarrow{compile/reopen}
CW.
\]

每个箭头都不是自动映射，而是一个需要相称证据、权威和失败处理的门。三个形成循环和五种贯穿语义使该链条可以递归返回。

## 20.6 原创性应如何表述

本文的潜在原创贡献不应写成“首次提出权限、承诺、共同对象或多中心治理”。更准确的表述是：

> 本研究把任务相关主权边界、未预定义行动空间构成、条件性能力资格化、范围化授权与认领、目标世界效力、机制组合、局部确定性编译和 scoped reopen，组织为一套面向 Agent Entity、尤其是超级个体与 OPC 的统一可运行体系，并用正负实验持续改变其设计。

其原创性是否足以构成学术贡献，最终还取决于真实 OPC 结果和与强基线的比较。

# 21　经济模型：系统创造的不是“更多成交”，而是更真实的行动效率

## 21.1 协调成本结构

对事项 \(z\)，总成本至少包括：

\[
C(z)=C_{attention}+C_{disclosure}+C_{search}+C_{formation}
+C_{verification}+C_{execution}+C_{delay}+C_{governance}+C_{recovery}.
\]

其中 OPC 最稀缺的往往是 `C_attention`：创始人必须处理高语境判断、解释、异常和责任。一个系统即使增加模型调用和机器交互，只要显著降低人的高认知时间，也可能有正净值；反之，形式对象越多、每次都要求本人确认，也可能让系统失去价值。

## 21.2 错误成本

需要分别测量：

- **False Commit**：不该成交却承诺，产生违约、声誉、数据或机会损失；
- **False Reject**：本可形成的路径被静态表单或错误诊断排除；
- **Premature Commit**：条件尚未闭合就锁定资源；
- **Late Reject**：在投入大量协调和执行后才发现不兼容；
- **Unauthorized Effect**：越权动作进入现实；
- **Unaccepted Adoption**：目标域采用但主体未接受；
- **Hidden Externality**：第三方承担未被内部化的成本。

真实机制比较不能只看成交数。平台可能高效促成标准交易，却在非标准关系中产生大量 late reject；重型形成可能减少错误，却让简单任务成本过高。

## 21.3 价值函数

本文建议以主体级和系统级两套价值函数报告。

主体 \(i\) 的净值：

\[
V_i = B_i(Eff,Acc) - C_i - L_i - Risk_i - Regret_i.
\]

系统级值不应简单求和，因为权力和外部性可能不可公度。至少应报告：

- 每个必要主体的净值；
- 受影响第三方损失；
- 最差主体或约束违反；
- 总人类高认知时间；
- 真实处置时间 \(T_{truth}\)；
- 后悔和 reopen 率；
- 后续复用收益。

## 21.4 形成价值

一个形成动作的价值可能来自三类结果：

1. **Expansion**：创造新的合格路径；
2. **Transformation**：把不可接受路径改造成可接受路径；
3. **Protective Contraction**：更早排除伪路径或收窄权限；
4. **Clarification**：将 Unknown 转为可判断但不改变可达集。

因此，系统目标不是最大化 `COMMIT`，而是最小化达到真实处置的成本与错误。

## 21.5 长期复用与 Compiled World

首次形成可能昂贵，但稳定关系可以编译并复用。设初次形成成本 \(F_0\)，每次编译运行成本 \(c\)，开放重新协调成本 \(f\)，关系复用 \(N\) 次，Defeater 概率 \(p\)，重开成本 \(r\)。编译净节省为：

\[
Saving(N)=N(f-c)-F_0-pNr.
\]

这说明通爻更可能在有重复价值、边界可稳定且关系可编译的场景成立，而不是一次性、低价值、完全标准的事项。

## 21.6 与平台和人类经纪的真实比较

未来实验必须使用强基线：

- 成熟平台表单与规则；
- 具备完整上下文的强中心 Agent；
- 优秀人类经纪/顾问；
- 人类 + Agent 混合；
- 通爻组合 Router。

比较指标应包括：

```text
真实处置时间
高认知人类分钟
总披露量与敏感披露
关键条件召回
错误 Authority 归属
False Commit / False Reject
现实 Effect 与 Acceptance
30/90 天后悔与 reopen
每次复用边际成本
```

若通爻只比弱聊天机器人好，不足以支持产品和理论价值。

## 21.7 产品价值的可能落点

对于 OPC，最初产品不应是一个“Agent 社交网络”，而可能是：

- 主权 Mandate 与账户边界层；
- 非标准合作的 RelationVersion 工作台；
- 现实 probe、资源预留和 Effect readback 工具；
- 人类经纪的结构化增益工具；
- 将成功关系编译为重复运行的服务；
- 多 Agent 内部角色冲突和授权控制台。

开放市场和 Agent-to-Agent 发现只有在这些纵向闭环成立后才有稳定地基。

# 22　策略行为、权力、外部性与合法性

## 22.1 本地 Oracle 不一定诚实

主体可能隐藏容量、夸大能力、伪造证据、策略性提出 countercondition，或利用系统学习他人边界。廉价自报在早期合成实验中出现高虚假入选率；证据、声誉、验证和风险共担能降低，但不能消除。

系统需要组合：

- 可验证 Evidence；
- 反事实或现实 probe；
- 声誉与历史履约；
- 抵押、托管、保证和保险；
- 随机审计；
- 对虚假声明的补救；
- 不要求主体泄露全部商业秘密的证明形式。

## 22.2 协调器本身的权力

即使数据和权威保持本地，协调器仍可能通过以下方式拥有巨大权力：

- 决定谁被发现；
- 决定问哪些边界问题；
- 选择哪些形成算子；
- 排序候选和证据；
- 定义默认 Relation Schema；
- 控制运行时和 TrustAdapter；
- 通过日志和派生结果积累全局情报。

因此，Router、PFE 和诊断器必须可解释、可替换、可审计；关键排序规则和费用结构应能被主体理解和挑战。所谓“去中心化”若仍由一个黑箱协调器控制注意力和候选，也可能比传统平台更难审计。

## 22.3 平台目标与 Principal 目标

即使授权 scope 精确，若优化目标属于平台而非 Principal，系统仍可能在合法动作内产生偏离。历史合成实验曾显示，在高能力条件下，使用 Principal 目标的机制相对平台目标显著降低后悔。精确数字因原始实现不足被降级，但结构问题成立：

\[
Authorized(a) \nRightarrow Aligned(a).
\]

Mandate 必须同时表达“能做什么”和“为了谁的什么目标”。

## 22.4 第三方外部性

双边同意不保证关系合法或社会可接受。数据合作可能影响未参与的数据主体；平台匹配可能改变劳动条件；自动采购可能把风险转嫁给供应链；OPC 使用 Agent 承诺交付可能让外包者承担隐形加班。

系统必须允许：

- affected-party Standing；
- 外部性声明与政策 Gate；
- 第三方审计或代表；
- 不可由参与双方豁免的硬约束；
- 在 Effect 后提出 challenge 和 reopen；
- 对无法内部化的高风险事项转人工或制度裁决。

## 22.5 代表、理解与操纵

Agent 可能比 Principal 更擅长表达，从而让其输出看起来“更像真正意图”。这既是价值，也是风险。informed recognition 至少需要：

1. 差异摘要；
2. 对 material 条款的逐项解释；
3. explain-back：主体用自己的方式复述；
4. 对模型推断和主体原话的区分；
5. 高风险冷静期；
6. 撤回和申诉；
7. 不因拒绝而施加不当惩罚。

未来实验不能只记录“用户点了同意”，而应评估其理解、后悔和长期一致性。

## 22.6 人类不可替代位置

人类并非永远需要逐项审批。更合理的角色是：

- 定义和修订高层目标；
- 处理价值冲突和新类别风险；
- 授予或撤销 Mandate；
- 对 material RelationVersion 认领；
- 对不可逆高风险 Effect 决定；
- 接受、争议和救济；
- 对模型无法表达的身体、关系和情境作判断。

系统的成功不在于删除人，而在于让人的注意力集中在只有人或相称制度能作数的地方。

## 22.7 安全威胁模型

| 威胁 | 失败方式 | 主要防护 |
|---|---|---|
| Prompt injection | 外部内容诱导 Agent 越权 | Mandate Gate、工具隔离、数据来源标记 |
| Credential theft | 冒用 Entity/Authority | 强认证、短期令牌、硬件或多因素 |
| Scope creep | 长期运行逐步扩大权限 | 版本化 Mandate、过期、差异检查 |
| Evidence spoofing | 假日志/假回执 | 目标域 witness、签名、独立 readback |
| Boundary reconstruction | 多轮查询还原私有世界 | 预算、粒度、速率、用途限制 |
| Resource oversell | 多 Agent 重复承诺 | 原子 reservation |
| Model projection | 把平台/模型目标写成用户偏好 | 来源分离、explain-back、人工 Gate |
| Hidden externality | 双边关系伤害第三方 | Standing、政策门、审计与挑战 |
| Stale compilation | 旧规则继续运行 | Defeater、health check、scoped reopen |
| Collusion/strategic oracle | 多方合谋或虚假 countercondition | 证据、押金、随机审计、裁决 |

# 23　讨论、可证伪边界与下一阶段研究

## 23.1 这项研究目前真正建立了什么

目前已经建立的不是一个经过市场证明的通用 Agent 经济协议，而是：

1. 一套能够区分主体、执行、权威和现实结果的统一语言；
2. 一套从静态搜索转向行动构成的理论；
3. 一套将 Unknown 转为建设性形成动作的机制框架；
4. 一套中心化、A2A、人类经纪和确定性运行的组合原则；
5. 一套能在真实代码和技术域中防止若干具体错误的状态机和参考实现；
6. 一套经公开历史和访谈校准的制度变量；
7. 一套面向 OPC 的可操作纵向闭环和研究仪器。

这些成果已经足以指导真实系统建设，但尚不足以证明整体产品价值。

## 23.2 最深的开放问题

当前决定体系是否最终成立的核心问题是：

> 真实 OPC 是否能够通过范围化 Agent 委托和多机制形成，因果地获得一项强平台、强中心 Agent 或优秀人类经纪无法以更低成本无损产生的联合能力，并在长期保持理解、责任、接受和正净价值？

它包含四个子问题：

- 因果新颖性：是发现了既有路径，还是创造了新路径？
- 不可折叠性：中心机制是否真的无法保持同样权威和信息边界？
- 真实认领：主体是否理解并自由接受精确版本？
- 净价值：形成收益是否超过注意力、披露、验证和治理成本？

## 23.3 可证伪条件

若出现以下结果，本文核心理论应被显著修订或放弃：

1. 强中心 Agent 在保持相同信息、拒绝、退出、责任和 Acceptance 条件下，对非标准 OPC 事项稳定实现同等或更高净值，则主权 A2A 的必要域缩小；
2. 真实参与者无法理解版本化 Mandate/RelationVersion，或其认知成本高于人类经纪，则当前对象化方案失败；
3. 现实 probe 和 countercondition 很少改变可达路径，只增加流程，则 PFE 的中心地位需降级；
4. 版本图不能降低争议、后悔或审计成本，则其价值只剩内部工程；
5. 编译运行频繁因漂移失效，scoped reopen 成本高于持续适应，则两制度架构需改写；
6. 外部性和权力无法由 Standing/政策 Gate 有效处理，则系统不能用于高风险开放协调；
7. OPC 的单一责任根使多 Agent 内部治理比直接人类控制更复杂，且没有相称杠杆收益，则 OPC 不是合适首发域。

## 23.4 下一阶段：强基线历史语料

在真实外部资源有限时，仍可继续：

1. 建立 12–20 个 OPC 历史事项语料，覆盖成交、不成交、反悔、争议和长期复用；
2. 从公开访谈、播客、咨询案例、仲裁/合同争议、自由职业和创作者经营材料中提取过程，而非只用成功故事；
3. 进行双人独立编码，测量 materiality、Authority、Standing 和 outcome-chain 一致性；
4. 对每个截点运行平台、中心 Agent、人类经纪和组合 Router 的离线 replay；
5. 仅在离线结构确有差异时选择真实 live case。

## 23.5 下一阶段：可执行强基线

强基线必须真正执行：

- 平台基线：固定字段、排序、标准合同与争议规则；
- 中心 Agent：获得双方允许的同等上下文和工具，形成统一方案；
- 人类经纪：由有经验的撮合者或顾问处理；
- 组合 Router：允许局部主权 Oracle、probe 和多机制编排。

不允许把通爻实现成完整系统，却用简单表单或弱模型作为对照。

## 23.6 下一阶段：最小真实 OPC 实验

首个真实实验应为低风险、可逆、非标准、可产生真实 Effect 的合作。例如：一个 OPC 客户与一个 AI 服务 OPC 形成 7–14 天只读、无训练、预算封顶、可撤销的数据分析试点。

实验步骤：

1. 分别冻结双方私有前态；
2. 明确各自 Authority Locus 与 Agent Mandate；
3. 运行平台/中心/经纪/组合机制之一；
4. 对拒绝与 countercondition 记录 material change；
5. 执行一个可逆现实 probe，如在买方域创建并撤销只读凭证；
6. 对精确 RelationVersion explain-back；
7. 原子预留预算和时间；
8. 执行受限 Operation；
9. 由买方目标域确认 Effect 与 Adoption；
10. 分别记录 Acceptance；
11. T+7、T+30、T+90 记录后悔、重开和复用。

主要终点：真实处置时间、人类高认知分钟、敏感披露、关键条件召回、错误 Authority、Effect/Acceptance、后悔和净值。

# 24　结论

本文研究的不是 Agent 如何互相发消息，而是智能主体如何在不可折叠主权条件下共同形成现实。其最小对象不是模型，而是一个对外连续、可认证、可授权、可追责，内部却允许人、角色、模型、工具、账户和非数字化判断共同存在的 Agent Entity。其核心过程不是静态匹配，而是：通过任务相关边界构成问题，通过形成算子创造或排除路径，通过 CRA 把候选转为条件性能力，通过 Authority、Recognition、Commitment 和资源预留使其获得规范效力，再通过 Operation、目标世界 Effect、Adoption、Acceptance 和 Settlement 进入现实。

这套体系不把中心化视为敌人。标准任务、公共计算、索引、排期、支付和重复运行都应充分利用中心平台和确定性服务；只有完整信息无法合法集中、权威不能被代行、关系语法未形成或现实变化需要主体重开时，主权 A2A 才具有结构必要性。系统的输出也不以成交为唯一成功：快速而真实的拒绝、保护性收缩和有证据的未知，同样是协调价值。

多轮证据已经建立若干稳定不变量，也留下明确限制。合成机制、真实仓库、跨技术域、公开历史和访谈证明这些结构并非纯粹形而上；但它们尚未替代真实 OPC 的委托、认领和长期净价值。下一阶段最重要的不是增加新术语或更大的合成样本，而是用强平台、强中心 Agent、优秀人类经纪和组合 Router 共同进入真实低风险事项，测量是否真的形成了原本不可达的能力，并把人的注意力保留在只有真实主体能够作数的位置。

主权代理操作系统的最终价值不在于让 Agent 彼此说更多话，而在于：让一个超级个体能够在不放弃自己的边界、责任和真实性的前提下，稳定地形成过去无法独自承担的现实行动。
