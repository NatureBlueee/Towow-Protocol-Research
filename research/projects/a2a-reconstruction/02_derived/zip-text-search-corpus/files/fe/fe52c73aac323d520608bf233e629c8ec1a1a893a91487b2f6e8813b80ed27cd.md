# AI 原生规格读取协议

## 1. 规格节点

每条重要内容 SHOULD 是可寻址的 `SpecNode`，而不是只能依靠段落位置定位。

一个节点至少包含：

- id
- type
- title
- status
- scope
- normative_level
- statement
- rationale
- evidence_refs
- depends_on
- conflicts_with
- supersedes
- affected_views
- owner
- review_by

## 2. 读取优先级

发生冲突时，按以下顺序处理：

1. scope 更直接者；
2. status 为 accepted/current 者；
3. 明确 supersedes 旧节点者；
4. 证据等级更高且更新者；
5. 仍无法消解时生成 Conflict，不得自行融合。

## 3. 原子性

一个节点 SHOULD 只承担一个可独立修改的判断。  
长篇解释可以存在，但它必须引用节点，而不能成为唯一真相源。

## 4. 可否定性

每个重要节点 SHOULD 写清：

- counterexample
- failure_condition
- reconsider_when

只有“永远正确”的原则通常意味着边界没写清楚。

## 5. 正反样例

对容易误读的节点 MUST 同时给：

- conforming example
- non-conforming example

AI 比人更容易顺着形式相似性误推，反例是规格的一部分，不是附加说明。

## 6. 未知是一等对象

未知内容 MUST 使用 `UNKNOWN`、`OPEN_QUESTION` 或 `HYPOTHESIS` 表达。  
不得用模糊语气把未知伪装成已经决策。

## 7. 视图不是复制

PRD、页面、图表、运营手册和市场文本都是 `View`。  
View 必须声明来源节点，且不能反向改变规范内核。
