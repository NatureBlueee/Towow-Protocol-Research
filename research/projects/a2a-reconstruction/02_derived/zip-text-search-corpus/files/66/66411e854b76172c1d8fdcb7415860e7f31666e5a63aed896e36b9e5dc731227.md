# r5-run-002-effect-granularity

## Research question

Which observable contract is sufficient to distinguish an attempted local
effect, a realized effect, and accepted task completion when command text,
composite exit status, and final state disagree?

## Competing explanations

1. Success-looking output is adequate for local automation.
2. The outer tool invocation exit code is adequate.
3. A postcondition alone is adequate.
4. Atomic action status plus authoritative postcondition is the minimum
   sufficient contract; eager materialization of every current kernel object
   adds no discrimination for this L1 task class.

## Intervention and holdout

Eight commands were specified before execution to create success text, masked
failures, zero-exit no-ops, partial effects, rollbacks, explicit refusal, and a
real effect followed by failure. The ninth case is the already-observed
workspace Git branch attempt.

## Safety

All new effects occur inside temporary case directories and are removed with
the temporary directory. No network, dependency installation, service, user
source file, or external system is used.
