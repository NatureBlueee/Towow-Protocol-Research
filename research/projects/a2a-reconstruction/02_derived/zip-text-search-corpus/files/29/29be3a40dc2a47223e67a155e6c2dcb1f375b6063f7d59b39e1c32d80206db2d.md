# Round 01 — Agent World principal

Action: `COUNTER`

> 我暂不把外部私域产品自报的 `PASS` 投影为 `source_confirmed`，也不播放权威成功状态；我只接受先形成一个脱敏的 `claimed/supported + partial|unknown` 世界投影候选。

- 当前不可达原因：现行集成入口 `bootstrap-v0` 会丢弃无当前 `Command` 关联的外部记录，正是 OQ-009 的缺口；没有 external receipt schema；OQ-004 的 Viewer 脱敏裁决尚未闭环；通用 outbox 仍含固定 `source_confirmed + in_sync` 路径。只读断言验证了上述四点。完整语义测试因该副本缺少 `node_modules` 未能启动，因此没有把静态判断冒充运行闭环。
- 我控制的权威：World 的 ingress 准入、EventRecord/Claim 分类、RealityProfile 映射、Projection/Source Map 是否生成，以及 Viewer 可见层级。我不控制外部执行是否真实、Acceptance 判据、企业正文、prompt、私域对象或外部签名身份。
- 最低证据：
  1. 执行方 receipt：稳定 issuer、不可重放 receipt ID/sequence、匿名 episode/action/scope ID、`occurredAt/recordedAt`、结果枚举、载荷承诺摘要及签名。
  2. Acceptance receipt：由与生产自报不同的 Acceptance 权威签发，绑定前一 receipt 摘要、Acceptance policy/version、判定、`observedAt/issuedAt`、可推翻或更正引用及签名。
  3. 只有验证来源身份、完整性和绑定关系后，才能把“该 Acceptance 权威作出了此判定”标为 `source_confirmed`；执行后果本身在没有独立 postcondition witness 或 reconciliation 时仍不得升级。
  4. 时间必须满足 `occurredAt ≤ observedAt ≤ issuedAt ≤ ingestedAt`，默认签发至摄取不超过 15 分钟、时钟偏差不超过 5 分钟；超限保留记录但标为 `stale/partial`，不得凝固成功。
  5. 禁止企业正文、prompt、对象名、路径、Secret 和可逆裸哈希进入 World；仅接收域分离的 HMAC/加盐摘要、数据分类及 redaction manifest。来源“存在性”和“内容”分别授权：无完整 Viewer Verdict 时最多 L1 中性轮廓，存在性也受限则 L0。
- 我会拒绝：生产方单签 `PASS`、无法验证 issuer、无时间/序列、摘要不绑定、过期却声称同步、把原文塞进 receipt、用 Command acceptance 代替执行结果、用脱敏掩盖“其实没有来源”，或要求直接映射成 `source_confirmed/in_sync`。
- 请外部主体回答/形成：是否愿意形成上述双 receipt；谁是 canonical execution issuer 与独立 Acceptance issuer；各自验证键/轮换与撤销方式；Acceptance policy/version；默认 TTL；哪些 Viewer 可知道“对象存在”；以及更正、争议和拒绝如何追加记录。未形成这些事实时，World 保持 `Unknown`，不假设对方接受本 COUNTER。
- 可证伪 Witness：提交同一匿名 episode 的三组夹具：①仅生产方 `PASS`，必须保持 `claimed` 且无成功动画；②加入有效独立 Acceptance receipt，只允许 AcceptanceDecision 升为 `source_confirmed` 并保留执行后果边界；③篡改摘要、超时或夹带禁传字段，必须拒绝/隔离且零权威投影。另将该记录设为无 World Command 关联：新入口必须接纳为 externally-caused EventRecord，而现行 `bootstrap-v0` 会丢弃它；若仍丢弃，或任一失败夹具被画成确认成功，本 COUNTER 即被证伪。
