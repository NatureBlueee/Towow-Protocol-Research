# Current system patch

## Stable distinctions retained

- Process trace, target-domain adoption, and authorized Acceptance remain
  separate witnesses.
- Capability prediction remains frozen before intervention; later negotiation
  cannot be backfilled as a prediction hit.
- Least-privilege central remains the strong default when context, authority,
  responsibility, and failure domains can safely collapse.
- R5.2/R5.3 canonical commit, logical-action, fingerprint, readback, and
  acceptance distinctions remain evidence instrumentation rather than the core
  research object.

## Claims requalified

- Generative A2A is not established by a plausible new contract. It requires
  pre-state unreachability, signed authority, target adoption, counterfactual
  necessity, preserved value, and positive net value.
- Functional context separation is not sovereignty. A trusted root that can see
  both dossiers is a material architectural fact.
- A hidden implementation is an engineering oracle only for its declared
  acceptance, not semantic truth when owner values conflict.

## Objects changed

- Promote `Formation Episode` as a record that can end in refusal,
  non-acceptance, or value conflict.
- Demote message count and contract verbosity as evidence of formation.
- Treat verification-failure remedy, disclosure, and entitlement floor as
  contract fields/policies until they demonstrate an independent lifecycle or
  authority; do not create new top-level objects yet.
- Add `legacy identity policy` to reference-lifecycle acceptance. It needs an
  explicit owner and corpus witness.

## Authority facts

No canonical product authority changed. The research root reconstructed a
counterfactual only in an isolated validation worktree. No branch was merged,
deployed, or accepted on behalf of the product owner.

## Transferable implementation change

When identity moves from locator to composite owner/locator, all of these must
move together:

1. canonical producer shape;
2. ordered event fold;
3. projection/upsert/remove/replay;
4. auxiliary event identity and routing;
5. gate and migration evidence;
6. CLI/owner verification;
7. legacy policy and acceptance tests.

Changing only consumers or a registry creates false closure.

## Defeaters

This patch to the research judgment is wrong if a future paired task with
non-collapsible authority shows:

- the relevant action was unavailable before interaction;
- the interaction creates the missing condition;
- both authorized subjects accept;
- the target domain adopts;
- removal of the critical interaction destroys the result;
- a fair central/static baseline cannot reach it;
- accepted original value exceeds all added costs.
