# 统一术语表（研究交接版）

## Principal

拥有最终价值、责任、拒绝权、Recognition 与 Acceptance 的人或组织。Principal 可以委托，但模型不能自动产生其权威。

## SovereignDomain / AuthorityDomain

由 Principal 控制的软件、数据、工具、策略或业务域。它可以决定局部技术事实，例如是否采纳一条记录，但不自动等于完整 Principal。

## AgentExecution

某一模型、程序或 Agent 在具体时间、上下文、工具和 AuthorityGrant 下的一次可归因执行。应避免用长期拟人身份掩盖授权和版本。

## AuthorityGrant

限定动作、对象、目的、期限、资源和撤销条件的授权。

## RecognitionAction

Principal 对精确目标版本、方案、能力范围或承诺条款的理解与认领。Recognition 不等于 Agent 获得执行权。

## ObjectiveVersion

原始目标及其物质性修订谱系。目标重构必须记录价值保留、放弃和剩余缺口。

## Sovereign World

Principal 的私有世界，包括知识、目标、能力、工具、资源、政策、关系、本地 Harness 和历史。

## CollapseSafe(T)

任务 $T$ 能否安全折叠到一个最小权限中心的条件集合，包括任务、隐私、权威、责任、战略、时效、故障和经济保真。

## Boundary / Behavioral Boundary

主体与外部世界之间任务相关、可交互的有限接口。它可以返回投影、Witness、Defeater、Countercondition、Unknown、Refuse 或局部执行结果。

## BIC

Behavioral/Boundary Interactive Sufficiency 的研究简称，用于表达任务相关的交互边界充分性。它是理论，不必对应单一运行时对象。

## NC / NAC

早期多语义/锚点坐标发现体系。NAC 以公共锚点相似度形成相对坐标和多尺度前缀，当前归位为 Discovery Provider，而非协议本体。

## Discovery Provider

负责提名可能相关主体、资源或关系的可替换方法，例如 NAC、Embedding、图、Agent Card、人工转介。

## Coordination Schema

共享协调语言的版本化定义，包括角色、对象、关系、约束、证据和动作类型。

## SJAC

Sovereign Joint Action Constitution。强调在具体行动安排之前，协调问题的语法、变量和约束本身可能需要形成。相关 Benders/Column Generation 是特定 Solver 路线。

## JAA

Joint Action Arrangement。多方共同编辑、版本化、可分叉的联合行动安排。可作为 SharedArtifactVersion 的重要类型。

## SharedArtifactVersion

候选方案、JAA、边界合同或合同草稿的版本化共享对象。包含作者、哈希、Patch、Fork、Stance 和 Provenance。

## Unknown

尚无足够信息或条件。需要区分诊断型 Unknown（能力已存在但未知）与构造型 Unknown（能力需要改变条件才能形成）。

## PFE

Possibility Formation Engine / 可能性形成理论与策略族。负责诊断缺口、选择探问或形成动作、运行局部实验并更新候选方案。PFE 不维护正式能力事实。

## VOI

Value of Information。衡量一个问题的回答是否可能改变决策，扣除披露、等待和人类注意力成本。

## EVPF

Expected Value of Possibility Formation。衡量一个现实形成动作是否扩大可达行动空间，扣除成本、风险、隐私和人类注意力。

## Formation Operator

能够改变状态或条件的动作，例如工具接入、训练、伙伴加入、授权、任务拆分、风险保障和恢复结构。

## CEGIS

Counterexample-Guided Inductive Synthesis。候选方案经验证器或现实反例推翻后继续修复和迭代。

## CRA

Capability Realization and Assurance / Qualification Pipeline。负责将形成路径通过复现、留出、迁移、容量、组合、漂移和开放复核限定为可依赖的能力 Claim。

## Capability Claim

在明确目标、运行域、环境、前置条件、Authority、恢复、证据、有效期和 Defeater 下的条件性能力主张。

## CapabilityEnvelope

从 Capability Claim、Scope、Evidence 和 Defeater 派生的运行视图。便于调度和审计，但不应维护第二套正式状态。

## AssuranceCase

从 Claim、Evidence、Assumption 和 Defeater 生成的审计论证视图。论证文本不能替代证据。

## Claim

带 issuer、scope、validity 和 status 的限定主张。可以被 Evidence 支持、降级或推翻。

## Evidence

支持或反驳 Claim 的可解释、可搬迁、可重放材料。完整 Evidence Closure 不仅是 checksum。

## WitnessPolicy

某类 Claim 允许的证据来源、时效、一致性、独立性、阈值、Defeater 和接受谓词。

## Defeater

一旦出现会降级、暂停或推翻 Claim 的条件或证据。

## Commitment

经 Recognition、Authority 和资源可行性 Gate 后形成的正式义务网络。

## ResourceReservation

对稀缺资源、预算、容量或唯一席位的正式占用。

## LogicalActionKey

同一现实意图在重试间保持稳定的逻辑身份。

## AttemptID / ActionAttempt

一次具体物理执行尝试的唯一身份和记录。多个 Attempt 可对应一个 LogicalActionKey。

## Effect

目标权威世界中实际发生的状态变化。不能由工具自述或最后退出码代答。

## DomainAdoptionReceipt

目标技术域正式采纳、撤销或拒绝某项输入的权威记录。它不等于人的最终 Acceptance。

## Verification

依据明确规则核验 Claim、Artifact 或 Effect。

## Acceptance

有权 Principal 或业务域对目标价值的接受。技术测试通过不能自动代替。

## Settlement / Dispute

承诺履行后的效力、结算、救济和争议状态。

## Harness

将目标、上下文、计划、Agent、工具、验证、失败恢复和事件回流组织成长期可靠执行的运行系统。它是通爻共同现实形成链的操作底座。

## Context Compiler

根据任务、主体、权限、状态和政策动态生成最小充分执行环境的机制。

## Effect Gateway

所有高后果外部副作用的受控中介，实施权限、幂等、验证、补偿和日志。

## Event Ledger

追加式权威事件记录。事件存在不代表所有消费者已经采纳或接受。

## Compiled World

权威对象和事件的可操作、可视化投影。它让人和 Agent 看见、操作和审计共同世界，但不拥有第二套事实。

## Formation Phase / Compiled Runtime

候选架构：在开放、不确定阶段使用主权、自适应形成；边界和合同稳定后，编译为最小权限确定性运行；Defeater 触发重新形成。

## WoWok

下游可编程信任、权限、确定性执行、托管、结算和争议基础设施。通爻向其输出已形成、已认领和已授权的 Commitment，而不受其当前对象模型锁定。
