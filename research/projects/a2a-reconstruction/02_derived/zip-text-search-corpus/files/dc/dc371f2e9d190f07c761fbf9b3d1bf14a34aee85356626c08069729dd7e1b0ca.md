# 版本、变更与方法治理

## 1. 三类版本

- **Method Version**：方法对象、质量门、路由和产物契约的版本。
- **Project Spec Version**：具体产品规范版本。
- **View Version**：页面、外部语言、运营手册等投影版本。

三者不能使用同一个版本号假装同步。

## 2. ChangeSet 最小内容

- 变更原因；
- 触发证据；
- 修改对象；
- 被替代决策；
- 影响的 requirements、loops、views、claims；
- 兼容性；
- 迁移步骤；
- 回放结果；
- 审查人与批准人。

## 3. 禁止追加式更新

重要变更不得只在文档末尾增加“最新补充”。必须：

1. 修改规范内核；
2. 标记旧结论 superseded；
3. 执行影响扫描；
4. 更新所有受影响视图；
5. 运行回归验证；
6. 生成迁移说明。

## 4. 方法发布准入

方法卡或质量门修改前，需要在：

- 一个历史项目上回放；
- 一个当前项目上试运行；
- 一个不同领域的小项目上迁移验证。

至少两项表现改善且没有关键退化，才可升级为默认规则。

## 5. 单一真相源

Word、幻灯片和网页可以作为发布快照，但规范真相应来自结构化 registries 和版本化 artifact。任何发布物都要标注生成自哪个 spec version。
