# 通爻 A2A 旗舰建设性实验：解释、因果判断与研究结论

## 一句话结论

本实验第一次在两个彼此独立的技术权威域之间形成了一条此前不存在的、可运行、可撤销、可恢复、可留出验证的跨域事实路径：Allbuddy 的本地消费者权威能够在不泄露 Artifact 正文的条件下，把 adopted / revoked / not_adopted 状态交给 Agent World；Agent World 按自己的语义、存储和展示规则正式采纳，并在重启、离线和冲突条件下保持诚实。

它证明的是一项 **跨域技术采纳能力**，不是两个人之间的主权 A2A，也不是人类偏好、责任、商业价值或社会承诺已经成立。

---

## 一、现实语言解释：实验前到底缺什么

Allbuddy 可以生成一个分析结果，界面也可以显示 `completed`。但这只说明生产方或运行时说“我做完了”。它没有回答：

1. Allbuddy 的真实消费者是否采用了这个结果；
2. 采用决定是否持久、可撤销、可恢复；
3. Agent World 能否在不读取客户内容的情况下，独立知道消费者当前报告的状态；
4. Agent World 是否真的把这项状态写入自己的正式世界，而不是只收到一个 HTTP 200 或一段文本；
5. 状态被撤销、来源离线或证据冲突时，旧成功是否会被诚实降级。

直接把完整 Artifact 交给 Agent World 会破坏隐私边界。让 Allbuddy 直接在 Agent World 中写“已采用”，又会让生产方冒充消费者和目标域的权威。

所以实验前真正不存在的不是一条网络连接，而是：

> 一条能把“来源域有权声明的事实”交给“目标域有权采纳和呈现的世界”，同时不转移双方权威的路径。

## 二、三个技术域分别控制什么

### Allbuddy

控制：

- 私有任务和 Artifact；
- 本地产品消费者是否 adopted / not_adopted / revoked；
- 哪些粗粒度状态允许跨边界；
- revision、correction、cancel 和本地恢复。

不控制：

- Agent World 是否接受外部来源；
- Agent World 怎样生成 EventRecord、Projection 或 Source Map；
- 人类是否认为分析有业务价值。

### Agent World

控制：

- 外部报告是否符合自己的来源、语义、隐私和版本规则；
- 是否进入自己的 canonical journal；
- 是否物化为自己的 C2 EventRecord、C4 Projection 和 SceneDelta；
- 来源离线、冲突或证据无效时怎样降级认知状态。

不控制：

- Allbuddy 消费者是否真的采用；
- Artifact 是否业务正确；
- 人类是否愿意承担该结果。

### Root integrator / 本地研究者

控制本地试验、代码集成、故障注入和证据整理，但不应被视为两个软件域的最终业务 Principal。

关键修正：Allbuddy 和 Agent World 是 **技术权威域 / 执行域**，不是完整意义上的 Principal。真正的 Principal 应是能够拥有价值、责任、拒绝权、退出权和最终接受权的人或组织。

## 三、最终形成了什么新路径

最终路径可以写成：

```text
Allbuddy producer result
→ 本地 consumer session
→ canonical adoption / cancel / revoke decision
→ monotonic revision lineage
→ scoped claim / readback / ack interface
→ Agent World 独立进程 claim
→ 只读取六字段粗状态
→ journal-before-ack
→ 目标域 C2 / C4 / SceneDelta 物化
→ 明确 ack
→ fresh restart 复建同一状态与身份
```

真实状态轨迹为：

```text
adopted@rev1
→ revoked@rev2
→ source offline / epistemic unknown
→ adopted@rev3
```

这里发生了两个不同层次的变化：

1. 来源事实变化：adopted / revoked / adopted；
2. 目标域知识状态变化：in_sync / offline-unknown / in_sync。

这一区分很重要。来源离线并不等于来源事实自动撤销；目标域只能说“我现在无法确认其仍然新鲜”。

## 四、消融和反例真正证明了什么

### 删除消费者决定

producer 仍然 `completed`，Agent World 为 0 EventRecord、0 Projection。

证明：producer completion 不能代替 consumer adoption。

### 使用错误 World 权威

没有 delivery，也没有 projection。

证明：传输接口必须绑定明确接收权威，能够连上服务不等于有权读取。

### 来源离线

目标域保留最后来源值，但把 epistemic 状态降为 `unknown/offline`。

证明：来源状态和观察者知识状态必须分离。

### 私有字段或 malformed evidence

不进入 journal，并且已有“当前成功”会被降级为 stale/unknown，而不是继续看起来新鲜。

证明：无效新证据不能只是被忽略；它可能成为旧 Claim 的 Defeater。

### SceneDelta 缺失、ack body 为 false

不能 ack。

证明：transport receipt 不能代替完整目标域 postcondition。

### Viewer 映射错误

不能把来源 Viewer 的授权自动扩展到任意目标 Viewer。

证明：来源读取权和目标呈现权是不同权威。

### 同一 `(reference, revision)` 更换 eventId 或内容

进入 dispute / fail-closed，不产生新的普通事实或 ack。

证明：revision identity 必须稳定，不能靠换 eventId 重写历史。

### fresh restart

目标域从自己的 journal 复建相同 projection 和 EventRecord，不依赖来源重发。

证明：目标域采纳不是临时内存显示，而是自己的持久事实。

### 预冻结 `not_adopted@rev1` holdout

新任务族在同一协议和环境中保持负状态、隐私和 restart identity。

证明：形成的接口在同一局部运行域内具有一次前瞻复用证据，而不是只解释 formation happy path。

## 五、Scoped PASS 的精确边界

这次 PASS 只允许以下表述：

> 一个单机、本地、synthetic consumer policy 下的 Allbuddy 来源，能够通过固定 claim/read/ack 契约，把粗粒度 adoption 状态交给独立 Agent World 进程；目标域能保存、撤销、离线降级、恢复、冲突拒绝和重启复建，并在一个未见负状态任务上保持该语义。

它没有证明：

- 两个真实人或组织形成了共同意图；
- ProductShell 自动采用代表真实人偏好；
- Artifact 正确、有用或有商业价值；
- 跨组织、跨主机、生产 IAM、HA 和真实持久性；
- 不同协议版本、模型和环境可以迁移；
- A2A 唯一创造了架构；
- 主权 A2A 比 matched central formation 更好；
- 一项社会承诺、付款或法律责任已经形成。

## 六、它是否填补了原有三个设计缺口

### 1. 边界怎样形成

**得到 scoped design evidence。**

边界并不是先设计一个通用 receipt 再要求双方接入。实际路径是：

```text
确认谁有权声明什么
→ 各域拒绝自己无权或无法证明的字段
→ 运行能推翻当前方案的本地探针
→ 只传对方下一步真正需要的反条件
→ 删除没有真实 issuer / policy / threat model 支撑的 TTL、签名、HMAC 和 payload commitment
→ 冻结最小可验证边界
```

这支持“边界由权威和反例共同形成”，但没有证明本实验的六字段接口是通用最优边界。

### 2. 缺少的条件怎样被创造

**得到真实局部机制证据。**

实验创造了此前不存在的：

- 持久 consumer authority；
- recoverable session 和 operation identity；
- monotonic adoption/cancel/revoke lineage；
- 独立 World claim/read/persist/ack；
- target-domain journal 和语义物化；
- offline / disputed / invalid evidence 的降级；
- restart replay。

这些是真实代码和状态变化，不是语言重述。

但它们形成的是一项跨域技术能力，而不是人际、组织或商业联合能力。

### 3. 新能力怎样验证和复用

**得到一个窄实例。**

开放复核、反例修复、关键消融和一个预冻结负状态 holdout，支持同协议、同环境、单机 synthetic adapter 的局部复用。

它仍不足以支持跨版本、跨环境、跨主体或商业能力合同。

## 七、因果归属：每一部分到底贡献了什么

| 来源 | 实际贡献 | 不能归给它的内容 |
|---|---|---|
| 静态模型架构 | 一次性提出了大部分概念骨架：生产/采用分离、持久状态、粗 receipt、外部 ingress、隐私和 revocation | 没有形成运行路径，也没有证明这些条件在现实中足够 |
| 主体拒绝与反条件 | 删除没有现实权威的签名、TTL、HMAC、action/scope；明确三层权威；把“不能泄露”变成可执行边界 | 不能证明 A2A 独有地发明了整体架构 |
| 本地现实探针 | 发现并发丢失、response-loss orphan、abort 反转、锁死、revision replay、false ack、Viewer 越权、journal conflict | 探针本身不决定最终价值和权威 |
| 工程实现 | 真正创造持久状态、恢复、outbox、journal 和目标域 materialization | 代码成功不等于主体认领或商业价值 |
| 开放 World 复核 | 在测试全绿后发现五轮未预设 Defeater，防止假闭环 | 同一模型家族与同一根研究者限制了独立性 |
| 消融与 holdout | 说明若干条件在本 scope 中不可缺少，并给出一次前瞻复用 | 不能推出一般协议能力或商业优越性 |

### A2A 互动真正增加了什么

A2A 的可归因增量不是“发明了所有架构”，而是：

1. 让每个域能够拒绝对方无权要求的内容；
2. 把集中分析者容易忽略的本地权威和失败条件带入共同设计；
3. 通过反条件削减过度设计；
4. 形成一个双方技术域都能够执行和否决的边界合同；
5. 使新的现实反例能够重新打开设计，而不是被中心静态 Schema 吞掉。

但静态 baseline 接收了由根研究者综合后的 `PRESTATE + Formation Oracle + baseline repo code`。这本身是一种高质量中心投影。在真实不可折叠世界中，如何得到这份完整摘要正是问题的一部分。因此“静态 Agent 已提出大部分架构”只能证明：

> 当可信中心已经拥有任务充分的跨域表示时，一次性强模型推理可以非常强。

它不能证明真实中心能够在同样隐私和权威条件下自行获得该表示。

同样，least-privilege central 只在接口冻结后被评估执行能力，没有进行 matched formation。因此当前证据不能比较“谁更会形成边界”，只能比较“接口形成以后谁更适合日常执行”。

## 八、对候选运行架构的判断

现有证据支持一个 **限定性的候选结构**：

```text
主权、适应性的形成阶段
→ 边界和权威合同冻结
→ 最小权限确定性运行
→ 监控 Defeater、版本、目标、环境与权威变化
→ 必要时重新打开形成
```

它解决的是：

- 开放设计阶段需要本地上下文、拒绝、反条件和实验；
- 形成后的稳定事务不应永久支付多 Agent 协调成本；
- 权威保留在本地，并不要求每次运行都使用分布式推理。

### 在什么条件下成立

- 目标和验收规则已经稳定；
- 边界接口能够表达所有高频状态；
- 运行域较窄；
- 关键本地动作有 canonical readback；
- 权限、恢复和版本可机械检查；
- 日常 episode 不再需要形成新条件或偏好。

### 什么会重新打开形成

- ObjectiveVersion 发生物质性变化；
- Principal、AuthorityGrant 或 Acceptance policy 改变；
- 新状态无法由冻结 Schema 表达；
- 环境、模型、工具或协议指纹漂移；
- holdout / production monitoring 出现 Defeater；
- revocation、dispute、隐私边界或成本结构变化；
- 确定性运行返回 Unknown、无法恢复或需要例外；
- 新主体进入或旧主体退出。

### 可以集中什么

- 已冻结合同的路由、重试、dedupe、journal、版本检查；
- 最小权限调用；
- 结构验证和监控；
- 固定投影和状态机；
- 回归测试与告警。

### 不能被中心吸收什么

- 原始私有上下文；
- 未委托的本地判断；
- adoption / revocation 的最终本地权威；
- Principal 的价值、责任、退出和最终 Acceptance；
- 私有策略和资源控制；
- 新 Defeater 出现后的边界重新定义权。

### 对主权 A2A 理论的影响

这不是冲突，而是具体化和限定：

> 主权要求权威和不可集中事实保留在主体域，并不要求每一次稳定执行都由多个智能 Agent 持续谈判。

但目前只得到一个局部实例，而且 matched central formation 未运行。因此它应是候选默认优化，不是最终统一架构。

## 九、对 authority-first countercondition reduction 的判断

它不应成为新的顶层引擎。它更准确的身份是：

> PFE 中的一种 formation policy，同时使用协商、CEGIS、边界最小化和 CRA 资格化。

它与现有结构的关系：

- **PFE**：寻找能消除当前不可达条件的下一动作；
- **Boundary**：限制各域只释放有权且任务相关的投影；
- **CEGIS**：候选方案被本地 Defeater 推翻，再修订；
- **协商**：主体可以 REFUSE / COUNTER / UNKNOWN；
- **CRA / Assurance**：开放复核、消融、Claim freeze 和 holdout；
- **Recognition**：本实验没有真实人类 Recognition，仅有 synthetic domain policy；
- **Commitment**：形成了技术接口合同，没有形成社会承诺。

### 属于运行时的步骤

- 查询本地权威；
- 运行本地 reality probe；
- 返回 typed Witness / Defeater / Countercondition / Unknown；
- 更新共享候选安排；
- 形成最小边界接口；
- 触发重新开放。

### 属于研究和资格化的方法

- 不带预设缺陷清单的开放复核；
- condition ablation；
- pre-frozen holdout；
- matched baseline；
- source patch 和 evidence portability。

### 它会在哪些情况下失效

- 权威并非主要瓶颈，中心已能安全折叠；
- 本地主体无法提供可靠探针或 Witness；
- 反条件只增加文字，不改变行动空间；
- 偏好持续变化，无法冻结运行合同；
- 模型错误高度相关，所谓独立复核只是同一先验自证；
- 探针和协商成本高于形成价值；
- 对手利用拒绝和 Unknown 阻塞系统；
- 现实任务要求持续开放生成，无法进入稳定运行域。

## 十、四类结果归档

### Allbuddy / Agent World 特定实现

- 六字段 readback；
- ProductShell synthetic auto-adoption；
- 24h HttpOnly session；
- C2、C4、SceneDelta；
- Viewer 常量和本地 bearer；
- 文件 journal 和具体 ID 规则；
- Agent World AWIR 计数器；
- Allbuddy route 和 React marker。

### 可迁移跨域工程不变量

- producer completion 不等于 consumer adoption；
- 来源事实和目标域 epistemic/sync 状态分离；
- negative decision、revocation 和 correction 是一等事实；
- canonical readback；
- journal-before-ack；
- stable logical identity 与 revision lineage；
- target domain 只物化自己有权认领的事实；
- invalid evidence 可以成为旧 success 的 Defeater；
- restart replay 和 idempotent handoff；
- source read authority 与 target presentation authority 分离。

### A2A 形成机制证据

- 主体拒绝能删除无真实权威支撑的协议字段；
- 局部探针比继续对话更有效地暴露形成条件；
- Countercondition + reality action + re-review 可以把候选边界推进为运行接口；
- A2A 增量主要在 formation，而不是冻结后执行；
- 负面决定和 Unknown 能推动更诚实的联合设计。

### 足以改变统一理论与运行架构的结论

- 软件系统是 Sovereign / Authority Domain，不自动是 Principal；
- authority delivery 是能力的一部分，不只是 transport；
- target-domain adoption 已从理论对象升级为 scoped local mechanism evidence；
- 形成阶段与运行阶段分离获得局部现实支持；
- 运行期 least-privilege central 是冻结 scope 中的合理默认优化；
- PFE 获得一条具体策略：local probe + countercondition reduction；
- CRA 应吸收开放复核、关键消融和 pre-frozen holdout；
- Capability Contract 得到一个真实跨仓、跨进程的技术实例，但不是 human/organizational capability。

## 十一、下一步判断

**判断：先完成现实主体确认。**

原因不是技术实验不重要，而是当前最会改变核心设计的 Unknown 已经从“跨域技术状态能否闭合”转移为：

> 两个真实人或组织的不可折叠世界，能否通过各自 Agent 形成一条此前不存在、分别理解并认领、最终愿意承担的联合行动路径。

继续只在 Allbuddy—Agent World 上实现，会进一步优化一个 synthetic automatic policy，却不能回答：

- Agent 是发现了人的真实潜在意图，还是替人发明了偏好；
- 人愿意把哪些权威委托给 Agent；
- 什么条件足以让人改变“我不能／我不愿意”的判断；
- 形成路径是否减少了真实高认知协调；
- 责任、信任和价值是否成立；
- 新机会是否真的值得成本。

因此，下一项核心研究对象应从软件系统切换到两个真实 Principal。现有仓库、Agent World、Harness 和桥梁全部退回为基础设施、工具和证据层。
