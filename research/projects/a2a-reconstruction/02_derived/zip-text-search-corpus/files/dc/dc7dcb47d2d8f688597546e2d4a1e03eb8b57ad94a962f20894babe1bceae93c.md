# Skill、流程与描述体系的分工

## 描述体系

负责表达：

- 事实；
- 概念；
- 对象；
- 关系；
- 决策；
- 需求；
- 质量；
- 风险；
- 语言映射。

它回答“世界和要求是什么”。

## Skill 体系

负责把一种标准输入转成一种标准产物，例如：

- 历史方案扫描；
- 对象本体建模；
- 闭环设计；
- 状态矩阵生成；
- 页面投影；
- 对外语言编译；
- 冲突扫描；
- 影响分析。

它回答“怎样完成一种认知或设计变换”。

## 流程体系

负责规定：

- 哪些 Skill 在何时运行；
- 哪些可并行；
- 依赖什么；
- 何时进入质量门；
- 失败后修复、重路由还是升级。

它回答“怎样把多个变换组织成一次可靠生产”。

## Harness

负责实际调度、上下文注入、工具调用、并发、重试、缓存和遥测。

它回答“怎样执行”。

这四层 MUST 分离。否则方法论会和某个 Harness 绑死，或让 Harness 在运行时偷偷决定产品语义。
