# 测试与诊断规格 v1.0

**适用：** 召集台×通爻协议合体系统的协议侧全部组件；与 [Z§11.4] 测试标准并行互补（[Z] 管产品与平台通用测试，本文管协议内核的可诊断性）。
**意图陈述：** 本规格的目标不是"测过"，是**可归因**——系统一旦不 work，症状能在分钟级被定位到漏斗段→模块→不变量；定位不了的，有一套预先定义的测量策略把"未知"变成"下一次可知"。未覆盖情形按此外推：**一个不能帮助定位故障的测试，无论覆盖率多高，都不算完成本规格的义务。**

## 一、三条结构性诊断资产（为什么这个系统天生可诊断）

1. **事件溯源可重放**：志（E1–E5）append-only、投影确定性（零温度、版本钉扎）⇒ 任何历史故障可比特级复现。重放是主诊断工具，其余一切建立其上。
2. **编号不变量即断言**：I-Q1、I-C1~5、I-O1~3、I-X1~5、K1~4——每条不变量同时是①设计条款②CI 断言③（廉价者）生产运行时守卫。**不变量违例自动定位责任模块**，这是"马上知道原因"的第一机制。
4. **漏斗即诊断脊柱**：发射→保真→召回→收敛→转化→履约→环增益（00A§11.2 合流表），每段一个 owner 模块、一个仪表。"系统不 work"永远先问：漏斗哪一段掉了。

## 三、诊断脊柱（症状 → 定位的判别树）

入口只有一个问题：**漏斗哪一段掉了？**（运营驾驶舱第二页签即此表。）然后走对应主树：

**树 A · 该被撮合的没被撮合（召回段）**
① 对该案开**差分全扫**（笨对照，见第四节）→ 全扫找得到？
　是 → 路由故障，三个具名原因逐查：STALE 子树（widen_seq 审计）／阈值配置（预算曲线日志）／版本窗口错配（VERSION_UNSUPPORTED 计数）。
　否 → 信号故障：从 provenance **重投影**（确定性审计）→ 坐标不一致＝投影/版本故障；一致＝**信号里本来就没有**——这不是 bug，是品位问题（E-H\* 辖区），修的是锚点覆盖或采访层，不是路由。**"没坏"与"够不着"的区分是本树最重要的产出。**

**树 B · 撮合了但没人理（收敛段）**
接地拦截率异常高？→ 综合器或披露不足。多样性指数塌缩？→ 化妆重复（结构距离度量失效）。都正常？→ 走 M4§7 既有诊断三分支：接地不足／价值密度不足／选品错误——顺序排查，机械冻结至诊断完成。

**树 C · 接受了但执行崩（转化/履约段）**
重放该结构的三灯报告 → 哪个检查器放行了不该放行的？→ K 检查器缺口，直接喂 F4（每个漏检就是账本的下一条规则）；三灯本来全绿而执行仍崩 → 归因执行轨（结果观测点回放，I-X2 保证观测点必在），属现实风险非机制缺陷，入沉淀为负标签。

**树 D · 越用越差（环增益段）**
最近变过什么公共几何？→ **W 版本二分**（I-O1 保证中继零耦合，回滚 W 免费）／锚点版本二分（重叠窗口双写使新旧可并行对照）／隔离区审计（污染标签是否漏进训练集）。三者皆清 → 分布漂移，转 T4 控制图定位漂移起点时刻，再重放该时刻前后差异。

**树 E · 系统级不可用**：归 [Z§11.5] 运维标准（SLO/告警/回滚）管辖；协议侧唯一附加义务：降级进入只读模式时事件日志完整性不受损（后果动作暂停，志不停）。

## 四、笨对照律（本规格的核心设计律）

**每个聪明组件必须随行一个朴素而确定的对照实现，可按案例一键切换。** 聪明件失灵时，笨孪生跑同一输入，分歧点即故障点——这是"马上知道原因"的第二机制，也是差分测试（differential testing）在本系统的制度化。

| 聪明件 | 笨孪生 | 已有出处 |
|---|---|---|
| 包络剪枝路由 | 全扫精排 | M3§8 验收 |
| W 核评分 | 单位阵内积 | M5 激活闸门 |
| 反射路径（未来） | 包络路径 | M3 召回等级 |
| LLM→账本编译 | 模板直出（对照组） | F4 |
| NAC 语义匹配整体 | 规则+标签粗排（B0=[Z] Matching v0） | E-H0 |
| 综合器候选 | 人工撮合建议 | 运营人工推荐通道 |

新增任何优化型组件，笨孪生**先行合并**（演进章程第三节第 4 步）；无孪生的优化不许上线。

## 五、定位不了时的测量策略（把未知变成下一次可知）

1. **重放二分**：全输入皆事件＋投影确定 ⇒ 沿时间轴/版本轴二分重放，收敛到首次出现故障的最小事件区间。
2. **差分对照**：对故障案例逐个开启笨孪生，第一处分歧即嫌疑组件。
3. **假设驱动埋点**：前两步无果 → 把故障写成可证伪假设 → 只加**一个**能判别该假设的度量（无假设不加仪表，防指标蔓延——Q-08 在观测侧的镜像）→ 灰度上线等复发。**因日志全量：多数新度量可对历史事件回溯计算，不必等复发**——"回溯度量"是事件溯源送的礼物，优先用。
4. **事故入库与不复发律**：每次归因完成 → 案例入库（症状→脊柱路径→根因→新增的 T0/T2 测试或脊柱分支）。铁律：**同类故障的第二次出现即流程缺陷**——上次的归因没有转成测试就是违规。

## 六、测试数据治理

金样本集与锚点版本共同版本化（锚点大版本必然使旧金集判读失效，双写窗口内双评）；性质测试用合成生成器（随机盒/随机账本/随机课程），不依赖真实数据；生产数据入测试须过 [Z§11.5]"生产数据不下沉低环境除非脱敏"与 [P-11] 权属条款双闸。

## 七、可观测性接线

trace_id ≡ match_context_id（分布式追踪与协议会话对象一一对应，OTel [S19]）；三张常备表：漏斗表（脊柱入口）、不变量违例表（应恒为零，非零即 P0 级告警）、预算曲线表（J3 口径的"预算可知"落地为可查询对象）。

## 八、本规格自身的可证伪判据

季度**故障注入演练**（GameDay）：从已知故障类型库随机注入 N 类（过期包络、污染标签、化妆重复、阈值错配、版本窗口违约……），盲测值班者沿脊柱定位。指标：定位正确率、定位中位时长。**脊柱定位率不增长的季度，说明事故入库律没被执行**——这是测试体系的测试。
