# PRSE-OS 发展路线 v0.3-dev → v1.0

## M0：交接与基线（现在）

- 包结构、设计历史和 Archive 完整；
- 本地团队可理解层次和边界；
- 离线校验通过。

## M1：Harness 最小适配（2—4 周）

- 七个逻辑钩子可执行；
- MethodEvent 可导出；
- 一个 Skill + 一个 Validator 垂直跑通；
- 召集台盲消费者实验完成。

退出条件：能区分 Channel/Capability/Specification/Execution failure。

## M2：召集台 Reference Runtime（1—2 月）

- 召集台核心节点、对象、闭环和 UI View 全部进入结构化 Registry；
- 变更传播测试可运行；
- Clean-room 原型自动生成并评审；
- 方法健康面板 v0.1。

退出条件：修改一个核心定义后，受影响 View 和 Claim 无静默遗漏。

## M3：第二产品迁移（2—3 月）

选择一个与召集台明显不同的产品，验证方法的通用性。删除只对召集台有效却伪装成通用规则的部分。

## M4：质量与成本实验（3—5 月）

- 对比不同 Agent 拓扑、Context 策略和 Validator 独立性；
- 测量规则带来的质量提升和成本；
- 建立方法卡资格与停用机制。

## M5：开发者体验与规范发布（5—8 月）

- CLI / package linter；
- Registry API 或文件协议稳定；
- 完整示例项目；
- 兼容性与迁移政策；
- 考虑 v1.0 的公开/内部治理边界。

## v1.0 候选条件

- 至少两个异质产品验证；
- 至少两个不同 Harness 可消费；
- 盲交显著降低误解；
- 质量门的净收益得到数据支持；
- 核心 Schema 有迁移和兼容政策；
- 对方法不成立的边界有明确说明。
