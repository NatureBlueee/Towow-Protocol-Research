# 语言架构与语义编译

## 1. 五层语言

| 层 | 目的 | 例子 |
|---|---|---|
| L0 规范语言 | 定义对象、规则、状态、证据 | AcceptanceDecision |
| L1 团队语言 | 协作与运营 | 等待需求方接受 |
| L2 界面语言 | 当前动作与后果 | 接受本次交付 |
| L3 市场语言 | 价值与购买理由 | 让试点交付有清晰依据 |
| L4 公共语言 | 政策、学术、伙伴沟通 | 可验证协作基础设施 |

## 2. 编译链

`Concept / Decision / Evidence → ClaimRecord → AudienceMessage → Back Translation → Approval`

## 3. 共识分层

- 事实共识：我们知道什么。
- 语义共识：我们说的词是什么意思。
- 规范共识：我们决定坚持什么。
- 叙事共识：针对不同受众如何表达。

## 4. 对外主张准入

每条主张必须有：

- capability status；
- scope；
- qualifiers；
- evidence；
- review date；
- forbidden extensions。

## 5. UI 语言准入

UI 文案必须：

- 以用户动作和后果为中心；
- 区分事实、AI 建议和主体决定；
- 对危险动作复述范围与后果；
- 给错误提供恢复路径；
- 不使用超出领域模型的概念。

## 6. 回译测试

另一个 Agent 只看对外文本，尝试回译产品对象、边界和能力。如果回译出的产品比规范内核更强、更自动或更安全，说明对外语言发生漂移。
