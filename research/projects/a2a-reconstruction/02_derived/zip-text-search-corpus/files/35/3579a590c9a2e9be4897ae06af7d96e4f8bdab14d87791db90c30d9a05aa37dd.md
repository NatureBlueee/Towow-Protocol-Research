# Towow Fieldkit v0.5

Towow Fieldkit 是研究“不可折叠权威条件下，关系怎样被形成、重构、收缩、执行、挑战和局部重开”的最小研究仪器。它不是生产协议、法律签署系统、身份基础设施或安全控制。

## v0.5 新增

公开制度档案表明，双边签署或 Effect 不能被直接写成全球 Settlement。本版增加：

- `standing_rules`；
- `jurisdiction_rules`；
- `challenge_rules`；
- `settlement_rules`；
- required/covered jurisdiction gate；
- required/reviewed external standing gate；
- open material challenge 与 contingency；
- `READY_WITH_CONTINGENCY`；
- 编译器不得创造 jurisdictional clearance 或 Settlement claim。

Fieldkit 仍保持六类事实对象的最小内核，不把 standing、challenge、SourceRecord 或 Settlement 提升为新的 aggregate root。

## 它解决什么

一次形成研究最容易失败的地方不是程序崩溃，而是事后无法回答：

- 哪些候选、条件、授权和工具在协调前已经存在；
- Agent 到底得到过什么 Mandate；
- 哪些内容只存在于某方私有世界；
- 一次拒绝、反条件或外部 challenge 是否改变了合格行动空间；
- 各方是否指向同一个精确 RelationVersion；
- 是否真的发生目标世界 Effect；
- bilateral Effect 是否仍受到外部 jurisdiction/standing 的挑战；
- Adoption、Acceptance 和 scoped Settlement 分别成立到哪里；
- 研究者是否把优秀中介的发现、制度规则或事后叙事误写成 Agent 形成。

## 它明确不解决什么

- 加密存储、正式访问控制和去标识；
- 法律身份、签名、Mandate 有效性和合规判断；
- 自动发现全部 jurisdiction 或受影响者；
- 自动裁决现实语义争议；
- 生产权限执行与资产安全；
- Relation Schema 的现实完备性；
- 机制效果、用户接受或商业净价值。

真实参与者材料必须放在另行受控的存储中。`export-redacted` 只排除 `private/`，共享自由文本仍需人工复核。

## 基本流程

### 1. 建立案例和 Authority domain

```bash
PYTHONPATH=. python -m towow_fieldkit init ./case_demo \
  --title "14 天企业 AI 只读试点" \
  --case-id case-demo-001

PYTHONPATH=. python -m towow_fieldkit add-party ./case_demo \
  --party-id buyer_budget \
  --label "采购方预算权威" \
  --authority-root "org:buyer:budget"
```

`party` 表示需要独立产生事实或决定的 Authority domain，不一定是一整个法人，也不等同于软件 Agent。

### 2. 冻结前态和 Mandate

```bash
PYTHONPATH=. python -m towow_fieldkit set-intake ./case_demo \
  --party-id buyer_budget \
  --file ../templates/private_intake.json

PYTHONPATH=. python -m towow_fieldkit issue-mandate ./case_demo \
  --party-id buyer_budget \
  --file ../templates/mandate.json
```

### 3. 建立 RelationVersion

```bash
PYTHONPATH=. python -m towow_fieldkit add-relation ./case_demo \
  --file ../templates/relation_version.json
```

每次 material schema change 建立新版本；参数变化仍应记录事件，但不必重建模式。

### 4. 记录形成、Effect 与 challenge

```bash
PYTHONPATH=. python -m towow_fieldkit event ./case_demo \
  --type REFUSAL \
  --actor buyer_data \
  --relation-version 1 \
  --authority-ref mandate-buyer-data \
  --payload refusal.json
```

推荐事件类型包括：

```text
DISCOVERY_PROJECTION
ASSERTION_MADE
REFUSAL
COUNTERCONDITION
PROBE_AUTHORIZED
PROBE_RESULT
CAPABILITY_PATH_FORMED
STANCE_RECORDED
COMMITMENT_RECORDED
OPERATION_ATTEMPT
EFFECT_WITNESSED
ADOPTION_RECORDED
ACCEPTANCE_STANCE
EXTERNAL_CHALLENGE_RAISED
EXTERNAL_CHALLENGE_DECIDED
DEFEATER_RAISED
REOPEN_TRIGGERED
WITHDRAWAL
DISPUTE
```

### 5. 判断 materiality

```bash
PYTHONPATH=. python -m towow_fieldkit classify-change \
  --old relation_v1_schema.json \
  --new relation_v2_schema.json \
  --current-state FORMING \
  --active-resources source_data pilot_output \
  --active-roles buyer_budget buyer_data provider_business provider_tech
```

`standing_rules`、`jurisdiction_rules`、`challenge_rules`、`settlement_rules` 的变化默认 material，除非领域特定证明能说明其与当前任务无关。分类器是有界辅助，不替相称 Authority 裁决未形式化争议。

### 6. 检查 compile readiness

```bash
PYTHONPATH=. python -m towow_fieldkit compile-check \
  --schema relation_v2_schema.json \
  --state relation_v2_state.json
```

结果为：

- `READY`：当前可达子图可以按已记录范围编译；
- `READY_WITH_CONTINGENCY`：存在 material challenge，但有明确 contingency；
- `NOT_READY`：缺少 Authority、Effect witness、Stance、Mandate、jurisdiction/standing review、reopen 或关键反例仍未解决。

编译只保持既有 Authority、动作、数据权利和 scoped Settlement，不得创建新的 Mandate、Stance、Commitment、Effect、jurisdictional clearance 或 Settlement。

### 7. 验证、指标、裁决与导出

```bash
PYTHONPATH=. python -m towow_fieldkit validate ./case_demo
PYTHONPATH=. python -m towow_fieldkit metrics ./case_demo --output metrics.json
PYTHONPATH=. python -m towow_fieldkit adjudicate ./case_demo --file ../templates/adjudication.json
PYTHONPATH=. python -m towow_fieldkit export-redacted ./case_demo ./case_demo_redacted
```
