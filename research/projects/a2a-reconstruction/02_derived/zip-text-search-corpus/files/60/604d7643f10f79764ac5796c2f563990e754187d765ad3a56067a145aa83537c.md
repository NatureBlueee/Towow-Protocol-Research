# 演进时间线

## A. 召集台 v0.6：蓝图阶段

建立 OPC 产业园、能力入驻、需求发布、项目召集、安全披露、执行验收、结清复盘、运营驾驶舱等主线；同时混入了较具体的页面、技术架构和单一大状态机。

## B. 稳定底子纠偏

用户明确指出：当前任务不是决定自动化和技术选型，而是规定“需要存在什么机制、机制准入是什么、前端必须让结构看得见”。由此提出底层规格工程。

## C. v0.7：对象化与本体化增补

把对象化、本体化上收为语义架构与领域建模，并补入边界化、关系化、生命周期化、政策化、证据化、视角化等同级动作。

## D. 原型冲突处理

面对旧原型，形成“不要继承页面，继承模式；不要继承样式，继承视觉隐喻；不要继承流程，继承闭环证明”的原则。旧原型被降级为设计证据而非蓝图。

## E. v0.8：整体重构

关键纠正包括：

- 产品从“可验证外包平台”重定义为“机会编排与可验证协作系统”；
- 一条大状态机改为宏观主弧线 + 多对象生命周期；
- 卡片从本体降为 UI 投影；
- 事件、审计、证据、活动流分离；
- VerificationResult 与 AcceptanceDecision 分离；
- Agent 有执行身份但不承担最终责任；
- 对等披露改为最小必要、目的限定与条件化授权；
- 固定页面数量改为稳定目的地 + 页面语法；
- 引入 3 秒/30 秒/3 分钟可读性契约。

## F. PRSE-OS v0.1

把“如何做好召集台”抽象为“规格如何被生产”：方法对象、能力模型、Context Pack、Skill、质量门、升级和观测。

## G. AI 原生 v0.2

用户指出未来文档的主要读者是 AI，消费者数量和形态未知。由此引入稳定 SpecNode、包协议、Harness Adapter、Conformance、盲消费者测试，并把 Agent 数量从质量本身降为执行资源计划。
