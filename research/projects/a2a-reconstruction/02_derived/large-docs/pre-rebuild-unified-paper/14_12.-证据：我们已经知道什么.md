# 12. 证据：我们已经知道什么

![图 7：现有证据阶梯与尚缺的 Principal 层。](../figures/fig7_evidence_ladder.png){#fig:evidence width=80%}

## 12.1 形式和理论证据

较强的结论包括：

- 有限静态画像对开放未来任务不完备；
- 概率不能产生权威；
- 候选、能力、Recognition、Commitment 和 Effect 不可等同；
- 有限证据不能无条件保证未观测运行域；
- 开放能力形成包含规划难题，不存在通用完备且保证终止的求解器；
- 双边机制设计中，效率、真实性、自愿和预算平衡不能在所有场景同时完美满足 [@myerson1983]。

## 12.2 合成机制证据

合成实验支持以下机制方向：

- 多方组合问题不能退化为简单两两匹配；
- CEGIS 在可形式化反例下比“验证失败即拒绝”更能同时提高安全和吞吐；
- VOI 与状态改变型形成价值适用于不同 Unknown；
- 校准和风险门可以形成覆盖率—错误率工作点；
- 草稿 CRDT 与承诺串行门需要分离；
- 静态画像、一次成功和永久能力证书会产生系统性误判。

这些实验主要证明“机制可能有用”和“某类失败可以发生”，不能作为现实商业效果估计。

## 12.3 真实 Harness 证据

真实仓库和运行时暴露：

- outer exit、成功文本和 terminal label 可能误判真实 Effect；
- timeout 可能丢失已经完成的 verdict；
- EventLog raw bytes 不等于 canonical event；
- 环境、worktree、PYTHONPATH、temp-root、工具路由会改变能力；
- 能力轴的留出预测仍然很弱；
- least-privilege central 在本地可折叠任务中是强基线 [@r52harness2026]。

## 12.4 真实模型负对照

R5.4 中，静态 Agent 已发现主要源码身份缺陷，固定中心查询已暴露核心价值冲突。多轮 A2A 增加了披露、救济、权益底线和恢复条款，却没有产生被双方接受的新能力或补丁。该结果支持：

- 语言互动能够生成更丰富的规范候选；
- 在可折叠、无干预权、剩余问题是主体价值选择的任务中，A2A 不应被默认使用；
- 不能把更多条款或对话轮数当作可能性形成 [@r54negative2026]。

## 12.5 跨技术权威域形成证据

R5C 首次形成：

```text
consumer authority
→ canonical adoption/revocation readback
→ independent world claim/read
→ durable journal
→ local materialization
→ verified ack
```

并通过撤销、离线、错误权威、私域字段、假 ack、revision 冲突、journal 冲突、重启和同协议负状态 holdout。它支持：

- 来源报告与目标域采纳分离；
- 拒绝和现实探针可以削减过度设计；
- 边界冻结后可由最小权限协调器执行；
- 开放复核和消融应进入资格化。

但它的 Principal 是技术域，不是真实人；静态中心拥有一个高质量跨域摘要；matched central formation 没有运行。因此，它不是完整主权 A2A 的证明 [@r5c2026]。

## 12.6 证据如何改变设计，而不只是增加置信

现有研究的价值不在于测试总数，而在于若干现实结果直接改变了系统：

| 现实结果 | 被否定的旧理解 | 设计变化 |
|---|---|---|
| terminal/exit 与真实 Effect 不一致 | 工具成功可以直接完成任务 | 增加 LogicalActionKey、ActionAttempt 和 claim-specific readback |
| raw JSON 存在但 EventLog 不可见 | 文件中有字节即制度事件存在 | canonical writer 与消费者采纳分离 |
| 返回包 checksum 全过但 Claim 引用 0/29 | 完整性等于证据可用 | EvidenceClosure 增加可达、解释、重放与相关性 |
| 静态 Agent 已找到主要源码缺陷 | 多轮 A2A 天然创造技术方案 | 可折叠任务先采用 least-privilege central |
| 纯谈判产生条款却无可执行路径 | 更丰富文本等于可能性形成 | 形成实验必须赋予现实条件形成权 |
| adopted/revoked/offline/restart 可跨域复建 | 目标域采纳只是理论对象 | DomainAdoptionReceipt 获得 scoped mechanism evidence |
| 过度签名/TTL/HMAC 被本地域拒绝 | 更复杂边界必然更安全 | 权威优先、反条件削减、删除无 issuer 的机制 |
| 软件域闭环不等于人认领 | 技术域可充当 Principal | SovereignDomain 与 Principal 正式分离 |

这张表也说明，建设性系统研究需要理论、实验与工程互相施压：若代码只负责实现理论，研究会越来越自洽而不真实；若实验只修仓库 Bug，研究又会失去元问题。
