# 5. 生成式协调：从 Unknown 到新行动路径

## 5.1 Unknown 的机制类型

同一句“不能做”可能意味着完全不同的现实：

- 能力已经存在，但系统不知道；
- 缺少信息或证据；
- 缺少工具、训练、伙伴、权限、资源、验收或恢复条件；
- 当前任务结构不合理；
- 主体不愿意参与；
- 这是一个必须由 Principal 取舍的价值冲突；
- 对允许的全部变换仍然不可行。

因此，系统不能用一个二元 `capable` 字段处理所有否定。边界响应至少需要表达 `WITNESS`、`DEFEATER`、`COUNTERCONDITION`、`REFUSE`、`UNKNOWN` 和有范围的不可行性证书。

## 5.2 形成动作的统一价值

设当前共同状态为 $s$，候选动作 $a$ 可以是查询、局部探针、传递验证程序、创建工具、请求训练、邀请伙伴、申请授权、修改任务结构、增加恢复条件或停止。动作后的状态为 $s'$。系统选择动作时，应评价：

$$
a^*=\arg\max_{a\in\mathcal A(s)}
\mathbb E\left[V^*(s')-V^*(s)\right]
-C(a)-\lambda_rR(a)-\lambda_dD(a)-\lambda_hH(a),
$$

其中 $C$ 是执行与协调成本，$R$ 是风险，$D$ 是披露成本，$H$ 是人类注意力成本。

若动作只改变信念，不改变世界状态，该式退化为信息价值（VOI）；若动作改变工具、授权、伙伴或环境，它评价的是可能性形成价值。第三阶段的合成实验表明，在“能力原本存在但未知”的世界中，VOI 式查询更有效；在“能力必须通过现实干预形成”的世界中，状态改变动作更有价值。该结果只支持机制区分，不构成通用最优策略。

## 5.3 建设性的形成循环

真正的形成不是先把合同谈完，再让 Builder 实现，而是设计与执行共同演化：

```text
诊断不可达原因
→ 选择最有价值的边界交互或现实动作
→ 在本地主权域执行局部试验
→ 返回 Witness / Defeater / Countercondition
→ 修改边界、角色、工具、授权或方案
→ 继续，直到形成 scoped path 或诚实停止
```

![图 4：从 Unknown 到形成路径的建设性循环。](../figures/fig3_formation_loop.png){#fig:formation width=100%}

R5.4 的真实模型负对照说明，若 Agent 只有语言谈判权、没有运行试验、构造工具、申请授权或改变任务结构的能力，多轮交流主要会产生更精确的冲突描述，而不是新能力 [@r54negative2026]。

R5C 跨技术域实验则给出一个限域的正例：Allbuddy 域和 Agent World 域通过拒绝无权证明的字段、本地现实探针、最小反条件交换、持久 adoption/revocation lineage、目标域 journal-before-ack 和开放复核，形成了一条实验前不存在的技术采纳路径 [@r5c2026]。该路径经历 `adopted@rev1 → revoked@rev2 → source offline/unknown → adopted@rev3`，并在重启和负状态 holdout 中保持 scoped 语义。它支持“现实探针 + 反条件削减”作为一种形成策略，但不证明两个真实 Principal 已经形成联合意图。

## 5.4 参考形成算法

下面的伪代码不是协议公理，而是统一体系当前最一般的运行骨架：

```text
function FORM(case, budget):
    state ← compile_shared_state(case)
    while budget remains:
        if accepted_path_exists(state):
            return QUALIFY(state.best_path)

        gaps ← diagnose_unreachability(state)
        actions ← propose_boundary_and_formation_actions(gaps, state)
        actions ← remove_unauthorized_or_unsafe(actions)
        a ← select_by_expected_solution_gain(actions)

        if a is value_decision or nondelegable_authority:
            return ESCALATE_TO_PRINCIPAL(state, a)
        if a is empty or marginal_value(a) ≤ 0:
            return STOP_WITH_UNKNOWN(state)

        result ← execute_locally_under_boundary(a)
        append(result.witnesses, result.defeaters, result.costs)
        state ← revise_artifact_and_boundary(state, result)

    return STOP_WITH_BUDGET_EXHAUSTED(state)
```

该算法要求两个显式区分：

1. `diagnose_unreachability` 必须区分信息缺口、形成缺口、权威缺口和价值冲突；
2. `execute_locally_under_boundary` 只返回必要 Witness 或反条件，不默认上传完整私有世界。

系统可以在不同任务中替换动作生成器、Solver 和价值估计器。若一个普通中心 Agent 已经拥有任务充分且合法的表示，`FORM` 可以退化为中心规划；若本地权威不可折叠，则动作必须通过主权边界运行。

## 5.5 目标修订的价值守恒检查

任务重构可以创造可行路径，也可能成为制造成功的捷径。对原目标 $O_0$ 和修订目标 $O_1$，系统应保存价值维度向量 $v(O)$，并至少检查：

$$
Retention(O_1\mid O_0)=
\frac{\sum_k w_k\min(v_k(O_1),v_k(O_0))}
{\sum_k w_k v_k(O_0)}.
$$

加权保留率仍可能掩盖某一关键维度被完全牺牲，因此每个不可替代价值维度还应有最低阈值：

$$
v_k(O_1)\ge \tau_k,\qquad k\in K_{material}.
$$

物质性修订必须明确记录：保留了什么、放弃了什么、这是阶段性结果还是最终结果、怎样继续接近原目标，以及哪个 Principal 认领了该变化。

## 5.6 主体拒绝不是错误

`REFUSE`、`COUNTER` 和 `UNKNOWN` 是协调的有效状态。它们可以阻止系统：

- 用模型乐观替代主体意愿；
- 为了收敛而偷换目标；
- 让来源方冒充接收方采纳；
- 把未验证假设写入正式合同；
- 让一个中心 Schema 设计者垄断所有语义。

拒绝的价值不在于增加对话，而在于使本地主权世界能够把真实约束带入共同介质。
