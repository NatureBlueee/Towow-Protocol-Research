# 9. 候选运行架构：形成与运行的双阶段

现有证据支持但尚未证明一种候选架构：

```text
主权、自适应形成
→ 冻结边界、目标、权威和 Witness 合同
→ 编译为最小权限确定性运行
→ 监测 Defeater、版本、成本与环境漂移
→ 物质变化时重新打开形成
```

![图 5：形成期与运行期的候选双阶段架构。](../figures/fig5_two_regime.png){#fig:tworegime width=96%}

## 9.1 形成阶段

形成阶段允许：

- 本地私有上下文参与；
- `REFUSE / COUNTER / UNKNOWN`；
- 局部探针与工具形成；
- 请求授权、伙伴和资源；
- 调整任务结构和恢复条件；
- 共同编辑 SharedArtifact/JAA；
- 识别需要 Principal 取舍的价值冲突。

## 9.2 编译运行阶段

当目标、Schema、权威、边界、接受规则和运行域稳定以后，可以把日常执行编译为最简单的 least-privilege coordinator，承担：

- 固定路由和工具调用；
- journal、dedupe、retry 与 replay；
- 固定 Schema 验证；
- 目标域采纳适配；
- Defeater 和漂移监测。

主权要求权威留在本地，不等于每次执行都要让多个智能 Agent 持续谈判。

## 9.3 重开条件

以下事件应重新打开形成：

- ObjectiveVersion 物质变化；
- Principal、AuthorityGrant 或 Acceptance policy 改变；
- 新主体进入或退出；
- 冻结 Schema 无法表达新状态；
- 模型、工具、协议、环境或成本指纹漂移；
- holdout 或生产运行出现 Defeater；
- revocation、dispute 或不可恢复 Unknown；
- 隐私、责任或风险边界变化。

该架构在一个本地跨技术域形成实例中成立，但 matched central formation 尚未公平运行，不能升级为通用定理。
