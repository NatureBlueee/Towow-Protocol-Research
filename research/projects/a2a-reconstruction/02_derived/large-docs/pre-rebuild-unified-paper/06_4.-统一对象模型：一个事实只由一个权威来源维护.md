# 4. 统一对象模型：一个事实只由一个权威来源维护

多轮研究曾分别形成 PFE、CRA、CapabilityEnvelope、AssuranceCase、JAA、Compiled World 等对象。统一收束的原则不是概念越少越好，而是：

> **同一现实事实只有一个权威来源；不同失败、责任和证据必须仍然可区分。**

当前事实内核分为四个平面。

## 4.1 主体与权威平面

- `Principal`：最终价值、责任、拒绝、Recognition 和 Acceptance 主体；
- `SovereignDomain`：受 Principal 控制的局部技术与政策域；
- `AgentExecution`：一次可归因的模型或程序执行；
- `AuthorityGrant`：对动作、对象、目的、期限和资源的限定授权；
- `RecognitionAction`：Principal 对精确目标、方案、范围或能力版本的认领。

## 4.2 认识与证据平面

- `Claim`：带 issuer、scope、validity 和 status 的限定主张；
- `Evidence`：支持或反驳 Claim 的可解释、可搬迁和可重放证据；
- `WitnessPolicy`：某类 Claim 允许哪些证据来源、时效、独立性、阈值与接受谓词；
- `Assumption`：主张成立所依赖的条件；
- `Defeater`：一旦出现会降级、暂停或推翻 Claim 的事件或证据。

## 4.3 协调与规范平面

- `ObjectiveVersion`：原始目标及其物质性修订谱系；
- `CoordinationCase`：一次协调问题的边界、参与方和当前状态；
- `SharedArtifactVersion`：共同编辑的方案、JAA、边界合同或候选协议版本；
- `Commitment`：经 Recognition 和授权后形成的义务网络；
- `ResourceReservation`：稀缺资源和容量的正式占用。

## 4.4 操作与效力平面

- `LogicalActionKey`：同一现实意图在重试间保持稳定的逻辑身份；
- `ActionAttempt`：一次具体物理执行尝试；
- `Effect`：权威目标世界中实际发生的状态变化；
- `DomainAdoptionReceipt`：目标技术域正式采纳、撤销或拒绝某项输入的记录；
- `Verification`：依据明确规则核验 Claim 或 Effect；
- `Acceptance`：有权 Principal 或业务域对目标价值的接受；
- `Settlement` / `Dispute`：承诺履行后的效力、结算与争议状态；
- `Event`：所有权威状态变化的追加式记录。

## 4.5 哪些不再是权威对象

以下结构仍然有用，但不拥有第二套事实：

- NAC、Embedding、图、Agent Card：Discovery Provider；
- Benders、MILP、列生成、MCTS、模型规划：Solver Provider；
- PFE：可能性形成与条件搜索策略族；
- CRA：资格化、开放复核、消融、留出、漂移与再认证流水线；
- CapabilityEnvelope：从 Claim、Evidence、Scope 和 Defeater 生成的运行视图；
- AssuranceCase：同一事实的审计论证视图；
- Compiled World：权威对象和事件的可操作投影。

这种归位减少了“每个阶段一个引擎”的拼接感，也防止 PFE、CRA 和 UI 分别宣布主体已经具备能力。

## 4.6 权威状态与候选状态

统一内核必须把候选状态与权威状态放在不同命名空间中。模型输出、Solver 解、Agent 对话和局部试验首先产生候选对象：

```text
Hypothesis
CandidateClaim
DraftArtifact
ProposedBoundary
ProposedCommitment
```

只有满足相应 Gate 后，候选才触发权威事件。例如：

```text
DraftArtifact + Principal Recognition
+ valid AuthorityGrant
+ resource feasibility
→ CommitmentCreated
```

```text
ActionAttempt + target-domain authoritative readback
→ EffectObserved
```

```text
EffectObserved + WitnessPolicy satisfied
→ VerificationRecorded
```

```text
VerificationRecorded + authorized value decision
→ AcceptanceRecorded
```

Gate 不应由自然语言 Prompt 隐式承担。每次转换至少记录：输入对象版本、授权来源、验证规则、失败原因、产生的事件和可逆/补偿属性。

## 4.7 统一事件语义

系统内部建议采用追加式事件模型，但“事件存在”不意味着所有消费者都已经接受它。事件至少包括：

| 事件类别 | 表达的事实 | 典型权威 |
|---|---|---|
| `ProposalEmitted` | 某执行实例提出候选 | AgentExecution |
| `BoundaryResponseRecorded` | 主权域返回 Witness、Defeater、Countercondition 等 | SovereignDomain |
| `ArtifactVersionCreated` | 共同制品形成新版本 | Coordination ledger |
| `RecognitionRecorded` | Principal 认领精确版本 | Principal |
| `CommitmentCreated` | 义务和条件正式生成 | Commitment compiler + parties |
| `ActionAttempted` | 发生一次现实执行尝试 | executing runtime |
| `EffectObserved` | 目标世界出现可读回状态变化 | target domain |
| `DomainAdoptionRecorded` | 目标技术域将输入纳入本地正式状态 | target domain authority |
| `VerificationRecorded` | 明示规则得到结果 | verifier |
| `AcceptanceRecorded` | 目标价值被有权主体接受或拒绝 | Principal / business authority |
| `SettlementRecorded` | 结算、解除、补偿或争议状态变化 | Trust Adapter |
| `ClaimDefeated` | 新证据使旧 Claim 降级或失效 | WitnessPolicy / adjudicator |

这组事件可以由不同物理服务实现，但语义必须跨实现保持一致。
