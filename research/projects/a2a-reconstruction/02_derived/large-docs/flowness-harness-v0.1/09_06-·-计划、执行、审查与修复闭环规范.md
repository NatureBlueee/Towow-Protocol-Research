# 06 · 计划、执行、审查与修复闭环规范

## 1. 计划是编译，不是任务列表

计划将 Engineering IR 和 Scoped Consensus 编译为可执行任务图。

它需要同时优化：

- 认知闭包；
- 依赖正确；
- 并行度；
- 合并风险；
- 上下文成本；
- 验证成本；
- 失败隔离；
- 关键路径；
- 人工审批点。

## 2. 任务对象

每个任务至少包含：

- 任务身份；
- 交付物，而不是仅动作；
- 设计与工程来源；
- 完成合同；
- read/write set；
- 目标对象和文件；
- 上游依赖；
- 预期消费方；
- 所需共识；
- 权限和工具；
- 资源预算；
- 必须运行的验证器；
- 失败与升级路径；
- 合并方式。

## 3. 怎样判断要不要拆成多个 Agent

多 Agent 只有在以下收益大于成本时成立：

- 独立搜索空间；
- 上下文隔离；
- 并行速度；
- 专业化；
- 权限隔离；
- 独立验证；
- 故障隔离。

协调成本包括：

- 信息损失；
- 重复工作；
- 术语漂移；
- 合并冲突；
- 调度和审查；
- 任务包构造；
- 下游依赖等待。

一个强 Agent 可以连续完成的闭环任务，不应为“体现多 Agent”而拆散。

## 4. 任务原子性的真实标准

原子不是任务足够小，而是：

- 有单一可验证交付物；
- 所需信息可以形成闭包；
- 写集边界清晰；
- 失败不会污染过大范围；
- 能独立提交或明确合并协议；
- 交付后下游可消费。

## 5. 依赖图

依赖必须是显式类型化边，而不是散文：

- 数据依赖；
- 接口依赖；
- 状态依赖；
- 资源冲突；
- 审批依赖；
- 验证依赖；
- 同一写集互斥；
- 迁移顺序。

计划冻结前检查循环、假依赖、遗漏依赖和跨计划冲突。

## 6. 执行环境

执行 Agent 应在隔离、可审计、可恢复的工作空间中运行：

- 独立 worktree 或沙箱；
- 明确分支和提交权限；
- 绑定 session/task/plan；
- 工具按需加载；
- 运行时心跳；
- 所有重要动作留 Trace；
- 产物可由其他会话接手；
- 会话死亡不等于工作丢失。

## 7. 执行合同

Agent 开始前确认：

- 任务包版本；
- 事实投影新鲜度；
- read/write set；
- 允许和禁止动作；
- 当前活跃冲突；
- 必须返回的产物；
- 完成验证；
- 回流条件。

执行中发现上游错误，不得盲目“尽力完成”。应创建 Finding 并选择正确回流。

## 8. 独立审查

自检不能只由编码会话完成。独立审查应至少隔离上下文，并根据风险选择不同证据路径、模型或工具。

审查视角包括：

- 需求和设计覆盖；
- 工程契约；
- 代码和架构；
- 安全；
- 测试；
- 运维；
- 性能；
- 迁移；
- 局部与全局一致性；
- 是否创造了未授权对象或能力；
- 是否真正进入运行路径。

## 9. Finding

Finding 是一等对象，不是 Reviewer 的一段评论。

至少包含：

- 现象；
- 严重度；
- 证据；
- 受影响对象；
- 可能原因；
- 竞争解释；
- 建议回流层；
- 临时缓解；
- 完成判据；
- 所有者；
- 生命周期。

## 10. 六类回流

### 10.1 Re-execute

环境、暂态依赖或一次性失败，原任务不变。

### 10.2 Repair

局部实现偏差，任务和工程方案不变。

### 10.3 Replan

任务拆分、顺序、资源或依赖错误。

### 10.4 Re-engineer

技术方案、接口、容量或工程假设失效。

### 10.5 Redesign

系统结构或机制无法满足需求，或产生不可接受副作用。

### 10.6 Re-interview

用户意图被误解、发生变化或出现新的价值冲突。

回流分类器必须提供证据；无法确定时优先调查，不得自动扩大返工范围。

## 11. 合并和提交

- 每个任务独立提交；
- 提交只包含声明写集；
- 检测夹带他人修改；
- 公共接口修改需要契约验证；
- 合并前重新检查目标分支变化；
- 局部测试通过不等于全局可合并；
- 合并后运行集成、回归和影响相关验证器；
- 失败可定位到任务、提交、Agent 和共识版本。

## 12. 计划与执行完成标准

- 所有任务到合法终态；
- 依赖和写集没有静默冲突；
- 所有承重 Finding 已解决、接受或转债；
- 产物已被消费或可被下游发现；
- 独立验证通过；
- 代码和运行状态一致；
- 未验证内容明确；
- 运行证据可以闭合原始目标。
