# 附录 B · 设计评审攻击手册

## 1. 使用方法

本手册用于主动证明设计不成立。评审者不应只问“有没有覆盖清单”，而应构造足以暴露机制漏洞的场景。

每次攻击记录：

- 被攻击设计决定；
- 场景与前置条件；
- 预期失败；
- 实际推演；
- 证据；
- 是否阻塞；
- 修复后如何复验。

## 2. 需求忠实度攻击

- 方案解决的是用户的目标，还是用户随口提出的手段？
- 有没有高优需求没有任何设计响应？
- 有没有设计对象找不到服务目标？
- 隐性需求是否只是 Agent 自己发明？
- 如果去掉所有术语，用户是否仍会认可结果？

## 3. 机制攻击

- 功能存在，但稳定产生功能的机制是什么？
- 用户或 Agent 能否绕开关键机制？
- 机制依赖的假设在真实环境成立吗？
- 两个机制同时运行会不会互相抵消？
- 如果主要 Agent 失效，制度是否仍成立？

## 4. 对象攻击

- 对象是否有稳定身份？
- 同名对象是否被混成一类？
- 谁创建、拥有、修改、消费、废弃？
- 重复、孤立、过期、部分创建怎样表达？
- 对象存在于文档、数据库、代码还是运行时？这些投影如何一致？

## 5. 关系攻击

- 连线是否说明方向、条件、强度、版本和失败影响？
- 关系是声明还是可由代码和数据重建？
- 上游变化后，下游如何知道？
- 消费方清单会不会过期？
- 是否存在一对多、多对多、循环或隐藏依赖？

## 6. 生命周期攻击

- 初始态和终态是什么？
- 中途失败留下什么？
- 重试是否产生重复副作用？
- 取消、暂停、恢复、迁移和废弃如何发生？
- 同时收到两个相反事件怎样处理？
- 历史状态如何回放？

## 7. 权限攻击

- 谁能改变公共定义？
- Agent 能否通过间接工具绕权？
- 审批是否只是提示词而非机械边界？
- 紧急绕过如何记录和补偿？
- 身份借用是否造成不可追责？
- 人类延迟回应时系统怎么维持安全？

## 8. 信息攻击

- Agent 是否看到必要信息？
- 是否因为信息太多忽略红线？
- 信息是否过期、冲突或来源不明？
- 上下文截断时先丢什么？
- 不同 Agent 是否收到不同版本事实？
- 系统能否说明为什么加载某条规则？

## 9. 质量属性攻击

### 性能

负载、并发、峰值、冷启动、慢依赖和资源耗尽时怎样？

### 可靠性

进程、网络、模型、队列、数据库或外部 API 失败时怎样？

### 可维护性

一年后新工程师能否理解？规则、事件和 Gate 数量是否失控？

### 安全

数据越权、Prompt Injection、密钥、供应链和工具滥用如何处理？

### 成本

正常、异常和最坏情况下 token、模型、存储和人工成本是多少？

## 10. 演化攻击

- 模型、框架、技术栈或组织变化后还能运行吗？
- 版本升级是否需要一次性大迁移？
- 旧任务如何回放？
- 新规则会不会错误审判旧代码？
- 一个临时例外会不会变成永久债？

## 11. 组织现实攻击

- 谁愿意维护这些物料？
- 谁对错误负责？
- 团队能否理解和遵守？
- 流程成本会不会让人绕过？
- 审批人是否成为瓶颈？
- 指标是否制造错误激励？

## 12. 最小性攻击

- 不做会怎样？
- 只加观测是否够？
- 能否用更简单机制达到 80% 效果？
- 新对象、Agent、Gate 和数据库是否都有不可替代价值？
- 方案是不是为了追求完备而制造长期复杂度？
