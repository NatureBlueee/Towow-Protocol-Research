# 附录 D · 百万行代码重构资格审查

## 1. 基本判断

“能否重构几百万行代码”不是一个是非题。需要先判断目标、代码库可理解性、验证能力、迁移方式和组织条件。

Harness 可以管理超大型重构，但不能承诺把陌生仓库交给 Agent 后全自动完成。

## 2. 项目准入信息

### 业务

- 为什么要重构；
- 不重构的成本；
- 允许的停机和风险；
- 哪些业务行为绝不能改变；
- 谁拥有最终验收权。

### 代码库

- 语言和构建系统；
- 仓库、服务和模块数量；
- 活跃与废弃代码；
- 所有权；
- 依赖图可恢复程度；
- 生成代码和第三方代码；
- 代码版本治理区。

### 验证

- 能否完整构建；
- CI 时间和稳定性；
- 单元、集成和端到端覆盖；
- 是否有 characterization tests；
- 是否有生产流量回放；
- 数据一致性如何验证；
- 关键性能基线。

### 运行

- 部署拓扑；
- 数据库和消息；
- 发布频率；
- 灰度、双写和回滚；
- 可观测性；
- 事故历史。

### 组织

- 架构负责人；
- 模块 Owner；
- 评审与发布权限；
- 业务专家；
- 迁移时间窗口；
- 并行业务需求。

## 3. 拒绝或降级条件

出现以下情况，不应承诺自主大规模重构：

- 无法稳定构建；
- 没有可信测试和行为基线；
- 核心模块无人理解；
- 数据迁移不可回滚；
- 需求是“顺便把代码变好”；
- 没有业务验收人；
- 生产发布和观测极弱；
- 要求一次性替换；
- 时间预算不足以建立安全网。

可以先承接调查、资产盘点、依赖图、测试补齐和迁移设计。

## 4. 推荐阶段

1. Inventory：代码、服务、Owner、数据和依赖；
2. Baseline：构建、测试、性能和运行行为；
3. Characterization：为关键旧行为建立保护；
4. Target Design：明确目标架构和不变行为；
5. Seams：寻找兼容层和迁移切口；
6. Pilot：选一个低风险垂直切片；
7. Parallel Run：新旧路径对照；
8. Progressive Migration：按模块和数据逐步迁移；
9. Decommission：确认消费方清空后退役旧路径；
10. Long-tail Cleanup：处理临时兼容和债务。

## 5. Harness 在其中的角色

- 维护事实和资产图；
- 编译模块上下文；
- 管理目标设计和工程契约；
- 拆任务和写集；
- 隔离执行 Agent；
- 运行多层验证；
- 管理 Finding 和回流；
- 追踪迁移状态；
- 防止规则跨治理区误用；
- 为人类架构委员会提供证据。

## 6. 第一阶段可销售承诺

可信的承诺是：

> 用 Agent Harness 完成超大型代码库的调查、设计、迁移规划、分批执行和证据治理。

不可信的承诺是：

> 全自动重写几百万行代码并保证没有问题。
