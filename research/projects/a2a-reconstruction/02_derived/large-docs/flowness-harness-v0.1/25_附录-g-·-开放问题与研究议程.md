# 附录 G · 开放问题与研究议程

以下问题没有在 v0.1 中假装解决。它们应作为持续研究对象，逐项建立实验和证据。

## 1. 认知编译

- Problem、Requirement、Design 和 Engineering 的最小通用 Schema 到底是什么？
- 哪些内容应进入 ConceptGraph，哪些应保持阶段产物？
- 如何检测阶段转换中的语义丢失？
- 怎样比较两个设计是否真正机制不同？
- 怎样校准语义验证器的误报和漏报？

## 2. 实时语义空间

- File/Symbol 与概念如何自动绑定且保持新鲜？
- 代码分析、运行 Trace 和人工声明的关系如何融合？
- 上下文增量编译的最佳频率是什么？
- 如何测量一条上下文是否真的被 Agent 使用？
- 怎样防止错误图关系造成错误注入？

## 3. Agent 行为算法

- 轨迹片段如何跨模型和工具统一？
- 结果归因如何排除任务难度？
- 怎样进行低成本反事实实验？
- 策略优化何时需要机器学习，何时规则足够？
- 如何防止指标改变记录而不改变真实行为？

## 4. 多 Agent 协作

- 何时多 Agent 的认知收益超过协调成本？
- 如何自动评价任务拆分？
- 怎样避免多个 Reviewer 共享盲点？
- 如何进行长期任务接力而不丢失语义？
- 分布式账本和多仓库事实如何合并？

## 5. 共识与变化

- 共识作用域如何自动计算？
- 消费方发现的准确率能达到多少？
- 变更涟漪如何避免告警风暴？
- 旧规则、新规则和历史代码如何长期共存？
- 什么时候应该重验证，什么时候直接迁移？

## 6. 验证器

- 设计质量怎样建立跨项目 Benchmark？
- 如何证明验证器覆盖真实失败而非模板合规？
- 语义验证和机械验证怎样组合？
- 长反馈周期领域如何进行治理？
- 验证器之间冲突如何裁决？

## 7. 产品与组织

- 专家认知外骨骼如何逐步服务较弱用户？
- 哪些专家判断可以沉淀，哪些必须保持人类在场？
- 如何降低 Flowness 对普通团队的进入成本？
- 深语义内核如何导出轻量组织界面？
- 企业愿意为何种结果付费？

## 8. 工程经济性

- 每新增一个对象、事件、Gate 的真实维护成本是多少？
- 哪些机制只需要观测，不值得强制？
- 什么规模下事件和图模型优于文档物料？
- 如何计算 Harness 本身的复杂度债？
- 什么时候应该停止自研并使用外部组件？

## 9. 长期终局

- 软件工程中证明的机制能迁移到哪些领域？
- “验证器成熟到哪里，自动化就到哪里”如何被量化？
- 人和 Agent 的权力、责任、身份和信用如何组织？
- Harness 是否会成为组织操作系统，还是只是一类专业生产控制平面？

每个开放问题进入研究时，都应创建 Problem IR、证据计划、候选方案和停止条件，避免开放议程再次变成无限发散许可证。
