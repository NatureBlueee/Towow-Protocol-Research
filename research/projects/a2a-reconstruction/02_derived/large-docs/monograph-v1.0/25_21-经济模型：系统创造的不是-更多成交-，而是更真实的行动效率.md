# 21　经济模型：系统创造的不是“更多成交”，而是更真实的行动效率

## 21.1 协调成本结构

对事项 \(z\)，总成本至少包括：

\[
C(z)=C_{attention}+C_{disclosure}+C_{search}+C_{formation}
+C_{verification}+C_{execution}+C_{delay}+C_{governance}+C_{recovery}.
\]

其中 OPC 最稀缺的往往是 `C_attention`：创始人必须处理高语境判断、解释、异常和责任。一个系统即使增加模型调用和机器交互，只要显著降低人的高认知时间，也可能有正净值；反之，形式对象越多、每次都要求本人确认，也可能让系统失去价值。

## 21.2 错误成本

需要分别测量：

- **False Commit**：不该成交却承诺，产生违约、声誉、数据或机会损失；
- **False Reject**：本可形成的路径被静态表单或错误诊断排除；
- **Premature Commit**：条件尚未闭合就锁定资源；
- **Late Reject**：在投入大量协调和执行后才发现不兼容；
- **Unauthorized Effect**：越权动作进入现实；
- **Unaccepted Adoption**：目标域采用但主体未接受；
- **Hidden Externality**：第三方承担未被内部化的成本。

真实机制比较不能只看成交数。平台可能高效促成标准交易，却在非标准关系中产生大量 late reject；重型形成可能减少错误，却让简单任务成本过高。

## 21.3 价值函数

本文建议以主体级和系统级两套价值函数报告。

主体 \(i\) 的净值：

\[
V_i = B_i(Eff,Acc) - C_i - L_i - Risk_i - Regret_i.
\]

系统级值不应简单求和，因为权力和外部性可能不可公度。至少应报告：

- 每个必要主体的净值；
- 受影响第三方损失；
- 最差主体或约束违反；
- 总人类高认知时间；
- 真实处置时间 \(T_{truth}\)；
- 后悔和 reopen 率；
- 后续复用收益。

## 21.4 形成价值

一个形成动作的价值可能来自三类结果：

1. **Expansion**：创造新的合格路径；
2. **Transformation**：把不可接受路径改造成可接受路径；
3. **Protective Contraction**：更早排除伪路径或收窄权限；
4. **Clarification**：将 Unknown 转为可判断但不改变可达集。

因此，系统目标不是最大化 `COMMIT`，而是最小化达到真实处置的成本与错误。

## 21.5 长期复用与 Compiled World

首次形成可能昂贵，但稳定关系可以编译并复用。设初次形成成本 \(F_0\)，每次编译运行成本 \(c\)，开放重新协调成本 \(f\)，关系复用 \(N\) 次，Defeater 概率 \(p\)，重开成本 \(r\)。编译净节省为：

\[
Saving(N)=N(f-c)-F_0-pNr.
\]

这说明通爻更可能在有重复价值、边界可稳定且关系可编译的场景成立，而不是一次性、低价值、完全标准的事项。

## 21.6 与平台和人类经纪的真实比较

未来实验必须使用强基线：

- 成熟平台表单与规则；
- 具备完整上下文的强中心 Agent；
- 优秀人类经纪/顾问；
- 人类 + Agent 混合；
- 通爻组合 Router。

比较指标应包括：

```text
真实处置时间
高认知人类分钟
总披露量与敏感披露
关键条件召回
错误 Authority 归属
False Commit / False Reject
现实 Effect 与 Acceptance
30/90 天后悔与 reopen
每次复用边际成本
```

若通爻只比弱聊天机器人好，不足以支持产品和理论价值。

## 21.7 产品价值的可能落点

对于 OPC，最初产品不应是一个“Agent 社交网络”，而可能是：

- 主权 Mandate 与账户边界层；
- 非标准合作的 RelationVersion 工作台；
- 现实 probe、资源预留和 Effect readback 工具；
- 人类经纪的结构化增益工具；
- 将成功关系编译为重复运行的服务；
- 多 Agent 内部角色冲突和授权控制台。

开放市场和 Agent-to-Agent 发现只有在这些纵向闭环成立后才有稳定地基。
