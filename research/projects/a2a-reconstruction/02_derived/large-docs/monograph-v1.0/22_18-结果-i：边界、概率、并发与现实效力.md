# 18　结果 I：边界、概率、并发与现实效力

## 18.1 Boundary Oracle：任务自适应边界优于静态投影

在私有线性约束生成器中，`adaptive_1/2/4/8` 四种边界轮数的可行率均为 1.0，中位披露量分别为 22、25、31 和 46；完整披露的中位量为 90。静态投影在四种设置中的可行率均为 0。

![静态投影与任务自适应边界的可行率比较。](figures/boundary_feasibility.png){width=78%}

该结果支持一个限域结论：当本地约束能够以任务相关切割表达时，自适应边界可以显著减少披露并保持生成器内的可行性。它不证明现实主体愿意回答，也不证明当前策略在非凸、语言和策略行为中最优。

**Design Delta：**

- 公开 profile 从资格化依据降级为提名入口；
- 边界接口增加 cut、witness、unknown 和 refusal；
- “最小披露”改为披露—可行性—交互成本的多目标权衡；
- 未来边界实验必须加入重建攻击预算。

## 18.2 Team Constitution：公开能力画像无法表达隐藏贡献模式

在团队构成生成器中：

- price-guided local oracle 的可行率为 1.0，成本比为 1.000354，中位披露为 53；
- full private 的披露量为 75；
- public profile 的可行率仅 0.02；
- random 20% 的可行率为 0.9133，但成本比达到 1.8155。

![预定义搜索、随机列、价格引导本地 Oracle 与完整披露的比较。](figures/team_feasibility.png){width=78%}

该结果说明“主体能够公开独立完成什么”与“在当前组合和价格条件下愿意贡献什么”不同。随机探索可以找到部分组合，却以更高成本和披露为代价；本地价格引导列能逼近完整信息基线。

**Design Delta：**

- Capability Profile 只用于发现，不定义完整能力空间；
- OracleAssessment 增加 `COLUMN`，允许主体暴露条件性贡献；
- Router 支持临时联盟与高阶超边，而不只成对匹配；
- 组合能力必须经过资源预留和对外责任闭合。

## 18.3 Probabilistic Oracle：低熵和高置信可以稳定地错

在分布漂移设置中，unguarded 策略的错误率为 0.5603 和 0.6683。校准风险门将错误率降低到 0.0479 和 0.0612，但覆盖率仅为 0.0300 和 0.0235；审计自适应策略在严重漂移下选择零覆盖。

该结果有两个相反含义。第一，概率门能够显著减少被建模错误；第二，代价可能是系统几乎不自动执行。只报告低错误率而不报告覆盖率会误导。零覆盖也不等于系统失败：在高风险漂移下，正确行为可能是返回 Unknown 或请求现实证据。

**Design Delta：**

- 概率输出增加 abstain/Unknown；
- 模型置信与 Authority 分字段记录；
- 风险门绑定实际损失与 Effect 可逆性；
- 自动执行策略必须同时满足 risk、Mandate 和 witness；
- 低语义熵不得作为承诺或权威依据。

## 18.4 Trust Concurrency：最终一致的检查后写入会超卖

共享预算实验中，eventual check-then-write 的 overspend 率为 0.60461，而 serializable reservation 为 0。结果不是一般分布式性能结论，而是直接验证命题 7 在生成器内的必要性。

**Design Delta：**

- Commitment 之前引入原子 ResourceReservation；
- 草稿与候选可以最终一致，稀缺资源承诺必须有线性化点；
- Reservation 需要过期、撤销、释放和补偿事件；
- 多 Agent 同一 OPC 内部也不能共享一个没有并发语义的“剩余预算”字段。

## 18.5 R5 本地现实：日志、路径和工具存在性不足以证明 Effect 或能力

R5 在真实 macOS、Git、Docker、sandbox 和文件系统中得到四类结果。

第一，基线列出 18 条证据，但只有 2 条可由当前执行环境访问。证据“存在于某处”不等于当前 RelationVersion 可以合法、稳定地使用。

第二，在 9 个动作中，stdout 和外层退出码各只能正确指示 4/9 的现实状态；使用最小 Effect contract 和目标 readback 后达到 9/9。该结果直接促成 Effect Gateway 和 claim-specific witness。

第三，静态工具 profile 对 3 个 holdout 动作的可达性预测为 0/3；在 owner approval 和环境/权限索引加入后，3/3 变为可达。能力不是“安装了工具”，而是工具、环境、路径、权限和授权的组合。

第四，部分主权运行的时间开销约为中心路径的 4.54 倍。该负成本证据促使系统把普通本地审计默认路由到中心/确定性机制，而不是把主权隔离作为所有任务的默认。

**Design Delta：**

- 引入 canonical resource identity，避免路径别名和复制错误；
- Effect Gateway 以目标状态而非调用日志闭合；
- Capability 绑定环境、权限、资源和审批；
- Router 在低风险本地任务中旁路主权形成；
- 真实工程成本必须进入 CollapseSafe。

## 18.6 R5.2 Effect Reality Reconstruction：终态标签在 17 场景中错 10 次

R5.2 对 17 个真实 Harness 场景进行重建。naive terminal baseline 将 carrier、sentinel、index 或最终日志直接解释为完成，在 17 个场景中错 10 次。显式四阶段重建——Attempt、Effect、Adoption、Acceptance——在 17/17 场景中与现有权威源一致。

该结果不支持维护四套完全独立的平行数据库。相反，它支持在同一事件系统中保存四种不可混淆的语义，并复用现有 readback。实验还暴露了事件措辞问题：“parked for redispatch” 与 “consumed” 若使用相同终态标签，会导致恢复逻辑错误。

**Design Delta：**

- 保留四阶段语义，避免对象增生；
- 事件类型区分暂存、消费、采用和接受；
- fresh readback 优先于缓存终态；
- Settlement 与 Acceptance 作为派生/立场，不复制 Effect 事实。

## 18.7 R5.2 Capability Holdout：资格化门槛真实失败

六轴能力合同在 6 个真实可执行案例上预测正确 4/6，低于预注册的 80% 门槛；静态 `installed` 基线为 3/6。主要遗漏是具体文件系统形成条件和恢复环境。

这是一项重要负结果。若只与弱基线比较，可以写成“比静态 profile 好”；但相对预先门槛，它没有通过。该失败促使能力合同加入：

- executor version；
- environment；
- Authority；
- resources；
- recovery；
- freshness；
- explicit Unknown/withdrawal。

当前仍无证据证明 CRA 能在广泛任务上优于优秀人类判断。

## 18.8 R5.4：多轮真实模型协商增加规范表达，但没有形成能力

R5.4 的两个模型 Agent 形成了安全权利、披露、severability、争议、reopen 等更丰富条件。该结果说明模型能在给定角色上下文中进行规范语言构造。但实验没有产生：

- 最终签署；
- 产品补丁；
- 目标域 adoption；
- AcceptedOriginalValue；
- 可观察的新现实能力。

所有 AcceptedOriginalValue 为 0；在验证前，A2A 成本约为静态 builder 的 2.49 倍。中心综合路径还因 transport failure 未形成公平强基线，故不能得出 A2A 优于或劣于中心 Agent 的一般结论。

R5.4 的科学价值在于否定了“更多协商文本 = PFE = 新能力”的错误链条。规范条件增加可能只是更完整地表达已存在冲突。只有当交互改变合格行动空间或必要运行条件，才构成形成证据。

**Design Delta：**

- 语言协商与能力形成分离；
- A2A 前先检查任务是否可 CollapseSafe；
- 保留 `COUNTER/UNKNOWN/REFUSE`，但要求 probe 或 Effect 证明；
- 未来比较必须使用可运行强中心基线；
- “丰富条款数”从主效果指标降级为过程指标。

## 18.9 R5C：跨技术权威域形成了一条此前不可运行的路径

R5C 形成了 `adopted → revoked → offline/unknown → adopted` 的完整技术路径。关键结构包括：

1. Source authority 提供候选与受限接口；
2. Target authority 拒绝 producer-only 状态和错误 Authority；
3. 现实 probe 暴露 API、readback 和恢复缺口；
4. 最小 countercondition 修改执行与恢复条件；
5. Target 通过 canonical readback 产生 adoption；
6. revoke 和 offline 被目标域真实观察；
7. recovery 后重新 adoption；
8. portable verifier 复核 90 个文件、19 项 claims 和 36 条链接。

producer-only 与 wrong-authority 条件不能产生目标投影，说明目标域 Authority 和 readback 是必要条件。该实验比 R5.4 更强，因为交互确实改变了可达运行路径，而不只是文本。

但 R5C 仍是两个技术权威域，不是两个真实社会 Principal。它没有证明：人理解并认领了版本；系统优于同权限中心；商业净值为正。

**Design Delta：**

- 形成期采用 authority-first probe、refusal 和 countercondition；
- 冻结后编译为 least-privilege deterministic runtime；
- Source 不得替 Target 宣布 adoption；
- revoke、offline、unknown、recovery 成为一等状态；
- Human Recognition 和商业价值保留为独立证据门。

## 18.10 跨实验结果：什么真正改变了问题性质

R2–R5C 的联合结论不是“A2A 有效”，而是以下结构：

1. 静态投影不足以承担开放能力资格化；
2. 自适应边界在受限世界中能减少披露；
3. 高阶联合能力需要开放贡献和新列；
4. 概率风险可以管理但必须允许拒绝自动化；
5. 承诺需要原子资源语义；
6. 真实完成必须由目标世界 Effect 证明；
7. 一次成功不等于可承诺能力；
8. 模型语言形成不等于能力形成；
9. 现实 probe 与权威 countercondition 可以形成新技术路径；
10. 稳定子图应转入确定性运行。

这些结果共同支持一套形成—资格化—认领—效力—编译结构，而不是支持“所有 Agent 应持续自由协商”。
