# 12　形成期与编译运行期：局部稳定、局部重开

## 12.1 两种控制制度

开放形成需要适应性推理、边界询问、反条件、现实 probe 和主体回路；稳定运行则应尽量使用最小权限、确定性、可测试的机制。若所有日常动作都继续由高能力 Agent 自由协商，系统成本、漂移和越权面会持续扩大；若过早冻结，则无法吸收新证据和环境变化。

本文采用两种局部控制制度：

- **Formation Regime**：关系语法、能力、权威或接受尚未稳定；
- **Compiled Runtime**：特定子图已达到稳定 Gate，可以编译为确定性服务、工作流、合约、API、审批或托管规则。

## 12.2 五维稳定向量

单一 `stable=true` 会掩盖关键差异。本文定义：

\[
S = \langle s_{tech},s_{auth},s_{ep},s_{norm},s_{econ}\rangle,
\]

分别表示：

- technical/operational；
- authority/governance；
- epistemic/assurance；
- normative/legitimacy；
- economic/resource。

某个 API 可以技术稳定，却没有稳定治理；某项合作可以双方签字，却缺目标 Effect witness；某项机制可以合法但经济成本不可持续。关键维度失败不能被其他维度平均抵消。

## 12.3 Compile readiness

子图 \(G'\) 只有在以下 Gate 满足时可编译：

1. 当前可达动作都有有效 Authority；
2. 所有现实动作有明确 Operation Specification；
3. 关键 Effect 有目标世界 witness；
4. 必要 Mandate、Commitment 和资源预留有效；
5. material Unknown 已闭合、接受为残余风险或显式 defer；
6. 退出、恢复、补偿和争议路径存在；
7. 五维稳定向量达到任务风险所需阈值；
8. 编译机制不会丢失必要 Standing 和 recourse；
9. 运行成本低于持续开放形成成本。

Compile readiness 是针对任务族、风险等级、时间窗和当前状态的局部判断，而不是永久认证。

## 12.4 Compiled World

Compiled World 是联邦式权威—行动图的运行投影，包含：

- 已稳定的 RelationVersion 子图；
- 可执行 Operation；
- 策略和权限；
- 资源预留；
- Effect connector；
- 监控、Defeater 和 reopen 规则；
- 面向人的可解释视图。

它不成为第二事实源。若本地 Authority、目标世界或外部制度发生变化，Compiled World 必须通过事件更新或失效，而不能继续声称旧状态有效。

## 12.5 Defeater 类型

至少六类 Defeater 会触发重开：

1. `EVIDENCE_DEFEATER`：证据被推翻或过期；
2. `CAPABILITY_DEFEATER`：执行器、环境、资源或恢复能力变化；
3. `AUTHORITY_DEFEATER`：Mandate 撤销、角色变更或权限失效；
4. `EFFECT_DEFEATER`：目标世界状态被撤销、回滚或无法读取；
5. `NORMATIVE_DEFEATER`：新的受影响主体、法律或合法性挑战出现；
6. `ECONOMIC_DEFEATER`：成本、容量或价值变化使机制不再可持续。

## 12.6 依赖闭包重开

设关系图 \(G=(N,E)\)，节点为 Claim、Mandate、Commitment、Operation、Effect、Acceptance 等，边表示依赖。Defeater 作用于节点 \(n\) 时，重开集合为：

\[
Reopen(n)=\{m\in N \mid n\leadsto m \land dependency(n,m)\ is\ material\}.
\]

只重开依赖闭包，而非整条关系。若一个支付方式失效，不必重谈全部交付范围；若数据训练权变化，只重开依赖该权利的派生和长期学习，不影响已完成且独立的只读分析。

## 12.7 运行中的局部形成

现实系统可以同时存在：

- 已编译的支付和凭证服务；
- 尚在形成的数据使用条件；
- 已承诺的交付范围；
- 等待业务 Acceptance 的结果；
- 因新反例而重开的恢复路径。

因此“形成—运行”不是全系统二阶段瀑布，而是图上的局部状态。高能力 Agent 应集中在未稳定边界和异常处，而不是持续接管所有确定性工作。
