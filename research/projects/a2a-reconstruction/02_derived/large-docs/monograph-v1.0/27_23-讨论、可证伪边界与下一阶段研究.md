# 23　讨论、可证伪边界与下一阶段研究

## 23.1 这项研究目前真正建立了什么

目前已经建立的不是一个经过市场证明的通用 Agent 经济协议，而是：

1. 一套能够区分主体、执行、权威和现实结果的统一语言；
2. 一套从静态搜索转向行动构成的理论；
3. 一套将 Unknown 转为建设性形成动作的机制框架；
4. 一套中心化、A2A、人类经纪和确定性运行的组合原则；
5. 一套能在真实代码和技术域中防止若干具体错误的状态机和参考实现；
6. 一套经公开历史和访谈校准的制度变量；
7. 一套面向 OPC 的可操作纵向闭环和研究仪器。

这些成果已经足以指导真实系统建设，但尚不足以证明整体产品价值。

## 23.2 最深的开放问题

当前决定体系是否最终成立的核心问题是：

> 真实 OPC 是否能够通过范围化 Agent 委托和多机制形成，因果地获得一项强平台、强中心 Agent 或优秀人类经纪无法以更低成本无损产生的联合能力，并在长期保持理解、责任、接受和正净价值？

它包含四个子问题：

- 因果新颖性：是发现了既有路径，还是创造了新路径？
- 不可折叠性：中心机制是否真的无法保持同样权威和信息边界？
- 真实认领：主体是否理解并自由接受精确版本？
- 净价值：形成收益是否超过注意力、披露、验证和治理成本？

## 23.3 可证伪条件

若出现以下结果，本文核心理论应被显著修订或放弃：

1. 强中心 Agent 在保持相同信息、拒绝、退出、责任和 Acceptance 条件下，对非标准 OPC 事项稳定实现同等或更高净值，则主权 A2A 的必要域缩小；
2. 真实参与者无法理解版本化 Mandate/RelationVersion，或其认知成本高于人类经纪，则当前对象化方案失败；
3. 现实 probe 和 countercondition 很少改变可达路径，只增加流程，则 PFE 的中心地位需降级；
4. 版本图不能降低争议、后悔或审计成本，则其价值只剩内部工程；
5. 编译运行频繁因漂移失效，scoped reopen 成本高于持续适应，则两制度架构需改写；
6. 外部性和权力无法由 Standing/政策 Gate 有效处理，则系统不能用于高风险开放协调；
7. OPC 的单一责任根使多 Agent 内部治理比直接人类控制更复杂，且没有相称杠杆收益，则 OPC 不是合适首发域。

## 23.4 下一阶段：强基线历史语料

在真实外部资源有限时，仍可继续：

1. 建立 12–20 个 OPC 历史事项语料，覆盖成交、不成交、反悔、争议和长期复用；
2. 从公开访谈、播客、咨询案例、仲裁/合同争议、自由职业和创作者经营材料中提取过程，而非只用成功故事；
3. 进行双人独立编码，测量 materiality、Authority、Standing 和 outcome-chain 一致性；
4. 对每个截点运行平台、中心 Agent、人类经纪和组合 Router 的离线 replay；
5. 仅在离线结构确有差异时选择真实 live case。

## 23.5 下一阶段：可执行强基线

强基线必须真正执行：

- 平台基线：固定字段、排序、标准合同与争议规则；
- 中心 Agent：获得双方允许的同等上下文和工具，形成统一方案；
- 人类经纪：由有经验的撮合者或顾问处理；
- 组合 Router：允许局部主权 Oracle、probe 和多机制编排。

不允许把通爻实现成完整系统，却用简单表单或弱模型作为对照。

## 23.6 下一阶段：最小真实 OPC 实验

首个真实实验应为低风险、可逆、非标准、可产生真实 Effect 的合作。例如：一个 OPC 客户与一个 AI 服务 OPC 形成 7–14 天只读、无训练、预算封顶、可撤销的数据分析试点。

实验步骤：

1. 分别冻结双方私有前态；
2. 明确各自 Authority Locus 与 Agent Mandate；
3. 运行平台/中心/经纪/组合机制之一；
4. 对拒绝与 countercondition 记录 material change；
5. 执行一个可逆现实 probe，如在买方域创建并撤销只读凭证；
6. 对精确 RelationVersion explain-back；
7. 原子预留预算和时间；
8. 执行受限 Operation；
9. 由买方目标域确认 Effect 与 Adoption；
10. 分别记录 Acceptance；
11. T+7、T+30、T+90 记录后悔、重开和复用。

主要终点：真实处置时间、人类高认知分钟、敏感披露、关键条件召回、错误 Authority、Effect/Acceptance、后悔和净值。

## 23.7 下一阶段：Fieldkit v0.8

需要实现：

- 资源预留与容量图；
- cost-sensitive probe ranking；
- A2A、MCP、OAuth/Mandate、VC 连接器；
- Effect connector 与 authoritative readback；
- explain-back 和差异认领；
- Standing/外部性 Gate；
- 历史语料盲化 replay；
- 强基线统一接口；
- 30/90 天 follow-up；
- 对模型升级和 Mandate 漂移的 Defeater。

## 23.8 统一论文的持续演化规则

从本版起，后续每轮研究必须写回同一篇论文：

- 新理论进入定义、命题和相关工作；
- 新实验进入统一方法与结果，而不是独立阶段报告；
- 被推翻内容进入竞争解释和概念处置；
- 代码变更进入架构、协议和复现附录；
- 所有旧概念都有“保留、合并、降级、废弃”的明确状态；
- 页面增长不是目标，但任何删除都必须在内容回收账本中解释。
