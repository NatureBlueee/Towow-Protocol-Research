# 7　实验条件与强基线

## 7.1 条件 A：固定平台/表单

使用事项所在领域已有平台、标准表单或规则流程。平台可以包含真实的发现、支付、申诉和保障，不得故意削弱为简单问卷。适用于标准负控制和平台确实覆盖的事项。

## 7.2 条件 B：扁平强中心 Agent

使用与研究系统相同的模型、工具、时间、token 和查询预算。Agent 可以主动提问、调用 probe、提出反条件，但使用单一全局状态，不保存独立 Authority Locus、精确版本 Stance、目标域 Effect 与 Acceptance 分离。

该条件用于识别结构语义增量，不能通过减少工具或上下文把它做成弱对手。

## 7.3 条件 C：权威感知中心 Hub

部署仍然中心化，但保存 Authority、Mandate、RelationVersion、资源预留、Effect witness 和 Acceptance Gate。本地参与者可通过受限接口提供 assertion。它用于回答：很多价值是否来自语义结构，而不来自联邦拓扑。

## 7.4 条件 D：联邦 Relation 系统

各责任根保留本地世界和本地 Agent/Oracle，只共享必要 assertion、条件、证明、Stance、Commitment 和 Effect 引用。无中心可以静默替各方认领或接受。中心组件仍可承担索引、路由、公共计算、事件转发和确定性服务。

## 7.5 条件 E：优秀人类经纪

在人类经纪本来就是合理机制的任务中，邀请有真实经验的经纪、顾问、项目经理或行业撮合者处理同一冻结材料。若无法获得真人，经纪方法 Agent 只能称“过程代理基线”，不能冒充优秀人类。

## 7.6 公平性规则

- 相同事项与冻结前态；
- 相同模型版本、工具、执行环境和公开信息；
- 相同可查询参与者次数或明确计入额外成本；
- 相同现实权限上限；
- 各条件都可主动提问和提出 probe；
- 研究系统不得独占更高质量的人工帮助；
- 所有条件的 prompt、版本、重试和失败公开记录；
- 人类裁决者盲化系统名称和研究者预期；
- 系统无法运行的事项仍进入 intention-to-treat 分析。
