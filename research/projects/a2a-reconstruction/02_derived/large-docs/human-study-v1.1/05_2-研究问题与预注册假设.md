# 2　研究问题与预注册假设

## 2.1 主要研究问题

**RQ1：语义价值。** 保存 Authority、精确版本、资源预留、Effect witness 和 Acceptance Gate，是否比使用单一全局状态减少错误承诺和错误现实判断？

**RQ2：拓扑价值。** 在信息或权威不可在授权范围内集中时，本地世界与联邦 Relation 是否能在维持处置质量的同时减少敏感披露、保留退出和故障独立性？

**RQ3：形成价值。** 现实 probe、countercondition、任务重构和能力组装，是否能因果地改变合格联合行动空间，而不只是把既有方案说得更完整？

**RQ4：路由价值。** 系统能否在标准任务中主动旁路重型形成，在真正非标准、不可折叠的任务中及时开启形成，并在异常出现时升级机制？

**RQ5：编译价值。** 关系形成后，稳定局部被编译为确定性服务，是否降低重复任务的人工认知、披露和协调成本，而不增加越权、错误和后悔？

**RQ6：人类可用性。** 真实 OPC 能否准确解释 Agent 的 Mandate、当前 RelationVersion、未解决条件和下一现实动作？

## 2.2 主要假设

### H-sem：权威语义假设

相同模型、工具和信息预算下，权威感知条件相对扁平中心 Agent 将显著降低：wrong-authority decision、unauthorized Effect、stale-version commitment 和 Effect/Acceptance conflation。

### H-topology：本地世界假设

在预先标记为“不可在授权内无损集中”的事项中，联邦 Relation 相对权威感知中心 Hub 将降低敏感披露与单点暴露，同时不显著恶化 truthful disposition；在可集中事项中，两者可能无差异，且中心 Hub 成本更低。

### H-formation：建设性形成假设

至少一部分非标准事项会在冻结前态中不存在合格路径，而在特定 probe、countercondition、权限申请、工具/伙伴引入或任务重构之后出现新的 Qualified/Committed path。移除该形成动作时，路径应消失或降级。

### H-routing：机制旁路假设

对于预注册的标准负控制，Router 应优先选择平台、确定性服务、自执行或中心优化，而不是开放形成；对于具有多个不可代行权威、不可集中信息、无可信 Hub 或未形成接受标准的事项，Router 不应错误 collapse。

### H-compile：重复价值假设

同类事项第二次运行时，Compiled World 相对持续开放协商应降低高认知人工分钟、重复披露和确认次数；第三次注入 material drift 时，scoped reopen 应小于全局重开，同时不漏开依赖后代。

### H-explain：理解与认领假设

在不向参与者暴露全部内部本体术语的前提下，至少 80% 的 material Mandate/Relation 项能够通过 explain-back 被参与者正确复述；无法正确复述的条款不得进入 Commitment。

## 2.3 明确的否证结果

以下结果会削弱或推翻对应主张：

- 强中心 Agent 在保持同等隐私、拒绝权、责任和 Effect/Acceptance Gate 时表现相同或更好：联邦拓扑主张缩小；
- 移除 probe/countercondition 后新路径仍然成立：形成主张降级为发现或规范整理；
- 参与者无法理解 Mandate/RelationVersion，或解释后频繁改变决定：当前交互对象不适合直接暴露；
- 第二次运行成本不下降：Compiled World 商业价值未成立；
- Router 对标准任务持续重路由：机制组合器没有达到可用门槛；
- 真实接受与系统 Stance 高频不一致：Acceptance 模型或采集方式失效；
- 系统产生更多 false commit、后悔或第三方伤害：立即停止高权限扩展并修订设计。
