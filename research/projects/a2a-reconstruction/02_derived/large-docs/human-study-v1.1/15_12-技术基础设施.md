# 12　技术基础设施

## 12.1 身份与工作负载

- 人与组织身份：研究账户、强认证、明确代表关系；
- Agent/工作负载身份：可采用 SPIFFE/SPIRE 或等价短期工作负载凭证；
- 外部声明：可用 W3C Verifiable Credentials 表示来源可验证的资格/角色；
- 不把凭证“可验证”解释为内容必然真实或授权充分。

## 12.2 Mandate 与策略执行

Mandate 是通爻语义对象；底层可以通过 OAuth 2.1、短期 token、Cedar/OpenFGA 等策略适配执行。策略层必须支持：对象、动作、目的、资源上限、数据用途、对手方、有效期、再委托、撤销和人工 Gate。

## 12.3 Agent 与工具连接

- A2A：承载独立 Agent 的发现、Task、Message 和 Artifact；
- MCP：连接工具、数据与资源；
- 任何协议消息仍需绑定本研究的 Entity、Mandate、RelationVersion 和事件来源；
- 协议成功不自动产生 Commitment 或 Effect。

## 12.4 工作流与事件

- Durable workflow：Temporal 或等价系统管理长周期、重试、人工审批和恢复；
- Event envelope：兼容 CloudEvents，但补充 Authority/Version/Privacy/Effect 语义；
- Event ledger：append-only、哈希链、可派生 snapshot；
- Telemetry：OpenTelemetry 收集 trace、metric、log、模型/工具成本；
- Relation graph：保存版本、依赖、Stance、Commitment、Operation、Effect 和 reopen。

## 12.5 Effect Connector

每种现实动作必须有适配器：

```text
prepare -> authorize -> reserve -> execute -> readback -> verify -> compensate/revoke
```

适配器需支持幂等、最小权限、目标域 readback、错误分类、补偿、撤销和证据哈希。没有 readback 的工具只能产生 Attempt，不得进入 Effect。

## 12.6 中心化与联邦边界

可以中心化：公共索引、候选生成、排序、排期、模型服务、事件转发、非敏感计算、确定性重复流程。

默认本地保留：完整私有世界、原生授权、拒绝、风险承担、数据使用边界、最终 Commitment、Acceptance 和不可数字化判断。

系统可以在技术上部署于一个云环境，只要它仍然保持这些语义与访问边界；反之，部署分散但由一个主体静默代行所有决定，不构成不可折叠的 A2A。
