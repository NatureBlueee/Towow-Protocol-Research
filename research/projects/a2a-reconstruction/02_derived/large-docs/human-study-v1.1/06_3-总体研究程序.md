# 3　总体研究程序

## 3.1 阶段 H0：历史事项校准

**目的。** 使用 12–20 个已经结束的 OPC 事项，校准数据字典、Relation Schema、materiality、Authority Locus、真实转折、成本和后悔，而不干预现实。

**材料。** 当事人访谈、项目聊天/邮件的脱敏摘录、报价与版本、交付记录、目标系统结果、复盘和后续结果。至少包含成交、不成交、交付失败、反悔、争议、临时联盟、平台足够和重复复用。

**产物。** 双人独立编码、事件图、真实 Authority map、候选竞争解释、历史截点任务、强基线 case packet。

**进入下一阶段 Gate。** 80% 以上 material event 可由独立编码者定位；核心数据缺失不集中于某一机制；数据采集不会要求参与者交出完整私有世界。

## 3.2 阶段 H1：前瞻性 shadow mode

**目的。** 观察真实事项，但系统不执行现实动作、不向外方发送消息、不创建付款或权限。

**建议规模。** 6–8 个 OPC，每个连续记录 3–5 个事项，持续 4–6 周；预计 24–32 个事项。事项可以由参与者日常产生，不要求人为制造。

**系统行为。** 形成 Authority map、Mandate 草案、RelationVersion、风险/Unknown、机制路由和下一 probe 建议；参与者继续按自己的方式处理事项。研究系统只做影子预测和过程记录。

**价值。** 检验数据标准可用性、Router false-heavy/false-collapse、Agent 对真实语境的理解、Mandate explain-back，以及系统建议与真实决策的差异。

**进入 H2 Gate。** 无未授权外发；事件链完整率 ≥ 95%；material condition recall 经独立裁决达到预设门槛；参与者未因记录负担大幅改变自然工作。

## 3.3 阶段 H2：低风险可逆现实 Effect

**目的。** 允许系统在受限范围内产生真实但可撤回的 Effect。

**建议规模。** 8–12 个事项，来自 4–8 个 OPC。每个事项只允许一个或少量低风险 Operation，例如创建/撤销只读凭证、预约、提交 sandbox 作业、生成并发送经确认的报价、在项目看板创建任务、支付有严格上限的小额 probe 费用。

**核心要求。** 每个 Operation 必须引用有效 Mandate、精确 RelationVersion、资源预留、Effect connector 和目标世界 readback。Agent 自述或工具退出码不构成 Effect。

**进入 H3 Gate。** 未发生 unauthorized Effect；所有 Effect 均可由目标域独立确认；参与者能解释发生了什么、为什么有权发生、怎样撤回或补救。

## 3.4 阶段 H3：跨责任根双边形成或临时联盟

**目的。** 检验多个真实 OPC/超级个体之间的关系形成、局部权威、能力组装和多 Agent 交互。

**建议规模。** 4–8 组双边/联盟事项；每组 2–4 个责任根。至少包含一个形成成功、一个真实拒绝/退出、一个需要数据或工具留在本地域、一个需要临时能力组装。

**典型任务。** 联合投标、短期定制服务、创作者品牌合作、数据驻留分析、联合内容/课程、资源交换、白标交付、小型跨域原型。

**进入 H4 Gate。** 至少一条路径满足因果形成判据；至少一次拒绝被系统正确保存而非视为失败；贡献、权利、时间、质量 witness、退出和 Acceptance 均可追溯。

## 3.5 阶段 H4：重复、编译与漂移

**目的。** 检验商业价值是否来自形成后的复用，而不只是第一次协商。

**设计。** 对已完成关系运行第二个相似事项；第三次有计划地注入一个 material change，例如预算阈值变化、合作方退出、数据用途变化、模型/工具升级、验收标准变化或时间容量下降。

**比较。** 持续开放协商、完全确定性重放、Compiled World + scoped reopen。

**主要结果。** 第二次运行的人类高认知时间、披露、确认与延迟；第三次 reopen 范围、漏开、过开、错误继续执行和最终后悔。
