# 14　数据采集流程

## 14.1 招募前筛选

研究人员使用七行 Case Card：

```text
事项是什么？
为什么现在没有直接完成？
谁拥有最终业务/预算决定？
谁拥有数据/安全/交付/接受决定？
价格以外最关键的三个条件是什么？
最小可逆现实动作是什么？
预计何时可以得到处置？
```

不足以识别真实权威或可逆 Effect 的事项暂不进入 live 阶段。

## 14.2 初始访谈

采用半结构化采访，不向参与者展示系统猜测。先冻结个人答案，再允许 Agent 生成结构。访谈包括：目标、成功/失败、已知候选、能力、资源、不可接受条件、角色、数据、风险、此前类似经历和当前可达路径。

## 14.3 Mandate explain-back

系统用自然语言展示：

- 可自主做的动作；
- 必须先问人的动作；
- 金额/时间/数据/对手方限制；
- 何时失效；
- 怎样撤销；
- 哪些结果仍需本人接受。

参与者不看原文复述。错漏 material item 时，系统必须修订并再次 explain-back。

## 14.4 过程采集

所有系统条件在统一事件包络中记录。人工决定通过简短 Stance 界面记录，允许自然语言理由和“不愿说明”。参与者可把某事实标记为 local-only；本地 Agent 只返回决策相关边界。

## 14.5 Effect 与 follow-up

Effect 发生后立即 readback；24 小时内收集 Adoption/Acceptance；T+7 检查履行、撤回和新 Defeater；T+30 检查长期接受、后悔、复用和关系变化；高价值关系可 T+90。
