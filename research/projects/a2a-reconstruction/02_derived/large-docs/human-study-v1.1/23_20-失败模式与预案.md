# 20　失败模式与预案

## 20.1 招募困难

先扩大 H0 历史材料和 H1 shadow，使用撮合者、顾问和独立创业社群作为入口。不要降低事项真实性来追求数量。

## 20.2 参与者不愿填写结构

以访谈和自然工作流采集，由系统生成结构并让参与者确认差异；不要求参与者学习协议字段。

## 20.3 事项太标准

作为 Router 负控制保留，不强行制造 A2A。标准任务本身是必要证据。

## 20.4 事项太复杂或高风险

拆成最小可逆 probe；若仍无法封顶风险，转为 shadow/historical，不执行。

## 20.5 Agent 没有产生新路径

这不是失败。比较其是否提高真实处置、减少错误或更快拒绝；若强基线等价，缩小形成主张。

## 20.6 人类经纪优于系统

记录经纪使用了哪些隐性判断、信誉和关系；把经纪作为正式机制接入 Router，研究 Agent 如何减少其重复工作而不是替代全部判断。
