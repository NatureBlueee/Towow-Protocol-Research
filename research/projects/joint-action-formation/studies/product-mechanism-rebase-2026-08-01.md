# 从研究工具回到产品机制：2026-08-01 纠偏

状态：`ACTIVE_PRODUCT_CHAIN_REBASE / THREE_PARALLEL_RETURNS_INTEGRATED`

## 决定

机制比较是研究工具，不是通爻产品能力。它的唯一用途是帮助决定：产品内部直接采用什么成熟
机制、怎样组合、删除什么复杂度，以及哪个精确位置仍需完整创新。用户不会使用一套通用盲比较
平台；用户要的是一个模糊目标最终能否形成真实合作并被完成。

因此，任何新比较在启动前必须绑定一个明确的产品决定。若无法说明实验结果会改变哪一个产品
行为、接口、状态、依赖或机制选择，实验不得成为主研究任务。

## 保留的发现

此前比较研究仍保留其产品价值：

- 强中心在部分条件下更简单、更好；
- 成熟组合能够承担授权、执行、回读、撤销和恢复的有界能力；
- 偷看答案、controller 代做和 evaluator 错误可以制造假成功；
- RAG、目录、ARD 和 Agent Card 只覆盖已经表达、可索引的对象。

这些发现用于改变产品机制，不用于证明评价基础设施本身是产品。

## 已确认的漂移

Wave025 后半段把通用盲比较、复杂 feature、C01--C05、3,200 样本、byte-level 数学和收据门禁
逐渐当成连续主目标，却没有持续绑定它们正在决定的具体产品机制。这是“形式越来越完整，用户
问题没有更接近解决”的复发信号。

Wave025 从现在起定位为内部研究工具：保留已经发现的假绿、局部方法和失败；停止通用 3,200
系统、MODEL-INPUT、通用 classifier、数学 wrapper 与收据门禁的**无条件主动补齐**，先逐项
评估其必要性。若某个具体产品选择确实缺少这些证据，应按足以支撑该决定的完整范围恢复并做好；
不能为了纠偏而省略必要的评测能力。

网络安全、隔离绕过、权限攻击面和真实利用另按 `SECURITY-REVIEW-BOUNDARY.md` 交由安全人员，
本研究 Agent 不继续处理，也不作安全结论。

## 产品主链

七条母线共同服务同一条产品链：

```text
模糊目标
→ 发现缺失条件
→ 有控制地请求必要信息
→ 生成新的合作可能性
→ 找到或培养合适能力
→ 取得同意与授权
→ 形成关系和承诺
→ 执行真实行动
→ 验证 Effect
→ 获得 Acceptance
→ 失败、拒绝或变化时重新开放
```

七条母线是这条链上不同问题的共同研究视角，不是七套独立评价系统。

## 比较的准入问题

每项机制比较启动前只需回答五个问题；答不出来就不启动：

1. 对应哪一个真实用户任务和产品链节点？
2. 正在决定哪个具体产品机制或交互行为？
3. 竞争的成熟单项、组合和更简单方案是什么？
4. 哪个可观察结果会导致采用、组合、删除或创新？
5. 得到决定以后为什么应停止，而不是继续扩建实验室？

比较结束必须产生产品决定：`ADOPT / COMPOSE / REMOVE / INVENT / KEEP_UNKNOWN`。其中
`KEEP_UNKNOWN` 必须说明缺少的条件怎样创造；不能成为无限扩建通用评测的理由。

## 评测设施必要性门

评测设施本身也要接受产品价值审查。满足以下条件时，应建设或继续完善，而不是因其属于
“基础设施”就停止：

1. 它防止一种已经发生、且会改变产品机制选择的假绿或错误因果归属；
2. 直接用户任务结果不足以区分竞争机制，而该设施能产生有区分力的证据；
3. 错误选择的用户、工程或治理代价显著高于设施成本；
4. 设施能被多个具体产品决定复用，而不是只服务于形式完整；
5. 有明确的充分条件和停止点，完成决定后不会继续自我扩张。

当前初步分层不是最终删除决定：

| 设施 | 当前必要性判断 | 对应产品决定 |
|---|---|---|
| 独立 Effect/readback/Acceptance 与假绿回归 | `CORE_NECESSARY` | 判断一次合作是否真的完成、被谁接受，防止 controller/模型自证 |
| 真实任务 replay、拒绝/撤销/恢复记录 | `CORE_NECESSARY` | 判断产品链能否安全复用和重开 |
| 披露量、询问轮次、漏机会、误唤醒与完成率测量 | `CORE_NECESSARY` | 选择澄清、推断、目录、probe 与渐进披露的产品组合 |
| 通用 3,200 blind comparison | `CONDITIONAL_NOT_CURRENTLY_JUSTIFIED` | 仅当具体产品机制选择依赖该统计区分且更小任务评测不足时恢复 |
| 通用 feature/C01--C05/model-input | `CONDITIONAL` | 仅当产品决定确实依赖自动泄漏分类或同类预测能力；网络安全部分另交安全人员 |
| byte-level deterministic math | `CONDITIONAL` | 仅当跨 provider 精确复现会改变所选产品机制或证据可接受性 |
| 自动 receipt promotion/deletion gate | `CONDITIONAL` | 仅当产品需要自动改变正式状态；否则由外部权威或用户决定 |

这张表必须随产品任务证据更新。`CONDITIONAL` 不是“不做”，而是“先出现它负责的产品决定，
再按该决定所需强度做完”。

## 三线综合结果

产品旅程、机制组合与评测必要性已由三条并行线分别重建，并在
[`product-chain-t1-t3/SYNTHESIS.md`](./product-chain-t1-t3/SYNTHESIS.md) 综合。工作目录名保留了
启动时的历史称呼，但当前正典对象是 PT-001，不是旧 T3 证据。

当前结论不是“停止评测设施”，而是：

- 真实任务前态、fresh truth/solver separation、owner/Target 原生证据、独立 Effect/readback/
  Acceptance、base-episode failure replay 和产品 completion/reopen gate 为
  `CORE_NECESSARY`，应继续建设；
- targeted statistics、局部 byte determinism、RelationVersion 与 reciprocal probe 依产品残余
  为 `CONDITIONAL`，触发后应按决定所需范围做完整；
- 通用 3,200、C01--C05、MODEL-INPUT、全臂 tournament 和自动研究 promotion/deletion gate
  当前为 `NOT_JUSTIFIED_YET`，但保留已有材料，未来可由命名产品决定重新触发；
- 当前没有新机制获得 `INVENT` 晋升。未表达机会形成与自动 scoped reopen 是
  `KEEP_UNKNOWN`，不因 Unknown 而停止理论、组合和模拟研究。
