# 现有技术优先：不以证明通爻独占或特别为目标

日期：2026-07-28  
状态：`ADOPTED_RESEARCH_DIRECTION`  
来源：用户校正——“通爻独占不重要，能够用现有技术实现就可以；既然他们都有，为什么他们
没有解决我们提出的问题？”

## 核心校正

通爻研究不以证明通爻原创、独占、不可替代或“特别”为目标。

已有标准、平台、算法、人类流程或它们的组合能够完整满足要求时，应直接采用。若采用现成
方案已经解决原始问题，研究成功，不因通爻没有保留独立机制身份而降级。

真正需要回答的问题改为：

> 已有能力分别存在时，为什么它们尚未共同产生多个独立 Principal 能够安全形成、执行、
> 验收并持续维护新关系的结果？剩余原因究竟是缺少技术能力、组合责任、产品实现、经济
> 激励、制度条件、现实授权，还是原要求包含原则上不能由系统替主体完成的部分？

“市场上没有一个叫通爻的完整产品”不是缺口证据。“我们能为每个子问题找到一个技术”也
不是原问题已经解决的证据。必须检查完整任务的权威事实、状态转换、失败恢复、主体认领和
生命周期净价值。

## 已有零件为什么可能仍未形成完整结果

1. **前提不同**：检索、工作流、授权、规划和事务系统通常从已定义的对象、角色、动作、
   目标或 authority root 开始；开放关系形成面对的是其中若干项尚未确定、不可安全汇聚或
   需要主体共同决定的情况。
2. **事实分属不同权威域**：身份系统、policy engine、workflow、目标业务系统和 Principal
   各自只拥有局部事实。认证或 `Allow` 不自动构成 Commitment，ActionAttempt 不自动构成
   Effect，Effect 不自动构成 Adoption、Acceptance 或 Settlement。
3. **组合不等于责任闭环**：现有组件可以被项目制集成，但字段映射、例外、责任、证据、
   版本失效和恢复往往仍由会议、合同、人工判断与专用 adapter 重新形成。
4. **经济与产品激励不同**：成熟平台优先优化高频、标准化、受自身控制的关系。低频、长尾、
   跨平台、跨专业和跨权威关系可能技术上可做，却因首次规则形成、责任和治理成本而没有成为
   通用产品能力。
5. **存在不可代行部分**：系统可以帮助发现、解释、比较、记录、阻断和执行，但不能凭空
   创造真实意愿、合法权威、社会信任或主体 Acceptance。

以上只是竞争解释，不是已经证实的通爻缺口。

## 后续研究纪律

每条研究线默认执行以下顺序：

1. 找到最强现有标准、平台、中心方案、人类流程和可复用 adapter；
2. 在相同信息、工具、权限、预算、风险与验收条件下建立“最佳现有组合”基线；
3. 运行完整任务，定位第一次需要重新定义关系、跨越权威、人工补语义或承担未归属责任的
   位置；
4. 区分剩余问题属于技术缺口、组合缺口、实现缺口、经济缺口、制度缺口、采用缺口，还是
   不可代行边界；
5. 只有当现有组合在公平条件下留下稳定、可复现、会改变结果的责任断点时，才提出最小
   `EXTEND`；不得从“没有现成一体化产品”直接推出新机制必要性；
6. 若现有组合等效或更优，则 `ADOPT / COMPOSE / CLOSE`，并删除多余对象或把通爻降为
   adapter、集成方法、运行配置或产品体验，不为保留名称稀释负结果；
7. 无论采用何种实现，继续区分 Capability、Mandate、Commitment、Execution、Effect、
   Adoption、Acceptance 与 Settlement，防止局部绿灯冒充原始问题解决；
8. 最终比较完整生命周期净价值，而不只比较模型费用、代码量、组件数量或演示成功率。

## 最强组合基线

后续端到端研究至少允许以下现有能力在同一基线中充分组合，而不是逐个建立稻草人：

- 检索、RAG、Agent/Service Card 与目录；
- VC、OAuth/GNAP、XACML、RBAC/ReBAC 与审批；
- BPMN/CMMN、case management、规划、HITL 与人工 amendment；
- negotiation/commitment protocols、合同与组织流程；
- event sourcing、workflow history、Saga/补偿与独立 readback；
- version/migration、revocation、telemetry 与人工恢复；
- 强中心平台、成熟 SaaS、顾问、项目经理和领域专家。

比较必须给予中心、人类和成熟平台真实优势。若它们在同等条件下已经完整解决任务，就不再
寻找“通爻特有部分”。

## 判别结果

| 观察结果 | 研究处置 |
|---|---|
| 最佳现有组合完整解决原问题，成本与风险可接受 | `ADOPT`；关闭相应新机制主张 |
| 只需清楚 adapter 或编排即可闭环 | `COMPOSE`；通爻最多是实现/集成方案 |
| 存在稳定、可复现且影响结果的责任断点 | 只对该断点提出最小 `EXTEND` |
| 技术可行但组织、商业或采用条件不成立 | 记录为经济/制度/采用问题，不伪装成协议缺口 |
| 缺少真实授权、意愿、信任或 Acceptance | 保持主体决定与 HITL，不声称自动形成 |
| 新组合增加的协调、验证和治理成本高于价值 | `CLOSE / DEFER`，接受中心、平台或人类更好 |

## 下一项承重实验

选择一个低风险但完整的跨权威关系任务，先实现并运行“最强现有组合”，而不是先实现新的
通爻机制。冻结：

- 原始需求与不可接受底线；
- 各 Principal、authority root、局部私有信息与拒绝权；
- 最佳现有组件及其 adapter；
- Capability 到 Acceptance 的逐段权威 readback；
- 会议、等待、集成、披露、验证、治理、恢复和认知成本；
- 第一次责任断点，以及移除任何候选通爻增量后的反事实。

只有该基线无法闭环且残差可复现时，才讨论通爻的最小新增责任。该实验的目标是解决问题，
不是证明通爻特别。
