### 1.3 外部现成方案核验状态

按用户后续明确指示，已改用环境自带网络通道，并只采用官方标准页、会议/期刊论文页、
作者/机构论文页。2026-07-28 实际核验到：

- OMG 当前规格页列出 [BPMN 2.0.2](https://www.omg.org/spec/BPMN/)；BPMN 提供业务流程
  的标准 notation、语义与 machine-readable schema。更重要的是，OMG 对
  [CMMN](https://www.omg.org/cmmn/) 的官方说明明确把它定位为 Adaptive Case
  Management：围绕 living information and relationships、由人保持决策权，并处理因
  evolving situations 而以不可预测顺序发生的活动。这使“现有流程方案只会执行预定义
  固定序列”成为不成立的弱基线。
- FIPA 官方的[当前标准清单](https://www.fipa.org/repository/standardspecs.html)列有
  Request、Contract Net、Iterated Contract Net、Brokering、Recruiting、Propose 等
  interaction protocols，以及 ACL、communicative acts 和 transports。
- 近期一手协议研究也覆盖了比“固定 FIPA 状态机”更强的能力：
  [Tango](https://www.ijcai.org/proceedings/2021/55)用 causality/integrity constraints
  支持异步、灵活重排的 enactment；
  [Langshaw](https://www.ijcai.org/proceedings/2024/23)用 `sayso` 表达谁对每个属性有
  设置优先权，用 `nono/nogo` 表达动作冲突，并生成适于异步 enactment 的消息协议。
- [SharedPlans 原论文](https://www.ijcai.org/Proceedings/93-1/Papers/052.pdf)不仅处理
  多主体复杂行动和 contracting out，还明确把协作规划视为持续细化 partial plan 的过程；
  因而不能再概括成“只处理完全预定义计划”。
- [Matching with Contracts 原论文页](https://www.aeaweb.org/articles?id=10.1257%2F0002828054825466)
  覆盖异质合同项、匹配、替代条件与 truthful worker-offering 算法，但研究对象仍是给定
  matching-with-contracts 模型内的配置与稳定性。
- [Dantzig–Wolfe 原论文记录](https://www.mathnet.ru/eng/mat300)、
  [Benders 原论文 DOI](https://doi.org/10.1007/BF01386316)和
  [Combinatorial Sketching/CEGIS 源论文入口](https://people.eecs.berkeley.edu/~sseshia/pubs/b2hd-solar-asplos06.html)
  确认了分解、局部子问题/切割/列和候选—验证—反例修复的成熟方法来源。
- Planning 也不只是在完整固定 action model 中搜索：
  [ARMS](https://auld.aaai.org/Library/ICAPS/2005/icaps05-025.php)从不完整 plan
  examples 学习 action model；
  [Learning STRIPS Action Models with Classical Planning](https://ojs.aaai.org/index.php/ICAPS/article/view/13870)
  接受部分指定的 action models；
  [Planning with Uncertain Action Models](https://ojs.aaai.org/index.php/AAAI/article/view/40954)
  研究执行动作后才获知 effect 的不确定模型。

核验边界：

- 这些来源足以证明强基线家族真实存在，并迫使 02/03 缩窄问题；
- 没有对具体商业平台做登录态功能测试，也没有证明标准实现自动提供通爻所需的
  Principal、Mandate、target readback、因果消融或净值；
- 因此可将 `prior_solution_review` 写为 `PRIMARY_SOURCES_REVIEWED / EXTEND`，不能写成
  “现成方案无覆盖”或“通爻机制必要性已成立”。

## 2. Line 02 — RELATION_CONSTITUTION

### 2.1 当前真实状态

旧 `LINE-02-RELATION-CONSTITUTION v0` 标记为 `ACTIVE`，但它绑定
`problem/v0.json`，不是 Problem v2 的活动合同。其五项历史能力并不处于同一状态：

| 能力 | 历史审计 | V2 覆盖 | 当前含义 |
|---|---|---|---|
| `CAP-REL-001` | `PARTIAL` | `EXPLICIT` | Relation Schema / material change 已有表示；从冷启动原始输入识别 materiality 未证明 |
| `CAP-REL-002` | `PRESERVED` | `EXPLICIT` | material change 新建版本、旧 Stance 不继承，可作为必须维持的不变量 |
| `CAP-REL-003` | `PARTIAL` | `EXPLICIT` | 版本可保留；多作者 contribution edge、局部来源与 Authority 回放不完整 |
| `CAP-REL-004` | `LOST` | `ABSENT` | 本地生成私有 candidate/column、只提交最小改善见证，没有当前明确 owner |
| `CAP-REL-005` | `PRESERVED` | `EXPLICIT` | candidate 不得越过 Authority Gate，可作为不变量 |

结论：这不是“关系构成机制整体待证明”，而是至少三个不同问题：

1. 冷启动时，何时是参数更新，何时是权威相关的关系 schema 变化；
2. 多来源共同对象怎样不吞掉局部范围、反对与精确版本；
3. 当行动集不能安全汇聚或枚举时，local-column 接口是否带来可测价值。

第 1、3 项可以立即启动；第 2 项应作为 provenance/stance 的验收维度，而不必先假定需要
新的顶层引擎。

### 2.2 最承重 scoped question

> 在同一冻结 Intent 与价值底线下，当新输入改变的是角色、可行动作、Authority、
> 证据义务或退出条件，而不仅是已有字段的值时，什么最小可观察证据足以要求新的
> `RelationVersion` 并阻止旧 `Stance` 继承；这个判别是否比
> “成熟工作流/案例管理 + amendment + HITL”或“authority-aware strong center”
> 更准确或更低总成本？

这比“关系能否被共同构成”更承重，因为判错的两个方向都会破坏后续研究：

- 把 schema change 当参数更新，会把旧认领错误套到新现实；
- 把普通参数更新都当新关系，会制造无穷版本、审批和治理成本。

`CAP-REL-004` 应另立 scoped question：

> 在主体的行动集私有、非枚举或只能本地验证时，local column/counterexample 接口是否
> 比中心全量收集、静态搜索和“不可行”终止，增加合格路径召回或减少必要披露？

### 2.3 现成方案 disposition

建议：`EXTEND`，但必须按能力拆分，不能把所有现成方案合成一个稻草人。

| 现成方案族 | 已覆盖部分 | 尚未关闭的差异 | disposition |
|---|---|---|---|
| SharedPlans、commitment/information protocols、FIPA | SharedPlans 支持 partial plan 的持续 refinement、复杂多主体行动和 contracting out；FIPA 有完整协议族；Tango/Langshaw 支持异步灵活 enactment、属性 sayso 和冲突 | 是否从原始开放输入盲判 schema materiality，并把真实 Authority/责任变化绑定到精确版本，仍需实测 | `REUSE + NARROW TEST GAP` |
| BPMN/CMMN、成熟 workflow/case management、RBAC/approval | CMMN 官方就覆盖 evolving situations、不可预测活动次序、living information/relationships 与 human-in-the-loop；足以成为 02 的最强基线 | `REL-002/005` 很可能大部可复用；是否保留跨独立 Authority root 的局部反对、不可汇聚行动集及 causal provenance 待测 | `REUSE FIRST / STRONG BASELINE` |
| event sourcing / versioned IR / provenance graph | 精确版本、事件来源、旧状态回放 | 不负责决定一次变化是否 material，也不自动产生多方认可 | `REUSE` |
| Dantzig–Wolfe / column generation、Benders | 私有/局部子问题返回改善列、切割或不可行见证 | 正式优化通常假定问题结构、诚实 oracle 和可计算目标；社会主体可拒绝、策略隐瞒且有 Authority | `EXTEND` for `REL-004` |
| CEGIS | 候选—反例—修复闭环 | 反例是否有权阻断、谁能改现实、何时形成承诺不由 CEGIS 本身解决 | `REUSE AS METHOD` |
| Matching with Contracts | 合同项、匹配与选择函数 | contract language、角色与 choice function 通常预先给定 | `REUSE WITH BOUNDED GAP` |

尚未被现成方案审计关闭的联合缺口是：

> 在 Authority 与信息不可安全汇聚的条件下，冷启动识别“关系语法发生了实质变化”，
> 保留多来源/局部反对/精确版本，并在行动集不能集中枚举时允许本地产生最小候选见证。

这仍只是待检验缺口，不是“独立 Relation Constitution Engine 已被证明必要”。

### 2.4 最强反例

最强反例不是一个糟糕中心，而是：

> 一个 authority-aware strong center 或成熟 case-management 平台，在相同信息、工具、
> 查询预算和拒绝权下，允许动态 schema amendment、精确版本 Stance、贡献来源、局部
> visibility 和 Authority Gate；它对所有测试案达到相同或更高保真，且总治理成本更低。

本地已有具体负控：NASA HLS 式固定采购 schema。若任务的角色、选择规则、审批与验收
本来就由正式制度预编译，复杂协作仍应路由到 `STATIC_PLATFORM` /
`CENTRAL_WORKFLOW`；除非被检验的是授权规则本身的改变，否则不构成关系构成正例。

另一个针对 `REL-004` 的反例是：共享求解器只需得到合法的摘要约束或安全多方计算结果，
不需要一个通爻特有的 local-column 协议；或 local column 因策略性遗漏导致更高假阴性。

### 2.5 最小可证伪判别

#### 判别 A：materiality router

冻结同一组案例、原始 Intent、authority/provenance、允许查询和成本口径。案例必须同时含：

- 参数更新：值、时间、数量变化但角色/动作/Authority/证据/退出语法不变；
- schema 变化：至少一项角色、允许动作、Authority、证据义务、退出/恢复规则变化；
- 对抗例：同义改写伪装成 schema change；实质变化伪装成字段更新；
- 固定制度负控：正式平台已完整预编译。

公平比较三臂：

1. 成熟 workflow/case amendment + HITL；
2. authority-aware strong center，可动态修改 schema；
3. RelationVersion / constitution candidate。

最小成功条件不是“第三臂会建新版本”，而是同时满足：

- 对 material change 的盲判别优于或补足基线；
- 旧 Stance 不被继承；
- contribution source、scope、未决反对可回放；
- 参数更新不过度重开；
- 总成本包含查询、人时、披露、误判、迁移与治理。

只要强中心/平台在同等条件下等效或更好，独立 constitution-layer 必要性即失败或缩窄。

#### 判别 B：local column

冻结一个中心不能直接枚举的私有行动集与可验证的全局目标。比较：

1. 中心请求全量行动集；
2. 静态摘要/约束；
3. 本地 oracle 只返回改善列、阻断反例或最小不可行见证。

至少测：合格路径召回、错误无解率、披露量、查询轮数、策略性遗漏、计算与治理成本。
移除 local generation 后若结果、披露和错误率不变，`CAP-REL-004` 的独立增量失败。

### 2.6 建议 V2 target / claim / hypothesis

建议不要注册一个包办五项能力的“Relation Constitution”新机制。先建立两个
`HISTORICAL_CAPABILITY_FAMILY` 类型的研究 target 候选：

#### Target 02-A：Material Relation Versioning

- `kind`: `HISTORICAL_CAPABILITY_FAMILY`
- `scoped_claim_id`: `CLM-REL-MATERIAL-VERSION`
- claim：
  在角色、动作语法、Authority、证据义务或退出条件发生实质变化时，必须创建新的
  `RelationVersion`，旧版本 `Stance` 不得自动继承；该 claim 不指定中心、联邦或平台拓扑。
- `hypothesis_id`: `H-REL-MATERIALITY-ROUTER`
- hypothesis：
  在盲化的参数变化/schema 变化/固定制度负控上，显式 materiality router 能在保留
  source、scope、version、局部反对的同时，较最强平台/中心基线降低承重误判或总成本。

#### Target 02-B：Private Local Column

- `kind`: `HISTORICAL_CAPABILITY_FAMILY`
- `scoped_claim_id`: `CLM-REL-LOCAL-COLUMN`
- claim：
  当行动集不能安全汇聚或中心枚举时，本地节点可以只返回改善当前解的 candidate/column、
  阻断反例或最小不可行见证，不因此产生承诺。
- `hypothesis_id`: `H-REL-COLUMN-VALUE`
- hypothesis：
  在冻结的私有/非枚举行动集上，local column 较全量收集与静态摘要提高合格路径召回或
  降低必要披露；移除 local generation 后该增量消失。

### 2.7 不可影响主张

任一结果都不得自动影响：

- Problem v2 的开放行动世界是否整体成立；
- NAC/Discovery 的 embedding、召回或跨模型主张；
- Possibility Formation 是否真实发生；
- Capability、Mandate、Commitment、Operation、Effect、Adoption、Acceptance 的成立；
- 中心、联邦、平台或混合拓扑的普遍优越性；
- `CAP-REL-002`、`CAP-REL-005` 已保留不变量的历史状态；
- 未纳入运行的 `REL-001/003/004` 其他子主张；
- 真实主体已认领关系、授权行动或接受后果。

### 2.8 启动决定

`ACTIVE`，但只表示：

- 可以立即补 V2 LineContract 候选和正式 prior-solution review；
- 可以从历史材料构造 materiality 的非评测 fixture；
- 可以恢复 `REL-004` 的最小接口/实验设计；
- 不能将旧 `v0 ACTIVE` 当成 V2 controller 已激活；
- 在官方一手方案复核、冻结场景和公平基线之前，不能 finalize 强机制结论。

## 3. Line 03 — POSSIBILITY_FORMATION

### 3.1 当前真实状态

旧 `LINE-03-POSSIBILITY-FORMATION v0` 同样只绑定 Problem v0。历史能力状态为：

| 能力 | 历史审计 | V2 覆盖 | 当前含义 |
|---|---|---|---|
| `CAP-FORM-001` | `PARTIAL` | `PARTIAL` | Unknown 可记录，但到 ask/probe/tool/partner/authority/rewrite/exit 的可执行路由未闭合 |
| `CAP-FORM-002` | `PARTIAL` | `EXPLICIT` | S0/operator/S1/ablation 有 R5C 技术证据；无真人 Principal 与匹配中心 |
| `CAP-FORM-003` | `PARTIAL` | `PARTIAL` | countercondition 可表示；现实频率、策略操纵和坏信号未测 |
| `CAP-FORM-004` | `TRANSFORMED` | `EXPLICIT` | 已迁入 Operation + Effect 的 probe/readback；证据仅本地 holdout |
| `CAP-FORM-005` | `PRESERVED` | `EXPLICIT` | 开放形成、稳定编译、局部重开规则存在；现实净值未知 |

现有正负证据必须同时保留：

- R5.4：主缺陷与冲突在交互前已存在；A2A 使规范条件更清楚，但未签署、未实现、未采用。
  这是“更多高质量对话不等于 formation”的直接负例。
- R5C：在合成、本地、技术权威域，probe、权威拒绝、最小 countercondition、目标域
  readback、撤销与恢复共同创建了一条此前不存在的路径；producer-only 与
  wrong-authority 控制没有 projection。
- R5C 不能说明真人偏好、客户 Adoption、商业价值、生产就绪或一般 A2A 能力；匹配的
  strong-central formation 没有运行，互动独特性为 `UNKNOWN`。

因此 PFE 当前最合适的身份仍是候选 policy/router/method family，不是正式事实根，也不是
每个 Intent 必经的顶层引擎。

### 3.2 最承重 scoped question

> 在冻结同一目标与价值底线 \(Q\)、前态 \(S_0\)、合格路径判据和 Authority/Effect
> 约束后，一个可归因 operator 是否第一次创造了合格路径；还是它只发现了隐藏路径、
> 细化了规范、调用了既有工具、降低了目标，或执行了强中心同样会做的普通 amendment？

次级承重问题：

> 对 typed Unknown，什么可观察条件足以选择 search、ask、probe、tool、partner、
> authority、rewrite 或 exit；这个 router 是否比强中心规划器 + HITL 带来更高成功率
> 或更低失败/治理成本？

### 3.3 现成方案 disposition

建议：`REUSE_AND_EXTEND`。

| 现成方案族 | 已覆盖部分 | 尚未关闭的差异 | disposition |
|---|---|---|---|
| 搜索、AI planning / replanning / action-model learning | 不仅在给定模型内搜索；ARMS、STRIPS action-model learning 和 PUMA 已覆盖从不完整案例学习模型、部分模型验证和执行后获知 action effect | 这些方法仍不自动获得现实 Authority、伙伴、资源或 target acceptance；但已显著缩窄“模型不完整所以需要 PFE”的主张 | `REUSE FIRST / STRONG BASELINE` |
| CEGIS | 反例驱动候选修复 | 通常修复候选/程序，不自动证明现实 Authority、资源或 Effect 条件被创建 | `REUSE AS METHOD` |
| Benders / column generation | 通过局部切割/列逐步扩大可行解表示 | 正式模型的可行域变化与社会世界中的授权/资源条件创造不同 | `REUSE WITH GAP` |
| workflow/case amendment + HITL | 人类补条件、改规则、加审批、调用工具 | 可能等效覆盖大量 formation；必须作为强基线，而不是被排除 | `REUSE / BASELINE` |
| multi-agent negotiation / commitment protocols | 提议、拒绝、counter、承诺状态 | 交互可细化条件，但 R5.4 已证明它不自动形成可达路径 | `REUSE, NO FORMATION INFERENCE` |

未关闭的局部缺口是：

> 一个 typed Unknown router 能否识别“缺的不是更多搜索，而是必须改变可归因现实条件”，
> 选择低风险可逆 operator，并用 target-authoritative readback 与消融证明新路径出现。

如果强中心规划器 + HITL 在同等权限、工具、信息和预算下完成相同 operator，PFE 仍可作为
过程表示，但其独立机制或 A2A 特有价值应降级。

### 3.4 最强反例

最强反例由五种竞争解释组成：

1. **隐藏路径**：路径在 \(S_0\) 已存在，只是首次搜索没有找到；
2. **目标偷换**：operator 通过降低原始价值底线，使较差路径冒充新合格路径；
3. **文本增量**：只增加说明、条款或对话，没有签署、权限、代码、资源或目标后条件变化；
4. **普通中心 amendment**：拥有同等局部工具和 Authority 的强中心/HITL 会执行相同动作，
   成本更低；
5. **错误归因**：实际变化来自更强模型、新代码、实验者整合或额外权限，而不是被声明的
   formation operator。

R5.4 具体支持第 1、3、4 种替代解释不能被忽略；R5C 又明确承认更强模型、新代码与根
实验者整合是 confound。

### 3.5 最小可证伪判别

#### 判别 A：R5C 因果重放

冻结：

- 原始 \(Q\) 与不可降低的价值底线；
- \(S_0\) 的实际可达路径枚举/测试；
- operator 的精确内容、执行者、Authority、输入与时间；
- 合格路径的 target-authoritative postcondition；
- same-information / same-tools / same-budget 的比较条件。

至少比较：

1. no-op / static search；
2. strong-central planner + HITL；
3. PFE/formation policy；
4. wrong-authority；
5. producer-only；
6. remove-operator 或 recovery/readback ablation。

成功必须同时看到：

- \(S_0\) 下不存在合格路径；
- operator 后 \(S_1\) 首次出现同一 \(Q\) 的合格路径；
- target authoritative readback，而非 producer 自证；
- 移除 operator、错误 Authority 或 producer-only 时失败；
- 对新代码、模型强度、人工整合、查询/人时/失败恢复做总资源核算。

若 strong center 以相同或更低成本形成同一路径，`formation happened` 仍可能成立，但
“PFE/A2A 独有或更优”失败。若移除 operator 仍可达，则 formation claim 失败并改判
discovery 或 ordinary execution。

#### 判别 B：typed Unknown router

构造盲化案例，真实缺口分别为：

- 信息缺失；
- 工具/技能缺失；
- 伙伴缺失；
- Authority 缺失；
- 现实 probe 才能判定；
- 任务表示错误；
- 主体明确拒绝；
- 原则性不可达。

比较固定追问、搜索/规划、强中心 + HITL 与 typed router。测量正确路由、合格路径、
不必要披露/打扰、误授权、无效循环、退出质量和总成本。若 router 只是增加分类文本，
没有改变动作或结果，则 `CAP-FORM-001` 增量失败。

### 3.6 建议 V2 target / claim / hypothesis

建议以现有历史方法族为 target，不预注册新的事实根：

#### Target 03-A：Causal Condition Formation

- `kind`: `HISTORICAL_METHOD_FAMILY`
- `scoped_claim_id`: `CLM-FORM-CAUSAL-CONDITION`
- claim：
  在冻结 \(Q\)、\(S_0\)、Authority 与合格路径判据后，可归因 operator 可以通过改变
  权限、工具、伙伴、任务表示或 Effect 条件，使此前不存在的合格路径第一次出现；
  formation 必须由 pre/post/readback/ablation 共同支持。
- `hypothesis_id`: `H-FORM-R5C-CENTRAL-REPLAY`
- hypothesis：
  R5C 的最小 authority/recovery/readback operator 在相同信息、工具和预算的
  strong-central 重建中仍是路径出现的必要条件；结果只支持本地技术域，不支持人类价值。

#### Target 03-B：Typed Unknown Action Router

- `kind`: `HISTORICAL_POLICY_FAMILY`
- `scoped_claim_id`: `CLM-FORM-TYPED-ROUTER`
- claim：
  Unknown 应按可观察缺口路由到 ask/probe/tool/partner/authority/rewrite/exit，而不是
  统一追问、统一搜索或统一 formation。
- `hypothesis_id`: `H-FORM-ROUTER-NET-VALUE`
- hypothesis：
  在异质 Unknown 案例上，typed router 较固定追问、搜索和 strong-center + HITL，
  以更低总成本获得更多合格结果或更少误授权/无效循环。

### 3.7 不可影响主张

任一结果都不得自动影响：

- Relation Constitution、NAC/Discovery 或其他未运行研究线；
- 某主体拥有能力、Mandate、Commitment 或愿意承担责任；
- technical Effect 等于 human Recognition、Adoption、Acceptance 或商业价值；
- PFE 是顶层引擎、所有 Intent 必经环节，或 A2A/联邦优于中心；
- R5C 已经证明真人 Principal、生产就绪、跨组织普遍性或长期净值；
- `CAP-FORM-004` 在本地技术域外的有效性；
- `CAP-FORM-005` 的现实复用净值；
- 未列入本次 hypothesis 的历史 FORM 子主张。

## 4. 两线之间的切分规则

两线必须互相施压，但不能互相吞并：

| 观察 | 归属 |
|---|---|
| 已有 schema 内找到未见候选 | discovery/search，不是 02 或 03 自动正例 |
| 角色、动作、Authority、证据或退出语法发生 material change | 02 的 RelationVersion/materiality |
| 本地只返回改善列或阻断反例 | 02 的 `REL-004` 方法能力 |
| 可归因 operator 改变条件，使同一 Q 下首条合格路径出现 | 03 的 causal formation |
| 只是规范更清楚、更多对话、更多文档 | 非 formation |
| candidate 通过 Authority Gate 成为 commitment | 05 Authority/Norms；不是 02/03 单独可认定 |
| target domain 出现权威后条件 | 06 Effect；可作为 03 的 formation 证据组成，但不是同一概念 |

一个 episode 可以同时包含 02 和 03，但返回必须分别落到 claim—hypothesis—capability，
不能用“整体成功”抹平冲突：

- schema 可能被正确重开，但没有新路径；
- 新路径可能通过既有 schema 的授权或工具变化出现，无需新 RelationVersion；
- local column 可能提高候选召回，却没有任何主体承诺；
- formation 可能成立，但 strong center 更便宜，因此 PFE 的部署价值为负。

   hypothesis、unaffected claims、强基线和 stop condition。
