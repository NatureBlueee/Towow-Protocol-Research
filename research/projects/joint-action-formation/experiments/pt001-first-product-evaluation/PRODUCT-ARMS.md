# PT-001 第一轮产品评测：D1/D2 竞争产品行为

日期：2026-08-01  
状态：`FIRST-RUN DESIGN / SYNTHETIC TASK / NO ORACLE ACCESS / NO SECURITY CLAIM`

## 1. 这次比较要决定什么

本轮只服务两个产品决定：

- **D1：**系统怎样从模糊目标形成用户仍然认领的可修改目标草稿；何时追问、提出假设、读取
  已许可上下文、转人工或保持 `UNKNOWN`。
- **D2：**系统怎样从已确认的目标草稿发现可行路径；何时直接旁路到标准平台，何时只搜索已
  表达目录，何时请求本地 task-relative projection，何时才有理由发起 reciprocal probe。

比较对象是用户实际经历的**产品行为**，不是模型文风、协议对象数量或通用实验设施。输出可以是
条件化组合，不要求选出一个对所有任务都最好的全局冠军。

本文件不包含也不推测未来 `TASK-ORACLE` 的任何具体答案。所有 arm 只能读取运行时明确派给它的
产品可见输入；oracle、隐藏必要条件、latent opportunity、decoy 和评分规则只属于独立评价侧。

## 2. 所有 arm 共同遵守的产品契约

### 2.1 实际可见输入

每个 arm 只能读取其声明的输入子集：

- 用户当前表达的 `FUZZY-INPUT`；
- 用户在本次交互中确认、改写、拒绝或撤回的内容；
- 该 arm 明确声明可读取的公开平台/目录信息；
- 该 arm 明确声明可读取、且对当前用途已有许可的本地投影；
- 运行过程中由真实用户、人工中介或 recipient 原生返回的新事件。

“系统里可能存在”“模型可以推断”“评价器知道”均不构成可见输入。没有收到原生返回的外部动作
一律保持 `NOT_RUN` 或 `UNKNOWN`。

### 2.2 允许的最远输出

D1 arm 最远只能产生：

- `GOAL_DRAFT`：带来源、未知项和待确认项的可修改草稿；
- `QUESTION`：一个会改变下一步动作的问题；
- `RETRACTABLE_HYPOTHESIS`：显式待用户确认/拒绝/修改的假设；
- `HONEST_UNKNOWN` 或 `HUMAN_REVIEW_REQUESTED`。

D2 arm 最远只能产生：

- `STANDARD_PATH_CANDIDATE`；
- `DIRECTORY_CANDIDATE`；
- `PROJECTED_OPPORTUNITY_CANDIDATE`；
- `PROBE_REQUEST_CANDIDATE`；
- `HONEST_UNDISCOVERABLE_UNDER_CURRENT_INPUTS`。

这些输出都不能自动推出 Capability、对方意愿、Authority、Commitment、Reservation、Effect 或
Acceptance。只有标准平台分支在平台原生动作、原生 readback 和独立 Acceptance 均完成后，才可
由后续产品链声明相应结果；D1/D2 arm 本身不得声明完成。

### 2.3 共同记录的产品成本与失败

第一轮至少保留以下直接可解释量，不先压成单一总分：

- 用户问题轮数、主动纠正次数、晚期返工次数；
- 用户原始目标和不可接受底线是否被保留；
- arm 提出的错误假设、未决假设与诚实 Unknown；
- 每个信息项的来源，以及它是否由用户确认；
- 披露给每个 recipient 的字段、目的与轮次；
- 返回候选数量、错误唤醒、陈旧候选和漏掉的合格机会；
- 人工分钟、等待时间、平台调用/操作次数；
- arm 在何处旁路、停止、转人工或申请 probe。

成功找到伙伴不能抵消目标改写、过度披露、虚构外部回复或把目录候选当承诺。保守 Unknown 也不
自动获胜：如果可用信息本可低成本推进却被持续拒绝，属于 false reject / opportunity miss。

## 3. 产品 arm

## A0 `STANDARD_OR_DECLARED_DIRECT`

该 arm 是同一 direct-first 产品入口的两个严格分离分支，不能把二者的状态合并。

### A0-P 标准平台直达

**前提**

- 用户目标能够映射到一个现存平台的稳定字段和支持动作；
- 需要的用途、时间、资源和执行边界已经足以发出标准请求；
- 平台提供当前状态及后续权威 readback 路径；
- 没有尚未表达、却会使标准表单失真的 material condition。

**实际可见输入**

- 当前 `FUZZY-INPUT` 和用户已确认字段；
- 平台公开 schema、当前可用入口和平台原生状态；
- 不读取本地未授权上下文、latent opportunity 或 task oracle。

**用户交互**

显示“可直接走标准路径”的理由、将提交的字段和仍未知的项目。用户可确认、修改、取消或选择
返回开放形成；不得把用户沉默当确认。

**允许动作**

- 判断 `DIRECT_ELIGIBLE / DIRECT_NOT_ELIGIBLE / UNKNOWN`；
- 映射已确认字段，跳转或调用平台原生流程；
- 在平台无法表达 material condition 时退回 D1，而不是强塞固定表单。

**禁止蕴含**

文本相似、目录存在、资源曾可用或表单提交成功，不蕴含当前可用、owner 同意、资源已预留或目标
完成。

**成本**

主要是一次路由确认、字段映射、平台操作和 readback；需要记录误旁路造成的返工。它应作为低成本
正基线，而不是因为机制简单而被降级。

**典型失败**

- 把非标准用途压进标准类别；
- 丢掉不可接受底线；
- 平台状态陈旧或 adapter 复制出第二事实源；
- 为普通标准任务仍强制进入多轮 formation。

**旁路或停止**

- 全部前提成立：旁路 D1/D2 的额外形成机制，进入平台原生链；
- 任一 material condition 不可表达或用户不确认：立即停止 direct，不做猜测，返回 A1/A2/A3/A4；
- 平台已能完整覆盖任务时，不启用 reciprocal probe。

### A0-D 已声明目录直达

**前提**

- 目标草稿已形成足以搜索的 query；
- 所需资源/能力可能已经由 owner 在目录、ARD、Agent Card、商品目录或已登记 provider 中显式
  声明；
- 目录的作用域、更新时间和字段语义可见。

**实际可见输入**

- 用户确认的 query 字段；
- 公开或本次合法可见的已声明目录记录；
- 不读取 owner 未声明的能力、偏好、关系或 oracle。

**用户交互**

呈现“这是已声明候选，不是已承诺伙伴”，显示来源、更新时间和仍需验证的缺口。用户可排除、
缩窄或选择进一步接洽。

**允许动作**

- 返回已声明候选及其可追溯来源；
- 对 no-match 返回 `NO_DECLARED_MATCH`；
- 当 query 本身未形成时退回 D1，不生成伪 query。

**禁止蕴含**

目录命中不蕴含当前能力、可用性、对方意愿、许可或承诺；`NO_DECLARED_MATCH` 不蕴含世界中没有
可形成机会。

**成本**

搜索、陈旧性检查和候选核验成本通常低；主要风险成本是 false wake、陈旧记录和过早停止探索。

**典型失败**

- 用 RAG/目录替代 query genesis；
- 把 index coverage 当世界 coverage；
- 忽略撤回、过期和用途不匹配；
- no-match 后错误宣称无解。

**旁路或停止**

- 找到能进入后续资格化的候选：停止本 arm，交给后续产品链验证；
- query 不足：退回 A1/A2/A3；
- 只有未表达机会残余：可转 A3，仍有可由最小询问区分的残余时才申请 A5；
- 当前 policy 下不可发现：诚实停止为 Unknown，或转 A4。

## A1 `INTERVIEW_CLARIFICATION`

**前提**

- 用户愿意回答问题，但系统不能假定其一开始知道资源名、实现方法或所有相关角色；
- 需要先确认原始价值、material constraints、不可接受底线和谁有资格确认。

**实际可见输入**

- `FUZZY-INPUT`、当前 transcript、用户已确认/拒答的内容；
- 可用一个最小通用 checklist 识别问题类别，但不得读取 oracle 或把 checklist 选项当用户事实。

**用户交互**

每次只问当前判断中最可能改变下一步动作的问题，并说明为何需要。允许“我不知道”“不想回答”
“问题问错了”和修改原目标；阶段性复述只标出已确认与仍未知内容。

**允许动作**

- 提问、复述、记录 `CONFIRMED / UNKNOWN / REFUSED / NOT_APPLICABLE`；
- 形成带来源的 `GOAL_DRAFT`；
- 当价值冲突、决定权不清或问题无法继续时转人工。

**禁止蕴含**

用户回答一个字段不蕴含完整 intent；用户拒答不蕴含没有需求或能力；问题全部问完不蕴含目标正确、
可执行或已获授权。

**成本**

用户轮数、认知负担、等待和反复复述。该 arm 维护成本低，但可能把形成任务转嫁给用户。

**典型失败**

- 穷举问卷、连续追问低价值细节；
- 用户其实不知道答案却被迫选择；
- 把问题措辞中的假设灌进目标；
- 过度优化问题数而遗漏底线或受影响主体。

**旁路或停止**

- 用户确认的草稿已足够决定 direct/search/next question：停止并进入 A0 或 D2；
- 连续问题没有改变任何产品动作、用户拒绝继续或必须由别的 Authority 回答：停止为 Unknown 或转 A4；
- 不因“还可以继续问”无限扩展访谈。

## A2 `RETRACTABLE_MODEL_HYPOTHESES`

**前提**

- 模糊表达存在多个合理解释，逐项追问预计负担较高；
- 用户能够理解并确认、拒绝或修改模型提出的少量候选；
- 所有未确认推断都能在下游被阻断。

**实际可见输入**

- 与 A1 相同的用户输入和 transcript；
- 通用模型自身知识只用于生成解释或问题，不能作为当前用户、资源 owner 或环境的事实；
- 不读取本地许可上下文、目录隐含字段或 oracle。

**用户交互**

模型提出少量相互竞争、可撤回的解释，逐条标为“系统猜测”，同时给出“都不对/暂不确定”。用户
确认后才进入 `GOAL_DRAFT`；修改前后保留差异，避免静默目标替换。

**允许动作**

- 生成 `RETRACTABLE_HYPOTHESIS`、解释歧义、建议下一个高价值确认项；
- 把已拒绝假设从当前候选中移除；
- 低置信、分歧大或高后果时转 A1/A4。

**禁止蕴含**

模型自信、常识、概率最高或用户未反对都不蕴含用户认领；一个合理行动计划不蕴含所需能力、伙伴
或权威已经存在。

**成本**

模型调用、用户校正和 anchoring 风险；优势候选是减少无差别追问，不预设一定比访谈更低成本。

**典型失败**

- 单一流畅解释锚定用户；
- 把推断写成已确认字段；
- 为了可解而重写目标；
- 省了早期问题却导致晚期大返工。

**旁路或停止**

- 用户确认/修改后形成足够草稿：停止并进入 A0/D2；
- 用户无法判断、解释持续分歧或 material item 未被有权主体确认：转 A1/A4；
- 模型不能凭继续生成更多假设来绕过 Unknown。

## A3 `LOCAL_PERMITTED_PROJECTION_PLUS_MODEL`

**前提**

- 用户或相关主体本地已有可能减少追问或发现机会的当前上下文；
- 对本次目的、输入来源和投影范围已有产品层可见许可；
- 可以只生成 task-relative projection，而不把完整本地世界传给协调模型或候选方。

**实际可见输入**

- 协调模型先看到 `FUZZY-INPUT` 和已有 transcript；
- 本地组件只读取本次许可范围内的来源，并输出最小投影、来源类别、版本/新鲜度和
  `KNOWN / UNKNOWN / REFUSED / STALE`；
- 协调模型只看到该投影，不看到被排除的原始上下文，也不读取 oracle。

本文件只定义产品信息流和可见状态，不验证许可系统、隔离、机密性或抗绕过能力；这些均不属于
本轮结论。

**用户交互**

在读取前显示“为了哪个决定，需要从哪些本地来源投影什么”。用户可允许、缩窄、拒绝或撤回；
输出中标明哪些内容来自用户、哪些来自本地投影、哪些仍是模型假设。进入对外披露前再次展示具体
字段和 recipient。

**允许动作**

- 用投影减少重复提问、补充 query、发现已许可范围内的候选；
- 让模型基于投影提出下一问题或候选，但仍需 member-check；
- 投影陈旧、冲突或不足时返回 typed Unknown；
- 在目录 no-match 后寻找“未登记但本地已有信号”的机会候选。

**禁止蕴含**

本地出现某事实不蕴含可向外披露；投影命中不蕴含对方愿意、能力可依赖或关系成立；没有投影结果
不蕴含世界无机会。产品层显示“已许可”不构成安全、法律或隐私保证。

**成本**

许可确认、投影计算、用户核对、来源/版本维护和累计披露负担。还应记录它相对 A1/A2 实际减少了
多少问题，以及增加了多少不必要读取或 false wake。

**典型失败**

- task-relative 名义下仍投影完整画像；
- 把本地历史或旧关系当当前许可；
- 模型抹掉来源、版本和拒绝；
- 投影产生更多候选，却没有改善最终合格机会；
- 为了减少问题而增加更高的读取/核对负担。

**旁路或停止**

- 已有许可投影使 A0-P/A0-D 足以推进：立即旁路，不继续扩大投影；
- 用户拒绝、来源陈旧或新增字段不再改变产品动作：停止扩展，回到 A1/A2/A4/Unknown；
- 目录与投影仍有一个可由明确 recipient 的最小询问区分的残余时，才申请 A5；否则停止为
  `HONEST_UNDISCOVERABLE_UNDER_CURRENT_INPUTS`。

## A4 `HUMAN_MEDIATOR_OR_CONSERVATIVE_UNKNOWN`

**前提**

- 价值冲突、角色/决定权不清、模型解释不稳定、用户不愿继续机器交互，或自动 arm 的错误代价
  超出第一轮可接受范围；
- 有合适人工中介时使用中介，没有时必须允许诚实 Unknown/退出。

**实际可见输入**

- 与用户明确同意交给人工的 transcript、草稿、来源和未决项；
- 人工中介不读取 oracle，也不能因为“是人工”获得额外未授权材料；
- 若没有人工可用，只保留已有产品可见事实。

**用户交互**

说明为什么转人工、人工会看到什么、预计等待与可撤回范围。人工可以重构问题、提出 counter 或
指出当前不可判断；用户可拒绝转交并以 Unknown/退出结束。

**允许动作**

- 人工澄清目标、识别未出现的权威主体、判断是否值得继续；
- 对无法合法或可靠推进的状态返回 `HONEST_UNKNOWN / DEFER / EXIT`；
- 将可机器化的已确认部分交回 A0--A3。

**禁止蕴含**

人工判断不自动成为 Principal mandate、owner 同意、能力证明或 Acceptance；Unknown 不等于失败，
也不等于产品已经保护性地解决了任务。

**成本**

人工分钟、排队等待、交接解释、可用性和跨任务一致性；也要记录 Unknown 导致的可避免机会损失。

**典型失败**

- 把所有困难任务都转人工，产品没有获得可复用能力；
- 人工代替缺席主体作决定；
- 保守 Unknown 成为零风险但零推进的默认；
- handoff 丢失用户原始目标或前面已经确认的事实。

**旁路或停止**

- 人工形成用户认领的草稿或明确下一动作：返回相应 arm；
- 缺少必须由外部主体提供的信息且当前无合法询问路径：停止为 Unknown/Defer；
- 用户退出、价值已低于继续协调成本或问题原则上不应推进：停止，不触发更多自动探索。

## A5 `RECIPROCAL_PROBE_CONDITIONAL`

A5 不是默认起跑 arm，也不是 D2 的普遍解。它只叠加在 A0-D/A3 后仍存在的精确 residual 上。

**启用前提**

- 已有一个具体、可说明来源的候选 recipient，而不是向未知世界广播；
- 目录/已许可投影不足以判断一个会改变下一步的精确问题；
- 该问题可由一次最小、低风险、可拒绝的询问区分；
- recipient、purpose、scope、expiry、允许答复以及响应的产品使用边界都已明确；
- 用户确认值得承担等待和披露成本。若标准平台已有权威当前状态，直接读取平台状态，不启用 A5。

**实际可见输入**

- 用户已确认的最小目标投影；
- 候选 recipient 的已声明接洽入口；
- 此前 A0-D/A3 返回的精确未决问题；
- 不读取 recipient 私有上下文、oracle 或隐藏机会真值。

**用户交互**

发送前展示收件方、目的、具体字段、有效期、可能答复和“不发”的继续路径。用户可缩窄、取消或
转人工。收到原生响应后，界面只展示该响应实际支持的精确范围。

**允许动作**

- 发出一个有界询问候选；
- 只接受 recipient 原生的 `ACK / COUNTER / REFUSE / DEFER / NO_RESPONSE`；
- 将响应登记为当前候选路径的一个事实，返回后续提案/资格化节点；
- 过期、重复或撤回后回到 Unknown。

**禁止蕴含**

“已发送”不蕴含“已收到”；ACK 不蕴含能力、承诺、授权或完成；没有回复不蕴含拒绝或无能力；
对一个问题的肯定不蕴含持续关系。controller/solver 自写的 receipt 不算 recipient response。

**成本**

对外披露字段、recipient 数、等待、被打扰/false wake、人工处理及撤回成本。A5 的净值必须相对
继续问用户、转人工或诚实 Unknown 比较。

**典型失败**

- residual 不具体就开始广播；
- 为了制造机会暴露与决定无关的上下文；
- 把 synthetic response 或发送日志冒充真实对方决定；
- 重复、过期或撤回后仍沿用旧答复；
- probe 成功后直接跳过资格化、授权或承诺。

**旁路或停止**

- 平台/目录/投影已经足以推进：旁路 A5；
- recipient 不明确、问题不能通过一次最小询问区分、用户不确认或协调成本过高：停止并转 A4/
  Unknown；
- 获得一个有效原生答复、明确拒绝/defer 或达到冻结的等待边界：停止本 arm，不做自动连锁 probe；
- 若真实低风险 recipient 未参与，本分支必须记录为 `NOT_RUN`，不能用模拟返回填充。

## 4. 第一轮允许比较的条件化产品策略

基础 arm 可以按以下**预先声明的产品策略**组合。组合不是为追求最高分临时拼装，任何新增步骤都
必须说明它解决了前一步的哪个残余。

| 策略 | D1/D2 顺序 | 要回答的产品问题 |
|---|---|---|
| P0 Direct-first baseline | A0-P；不合格则 A0-D；仍不足则 Unknown | 成熟平台/已声明目录能解决多少，额外 formation 是否多余 |
| P1 Interview baseline | A1 → A0 | 只靠高价值追问能否保持目标并形成有效 query |
| P2 Hypothesis baseline | A2 → A0 | 可撤回假设是否以更少负担得到同等目标保真 |
| P3 Local composition | A3（必要时嵌入 A2）→ A0 | 已许可本地投影是否真实减少追问并发现目录之外的合格候选 |
| P4 Human/Unknown baseline | A4 → A0 或停止 | 人工中介与保护性 Unknown 的真实成本和不可替代边界是什么 |
| P5 Residual probe overlay | 任一前述策略产生精确 residual → A5 | reciprocal probe 是否只在该 residual 上带来净新增合格机会 |

第一轮可以得到如下类型的决定：

- 某类任务由 P0 完整解决，额外机制 `REMOVE/BYPASS`；
- A1 或 A2 成为 D1 默认，另一项在特定不确定性条件下启用；
- A3 只在已有许可上下文确实改变问题数或合格机会时 `COMPOSE`；
- A4 保留为特定高冲突/高不确定状态的 fallback，而不是全局默认；
- A5 只对反复出现、能被最小询问区分的残余 `COMPOSE`；
- 所有现有组合仍无法解决一个稳定、可观察且有净值的精确缺口时，才把该缺口送入 `INVENT`。

不得根据一个 PT-001 合成任务宣布任何 arm 是全局冠军，也不得把较少提问、较高候选召回或更完整
日志单独当作产品胜利。最终选择必须同时保持用户目标、主体边界、合格机会、披露/等待/人工成本
和诚实停止能力。

## 5. 运行边界

- 本文件只是竞争产品行为规范，不是 task truth、TASK-ORACLE、评分表或评测结果。
- arm 实现者不得读取未来 oracle；评价者也不得把 oracle 内容回流进产品 transcript。
- 本轮不研究网络、容器、权限绕过、抗伪造、机密性或其他安全问题，不作任何安全保证。
- 如 A5 需要真实外部交互，只有获得独立授权和真实 recipient 参与才可标 `RUN`；否则保持
  `NOT_RUN`。
- 任何 arm 的合成运行只能支持产品机制在该设定下的候选判断，不支持现实覆盖率、真实主体接受
  或通爻问题已经解决。
