# 顶尖研究的开放式工作法

这是一组可选的思考支架，不是强制流程。若它妨碍当前问题，改变它。

## 1. 先找到真正承重的问题

一个好问题不只是“还不知道什么”，还会改变后续理论、设计或资源投入。可以问：

- 哪个前提一旦错了，会让大量后续工作失效？
- 哪个异常最不像噪声？
- 哪个对比能区分当前解释和最强替代解释？
- 有没有更简单的系统得到相同结果？
- 我们是在研究真实对象，还是在研究自己的表示？

研究问题可以在工作中变化。变化本身若来自重要证据，就值得记录。

## 2. 保留发散与收敛两种模式

发散时：

- 广泛寻找跨学科连接、反例和新表示；
- 允许临时概念、草图、模拟和不完整原型；
- 不让现有 ontology 或任务包提前关闭可能性；
- 鼓励多个互相冲突的解释同时生长。

收敛时：

- 找到会改变决定的最小证据；
- 对最强替代解释做公平比较；
- 把结论限定到证据真正覆盖的范围；
- 明确下一项最有信息价值的行动。

长期只发散会失去兑现，过早收敛会失去发现。Agent 应根据研究现场切换。

## 3. 让现实施加压力

文献、形式推理、模型讨论、代码和真实任务各自暴露不同错误。尽可能让重要想法接触它最怕
的现实：

- 定义怕反例；
- 因果解释怕干预和替代解释；
- 能力主张怕留出任务和迁移；
- 架构主张怕真实故障、成本和用户路径；
- 主权主张怕边界旁路；
- 普遍性主张怕异质环境；
- 产品价值主张怕强基线与真实验收者。

不需要每次同时使用所有方法。选择最能命中当前脆弱点的一个。

## 4. 记录服务于思考

只记录三类难以重建的东西：

1. 原始证据和关键环境；
2. 改变方向的决定；
3. 后续研究者需要的接续点。

模板只是空白起点。可以删节、扩写或不用。不要为了“完整记录”打断洞见，也不要让重要
结果只存在于会话记忆里。

## 5. 使用 Agent 群体而不制造伪独立

多 Agent 可以用于并行阅读、竞争性解释、独立实现、反例搜索、审稿和工具构建。真正的价值
来自视角、信息或实现路径的差异，而不是调用数量。

需要独立性时，刻意控制他们看见什么。需要综合时，保留分歧，不急着投票。让一个 Agent
重新定义问题，有时比让十个 Agent 检查同一清单更有价值。

## 6. 结论是一种暂时承诺

好的研究结论同时告诉读者：

- 当前最可信的判断；
- 它为什么比替代解释更好；
- 它覆盖到哪里；
- 什么仍然未知；
- 什么证据会让我们改变看法。

稳定不是永不改变，而是改变时能指出触发它的新证据。
