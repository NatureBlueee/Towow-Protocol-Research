# 第五阶段本地研究证据合同

## 1. 目的

本合同规定：本地实验室返回的重大判断必须能够回到环境事实、代码、事件、模型调用、实验、成本和失败轨迹。总结报告不是证据本身。

原则：

> 每个强主张都必须携带与其强度相匹配的证据；每个无法判断的关键问题都必须指向缺失条件和下一项可执行研究。

---

## 2. 证据等级

| 等级 | 含义 | 可支持的表述 |
|---|---|---|
| E0 | 直觉、候选解释 | “值得研究”“可能” |
| E1 | 理论推导、反例或形式约束 | “在给定前提下必须/不可能” |
| E2 | 合成机制实验 | “机制可产生该现象”，不能估计现实频率 |
| E3 | 半真实环境：真实代码/模型，但任务或边界受控 | “在该环境中成立” |
| E4 | 真实本地工作区、真实任务、真实 Agent 与边界 | “对该任务族具有现实支持” |
| E5 | 多环境独立复现或低风险生产影子 | “具有一定外部效度” |
| E6 | 生产长期证据 | 仅在明确范围和持续监控下表述 |

不得用 E2 证据支撑普遍生产结论，也不得把一次 E4 成功表述为通用能力。

---

## 3. 每个研究主张必须包含

- `claim_id`；
- 精确、可反驳的主张；
- 主张类型：理论 / 机制 / 工程 / 现实 / 价值 / 安全；
- 当前状态：supported / weakened / rejected / qualified / unknown；
- 作用域和前提；
- 支持证据路径；
- 反例与替代解释；
- 证据等级；
- 未解决限制；
- 设计或工程后果；
- 下一项能够提高判别力的行动。

更新 `CLAIM_EVIDENCE_UPDATE.csv`，不要只在散文中表述。

---

## 4. 环境事实证据

必须保存 `ENVIRONMENT_FACTS.json`，至少包含：

- 工作区路径与仓库根；
- 操作系统、架构、时间；
- Git HEAD、分支、dirty 状态、远程；
- `AGENTS.md` 路径和摘要；
- 语言、包管理器、测试和构建入口；
- 当前 Codex Agent、模型、CLI/App、其他 Agent/SDK 及版本；
- 可用工具和权限；
- 禁止路径、外部副作用和秘密边界；
- 本地执行方式、会话/进程标识，以及 smoke 结果；
- 研究分支或 worktree；
- 所有无法调用的资源及真实错误。

Git 状态必须在研究开始、每个重要 commit 和返回前分别记录。

---

## 5. 每次关键实验的目录合同

推荐结构：

```text
runs/<run_id>/
  run.json
  hypothesis.md
  input/
  config/
  prompts/
  events.jsonl
  logs/
    stdout.log
    stderr.log
  outputs/
  verdicts/
  costs.json
  human_interventions.jsonl
  boundary_and_disclosure.json
  git_state.json
  analysis.md
  checksums.sha256
```

`run.json` 至少包括：

- run_id、时间和研究问题；
- 目标与 ObjectiveVersion；
- 策略、基线与预算；
- 节点、主体、模型、工具和权限；
- 数据/任务来源和留出方式；
- 独立性设计；
- 启动命令、退出码和超时；
- 成功、失败、拒绝和停止定义；
- 是否有外部效果；
- 证据等级；
- 相关 Git commit。

机器结构应符合 `schemas/experiment_record.schema.json`。

---

## 6. 模型与 Agent 调用证据

每次关键调用保存：

- provider、模型/Agent、精确版本；
- 上下文来源列表及哈希；
- 工具权限；
- 提示版本；
- temperature / seed / 预算等配置（若可用）；
- 完整可公开输出或脱敏输出；
- token、成本、延迟、重试；
- 人类修改、选择或补充；
- 退出状态和错误。

必须区分：

- 模型推测；
- Agent 实际执行；
- 工具返回；
- 人类认领；
- 环境真实效果。

---

## 7. 成本与净价值

至少分别记录：

- 模型 token / API 成本；
- 本地计算和墙钟时间；
- 人类介入时长和次数；
- 消息与制品传输；
- 私有状态披露与边界转录；
- 等待、重试和返工；
- 失败恢复；
- 基线成本；
- 原始目标价值、阶段性价值和放弃价值。

不得把通信字节直接当作隐私损失。需要分别记录：

- 必要制品；
- 未授权私有状态暴露；
- 可推断泄漏或重建风险；
- 目的、受众和保留期。

若无法货币化，使用透明的多维成本向量，不强行压成一个总分。

---

## 8. 目标保真证据

每次真实任务保存：

- 原始目标；
- 验收者；
- 关键价值维度和最低线；
- 每个修订版本；
- 保留/放弃价值；
- 残余缺口；
- 继续向原目标推进的条件；
- 对精确版本的 Recognition；
- 原目标与修订目标分别的结果。

完成一个更容易的任务不能标记为原目标成功。

---

## 9. 能力形成与因果证据

任何“某条件创造了新能力”的主张，应尽可能保存：

- 形成前状态；
- 候选条件；
- 为什么预计改变可达空间；
- 条件实际创建过程；
- Witness；
- 配对重放、随机开关、阶段引入或其他干预；
- 形成后结果；
- 替代解释；
- 迁移/留出表现；
- 失败边界；
- 主体是否理解、认领和授权。

若没有干预或留出，只能表述为相关性或候选解释。

---

## 10. 主权 A2A 证据

若实验标记为 `sovereign_a2a`，必须证明：

- 私有边界的实际实施方式；
- 协调器越权读取探针；
- 主体对本地工具和资源的控制；
- 拒绝、退出、Unknown 或反条件轨迹；
- 非共享隐藏状态；
- 独立签名或归因；
- 无全知 fallback；
- 边界泄漏和成本记录。

缺一项时，应标记为 `partial_sovereign` 或 `multi_agent_orchestration`，而非强 A2A 证据。

---

## 11. 独立验证证据

独立验证必须说明隔离在哪里：

- 不读参考实现；
- 不读作者结论；
- 不共享隐藏上下文；
- 使用不同模型、提示、实现或数据；
- 能够运行反例或拒绝现有解释。

保存：

- 独立任务说明；
- 提供给评审者的材料；
- 未提供的材料；
- 输出和代码；
- 与主实现分歧；
- 最终如何处理分歧。

“另一个 Agent 同意”不构成独立证据。

---

## 12. 代码与工程证据

返回包必须包含：

- baseline commit 和最终 commit；
- 分支/worktree；
- 完整 diff 或 patch；
- 新增/修改文件列表；
- 测试、lint、类型检查和构建结果；
- 失败测试和修复前后轨迹；
- 未提交文件；
- 任何性能或安全回归；
- 回滚方式。

代码声称实现某理论对象时，必须指向具体文件、类型、状态转换和测试，不得只给模块名称。

---

## 13. 失败与负结果

必须返回：

- 失败实验；
- 没有新增价值的机制；
- 中心化/人工方案更好的情况；
- 无法复现的结果；
- 模型或 Agent 拒绝；
- 权限、环境和预算阻塞；
- 违反预期的异常；
- 被删除、合并或降级的概念。

每个失败说明：

- 为什么失败；
- 是理论、实现、配置还是环境问题；
- 它改变了什么；
- 下一项建设性行动；
- 是否存在不可能性边界。

---

## 14. 复现要求

每个重大结果应具备：

- 单命令或明确步骤；
- 固定依赖或锁文件；
- 数据来源和哈希；
- 随机种子；
- 环境变量清单（不包含秘密值）；
- 预期退出码；
- 结果文件路径；
- 已知非确定性；
- 最小硬件/权限；
- 清理方式。

无法复现的现实事件仍可作为证据，但必须保存足够轨迹，并降低证据等级。

---

## 15. 结果提升规则

一个主张准备从“研究假说”提升为“当前稳定结论”时，至少检查：

1. 是否有可反驳定义；
2. 是否有独立或异质证据；
3. 是否排除至少一个强替代解释；
4. 是否在真实或半真实任务中成立；
5. 是否改变设计或工程行动；
6. 是否明确作用域和失效条件；
7. 是否保留负结果；
8. 是否能够被另一个实现或运行路径复核。

未满足时保持 qualified，不要依靠语言强度升级结论。

---

## 16. 最终返回证据结构

最终返回包至少包括：

```text
RETURN_SUMMARY.md
ENVIRONMENT_FACTS.json
RESEARCH_STATE.yaml
DECISION_LOG.md
CLAIM_EVIDENCE_UPDATE.csv
experiments/
code_changes/
independent_reviews/
failures/
blockers/
NEXT_RESEARCH_ACTIONS.md
MANIFEST.json
CHECKSUMS.sha256
```

详细内容见 `06_RETURN_PACKET_TEMPLATE.md`。
