## A. 直接调查当前本地环境

不要先向用户询问固定实验，也不要假设环境结构。

在修改任何代码之前，直接使用当前 shell 和文件系统完成：

1. 确认当前工作目录和 Git 根目录；
2. 读取工作区根目录及相关子目录中的 `AGENTS.md`；
3. 读取 README、项目说明、构建配置、测试入口和安全政策；
4. 记录：
   - 工作区绝对路径；
   - Git HEAD、分支、dirty 状态、未跟踪文件和远程；
   - 操作系统、架构、语言、包管理器；
   - 当前 Codex/Agent/模型执行环境和可查到的版本；
   - 可用 CLI、SDK、测试、构建和运行入口；
   - 允许修改和禁止触碰的路径；
   - 已知外部副作用入口、秘密和私有数据边界；
   - 当前无法使用的资源及真实原因。
5. 把事实写入：

```text
.ai-research/towow-a2a-r5/state/ENVIRONMENT_FACTS.json
```

不要 reset、stash、覆盖、清理或删除用户已有修改。

## B. 完成直接本地 smoke

你本身就是正在运行的本地 Agent，直接完成下述验证。

使用 `templates/LOCAL_WORKSPACE_SMOKE_TASK.md` 作为约束，直接执行一次最小只读 smoke：

- 不修改项目源文件；
- 不安装依赖；
- 不启动生产服务；
- 只允许运行版本、状态、测试发现等无害命令；
- 只在以下位置写入一个结果文件：

```text
.ai-research/towow-a2a-r5/smoke/CODEX_LOCAL_SMOKE_RESULT.json
```

结果必须记录真实 cwd、repo root、Git 状态、Codex/Agent 环境信息、发现的测试命令、实际运行命令及退出码。

只有该文件与实际命令输出一致，才能认定本地执行链可用。

## D. 连续开展第五阶段本地研究

不要在 smoke 或第一个 Demo 后返回。不要机械迁移参考实现，也不要预设固定节点数、固定任务和固定结论。

你应根据真实仓库自主选择最高判别力的问题。内部循环必须持续包含：

```text
理解真实环境
→ 识别最承重假设
→ 选择真实或接近真实的高价值任务
→ 构造并运行初始实验/任务切片
→ 检查失败、异常、反例和替代解释
→ 进行干预、消融、留出、迁移或独立复核
→ 更新代码、证据和当前判断
→ 决定继续、转向、合并、删除或返回
```

你可以自主决定：

- 使用几个节点；
- 是否使用容器、独立进程、worktree、独立服务或不同模型；
- 是否让子 Agent 承担独立实现或盲审；
- 哪些实验应合并、替换或暂缓；
- 是否存在比当前统一体系更简单、更有效的结构。

优先研究那些会改变真实设计决策的问题，例如：

- 哪些形成条件真的改变了行动空间，而不是语言重述；
- 能力 Claim 是否能预测留出任务；
- 目标重构是否保留原始价值，而不是缩小目标制造成功；
- 主权 A2A 是否在某些现实条件下产生高于协调成本的净价值；
- 中心化强 Agent、人工或现有 Harness 是否其实更好；
- 哪些现有概念真正改变运行行为，哪些只是派生视图或重复状态；
- 当前统一内核是否足以承载真实 Harness 轨迹；
- 真实环境是否暴露出当前语言无法表达的承重变量。

若研究主权 A2A，主体边界必须由 OS、容器、独立服务、文件权限、独立工作区或同等机制真实实施。不能把同一个中心内部的多个子调用称为主权 A2A，也不能在失败后让协调器偷偷读取完整私有状态。

## E. 证据与独立性

所有重大判断必须满足 `04_EVIDENCE_CONTRACT.md`。至少保留：

- 实际模型、Agent、工具、CLI、SDK 和版本；
- 输入、配置、输出、退出码、错误和重试；
- token、墙钟、人类介入、等待、披露、返工和恢复；
- 原始目标与任何修订目标；
- Git diff、测试、事件和真实文件变化；
- 失败、拒绝、Unknown、回滚和中心化方案更优的情况；
- 与当前理论一致和不一致的结果；
- 未预设的新发现；
- 可复现命令和环境依赖。

重大主张应尽可能接受实质隔离的验证，例如：

- 独立 Agent 不读参考实现，只读规范或任务；
- 第二实现路径；
- 不同模型分析同一证据；
- 盲审 Agent 不获得作者期望结论；
- 通过干预、消融、留出或反例区分替代解释。

不要让同一套先验反复总结自己。

## G. 合理返回条件

不要按固定时长、实验数量或完成清单停止。只有以下情况之一成立时才生成返回包：

1. 获得能够支持、削弱、推翻或重新限定核心判断的证据；
2. 当前关键问题已形成足以指导下一行动的结论；
3. 遇到必须由用户提供凭据、价值判断或不可逆授权的真实阻塞；
4. 继续运行只能重复已有结果，暂时没有新增知识价值；
5. 新发现使研究自然转入另一层，需要首席研究者重新整合。

## H. 返回完整证据包

按 `06_RETURN_PACKET_TEMPLATE.md` 生成：

```text
.ai-research/towow-a2a-r5/return-packet/
```

将其压缩为单个 zip。返回时同时报告：

- zip 绝对路径；
- baseline/final Git commit、分支和 dirty 状态；
- 最出乎预期、最可能改变理论的发现；
- 哪些判断被支持、削弱、推翻或重新限定；
- 关键证据路径和复现命令；
- 实际代码和系统发生了什么变化；
- 无法完成的调用及真实原因；
- 下一步最有价值的研究行动。

不要只返回成功总结。失败实验、没有价值的结构、中心化方案更好和无法判断的情况同样必须完整返回。

现在直接从当前工作区的环境事实调查开始。只有遇到安全授权、外部凭据、不可逆动作或必须由主体做出的价值判断时，才暂停并请求用户。
