# 通爻 Agent-to-Agent 当前统一体系

**版本：** Local Codex Research v1.1，基于第五阶段第一现实闭环。  
**状态：** 当前最佳研究版本；不是最终标准、生产安全认证或跨行业已验证协议。

---

## 0. 一句话定义

通爻研究的不是“两个 Agent 怎样发消息”，而是：

> 多个拥有各自主权、私有世界、目标、资源和责任边界的主体，怎样在不能或不应集中全部世界的条件下，共同发现、形成、验证、认领并兑现此前不存在或未被意识到的行动能力，同时让模型智能、主体权威、现实承诺和外部效果保持可区分、可追责、可反驳。

现有 A2A/MCP 可以承担传输、任务和工具互操作；通爻研究的是其上的协调语义、能力形成、权威与效力路径。

---

## 1. 元问题

设主体集合为 \(P=\{p_1,\ldots,p_n\}\)。主体 \(p_i\) 拥有协调器不能任意读取的私有世界 \(X_i\)，其中包含：

- 历史与上下文；
- 当前和潜在目标；
- 数据、工具、资源和关系；
- 权限、风险、责任与退出条件；
- 主体尚未清楚表达或尚未意识到的可能性。

系统希望形成现实效果 \(Y\)，但必须同时面对：

1. 私有世界不能被一个后台全知者默认集中；
2. 当前自我描述不是完整能力边界；
3. 模型理解是概率性的，且不能自动生成权威；
4. 一条逻辑可行路径不等于现实可靠能力；
5. 主体必须能够拒绝、退出、提出反条件或拒绝认领；
6. 目标可能被重构，但不能借此制造虚假成功；
7. 承诺、容量、效果、验证、接受和结算具有不同现实后果；
8. 主权协调本身有成本，不应在中心化方案更合适时强行使用。

因此，通爻当前研究的是：**主权私有世界之间的生成式、制度化和可兑现协调。**

## 2. 当前统一语义内核

前四阶段产生过 BIC、SJAC、PFE、CRA 等阶段性名称。当前不再把它们视为并列事实系统。协议事实集中在一个事件溯源内核中；规划、求解、资格化和展示只是 Provider、Pipeline 或派生视图。

### 2.1 主体与权威

- `Principal`：承担价值、后果与最终责任的人或组织。
- `AgentExecution`：一次可归因的智能执行，不假设持久人格。
- `AuthorityGrant`：某执行在对象、目的、动作、资源和期限上的授权。

**不变量：** 技术能力与规范权威正交。模型或 Agent 能够做某事，不等于有权代表主体做出承诺或改变现实。

### 2.2 私有世界与行为边界

- `SovereignWorld` 不是集中数据库，而是主体控制的上下文、工具、资源和规则集合。
- `BoundaryPolicy` / typed local response 决定在具体目的、受众、风险和会话状态下，主体愿意释放什么。
- 静态 Agent Card、Capability Profile、Embedding、NAC 或知识图只可作为候选索引，不能成为主体完整行动空间的权威表达。

**真正 A2A 的最低现实条件：**

1. 私有边界不能被协调器后台绕过；
2. 主体控制本地数据、工具和资源；
3. 主体可以拒绝、退出、返回 Unknown 或提出反条件；
4. 不共享完整隐藏状态；
5. 消息、证据和行为分别归因；
6. 协调成本和披露成本可见；
7. 失败后不能偷偷回退到全知中心。

这些是实验准入条件，不是新的协议对象。

### 2.3 目标与价值谱系

- `ObjectiveVersion`：当前真正被追求和验收的目标版本。
- `ValueDimension`：原始需求中不能被单一总分掩盖的价值维度。
- 目标版本记录父子关系、保留价值、放弃价值、残余缺口和继续接近原目标的条件。

旧 `GoalRevision` 被吸收到 `ObjectiveVersion` 谱系。物质性目标改变必须被相关主体认领，修订目标完成不能自动继承原目标完成标签。

### 2.4 持续协调聚合

- `CoordinationCase`：一次持续协调的聚合根。
- `SharedArtifactVersion`：版本化共同对象。
- `COORDINATION_SCHEMA`：问题、角色、变量和验证语言。
- `ARRANGEMENT`：当前联合行动安排（JAA）。
- Plan、EffectSpec、Report 等可作为同一版本机制的不同 `ArtifactKind`。

Schema 与 Arrangement 保持职责差异，但复用统一版本、作者、证据、内容哈希和父子关系，避免多套平行版本系统。

### 2.5 主张与证据

- `Claim`：关于事实、假设、未知、风险、能力、容量或政策的可反驳主张。
- `Evidence`：主张或验证引用的现实证据。
- Claim 必须携带作用域、保证等级、假设、已知反驳、有效期和来源。

`CapabilityEnvelope` 与 `AssuranceCase` 当前被视为派生视图：它们从 Claim、Evidence、Scope、Assumption 和 Defeater 生成，不维护第二份权威能力状态。

### 2.6 认领、承诺与资源

- `RecognitionAction`：主体对精确内容哈希的认领、条件认领、拒绝或撤回。
- `Commitment`：义务、授权、能力主张、资源预留、验收和救济条件的规范对象。
- `ResourceReservation`：容量和稀缺资源的现实占用。

Recognition 不证明技术可靠性，也不自动生成授权；能力 Claim 不自动生成 Commitment；Commitment 不自动表示资源可用。

### 2.7 外部效果与闭合

- `Effect`：经过唯一 Effect Gateway 记录的沙箱或现实效果。
- `Verification`：技术、规则或证据检验。
- `Acceptance`：业务主体是否接受结果。
- `Settlement`：确定性结算、托管或 dry-run 回执。
- `Dispute`：争议、救济和恢复路径。

执行、验证、接受和结算保持分离。任何生产副作用必须来自明确授权、承诺、资源和 Gate，而不能由模型文本直接触发。

### 2.8 事件账本与编译世界

- Event Ledger 记录权威状态变化、来源和内容哈希。
- Compiled Observable World 是事件和对象的可操作投影，不是第二事实库。
- 可观测性必须能回到原始事件、证据、权限和版本，不能只展示 Agent 动画。

## 3. 哪些是策略、Pipeline、Provider 或视图

| 历史名称或机制 | 当前身份 | 不得承担的权力 |
|---|---|---|
| NAC、Embedding、图、Agent Card | Discovery Provider | 不能定义真实能力、意图或承诺 |
| BIC / 行为边界充分性 | 理论与 BoundaryPolicy 设计原则 | 不是独立运行时事实库 |
| SJAC、Benders、Column Generation | 特定世界类中的 Solver / Oracle Provider | 不能成为统一社会目标函数或中央权力 |
| PFE | 发现和形成条件的规划策略 | 不能自行宣布能力成立或主体愿意参与 |
| CRA | 资格化 Pipeline | 不能维护第二套正式能力状态 |
| VOI / EVPF | 查询与干预调度策略 | 不能自动突破隐私和权威边界 |
| CapabilityEnvelope | 能力 Claim 的运行视图 | 不维护第二份权威状态 |
| AssuranceCase | Claim/Evidence 的审计视图 | 不能替代证据和主体认领 |
| TrustAdapter / WoWok Adapter | 下游效力适配器 | 不决定上游意图或协调语义 |
| Compiled World | 人与 Agent 的可操作投影 | 不成为隐藏事实源 |

## 4. 当前统一状态路径

```text
Private Sovereign World
    ↓ BoundaryPolicy / typed local response
CoordinationCase
    ↓
ObjectiveVersion + SharedArtifactVersion
    ↓
Claim / Evidence / Unknown / Risk
    ↓
Discovery / Solver / PFE / Qualification strategies
    ↓
Candidate Arrangement
    ↓ exact-hash RecognitionAction
Commitment + AuthorityGrant + ResourceReservation
    ↓ Effect Gateway
Effect
    ↓
Verification
    ↓
Acceptance
    ↓
Settlement / Dispute
    ↓
Event Ledger / Compiled Observable World / Layered Learning
```

模型可以出现在多个位置，但产生的是提议、解释、候选、反例和修复。只有内核状态转换决定什么开始作数。

## 5. 能力的当前定义

能力不是静态标签，而是一项有条件的、可反驳的可达性和可靠性主张：

\[
P_{\omega\sim D_\Omega}
\left[
Accept_G(Y)=1 \land Violation(Y)=0
\mid do(z),\pi,\theta,\omega
\right]
\ge 1-\epsilon.
\]

其中：

- \(G\)：明确的 EffectContract；
- \(z\)：主体、任务、伙伴、环境、制度、观测和恢复组成的联合实现配置；
- \(\pi\)：执行策略与 Harness；
- \(\theta\)：模型、工具、代码和路由版本；
- \(\Omega\)：声明运行域；
- \(D_\Omega\)：该域中的任务与环境分布。

必须区分：

```text
Declared
→ Hypothesized
→ Counterfactual
→ Sandboxed
→ Witnessed
→ Recognized
→ Delegated
→ Committable
→ Performed
→ Accepted
```

这些状态不一定都需要成为独立顶层对象，但现实差异不能消失。模型置信度、逻辑计划、沙箱见证、主体认领、代理权、容量和履约结果互不替代。

## 6. 目标重构与价值保真

设原始目标含价值维度 \(d_j\)，权重为 \(w_j\)，新目标保留比例为 \(r_j\)：

\[
R(O'\mid O)=\frac{\sum_j w_j r_j}{\sum_j w_j}.
\]

但总分不足以保护关键价值，还需要：

\[
r_j\ge m_j,\qquad \forall j\in D_{critical}.
\]

物质性目标变化必须记录：

- 原始目标与新目标；
- 每个价值维度保留和放弃内容；
- 它是阶段性目标还是最终可接受结果；
- 继续接近原目标需要创造的条件；
- 协调和保障成本是否超过剩余价值；
- 谁认领了精确目标版本。

目标重构可以是形成路径，不能成为制造成功的手段。

---

## 7. 主权协调的价值条件

相对于最佳可用基线，定义净协调剩余：

\[
\Delta V = U(Y)
- C_{compute}
- C_{human}
- C_{delay}
- C_{disclosure}
- C_{risk}
- C_{recovery}
- V_{baseline}.
\]

只有在 \(\Delta V>0\) 或中心化方案因法律、竞争、隐私、责任或权限不可用时，主权 A2A 才有现实理由。

通爻不默认优于中心化强 Agent。中心化更便宜、更快的结果必须如实返回。

## 8. 目前相对稳定的结论

以下结论拥有理论理由、代码约束和至少一种机制或半现实证据，但不等于跨行业生产证明。

1. **有限静态画像不能穷尽主体对全部未来任务的相关性。**  
   设计后果：Profile 只能做索引，不能做最终能力边界。

2. **模型概率与主体权威正交。**  
   设计后果：推理、认领、授权和外部效果使用不同 Gate。

3. **真正 A2A 需要不可绕过的主体边界和独立行动控制。**  
   设计后果：提示词中的“不能看”不算证据。

4. **可能性、限定能力、容量、承诺和履约不能合并。**  
   设计后果：不同失败必须拥有不同证据和状态路径。

5. **主体认领必须绑定精确内容和版本。**  
   设计后果：物质性变化后旧认领不能自动继承。

6. **高后果副作用必须经过确定性 Effect Gateway。**  
   设计后果：模型文本和 Draft 不能直接改变现实。

7. **目标修订不能继承原目标成功标签。**  
   设计后果：维护 ObjectiveVersion 谱系和价值保真约束。

8. **Unknown / Refused / No-safe-operator 是一等结果。**  
   设计后果：不能用生成式乐观掩盖不存在的证据。

9. **同一事实应只有一个权威来源。**  
   设计后果：Envelope、Assurance 和 World 优先作为派生视图。

10. **主权协调存在真实价格。**  
    设计后果：必须与人工、静态和中心化基线比较净价值。

## 9. 仍然承重、但证据薄弱的假说

本地实验室应优先寻找能够支持、限定或推翻这些假说的真实证据：

1. 强模型能够在真实私有边界下稳定生成安全的形成条件，而不泄漏或冒领主体世界。
2. PFE 发现的“新可能性”在真实任务中不是语言重述，而是行动空间真实扩张。
3. Capability Claim / Envelope 能比一次成功、最近成功率或模型信心更好地预测留出任务。
4. exact-version Recognition 能提高主体理解并减少作用域争议，而不是只增加交互负担。
5. 统一内核足以承载真实 Harness 轨迹，不需要重新恢复多个平行事实引擎。
6. 主权协调在某些真实场景中的隐私、责任或可行性价值能够覆盖额外协调成本。
7. 两个或多个主体的联合能力能够通过明确接口和 Integration Witness 被可靠组合。
8. 当前目标价值谱系能够防止“稳定完成一个无用缩小目标”，且不把正常迭代变成过重流程。
9. 当前对象模型能够由独立实现者一致解释，而不是依赖作者脑中的隐含语义。
10. WoWok / 国内平台等 Trust Adapter 可以接住已认领承诺，而不倒逼上游理论绑定单一基础设施。

## 10. 第五阶段第一现实闭环证明了什么

第一现实闭环使用三个 Linux 用户、独立文件权限、私钥和签名消息，构造生产主体 A、验证主体 B 和协调器：

- 协调器不能读取 A 原始数据或 B 私有政策；
- A 与 B 不能读取对方私有目录；
- 节点可以返回 `MISSING_TOOL`、`CONDITIONALLY_FEASIBLE` 和 `UNRESOLVED`；
- 协调器基于公共信息提出工具形成动作，但安装和本地验证由主体执行；
- 真实轨迹形成了单位转换工具和冲突证据；
- 无安全形成算子时保留未解决状态；
- 轨迹写入统一内核，形成目标、证据、认领、承诺、效果、验证、接受和 dry-run 结算闭环。

七个场景结果：

| 策略 | 原目标接受率 | 私有目录暴露率 | 平均形成条件 | 平均研究成本单位 |
|---|---:|---:|---:|---:|
| 静态能力描述 | 28.6% | 0% | 0.00 | 1.60 |
| 中心化全知 | 85.7% | 100% | 0.00 | 0.11 |
| 全量披露 | 85.7% | 100% | 0.00 | 0.92 |
| 主权类型化 A2A | 85.7% | 0% | 0.71 | 4.97 |

它支持：主权路径可在不集中私有目录时形成缺失条件；它也诚实显示中心化路径在当前任务上更便宜。

---

## 11. 第一现实闭环没有证明什么

- 节点是确定性 Python Agent，不是真实强模型或 Codex Agent；
- 任务由研究者构造，不是用户真实仓库历史；
- 没有复杂利益冲突、策略性欺骗和真实人类认领；
- 没有真实支付、电子签、链上或生产写入；
- 没有证明能力包络对域外任务有预测力；
- 没有证明主权路径的商业价值高于真实组织协调成本；
- 没有证明当前对象模型是最简或跨行业通用；
- 尚未在用户的真实本地 Harness 仓库中完成独立 Codex Agent 的持续现实验证。

本地实验室的使命正是让这些边界开始接受现实压力。

## 12. 与外部基础设施的关系

- **A2A / MCP：** 可承担传输、任务和工具互操作。通爻不重新发明这些层，而提供目标、主张、认领、承诺和效力语义。
- **可验证凭证：** 可承载身份、授权或证据来源，但“可验证”不等于主张为真，也不替代授权决策。
- **WoWok：** 位于下游 Trust Adapter，承接已形成、被认领、获权并适合确定性执行的权限、资产、托管、结算或争议。通爻不替代 WoWok，也不被其当前对象锁定。
- **国内等价路径：** 实名/企业认证、可靠电子签、平台事件账本、持牌支付/托管、发票与仲裁可以承担类似功能，但必须明确保留和缺失的保证。

## 13. 本地现实研究的杀死条件

以下结果应迫使当前结构被缩小、合并或改写，而不是被解释掉：

- PFE 的“新可能性”主要是语言重述，无法通过干预改变行动空间；
- Capability Claim / Envelope 无法比简单成功统计预测留出任务；
- Recognition 不减少误解或争议，却显著增加负担；
- 主权路径扣除模型、人类、等待、披露和恢复成本后不优于更简单基线；
- 主权节点必须不断泄露完整上下文才能完成协调；
- 价值主要来自一个后台全知强模型，边界和共同对象没有增量；
- 多个核心对象不能被盲实现者一致区分；
- 真实 Harness 已自然实现同一机制，而研究对象只是重新命名；
- 目标修订机制让系统稳定完成低价值替代目标；
- Trust Adapter 迫使上游承诺语义依赖某一基础设施的偶然实现。

任何杀死条件出现都不是研究失败；它是决定哪些结构不配进入协议内核的证据。

---

## 14. 当前最简定义

> 通爻是一个让主权主体通过受控边界共同维护目标、主张和行动安排，并把模型产生的可能性逐步转换为有证据、有认领、有授权、有资源且能够接受现实反驳的效果的协调内核。

模型扩大可能性空间；主体保留主权；统一内核规定什么开始作数；Harness 控制现实执行；Trust Adapter 连接确定性效力设施；编译世界使整个过程可见、可操作和可追溯。
