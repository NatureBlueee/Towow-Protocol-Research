# 通爻 A2A 第五阶段本地 Codex 研究任务包 v1.1

**任务包角色：** 当前研究会话负责理论整合、研究调度和证据吸收；本地 Codex Agent 直接在真实工作区中承担连续实验、代码修改、独立复核与工程执行。

把本任务包放进 Codex 能直接读取的位置，在目标仓库中启动 Codex，然后把 `05_CODEX_BOOTSTRAP_PROMPT.md` 的内容直接交给它即可。

这不是待办清单。它是一组研究边界对象，使一个不了解完整聊天历史、但能直接读取和修改本地工作区的 Codex Agent，能够在真实仓库中独立继续第五阶段，并把可复核证据带回来。

## 1. 这份包要解决什么

前五阶段已经形成统一语义内核、主权边界实验、能力形成与资格化理论，但最强证据仍不足以回答：这些结构能否在不由理论预先安排的真实工作区、真实 Agent、真实工具、真实失败与真实成本中产生净新增价值。

本地实验室的任务不是证明通爻正确，而是让现实决定：

- 哪些区分是必要的；
- 哪些对象只是阶段性表达或派生视图；
- 哪些形成条件真的改变行动空间；
- 哪些能力主张具有留出预测力；
- 哪些主权协调成本值得支付；
- 哪些更简单的中心化或人工方案实际上更好；
- 哪些失败要求修改理论、代码或研究问题。

## 2. 最简使用方式

1. 把整个任务包解压到 Codex 可以读取、但不会污染项目源代码的位置；也可以放在仓库内的 `.ai-research/towow-a2a-r5/packet/`。
2. 在目标真实仓库中直接打开或启动 Codex。
3. 将 `05_CODEX_BOOTSTRAP_PROMPT.md` 全文交给 Codex。
4. Codex 直接使用当前工作目录、shell、Git、文件系统和其可用工具完成环境调查与研究。
5. 首先完成只读本地 smoke，再创建隔离研究分支或 worktree。
6. 让它连续研究，直到形成有判别力的证据或遇到必须由用户处理的真实阻塞。
7. 最终将它生成的完整 `return-packet.zip` 上传回首席研究会话，不要只复制一段总结。

## 3. 文件地图

| 文件 | 作用 |
|---|---|
| `01_CURRENT_SYSTEM.md` | 当前最佳理论、权威对象、稳定结论、薄弱假说和第一现实闭环边界 |
| `02_LOCAL_RESEARCH_MISSION.md` | 本地研究目标、自主权、动态调度、候选问题与返回条件 |
| `03_EXECUTION_AND_SAFETY_CHARTER.md` | Git、权限、秘密、外部效果、主权边界和本地执行纪律 |
| `04_EVIDENCE_CONTRACT.md` | 任何重大判断必须携带的环境、代码、轨迹、成本与复现证据 |
| `05_CODEX_BOOTSTRAP_PROMPT.md` | 可直接交给本地 Codex 的启动提示 |
| `06_RETURN_PACKET_TEMPLATE.md` | 本地实验室最终返回包的内容与结构 |
| `07_MANIFEST.json` | 任务包版本、文件角色和来源 |
| `templates/` | 持续研究状态、实验卡、决策日志和本地 smoke 模板 |
| `schemas/` | 实验和证据记录的机器可检验结构 |
| `baseline/` | 第五阶段第一现实闭环的最小证据基线，不是完整历史论文集合 |

## 4. 指令优先级

在本地工作区中发生冲突时，按以下顺序执行：

1. 用户明确授权与工作区现有 `AGENTS.md` / 安全政策；
2. `03_EXECUTION_AND_SAFETY_CHARTER.md`；
3. `04_EVIDENCE_CONTRACT.md`；
4. `02_LOCAL_RESEARCH_MISSION.md`；
5. `01_CURRENT_SYSTEM.md`；
6. 其余模板与候选建议。

任何研究目标都不能覆盖真实安全边界。任何现有理论都不能覆盖真实反例。

## 5. 推荐的本地落盘位置

不要散落污染项目根目录。优先创建：

```text
.ai-research/towow-a2a-r5/
  packet/                 # 本任务包的只读副本
  state/                  # 当前研究状态和决策日志
  smoke/                  # 本地执行链 smoke 证据
  runs/                   # 每次实验的原始证据
  reviews/                # 独立实现与盲审结果
  return-packet/          # 最终返回包
```

如果 `AGENTS.md` 规定了其他位置，以工作区规则为准。

## 6. 单一事实原则

- Git、真实文件、测试结果、Agent 调用记录和事件轨迹优先于语言总结。
- 同一事实只在一个权威位置维护；报告、包络和保障案例优先作为派生视图。
- “模型认为”“Agent 实际执行”“代码实际运行”“用户认领”“生产效果”必须分开记录。
- dry-run、影子运行、沙箱成功不得表述为生产落地。

## 7. 返回方式

本地实验室结束本轮连续研究时，应按 `06_RETURN_PACKET_TEMPLATE.md` 生成压缩包，并同时给出：

- 返回包绝对路径；
- 当前 Git 状态；
- 关键结论对应的证据路径；
- 未解决阻塞；
- 下一步最有价值的行动。

把完整压缩包上传回首席研究会话即可继续第五阶段。
